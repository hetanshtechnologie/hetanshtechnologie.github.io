46. Scratchpads and Delegated Discovery

Some problems cannot be solved in a single pass because the agent does not yet know what it needs to know. It must explore, record what it finds, and change direction. Two structures make this reliable: a durable scratchpad that holds intermediate findings outside the fragile conversation, and delegation that sends discovery work to a focused subagent. This chapter explains how to design both and how to keep them from becoming dumping grounds.

Durable scratchpad design

A scratchpad is not the same as the chat transcript. The transcript is a record of messages; a scratchpad is a working set of claims with structure and status. It lives in your application storage, is updated after each reasoning step, and is injected into the model as a compact view. The model may propose changes, but your code decides what is committed.

Design the scratchpad around questions, not paragraphs. A useful record has an id, a question, the evidence collected so far, a current status, and a next action. Statuses should be small and explicit: open, supported, contradicted, abandoned. This turns "the agent is thinking" into an inspectable state machine.

{
  "scratchpad_id": "SP-220",
  "goal": "Explain why the batch job failed on 2026-11-18",
  "entries": [
    {"id": "Q1", "question": "Which service emitted the first error?",
     "evidence": ["log:worker-3 line 812 at 02:14"],
     "status": "supported", "next": "none"},
    {"id": "Q2", "question": "Did the retry policy change that week?",
     "evidence": ["diff:config/retry.yaml shows max_attempts 3 -> 1"],
     "status": "supported", "next": "confirm deployment time"},
    {"id": "Q3", "question": "Was the upstream API degraded?",
     "evidence": [],
     "status": "open", "next": "query status archive"}
  ],
  "guard": "open_entries <= 5 && total_evidence <= 40"
}

The two guards enforce hygiene. Unlimited open questions lead to aimless exploration; unlimited evidence recreates the context problem the scratchpad was meant to solve. When a guard is hit, the agent must close or merge a question before opening another.

Give each evidence item a stable reference — a log line, a diff id, a document and offset. An evidence string with no reference cannot be checked later, and an unchecked finding is just a guess wearing a lab coat.

Hygiene and limits

A scratchpad that never shrinks becomes a second context window with the same problems. Apply three hygiene rules on every update.

  1. One owner per entry. An entry is either a question or a finding, never a mixture. Mixed entries are hard to mark resolved.
  2. Append evidence, overwrite conclusions. Evidence accumulates; the current conclusion is replaced when new evidence arrives, with the previous conclusion retained in a short history.
  3. Close before you open. Cap open questions at a small number — five is a reasonable default — and require a decision to close one before adding another.

Set numeric limits on the scratchpad view injected into the prompt. A practical view includes at most ten entries, at most three evidence items per entry, and a total of roughly 2,000 tokens. Older or lower-priority entries remain in storage and can be fetched on demand. This mirrors the memory discipline from earlier chapters: keep the hot set small, keep the full record available.

Hygiene also means deciding when to discard. If a question has been open for more than a fixed number of tool cycles without new evidence, mark it abandoned and record why. Continuing to carry a dead question wastes attention and invites the model to fabricate an answer to close it.

A scratchpad is not proof. A claim marked supported means "there is a recorded reference," not "the reference was verified." For high-stakes conclusions, add a verification pass that actually opens the cited evidence.

Why delegate discovery

Discovery is the search for information whose shape you do not know in advance. It is a poor fit for the main agent for three reasons. First, it is noisy: failed searches and irrelevant documents pollute the main conversation. Second, it is long: exploring twenty sources consumes context that the main agent needs for reasoning. Third, it is separable: the exploration task has its own goal and can be judged independently.

Delegation addresses all three. A subagent receives a narrow question, explores freely within its own context, and returns a compact summary with references. The main agent never sees the noise, only the result. This is a form of attention isolation — the expensive mess stays in one place.

Work typeKeep with main agentDelegateReason
Understand the user's goalYesNoNeeds full conversational nuance
Search twenty documents for a valueNoYesHigh noise, clear stop condition
Reconcile two conflicting findingsYesNoRequires authority and judgement
Verify a citation actually supports a claimNoYesMechanically checkable
Choose the final answerYesNoAccountability stays with the main agent

Delegate exploration and verification; keep interpretation and decisions. If you delegate the decision as well, you lose the clear line of accountability and make it harder to explain why an action was taken.

Delegation prompts and returns

A delegation prompt must be self-contained. The subagent cannot see the main conversation, so include the goal, the specific question, the sources it may use, the output format, and the stopping rule. Ambiguity here produces a confident but irrelevant report.

A strong prompt follows a fixed skeleton:

  1. Context: one or two sentences of background, without conversational filler.
  2. Task: a single question with a measurable answer.
  3. Allowed sources: an explicit list or a tool with a bounded scope.
  4. Return format: a structured envelope with findings, evidence references, and an unresolved list.
  5. Stop rule: a budget such as "at most 12 tool calls, then report what you have."
return {
  "task_id": "D-77",
  "answer": "max_attempts changed from 3 to 1",
  "findings": [
    {"claim": "config changed on 2026-11-17",
     "evidence": "diff:config/retry.yaml#hunk2", "confidence": 0.93}
  ],
  "unresolved": ["deployment time not confirmed"],
  "tool_calls_used": 9,
  "status": "partial"
}

Note the status and unresolved fields. A subagent that returns only a tidy answer hides its gaps. Requiring it to list what it could not determine lets the main agent decide whether to accept, ask the user, or delegate a follow-up. Cap the return at a fixed size — a few hundred tokens — so delegation genuinely reduces context rather than relocating the bloat.

When several subagents run in parallel, give each a disjoint scope and a unique task id. Overlapping scopes produce duplicate findings and conflicting references; unique ids let the main agent merge results deterministically. If two subagents disagree, do not average their answers — carry both claims with their evidence into the main scratchpad and resolve explicitly.

Combining the two patterns

The scratchpad and delegation reinforce each other. The main agent records what it needs to know as open questions; a subagent is dispatched to resolve one or two of them; its structured return becomes evidence attached to those entries; the status changes from open to supported or contradicted. Because every finding carries a reference and a task id, the chain from final answer back to source is complete.

This loop also makes cost predictable. Each delegation has a tool budget, each scratchpad has an entry cap, and each return has a size cap. You can estimate the maximum work for a task before it starts, which is exactly what you need when an agent runs unattended. Durable discovery is not about letting the model wander; it is about giving wandering a container, a budget, and a memory that survives the trip.

Summary

  • A scratchpad is a structured working set of questions, evidence, and statuses stored outside the transcript.
  • Enforce hygiene with one owner per entry, append-only evidence, and a cap on open questions.
  • Delegate noisy, bounded discovery; keep interpretation and final decisions with the main agent.
  • Write self-contained prompts with sources, a return envelope, and a numeric stop rule.
  • Merge delegated findings into the scratchpad so every claim retains a reference and an owner.
