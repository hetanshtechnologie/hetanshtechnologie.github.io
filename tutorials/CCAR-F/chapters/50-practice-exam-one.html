50. Practice Exam One

How to take this paper

This is an original practice paper written for this book. It is not an official exam and does not reproduce any real question. Work through all twenty questions before reading the answer key. Give yourself forty minutes, use no notes, and treat each question as a design decision rather than a memory test. Every question has one best answer; several may look reasonable.

Scoring guide. 18–20: strong. 14–17: solid with gaps. 10–13: review the domains attached to your misses. Below 10: revisit the relevant chapters before continuing. The score is less important than the reason for each miss.

Questions

1. A team needs to classify support requests into four fixed categories and route each to a queue. The categories never change, the input format is stable, and auditors require identical output for identical input. What is the strongest architectural choice?

  1. A single agent with a classification tool and a routing tool.
  2. A deterministic workflow with a schema-constrained classifier at one stage.
  3. Two subagents that debate the category and return the majority answer.
  4. An agent with extended thinking and a detailed persona.

2. An agent repeatedly calls the same read tool with identical arguments and never reaches a stop condition. Which control best addresses the root cause?

  1. Raise the temperature so the model chooses differently.
  2. Add a paragraph to the system prompt asking it not to repeat itself.
  3. Detect repeated call signatures, halt the loop, and surface an honest failure.
  4. Give the agent a larger tool catalog so it has more options.

3. Which statement best distinguishes a tool from a resource in a tool-integration protocol?

  1. Tools are local; resources are remote.
  2. Tools describe actions the model may request; resources expose data that can be read.
  3. Tools are written in Python; resources are written in JSON.
  4. Tools require authentication; resources never do.

4. A tool's description says "does things with orders". Calls frequently hit the wrong tool. What is the most likely cause?

  1. The tool schema has too few optional parameters.
  2. The description does not give the model enough routing signal about purpose and boundaries.
  3. The model's temperature is too low.
  4. The tool returns errors that are too detailed.

5. A multi-agent system passes conversation history between agents as a growing prose summary. After four handoffs, key identifiers are missing. Which change most directly addresses the problem?

  1. Summarise more aggressively at each handoff.
  2. Increase the context window so more history fits.
  3. Define a typed handoff payload carrying required fields and validation at the boundary.
  4. Add another agent to check the summary.

6. A purchase action cannot be undone. The team currently relies on a prompt instruction that says "always ask the user first". What should replace it?

  1. A longer prompt with examples of asking first.
  2. A programmatic gate at a defined control-flow node that blocks execution until approval is recorded.
  3. A higher step budget.
  4. A second model that grades the first model's intentions.

7. Which best explains why summarising a long conversation loses facts?

  1. Summaries are always written by weaker models.
  2. Compression decides what to omit based on apparent importance, so exact values that looked minor disappear.
  3. Context windows shrink during a session.
  4. Summaries cannot contain numbers.

8. A RAG answer cites a document that was deleted last week. Which check would have caught this earliest?

  1. Verify that the cited identifier is present in the context supplied for this request.
  2. Add more few-shot examples to the answer prompt.
  3. Increase the model's temperature.
  4. Ask the model to sound more confident.

9. A team has one instruction file for a whole monorepo, and rules for the payments service keep being ignored in the web service. What is the most likely cause?

  1. The instructions are too short.
  2. Scope is wrong: service-specific rules should live in subdirectory instruction files that are loaded for that path.
  3. The model cannot read Markdown.
  4. The rules need to be written in XML tags.

10. A JSON-constrained extraction occasionally returns a syntactically valid object with a plausible but invented value. Which control addresses this directly?

  1. Switch to a looser output format.
  2. Swap to a different model family.
  3. Validate the value against an independent source or rule, and route failures to a retry or review path.
  4. Add more examples of the same invented value.

11. In a fan-out/fan-in pipeline, three of five workers succeed and two fail. What is the most defensible default behaviour?

  1. Return the successful three as if nothing failed.
  2. Retry the failed two with backoff, then report partial results with an explicit completeness flag if they still fail.
  3. Restart all five indefinitely.
  4. Convert the failure into a lower temperature setting.

12. Why is per-field confidence more useful than a single overall confidence score?

  1. It is cheaper to compute.
  2. It localises uncertainty, so only the suspect fields need review or re-derivation.
  3. It removes the need for a validation set.
  4. It guarantees the answer is correct.

13. A retrieval system is measured only by the accuracy of final answers. Quality is inconsistent. What measurement change would help most?

  1. Measure retrieval recall separately from generation, so you can tell whether the right evidence was found.
  2. Measure only response length.
  3. Remove the eval set and rely on user complaints.
  4. Increase the number of agents.

14. A remote tool integration must survive server restarts and support many concurrent clients. Which transport choice fits better?

  1. Local standard I/O, because it is simpler.
  2. Streamable HTTP, because it supports remote deployment, sessions, and scalability.
  3. Embedding the server code inside the prompt.
  4. Sending tool definitions as e-mail attachments.

15. Which is the best reason to scope tools per agent rather than giving every agent every tool?

  1. It makes prompts longer.
  2. It reduces selection ambiguity and limits the blast radius of a confused or manipulated agent.
  3. It removes the need for schemas.
  4. It makes models run faster per token.

16. An agent must pause for human approval and resume after a service restart. Which design property is essential?

  1. A longer system prompt.
  2. Durable state that records the exact step, inputs, and pending approval.
  3. A higher temperature on resume.
  4. A single monolithic function call.

17. A team wants a reusable investigation workflow that any project can invoke with a short name. Which Claude Code feature fits best?

  1. A custom slash command or skill with a clear input contract and team distribution.
  2. A longer global instruction file.
  3. A higher permission level.
  4. Removing all context from the repository.

18. A prompt works on five examples but fails on ambiguous real inputs. Which change is most likely to help?

  1. Add a persona describing the model as an expert.
  2. Add constraints, a no-answer option, and examples that cover ambiguous cases.
  3. Remove all examples so the model is "free".
  4. Increase the token budget for the answer only.

19. Tool outputs are filling the context window with large JSON blobs. Which trim strategy preserves the most correctness?

  1. Delete the oldest messages regardless of content.
  2. Filter the payload to required fields, reference the full artefact by ID, and summarise only what is needed.
  3. Replace every output with the word "success".
  4. Stop logging tool calls.

20. A synthesis report mixes claims from two sources that disagree. What should the output do?

  1. Silently choose the more confident wording.
  2. Annotate the conflict, attribute each claim to its source, and state what remains unresolved.
  3. Remove all citations to reduce length.
  4. Regenerate until the disagreement disappears.

Answer key with reasoning

1 — B

Fixed categories, stable input, and an audit requirement all point to determinism. A schema-constrained classifier inside a fixed pipeline gives identical handling for identical input and a testable boundary. Agents and debate add variable paths and cost without adding value.

2 — C

A repeated-call loop is a control-flow defect. Randomness, longer prompts, and more tools do not guarantee termination. Detecting a repeated signature and halting with an honest failure keeps the system bounded and observable.

3 — B

The distinction is capability type: a tool is an action the model may ask the harness to perform; a resource is data exposed for reading. Transport, language, and authentication are separate concerns.

4 — B

Tool descriptions are routing instructions. A vague description gives the model no basis to distinguish neighbouring tools. Schema width, temperature, and error verbosity do not fix selection ambiguity.

5 — C

Prose summaries drop details that seem unimportant at the time. A typed payload with required identifiers and validation at the handoff boundary makes loss detectable. Bigger context and extra agents only delay the problem.

6 — B

Irreversible actions require an enforcement point in code. A recorded approval at a control-flow node cannot be skipped by a persuasive sentence. Prompt-only rules are guidance, not a boundary.

7 — B

Compression is lossy by design. The summariser predicts what matters, and exact values often look minor. Mitigations include persistent fact blocks and explicit preservation of identifiers.

8 — A

Groundedness means claims are supported by supplied evidence. Checking that a citation exists in this request's context catches stale or fabricated references before the answer is shown. Style changes cannot detect a missing document.

9 — B

Instruction hierarchies exist to scope rules. Service-specific conventions belong in files loaded for that path. A single global file cannot express local precedence, regardless of length or formatting.

10 — C

A valid schema guarantees shape, not truth. Independent validation against a rule or source is the direct control, with a retry or review path for failures. More examples of a wrong value reinforce the wrong behaviour.

11 — B

Partial failure must be explicit. Retry transient failures with backoff, then report what completed and what did not, with a completeness flag. Silent partial success is a correctness bug.

12 — B

Field-level scores localise uncertainty. A single global score cannot say which part of a record is suspect, so it cannot drive targeted review. Calibration is still required for either form.

13 — A

End-to-end accuracy conflates retrieval and generation. Measuring recall@k on labelled queries tells you whether the right evidence is being found, which determines where to spend effort.

14 — B

Remote, concurrent, restart-tolerant deployments favour a network transport with session support. Standard I/O is appropriate for local processes and does not meet these requirements.

15 — B

Fewer tools reduce selection ambiguity and constrain what a manipulated agent can do. Schemas are still needed; per-token model speed is not meaningfully changed.

16 — B

Resume after restart requires durable state: the current step, inputs, decisions, and the pending approval. Without it, the system either restarts work or loses the safety gate.

17 — A

A named, reusable command or skill with a defined input contract is the right unit for a shared workflow. Global instructions, permissions, and context removal do not create an invokable workflow.

18 — B

Ambiguity needs explicit handling: constraints, a defined abstain path, and examples near the boundary. Personas and unbounded answers do not resolve unclear cases.

19 — B

Filtering to required fields, referencing full artefacts by ID, and summarising selectively preserves correctness while reducing volume. Blind deletion and blanket compression destroy evidence.

20 — B

Synthesis must surface disagreement. Annotating the conflict with source attribution preserves information and lets the reader decide. Confidence wording without attribution hides the problem.

Reviewing your result

For every miss, write one sentence naming the principle you forgot, then find the chapter that covers it. If two different questions miss for the same reason, that reason is a study topic. Repeat the paper in a week; a correct answer reached for the wrong reason still needs review.

Exercise 50.1 — Error taxonomy. Sort your misses into three buckets: wrong boundary (who owns the decision), wrong control (what mechanism fits), and wrong trade-off (cost versus safety). Which bucket is largest?
Exercise 50.2 — Rewrite one distractor. Choose a wrong option from a question you missed and rewrite it so that it becomes the correct answer. This forces you to articulate the distinguishing principle.

Check your understanding

  1. Why is a fixed workflow preferred for audited, stable classification?
  2. What property makes a tool description useful for routing?
  3. Why does a typed handoff payload outperform a prose summary?
  4. What does a completeness flag communicate in a partial fan-out result?
  5. Why must conflict in sources be annotated rather than resolved silently?

Summary

  • Twenty original scenario questions spanning architecture, tools, orchestration, reliability, Claude Code, prompting, and context.
  • Every answer includes the reasoning, not just the letter.
  • Use the result to locate weak domains and unclear principles.
  • Re-answer misses after a week rather than re-reading the whole paper.
  • Practise explaining why wrong options are wrong, not only why the right one is right.
