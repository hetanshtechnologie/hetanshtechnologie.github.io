Chat Agents & Advanced Workflows

Once you are comfortable with completions and chat, the real leverage comes from making Copilot know your project and act on it. This chapter covers the built-in chat agents, custom instructions, reusable prompts, spec-driven development, and AI code review.

1. Chat agents (@-mentions)

In chat, prefixing your message with an agent turns Copilot into a specialist. These are the most common built-in agents in VS Code:

AgentWhat it is good at
@workspaceQuestions about the whole repository: file structure, how a feature is wired, where a symbol is used. Builds/uses a local code index.
@terminalGenerates a shell command, explains an error, or suggests a terminal workflow.
@vscodeQuestions about editing: settings, keymaps, extensions, debugging config.
@githubGitHub-specific help: issues, PRs, actions workflows, Codespaces (requires connecting your GitHub account).
(Writing/fixing agents)Versions that carry context like files/tests to draft or fix features in a plan-review-apply loop.

Example: select a broken test, then @workspace /fix — the agent walks your repo to understand the code under test, then proposes a fix across files.

You can also create your own agents (VS Code): a markdown file .github/copilot-agents/<name>.md defines the agent's description, instructions, and which tools it can use (e.g., read_file, edit_file). This is how teams encode "someone who knows our build system" as a reusable persona.

2. Custom instructions (repository guidelines)

Want Copilot to always match your team's conventions? Add a file in the repo:

# .github/copilot-instructions.md
- Use TypeScript strict mode everywhere.
- Prefer named exports over default exports.
- Write tests for every new function (vitest).
- Use the repository pattern for database access, never raw queries in controllers.
- Error messages must follow "action_cannot_be_performed_on_entity" snake_case keys.
  • The file lives at .github/copilot-instructions.md (or a folder .github/instructions/*.md).
  • It applies to completions and chat for files in that repo when the workspace is opened in supported editors on a plan that honors it.
  • It is guidance, not a guarantee — model weight vs. instruction differs across contexts.
  • Point VS Code at extra files via github.copilot.chat.codeGeneration.instructions (shown in Chapter 2).

3. Reusable prompts (.prompt.md)

Turn a prompt you paste over and over into a named command the whole team can use:

# .github/prompts/review-api.prompt.md
---
description: Review an API endpoint for correctness and security
---
You are a senior platform engineer reviewing this API endpoint.

Check: authentication, authorization, input validation, SQL injection,
rate limiting, error handling, and OpenAPI metadata consistency.

Report findings as a table (Severity / Line / Issue / Suggested fix)
and end with a one-line verdict. Do NOT rewrite code unless asked.

Use it in chat with /review-api. Prompts live in .github/prompts/*.prompt.md (VS Code) or as *.prompt.md files your team checks in; newer versions also synchronize them with GitHub via the Copilot settings repo.

4. Spec-driven development (Copilot Specs)

For bigger changes, describe the system in plain text and let Copilot write it: the specdev workflow (GitHub's open-source spec-kit/copilot-spec CLI and VS Code "Create project from spec" experience) turns a requirement into chapters, then into a plan of code. The loop is:

  1. Spec — write the behavior as a doc with "Do", "Don't", and assumptions.
  2. Plan — Copilot generates ordered, file-level tasks.
  3. Code — implement file by file under your review.

The same idea works with the CLI: gh copilot multi-turn-command (or chat) can hand context between "add the endpoint" and "add the tests".

5. AI code review

Copilot can review code before you commit and in pull requests:

  • Editor review — the extension reviews changed lines and surfaces issues in the Problems panel / review pane.
  • PR review — enable Copilot code review for a repository; it comments on PRs with findings (docs, performance, security, correctness).
  • Custom review prompts — team rules written in the Copilot settings / instructions are applied when reviewing.
Instructor view: treat AI review as a cheap first pass, not a linter oracle. Merge its findings with your own judgment, especially around business logic and security decisions — the same rules apply to human teammates.

6. The CLI (gh copilot)

gh auth login
gh copilot suggest "connect to the postgres DATABASE_URL and run a migration"

The CLI gives you a pair programmer in the terminal: explain commands, generate shell one-liners, and script multi-step tasks. Useful for SSH sessions, Docker, git, and CI debugging where an editor cannot help.
