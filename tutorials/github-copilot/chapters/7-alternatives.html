Alternatives & Bonus Tools

Copilot is the right default for many people, but it is not the only good AI coding tool — and the landscape moves fast. This final chapter tours the main alternatives so you can choose deliberately, revisits custom instructions now that your skills have grown, and ends with the responsible-AI habits that protect you in every tool.

1. Claude (Anthropic)

Claude is Anthropic's model family, and Claude Code is its coding agent (CLI + editor integrations). It is especially strong at long, multi-turn reasoning and careful code review:

ToolWhat it isStrong atWatch for
Claude CodeTerminal-based agent that reads your repo, plans, edits, and runs commandsLong autonomous multi-file tasks, refactors, "explain this codebase"You still review; token usage can climb fast
Claude in copilotsModel option inside some editors and GitHub Copilot model pickerChat reasoning, long conversationsModel availability differs per plan

Try it for the exact exercise from Chapter 6 — a paginated table — and compare the agent's plan, its diff, and how clearly it explains its own changes. That comparison matters more than any benchmark.

2. Vercel v0

v0 is a UI-generation service: you describe a screen, it returns React/Tailwind (and increasingly shadcn/ui, Next.js) code you can import. Where Copilot works in a codebase, v0 works at the beginning of an interface:

  • Great for: idea stage, design exploration, a dashboard mockup, a landing page, or a component library look-and-feel.
  • Workflow: describe → iterate on natural language → copy the React snippet (or install via shadcn) into your project → adapt.
  • Limit: it generates presentation, not your business logic. The real wiring — data, auth, state — is still your job (with Copilot).
Best practice: keep v0 for ideas and Copilot for the repo. Do not paste proprietary design assets or client data into either tool unless your policy allows it — the same rule as Chapter 4, everywhere.

3. Cursor AI

Cursor is an AI-first editor (a VS Code fork) where AI is the core, not an extension. It popularized Tab completions that edit multiple lines at once, a chat that understands the whole project (@codebase), and an agentic Composer for multi-file work.

  • Why people switch: feels faster out of the box; model choice is flexible; the cursor-level whole-file completion is genuinely different from classic ghost text.
  • Why people stay with Copilot: your GitHub identity, org policy and audit are already there; Copilot ships the same ideas (edits, agent mode, agents) into the editor you already use.
  • Practical takeaway: the prompting skills you learned here transfer 1:1. Explain the stack, give constraints, select code, review every diff.

4. Codeium (Windsurf) and others

Beyond the famous names are several capable tools, many with free tiers — course the ones worth knowing:

ToolPositioningNote for beginners
Codeium / WindsurfCompletions + chat + an agent ("Cascade") in a fast editor experienceGenerous free tier; good for trying agent workflows without a paid plan
TabninePrivacy-focused completions, on-prem / local model optionsChoose this if strict data-residency rules matter more than chat
Other chat models (GPT-4o / o-series, Gemini, etc.)Standalone chatbots or model options inside the tools aboveSolid for explanations and greenfield drafts; no native editor context unless integrated

Decision template — pick your tool by answering four questions, in order:

  1. Where does the code live? Editor-integrated tooling beats copy-paste chatbots for anything in a repo.
  2. What are your org's data rules? Secrets, IP, and compliance decide between cloud, regional, and local options.
  3. What is your budget? Free tiers are real for completions; agent mode and premium models are usually paid.
  4. Who is on your team? Shared policies, review habits, and consistency beat the "best model of the week."

5. Custom instructions: the update now that you are further along

In Chapter 4 you learned .github/copilot-instructions.md. Revisit it now with the experience from Chapters 5-6 — a mature instruction file goes beyond styling:

# .github/copilot-instructions.md (grown-up version)
## Stack
- Next.js 15 App Router + TypeScript; Express/Nodemon for the API; FastAPI for Python tooling.
## Conventions
- Server Components by default; client only for interactivity.
- No table/UI libraries unless asked; Tailwind utility classes only.
- Typed responses everywhere — never 'any'. Errors are thrown, not swallowed.
## Review gates (agents & edits)
- Add loading and error states for every fetch.
- Preserve existing behavior on refactors; add a smoke test that compares.
- No hardcoded keys or URLs; read from env with a clear failure message.
## Commits
- Conventional commits: type(scope): subject.

Two upgrades to make it count:

  • Publish as prompts too. The same content parses into .github/prompts/*.prompt.md for named slash commands (e.g., /scaffold-page). One source of truth, two surfaces.
  • Version it in the repo so a PR to the instruction file is reviewable like any code change — and your team can disagree productively.

6. Responsible AI practices (everything, consolidated)

Whatever tool you settle on, these habits never change:

  • Human in the loop. You approve every plan and diff. AI suggests; you decide. (The reviewer is always you.)
  • No secrets, no customer data. Keys, tokens, .env, and PII stay out of prompts and out of copied fixtures. Re-check before every paste — habits decay.
  • Sanitize untrusted text. Logs, scrapes, and emails can carry prompt injection; treat AI output as untrusted too and validate it like a stranger's PR.
  • Know the licensing boundary. Copilot can match public code; tools differ in how they surface and filter it. Keep the org's filtering on for proprietary work, and check affected code at the endpoint you ship.
  • Read before you run. Agent mode now runs build/test commands. That power is the point — and the reason your diff review is non-negotiable.
  • Test the output, not the vibes. A green npm run build is not correctness. Real tests, real reviews, real edge cases.
Where tools differ: telemetry, retention, and code-reuse policies are per-product and per-plan. Read the privacy terms of each tool before you let it near customer code — never assume "it's like Copilot."

7. What to build next

You have the full toolkit now. Turn the book upside down — teaching beats reading:

  1. Rebuild CashTrack's chart, CSV, and receipts from memory — no book, no prompt template — and let Copilot fill the gaps you forgot.
  2. Give a colleague an hour of "Copilot 101": setup, prompt template, review gates. Explaining it is the fastest way to find the holes in your own understanding.
  3. Contribute the copilot-instructions.md you grew to your team's repo and watch what breaks in the first sprint. Fix the rules, not the code.
✏️ Final exercise: (a) Run the same "paginated employees table" goal in two tools (e.g., Copilot agent mode and Claude Code or Cursor) and write a one-page comparison: plan quality, diff readability, failure recovery. (b) Upgrade your copilot-instructions.md with the Section-5 template, then run one agent task and confirm it obeyed a rule you added. (c) Write down your three personal "never automate" rules — the things you will always review manually — and keep them next to your keyboard.
