Server-Side: Express, Email & Python

CashTrack is a browser-only app. In this chapter you give it a backend — an Express server that stores transactions and emails a receipt — and then cross the line into Python, because Copilot has one of the best "translate my JS into Python" moves in the business.

1. Generate server code with Express (prompt tips)

Server code is a great Copilot target because the shape is institutional. Watch the prompt techniques that make it clean:

Panel (new thread, give the stack up front):
> Create an Express 4 server (Node 22, CommonJS) in server.js:
>   - POST /api/transactions   : validate {description, amount, type, category} with zod;
>                               require type in ['income','expense']; reject amount <= 0;
>                               store in an in-memory array; return 201 + the created row.
>   - GET  /api/transactions   : return all rows.
>   - PUT  /api/transactions/:id : update amount/description only.
>   - DELETE /api/transactions/:id : remove row, 404 if missing.
>   - Graceful errors: express.json() with a 500 handler that logs but returns a generic message.
>   - No database yet, no dotenv clutter: PORT from process.env.PORT || 3000.

Prompt tips used here (memorize these): state the stack+module system, enumerate endpoints with methods and status codes, give the field schema, and declare constraints (validate rules, no DB, no dotenv). Then verify with curl:

curl -X POST localhost:3000/api/transactions -H "Content-Type: application/json" \
  -d '{"description":"site hosting","amount":1200,"type":"expense","category":"hosting"}'
Fidelity check: always re-read the generated endpoint for the two things beginners skip — express.json() middleware actually mounted, and the order of 404 vs. 500 handling.

2. Setup sending emails with Resend

Email providers like Resend give you one API key and one SDK. Copilot wires the boilerplate fast; you supply the API key and the design decisions. Prompt for the whole flow, then split the apply/verify steps:

Panel:
> Add a POST /api/receipts endpoint that emails a transaction receipt using the Resend SDK
>   (from "resend"). Config: RESEND_API_KEY (env), from: "CashTrack <receipts@example.com>",
>   to comes from the request body. Email must include the transaction description, amount,
>   type and a plain-text body AND an HTML body with a simple table. Return 202 accepted,
>   and 400 if "to" is missing or invalid. Keep the API key out of source code.

Then follow-up:
> Handle the case where Resend SDK isn't installed: give me the npm install command for it,
> and make the endpoint import only if present (defensive) — actually, use the normal import and
> I'll install before running.

Security rules for email + AI:

  • Read the key from process.env or a secret manager — never ask Copilot to hardcode it (it may happily comply).
  • Validate to addresses server-side; email flows are spam/injection targets.
  • Ask Copilot to add an allow-list or rate limit if the endpoint could be spammed.

3. Convert JavaScript to Python step by step

This is one of Copilot's magic moments. Take CashTrack's downloadCsv (Chapter 3) and ask for a Python API that does the same job:

Copy the JS function into chat with a selection, then:
> Port this exact behavior to Python using only the standard library:
>   - function csv_for(transactions: list[dict]) -> str
>   - columns date, description, category, type, amount
>   - escape embedded double-quotes by doubling; wrap fields containing commas or quotes
>   - expense amounts prefixed with '-'
>   - prepend a UTF-8 BOM and use '\\n' line endings
>   - produce the same output string as the JS for identical input.

Why this prompts works: it pins behavior (the JS is the executable spec), constraints (stdlib, function signature), and equivalence (same output for same input). The counterpart function — downloadCsv → csv_for — is the kind of dry, fiddly function perfect for AI.

4. Generate a Python API endpoint

Panel:
> Add a FastAPI endpoint POST /trends that takes {transactions: [...]} and returns
>   {"labels": [...], "values": [...]} for expense totals grouped by category,
>   sorted descending, computed in pure Python (no pandas). Use pydantic for the input model,
>   custom validation: empty list → 422, unknown 'type' → 400.
> Also give me the uvicorn command to run it.
  • Copilot will happily pick a framework; you should tell it which (FastAPI vs. Flask). The course favors explicitness.
  • Ask for the run command and the health-check curl in the same thread — fewer windows to search.

6. Full-stack wiring prompt (what you just learned, combined)

@workspace -- "Connect the pieces we built: in Electron-but-simpler terms, make the CashTrack
  front-end POST new transactions to the Express server, and GET from it on load. Replace the
  localStorage persistence with the API. Keep the chart and CSV logic exactly as-is. Add a note
  in the README about running the server first."

One request, four files touched. Copilot Edits (Chapter 4) is the right surface for this — watch it change app.js, server.js, and the README while your review gates each diff.
