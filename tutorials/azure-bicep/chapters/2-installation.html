Chapter 2: Installation & Setup

2.1 Prerequisites

  • An Azure subscription (free account works for the examples in this book)
  • Azure CLI (recommended, works on Windows/macOS/Linux) or Azure PowerShell
  • A text editor — VS Code recommended for the best Bicep experience

You do not need to run the Bicep compiler directly for most workflows — the Azure CLI bundles Bicep and can install/update it for you.

2.2 Installing the Bicep CLI

Option A — Install via Azure CLI (recommended)

If you use Azure CLI, let it manage the Bicep CLI for you:

# Install the latest version of the Bicep CLI
az bicep install

# Show the installed version
az bicep version

# Upgrade when a new version ships
az bicep upgrade

This places bicep.exe (or bicep) in a cache folder managed by the CLI.

Option B — Install the standalone Bicep CLI

# Windows (PowerShell)
winget install Microsoft.Bicep

# Linux
curl -Lo bicep https://github.com/Azure/bicep/releases/latest/download/bicep-linux-x64
chmod +x ./bicep
sudo mv ./bicep /usr/local/bin/bicep

# macOS (Homebrew)
brew tap azure/bicep
brew install bicep

# Any platform with .NET SDK 8+
dotnet tool install -g Azure.Bicep

Verify the install

bicep --version
# Bicep CLI version 0.31.92 (…)

bicep --help         # list all commands

2.3 The Bicep CLI Commands You'll Actually Use

bicep build main.bicep            # compile to ARM JSON (main.json)
bicep build --stdout main.bicep   # print JSON without writing a file
bicep decompile main.json         # try converting an ARM template back to Bicep
bicep format main.bicep           # auto-format your file
bicep lint main.bicep             # run the built-in linter
bicep publish main.bicep --target br:...   # publish a module to a registry
bicep restore main.bicep          # fetch registry modules referenced by the file
Tip: bicep build is your safety net — run it after every edit to catch syntax, type, and linter errors before anything touches Azure.

2.4 Integration with Azure CLI

The most common way to deploy Bicep is through Azure CLI. Sign in and set your default resource group:

az login                              # opens a browser to sign in
az account set --subscription "My Sub" # pick a subscription
az group create --name rg-bicep-demo --location eastus

# Preview then deploy
az deployment group what-if \
  --resource-group rg-bicep-demo --template-file main.bicep

az deployment group create \
  --resource-group rg-bicep-demo --template-file main.bicep

If a main.parameters.json file sits next to main.bicep, the Azure CLI loads it automatically. You can also pass parameters inline:

az deployment group create \
  --resource-group rg-bicep-demo --template-file main.bicep \
  --parameters storageAccountName=mystor1000 environment=dev

PowerShell users have an equivalent: New-AzResourceGroupDeployment -TemplateFile main.bicep.

2.5 VS Code Integration (The Best Free Tooling)

Install the official Bicep extension by Microsoft from the VS Code marketplace (Extensions panel → search "Bicep"). What you get for free:

  • IntelliSense — autocomplete for resource types, property names, and API versions
  • Inline validation — errors underlined as you type, without running a build
  • Quick fixes — "Add resource property", "Fix naming conflict", snippet insertion
  • Go to definition / references across modules and parameters
  • Decompiling — convert an ARM JSON file by right-clicking
  • Bicep gallery — snippets for common resources (storage, app service, etc.)

{
  "bicep.enableTelemetry": false,
  "[bicep]": { "editor.formatOnSave": true },
  "editor.defaultFormatter": "ms-azuretools.vscode-bicep"
}

2.6 First Project Structure

A small, well-organised Bicep project looks like this:

webapp-infra/
├── deployment/
│   ├── main.bicep              ← entry point (what you deploy)
│   ├── main.parameters.dev.json
│   └── main.parameters.prod.json
├── modules/
│   ├── app-service.bicep
│   ├── storage.bicep
│   └── sql.bicep
└── .vscode/
    └── settings.json

This layout keeps the entry point thin (just parameters and module calls) and hides the details inside modules. You'll build exactly this kind of project in Chapters 4 and 7.

No VS Code / CLI on your machine? Bicep also works in Azure Cloud Shell (bash or PowerShell) — run az bicep install there and you're ready without installing anything locally.
Summary & Checklist:
  • Install Bicep via az bicep install or the standalone CLI
  • Learn the core commands: build, format, lint, decompile
  • Deploy with az deployment group create --template-file main.bicep
  • Always run what-if before creating a deployment
  • Install the official VS Code Bicep extension for authoring
  • Structure projects as: thin main.bicep entry point + reusable modules/
