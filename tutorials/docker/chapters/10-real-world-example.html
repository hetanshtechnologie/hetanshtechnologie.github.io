Real-World Example: Deploy a Web App with Docker Compose

Now the entire book converges into one believable, working stack: a Flask API, a PostgreSQL database with a named volume, and an Nginx reverse proxy in front — all orchestrated by Compose. Copy the files, run the commands, and you will have deployed a real multi-service production-shaped app in under two minutes.

10.1 The stack

Diagram (described in text): browser traffic enters on the left at nginx on port 80. Nginx proxies to the Flask app container on its internal "web" network port 5000. The Flask app reads/writes Postgres across the same network, and Postgres stores data in the named volume "pgdata", with database healthchecks drawn between app and db.

10.2 The files

app/app.py — a tiny API with a health endpoint and a counter backed by Postgres:

import os, time
from flask import Flask, jsonify
import psycopg2

app = Flask(__name__)
DB = os.environ["DATABASE_URL"]

@app.get("/healthz")
def health():
    return jsonify(ok=True)

@app.get("/")
def hit():
    conn = psycopg2.connect(DB)
    cur = conn.cursor()
    cur.execute("CREATE TABLE IF NOT EXISTS hits (n int)")
    cur.execute("UPDATE hits SET n = COALESCE(n,0) + 1 RETURNING n")
    row = cur.fetchone()
    if row is None:
        cur.execute("INSERT INTO hits (n) VALUES (1) RETURNING n")
        row = cur.fetchone()
    n = row[0]
    conn.commit(); conn.close()
    return jsonify(hits=n)

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)

app/Dockerfile — remember Ch. 5: copy manifests first, run as non-root, CMD=default args.

FROM python:3.12-slim
WORKDIR /opt/app
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app.py .
RUN useradd -mr appuser
USER appuser
EXPOSE 5000
ENTRYPOINT ["python", "app.py"]

app/requirements.txt:

flask==3.0.3
psycopg2-binary==2.9.9

docker-compose.yml — watches the app dir for changes (bind mount), waits for db health, publishes only nginx:

services:
  proxy:
    image: nginx:alpine
    ports:
      - "80:80"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - app
    restart: unless-stopped

  app:
    build: ./app
    environment:
      DATABASE_URL: postgresql://postgres:devpass@db:5432/app
    volumes:
      - ./app:/opt/app          # dev: live-reload of code
    depends_on:
      db:
        condition: service_healthy
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: devpass
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d app"]
      interval: 5s
      timeout: 5s
      retries: 10
    restart: unless-stopped

volumes:
  pgdata:

nginx.conf — the only published entry point:

server {
    listen 80;
    server_name _;
    location / {
        proxy_pass http://app:5000;
        proxy_set_header Host $host;
    }
}

10.3 Deploy it

# from the directory holding docker-compose.yml
docker compose up -d --build
docker compose ps            # 3 services: proxy, app, db — all healthy/running
curl http://localhost/healthz        # {"ok": true}
for i in 1 2 3; do curl -s http://localhost/; done     # hits: 1, 2, 3
docker compose logs -f app

10.4 Prove the persistence and the proxy

# counter survives a restart because the data is in the pgdata volume
docker compose restart app
curl -s http://localhost/               # hits: 4 — not reset!
# but the bind mount + volume survive even "down"; only down -v resets them
docker compose down && docker compose up -d
curl -s http://localhost/               # hits: 5 — still counted

If you run docker compose down -v, the volume is deleted and the counter resets to 1 — that's the "I destroyed my data" moment from Ch. 8, demonstrated safely on purpose.

10.5 Scale the worker pattern and clean up

docker compose up -d --scale app=2          # Compose serves 2 app containers behind nginx
docker compose ps
docker compose down                          # stop everything, keep pgdata
docker compose down -v                       # full reset (demo only)

10.6 Production notes on this exact stack

  • Secrets: devpass is in the file for demo. Real deploys use env from a vault or Docker secrets (Ch. 9.2).
  • Single host: Compose can't fail apps over or place replicas across hosts. When that matters, this same stack's images run under Swarm/Kubernetes (Ch. 12).
  • Backup: docker compose exec db pg_dump -U postgres app > backup.sql — schedule it in your ops routine (Ch. 6 pattern).
  • Resource limits: add deploy.resources.limits.memory: 256M per service before load-testing.

Summary

You built and ran a three-service stack: Nginx (port 80) → Flask (internal) → Postgres (named volume, healthchecked), with live code-reload via a bind mount and counters that survive restarts thanks to volumes. That's the entire Docker career's daily motion in one small project.
