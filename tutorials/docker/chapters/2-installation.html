Installing Docker (Windows, Linux, macOS)

You need two things to run containers: Docker Engine (or its Desktop bundle) and the Docker CLI. On Windows and macOS, the easiest path is Docker Desktop, which runs Linux containers inside a small VM. On Linux, you install the Engine directly and talk to it over a local socket.

2.1 Windows

  1. Enable the Windows Subsystem for Linux (WSL2 backend):
    wsl --install (run in an admin PowerShell; reboot when asked).
  2. Check the WSL version: wsl --set-default-version 2 and wsl -l -v (want VERSION 2).
  3. Download Docker Desktop for Windows and install it. During install choose Use WSL 2 instead of Windows Hyper-V.
  4. Launch Docker Desktop; wait for the whale icon in the tray to say Engine running.
# verify from a terminal
docker --version
docker info --format '{{.ServerVersion}}'
docker run hello-world
WSL2 disk space gotcha: Docker stores images inside the WSL2 VHD (docker-desktop-data). It can silently grow to tens of gigabytes. If you hit "no space", see Ch. 11 — don't just delete C:\Users\...\AppData files.

2.2 Linux (Ubuntu/Debian as the example)

# remove any old packages
sudo apt-get remove docker docker-engine docker.io containerd runc

# add Docker's official repo + key
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg |
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" |
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# give your user access to the daemon (avoids "permission denied" on /var/run/docker.sock)
sudo usermod -aG docker $USER
# log out and back in, then test
docker run hello-world
Why the group step matters: by default only root and members of the docker group can talk to the daemon socket. Adding your user to docker is equivalent to root access to the host — be careful with it on shared/multi-tenant machines (see Ch. 9's security notes).

2.3 macOS

  • Docker Desktop for Mac (Apple Silicon or Intel): download, drag to Applications, grant the requested permissions.
  • Homebrew + colima (lighter alternative): 
    brew install docker docker-compose colima
colima start --cpu 4 --memory 8
docker run hello-world

2.5 Sanity check: your first real container

docker version            # both "Client" and "Server" sections present = healthy
docker run -d --name web -p 8080:80 nginx
curl -s http://localhost:8080 | head -c 100    # you should see "<!DOCTYPE html>..."
docker stop web && docker rm web               # or: docker rm -f web

Diagram (described in text): your terminal (the client) → a local socket → the Docker daemon → pulls the nginx image from Docker Hub → runs a container publishing port 8080 on localhost.

Did "server" not appear on Windows/mac? Start Docker Desktop and wait for "Engine running"; the CLI then finds the daemon. On Linux, run sudo systemctl status docker and start it if stopped. Both cases land in Ch. 11 if they persist.

Summary

Install Docker Desktop on Windows and macOS (WSL2 or the built-in VM), or Docker Engine + compose plugins on Linux. Give your Linux user socket access, enable the service to start on boot, then prove the whole chain with docker run hello-world and one nginx container.

Checklist

  • ☐ docker version shows Client and Server sections.
  • ☐ docker run hello-world completes with "Hello from Docker!".
  • ☐ I ran nginx on a mapped port (curl http://localhost:8080 returns HTML).
  • ☐ Docker starts on boot / with the app (I know how on my OS).
  • ☐ I can explain whether I use Engine or Desktop and where the daemon lives.
