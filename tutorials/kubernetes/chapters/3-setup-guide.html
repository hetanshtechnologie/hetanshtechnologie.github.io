Setup Guide: Your First Local Kubernetes Cluster

Time to get your hands dirty. By the end of this chapter you will have a real, working Kubernetes cluster running on your own laptop, and you will be talking to it with kubectl — the exact same tool professionals use against cloud clusters.

What you will install

ToolWhat it isWhy you need it
kubectlThe command-line client for KubernetesEvery single command in this course goes through it
Minikube or kindTools that run a full (single-node) Kubernetes cluster on your laptopSo you can practice against a real API server
A container runtime (Docker/containerd)Runs the actual containersBoth local cluster tools need it
Choosing the local cluster tool: Minikube is the friendliest for beginners (it includes an Ingress add-on, a dashboard, and a tunnel command we will use in Chapter 4). kind (Kubernetes in Docker) starts in seconds and is loved by developers who work in terminal-heavy flows. Start with Minikube; both are installed below.

Prerequisites

  • RAM: at least 4 GB free (8 GB recommended).
  • Disk: about 20 GB free for images and cluster state.
  • Virtualization: enabled in your BIOS (check systeminfo / Task Manager → Performance → CPU → "Virtualization").
  • A package manager on Windows (we use winget, built into Windows 10/11) or Homebrew on macOS.

Step 1 — Install kubectl

Windows (winget)

winget install Kubernetes.kubectl

macOS (Homebrew)

brew install kubectl

Linux (direct binary)

curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl

Verify it works (open a new terminal so the PATH refreshes):

kubectl version --client

Step 2 — Install a container runtime (Docker)

Install Docker Desktop from docker.com/products/docker-desktop, then start it and leave it running. Minikube and kind will create their nodes inside Docker. On Linux you can alternatively install containerd and let Minikube use it (minikube start --container-runtime=containerd).

Windows users: after installing Docker Desktop, make sure it is using the WSL 2 backend (Docker Desktop settings → General → "Use the WSL 2 based engine"). It is the default and works best with Minikube.

Step 3 — Install and start Minikube

Windows

winget install Kubernetes.minikube

macOS

brew install minikube

Start your first cluster (this downloads a small VM/image, give it a couple of minutes):

minikube start --driver=docker --cpus=2 --memory=2048

You should see output ending with something like Done! kubectl is now configured to use "minikube".

Prefer kind? Two commands instead

brew install kind          # macOS :: or: winget install Docker.Kind / scoop install kind
kind create cluster --name dev

kind gives you a cluster in ~30 seconds. Everything in this course works on both.

Step 4 — Connect and confirm

Check which cluster kubectl is pointed at, and whether the connection works:

kubectl config get-contexts     # every row is a cluster you can talk to
kubectl config current-context  # the one kubectl is using right now
kubectl cluster-info            # confirms the API server is reachable
kubectl get nodes               # should list your minikube/kind node as Ready

You are now doing real cluster administration. The command kubectl get nodes output looks like:

NAME       STATUS   ROLES           AGE   VERSION
minikube   Ready    control-plane   2m    v1.29.0
Switching clusters while you learn: each local cluster tool writes a different "context" to your ~/.kube/config file. kubectl config use-context minikube (or dev for kind) points kubectl at the right one if things ever get mixed up.

Your first ten kubectl commands

This is the complete vocabulary you need for the next chapter:

CommandWhat it does
kubectl get podsList pods in the current namespace (short: kubectl get po)
kubectl get deploymentsList deployments (short: kubectl get deploy)
kubectl get servicesList services (short: kubectl get svc)
kubectl get allList the most common resource types in one screen
kubectl describe pod <name>Show detailed events/status for one object — the #1 debugging command
kubectl logs <pod>Show a pod's container logs (add -f to follow, like tail -f)
kubectl exec -it <pod> -- shOpen a shell inside a running container
kubectl apply -f file.yamlCreate or update resources from a YAML file
kubectl delete -f file.yamlDelete everything described in a file
kubectl get pods -o wideExtra columns (node, pod IP) — great for understanding networking
Aliases you will love: po, deploy, svc, ns, no, configmap (or cm), secret, pv, pvc, ing. Kubernetes supports them for almost every resource.

Troubleshooting your first minutes

SymptomFix
Docker Desktop not runningStart Docker Desktop and wait for the whale icon to stop animating, then minikube start again
kubectl not foundReopen terminal, then kubectl version --client; reinstall via package manager if needed
unable to connect to the serverMinikube stopped? Run minikube start first
Node stuck not-ReadyVirtualization disabled in BIOS; check RAM; try minikube delete && minikube start
Wrong cluster being usedkubectl config use-context minikube
