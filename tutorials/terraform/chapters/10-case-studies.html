Case Study 1 — Multi-Cloud Web Application

1.1 Scenario

A SaaS analytics platform serves customers in 14 countries. The product team requires the lowest possible latency for its React SPA and REST API, plus global CDN delivery. Regulatory contracts mandate that user PII never leaves a specific GCP region while telemetry can land on AWS. The architecture therefore spans three providers.

SPA hostingAzure App ServiceExisting AD integration; lower latency for primary market (NA/EU)
Analytics backendAWS Lambda + API GatewayPer-request billing matches spiky usage; mature Python ecosystem
CDN originGCP Cloud StorageRegulatory: assets with PII stay in GCP us-central1; CDN serves globally

DNSCloudflareSingle global load balancer; shields origin IPs; DDoS protection included

# modules/aks-namespaces/variables.tf

variable "teams" {
  description = "Map of team name to list of service names"
  type = map(object({
    services = list(string)
    enable_network_policy = optional(bool, true)
    resource_quota = optional(object({
      cpu    = string
      memory = string
    }), { cpu = "4", memory = "8Gi" })
  }))
}

# modules/aks-namespaces/main.tf

resource "kubernetes_namespace" "team" {
  for_each = var.teams

  metadata {
    name = "${each.key}-team"

    labels = {
      "team"                = each.key
      "managed-by"          = "terraform"
      "cost-center"         = each.key
    }

    annotations = {
      "scheduler.alpha.kubernetes.io/default-cpu-request"    = "250m"
      "scheduler.alpha.kubernetes.io/default-memory-request" = "256Mi"
    }
  }
}

resource "kubernetes_resource_quota" "team" {
  for_each = var.teams

  metadata {
    name      = "${each.key}-quota"
    namespace = kubernetes_namespace.team[each.key].metadata[0].name
  }

  spec {
    hard = {
      "requests.cpu"    = each.value.resource_quota.cpu
      "requests.memory" = each.value.resource_quota.memory
      "limits.cpu"      = "${tonumber(each.value.resource_quota.cpu) * 2}"
      "limits.memory"   = "${tonumber(regex("^([0-9]+)", each.value.resource_quota.memory)[0]) * 2}Gi"
      pods              = "40"
    }
  }
}

resource "kubernetes_network_policy" "deny_all" {
  for_each = { for k, v in var.teams : k => v if v.enable_network_policy }

  metadata {
    name      = "default-deny-all"
    namespace = kubernetes_namespace.team[each.key].metadata[0].name
  }

  spec {
    pod_selector {}
    policy_types = ["Ingress", "Egress"]
  }
}

resource "kubernetes_network_policy" "allow_same_team" {
  for_each = { for k, v in var.teams : k => v if v.enable_network_policy }

  metadata {
    name      = "allow-same-team"
    namespace = kubernetes_namespace.team[each.key].metadata[0].name
  }

  spec {
    pod_selector {}
    policy_types = ["Ingress"]

    ingress {
      from {
        namespace_selector {
          match_labels = {
            team = each.key
          }
        }
      }
    }
  }
}

      groups = [{

            alert = "HighErrorRate"

            for   = "5m"
            labels = { severity = "critical" }
            annotations = {

          }

Case Study 3 — Disaster Recovery Setup

A healthcare platform must meet RPO < 15 minutes and RTO < 1 hour for its patient portal. The primary region is East US 2; the secondary is West US 3. 3.4 Failover Function Logic

# modules/dr-failover/terraform.tfvars.example

# This is NOT executed by Terraform but deployed by it.
# The Python code lives alongside the Terraform module:

# modules/dr-failover/function_code/main.py

# modules/dr-failover/function_code/main.py

import azure.functions as func
import azure.mgmt.trafficmanager as tm
from azure.identity import DefaultAzureCredential
from azure.mgmt.resource import ResourceManagementClient
import os, json, logging

app = func.FunctionApp()

@app.timer_trigger(schedule="0 */5 * * * *", arg_name="timer")
def failover_check(timer: func.TimerRequest) -> None:
    """Every 5 minutes: check primary health, fail over if unhealthy."""

    credential = DefaultAzureCredential()
    subscription = os.environ["WEBSITE_SUBSCRIPTION_ID"]
    rg = os.environ["RESOURCE_GROUP"]
    profile_name = os.environ["TM_PROFILE_NAME"]

    tm_client = tm.TrafficManagerManagementClient(credential, subscription)

    profile = tm_client.profiles.get(rg, profile_name)
    primary_endpoint = profile.endpoints[0]

    if primary_endpoint.monitor_status != "Healthy":
        logging.warning(
            f"Primary endpoint unhealthy ({primary_endpoint.monitor_status}). "
            "Initiating Traffic Manager failover."
        )
        primary_endpoint.enabled = False
        tm_client.profiles.create_or_update(rg, profile_name, profile)
        logging.info("Failover complete — secondary endpoint now active.")
    else:
        logging.info("Primary endpoint healthy. No action taken.")

Case Study 4 — Cost-Optimized Development Environment

4.1 Scenario

Strategy: auto-shutdown VMs at 7 PM, use Spot instances for build agents, dev/test SQL pricing, lifecycle-managed databases, and budget alerts that auto-scale down when thresholds are hit.

These case studies demonstrate that effective Terraform architecture is as much about cost and operational decisions as it is about infrastructure code. Each pattern — multi-cloud federation, Kubernetes composition, cross-region failover, and lifecycle automation — is directly applicable to production workloads. The key principle across all four: codify not just the infrastructure, but the operational behaviors — shutdown schedules, failover triggers, budget guardrails — as first-class Terraform resources.
