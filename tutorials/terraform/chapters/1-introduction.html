Chapter 1: Introduction to Infrastructure as Code and Terraform

1.1 What is Infrastructure as Code?

Infrastructure as Code (IaC) is the practice of managing and provisioning computing infrastructure through machine-readable configuration files, rather than through manual processes or interactive tools. Instead of clicking through a cloud console, you define your desired infrastructure in code files that can be versioned, reviewed, tested, and shared.

Why IaC Matters

  • Repeatability — Deploy identical environments every time, eliminating "works on my machine" issues
  • Version Control — Track every infrastructure change with Git history and blame
  • Speed — Provision hundreds of resources in minutes instead of days
  • Collaboration — Teams review infrastructure changes via pull requests
  • Audit Trail — Complete record of who changed what and when
  • Disaster Recovery — Rebuild entire environments from code in hours

1.2 Why Terraform?

Terraform, created by HashiCorp in 2014, has become the industry standard for cloud infrastructure provisioning. Here's why:

Key Advantages

  • Cloud-Agnostic — Single tool for Azure, AWS, GCP, and 1000+ providers
  • Open Source — Free core with optional Terraform Cloud for teams
  • Mature Ecosystem — Largest provider registry, extensive module library
  • State Management — Tracks resource relationships and current state
  • Plan/Apply Workflow — Preview changes before applying them
  • Large Community — Abundant tutorials, modules, and community providers

1.4 Core Terraform Concepts

The Workflow

# 1. Write configuration
vim main.tf

# 2. Initialize (download providers)
terraform init

# 3. Plan (preview changes)
terraform plan

# 4. Apply (execute changes)
terraform apply

# 5. Destroy (tear down when done)
terraform destroy

Key Terminology

  • Provider — Plugin that interacts with cloud APIs (azurerm, aws, google)
  • Resource — Infrastructure object managed by Terraform (VM, VNet, S3 bucket)
  • Data Source — Read-only query for existing infrastructure
  • State — JSON file mapping config to real-world resource IDs
  • Module — Reusable, composable group of Terraform files
  • Plan — Execution preview showing additions, changes, and destructions
  • Backend — Where state is stored (local, remote, cloud)

1.6 Real-World Use Cases

  • Multi-cloud deployments — Run app tier on Azure, data tier on AWS, CDN on GCP
  • Environment automation — Spin up dev/staging/prod from same codebase
  • Disaster recovery — Replicate infrastructure across regions in minutes
  • Compliance as code — Enforce security policies through reusable modules
  • Cost optimization — Ephemeral dev environments that destroy nightly
  • Microservices infrastructure — Each service owns its Terraform modules

1.7 Setting Up Your Learning Path

This eBook is structured to take you from installation to production-grade patterns. Each chapter builds on the previous one:

Learning Path: Ch 1-2: Foundations (IaC concepts + installation) ▼ Ch 3-4: Core Skills (providers, variables, data sources) ▼ Ch 5-6: Intermediate (state management, modules) ▼ Ch 7-8: Operations (workspaces, CI/CD) ▼ Ch 9-10: Advanced (lifecycle, real-world patterns) ▼ Ch 11-12: Mastery (troubleshooting, future trends)
Summary & Checklist:
  • Understand what IaC is and why it matters for modern infrastructure
  • Know the difference between imperative and declarative approaches
  • Understand Terraform's core workflow: init → plan → apply → destroy
  • Be familiar with key terms: provider, resource, state, module, backend
  • Know how Terraform compares to CloudFormation, Pulumi, and Ansible
  • Understand the plan/apply workflow and why it's a key Terraform advantage
