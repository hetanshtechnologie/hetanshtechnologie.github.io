Search: The Foundation Skill

Everything else in a SIEM builds on search. Analysts spend much of their day querying data to confirm or refute hypotheses. Each platform has its own query language — but they share concepts. The most common are:

# KQL example: all failed logons from external IPs in the last hour
SecurityEvent
| where TimeGenerated > ago(1h)
| where EventID == 4625
| where IpAddress !startswith "10." and IpAddress !startswith "192.168."
| project TimeGenerated, Account, IpAddress, WorkstationName
| sort by TimeGenerated desc

Good query skills include: knowing the schema, using time ranges correctly, pivoting between entity fields (user, host, IP), and avoiding full-table scans where indexes exist.

Correlation Rules

A correlation rule is the core detection unit: a query or event pattern that, when matched, produces an alert. Rules vary from simple single-event filters to complex multi-stage, stateful correlations that track a sequence over time.

A well-formed correlation rule has several parts:

  • Trigger conditions: which events, fields, and thresholds.
  • Time window: how long events must occur within (e.g., 10 failed logins in 5 minutes).
  • Grouping: key events are correlated by (e.g., same user, same source IP).
  • Severity mapping: informational → critical based on impact.
  • Suppression: avoid alert storms (e.g., one alert per 15 minutes per host).
  • Response action: who is notified, what automation runs, which SOAR playbook fires.
Example rule (concept): "Brute Force Attempt" — fire when the same user has 10+ failed logins (EventID 4625) from the same IP within 5 minutes, severity Medium, suppress for 15 minutes, escalate to SOAR for IP enrichment.

Alerting and Alert Fatigue

Alerts are the SOC's daily currency — and their biggest pain point. Alert fatigue is the state where analysts receive so many alerts that they stop taking them seriously or cannot keep up. Statistics commonly cited in the industry: thousands to tens of thousands of alerts per day for a mid-size SOC, with only a small fraction being true positives.

Mitigations for alert fatigue:

  • Suppression and deduplication: collapse repeated identical events.
  • Risk-based alerting: score alerts by asset value + behavior and only surface the top ones.
  • Correlation quality: fewer, better rules beat many noisy rules.
  • SOAR pre-processing: automate triage and enrich before an alert reaches a human.
  • Alert feedback loops: analysts vote on false positives; rules get tuned or retired.

Dashboards and Visualizations

Dashboards give the SOC live visibility and are the primary Tier-1 monitoring surface. Common SOC dashboard panels:

  • Alert volume by severity, source, and time.
  • Failed logon spikes (often an early ransomware indicator).
  • Top attacked hosts, top external IPs, geo-map of login sources.
  • Coverage of critical assets (are the Crown Jewels being monitored?).
  • Ingestion health: EPS, lag, storage.

UEBA: User and Entity Behavior Analytics

UEBA uses machine learning to build a baseline of normal behavior for users, devices, and applications, then flags deviations. Examples: a finance user suddenly accessing 10x more documents; a service account logging in at 3 a.m.; an admin using a new geographic location.

Reporting and Compliance

SIEMs are heavily used for compliance evidence. Frameworks like PCI DSS, HIPAA, SOC 2, GDPR, and ISO 27001 require monitoring and log retention. Reporting capabilities include:

  • Scheduled reports (daily, weekly, monthly) for management.
  • Compliance-specific report packs.
  • Ad-hoc report generation for auditors.
  • Retention attestation (you can prove logs were kept X days).
Note: Compliance is a byproduct of good security operations, not the goal. Designing a SIEM purely around compliance reports typically yields terrible detection quality. Design for detection; export for compliance.

Advanced Capabilities in Modern SIEMs

  • Threat hunting: open-ended queries and hypotheses over historical data; hunting requires long retention.
  • Notebooks / Jupyter integration: Python-based investigation and ML analysis over SIEM data (Sentinel, Chronicle).
  • Fusion / AI: multi-signal alert fusion, grouping related alerts into incidents, and risk ranking.
  • Watchlists: dynamic lists (VIPs, critical assets, malicious IOCs) that enrich or boost alerts.
  • Integrated automation: native playbook/automation hooks (Sentinel Logic Apps, Splunk SOAR) that blur the SIEM/SOAR boundary.
  • Custom enrichment: user entity graphs, device vulnerability data, CMDB integration.

Comparing SIEM Capability Matrices

When evaluating a SIEM, score these dimensions: ingestion breadth and ease, parse/normalization quality, search performance, correlation and detection features, UEBA quality, automation/integration, reporting, scalability, multi-cloud support, and TCO. Weight the score by your SOC's actual needs — a boutique cloud-native SIEM with great automation may beat a legacy giant with a mature correlation engine for your workload.
