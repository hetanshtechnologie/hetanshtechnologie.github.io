9. Security Automation in Action

Chapter 9

Where Automation Delivers the Most Value

Not everything should be automated. The best candidates share these traits: high volume, well-defined decision logic, repetitive steps, clear data, low ambiguity, and (ideally) low blast radius. The canonical winners are alert triage, phishing response, malware analysis, IOC blocking, and deduplication.

1. Automated Alert Triage

Alert triage is the biggest time sink in most SOCs, so it is the first automation target. A triage playbook typically:

  1. Receives the alert from the SIEM.
  2. Normalizes artifacts and looks up the affected asset's criticality.
  3. Queries threat intelligence for each IOC.
  4. Scores the alert (e.g., 0-100) based on reputation, criticality, and behavior.
  5. Auto-closes clearly benign alerts with a documented reason.
  6. Escalates suspicious alerts to a case with all context prepopulated.
Result: Analysts only see the top-scored alerts, with enrichment already done. Typical reductions: 30-70% of alerts never reach a human, and the rest are resolved faster because context is gathered automatically.

2. Phishing Response

Phishing is the highest-volume automation use case. The automated workflow (from Chapter 8):

  • Parse the reported email (sender, subject, links, attachments, headers).
  • Detonate/sandbox attachments; scan URLs with reputation services.
  • Check the sender against known-good and allowlists.
  • Block malicious URLs/hashes on the email gateway and proxies.
  • Search mailboxes for other copies of the same email; quarantine them.
  • Notify the affected users with guidance; log metrics.

3. Malware Analysis Enrichment

When an unknown file is detected, a playbook can automate the analysis chain:

  1. Extract file hash and metadata from the alert.
  2. Query multiple reputation engines (VirusTotal, hybrid-analysis, local sandbox).
  3. If inconclusive, submit the file to a sandbox for behavioral analysis.
  4. Collect verdict, MITRE ATT&CK mapping, and C2 indicators.
  5. Attach the full report to the case and recommend containment actions.

4. IOC Blocking and Containment

Containment actions are powerful and must be gated carefully. Example flow:

  • Confirm IOC reputation as malicious (intel + sandbox).
  • Determine affected assets and their criticality.
  • For low-risk targets: block IP/domain on firewall/proxy/DNS automatically.
  • For critical assets: request analyst approval, then isolate via EDR.
  • Log every action with before/after state for audit.
Caution: Automatic blocking can break legitimate business. Predefine scope rules — for example, never auto-block IPs on a finance-critical allowlist, never quarantine domain controllers, and always notify owners when a block affects production traffic.

5. Alert Deduplication and Incident Grouping

During attacks, the same underlying event produces many near-identical alerts. Deduplication playbooks:

  • Key alerts by entity (user + source IP + rule) over a time window.
  • Merge duplicates into a single case with a counter.
  • Group related alerts (same attacker, same campaign) into one incident.
  • Suppress repeat notifications while still tracking escalation.

This reduces alert volume dramatically during genuine incidents — exactly when the SOC is busiest.

6. Automated Enrichment: Building the Context in Seconds

Enrichment is the glue that makes decisions possible. A single "enrich artifact" utility playbook is worth building first and reusing everywhere:

Enrichment for: IP 203.0.113.5
  - GeoIP location            -> US / datacenter
  - ASN / ownership           -> Cloud provider range
  - Threat intel reputation   -> 12/30 scanners flag malicious
  - Internal asset lookup     -> matches DMZ host "web-prod-01"
  - Recent SIEM activity      -> 40 connections in last hour
  - Historical incidents      -> 3 prior alerts involving this IP

Verdict: High risk -> escalate to analyst with full context

7. Automated Evidence Capture and Forensics

Before containment destroys evidence, automation can capture it:

  • Collect the relevant log window from SIEM and endpoint agents.
  • Snapshot memory and disk artifacts (via EDR/DFIR tools) where licensed.
  • Record process trees, network connections, and registry changes.
  • Attach all outputs to the case timeline with hashes for integrity.

8. Compliance and Notification Automation

Automation also keeps stakeholders informed and compliance evidence complete:

  • Notify management and regulators per policy within SLA.
  • Generate post-incident summary reports automatically.
  • Log evidence retention and case documentation per framework.

Build the Automation Roadmap

Prioritize automation candidates with a simple scoring approach:

CriterionWeightWhy
Alert volumeHighMore runs = more time saved
Task repetitivenessHighAutomation shines on same-path tasks
Decision clarityHighAmbiguous cases still need humans
Blast radiusLow scores betterKeep risk of automation failure small
Data availabilityMediumCan the needed data be reached via APIs?
Integration readinessMediumAre connectors already built?

Start with the top 3-5 highest-scoring use cases. Measure automation rate and MTTR before and after; iterate monthly.

Story: A team with 40,000 monthly alerts automated triage, phishing, and deduplication. Alerts reaching analysts dropped to 8,000/month. Analyst time per incident fell from ~20 minutes to ~4. MTTR for phishing dropped from 45 minutes to under 5. The team's next step was to use the freed capacity for proactive threat hunting.
Practice Task: Score 5 alert types from your own environment (or from this book) using the roadmap table above. Pick the top one and write a complete playbook design for it: trigger, steps, decision branches, approvals, notifications, error handling, and the metrics you will use to judge success after 30 days.
