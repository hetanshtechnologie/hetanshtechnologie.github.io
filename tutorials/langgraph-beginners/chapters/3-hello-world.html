Hello World: Your First Agent

We will build a real ReAct-style agent in LangGraph: one agent node that can call arithmetic tools, a routing loop, and the shared message state. When you ask it to compute something, it will decide to call a tool, get the result, and answer.

Step 1: Define the state

State is a typed dictionary. For chat agents we mark messages with the add_messages reducer, which tells LangGraph to append new messages instead of overwriting them.

from typing import Annotated, TypedDict
from langgraph.graph.message import add_messages

class AgentState(TypedDict):
    messages: Annotated[list, add_messages]

Step 2: Define tools

A tool is a plain Python function with a docstring plus the @tool decorator. The model reads the name, description, and a: float-style type hints to decide when to call it.

from langchain_core.tools import tool

@tool
def add_numbers(a: float, b: float) -> float:
    """Add two numbers together. Use this for any addition."""
    return a + b

@tool
def multiply_numbers(a: float, b: float) -> float:
    """Multiply two numbers together. Use this for any multiplication."""
    return a * b

tools = [add_numbers, multiply_numbers]

Step 3: Bind the tools to the model

bind_tools advertises the tool schemas to the LLM so it can emit a tool_calls argument instead of calling the function itself.

from langchain_openai import ChatOpenAI
from dotenv import load_dotenv
load_dotenv()

model = ChatOpenAI(model="gpt-4o-mini", temperature=0).bind_tools(tools)
Ollama users: replace the model line with model = ChatOllama(model="llama3.2", temperature=0).bind_tools(tools) — everything else is identical.

Step 4: Build the graph

from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import StateGraph, START, END
from langgraph.prebuilt import ToolNode, tools_condition

# --- Node 1: the agent "brain" ---
def agent(state: AgentState):
    system = SystemMessage("You are a helpful assistant. Use the math tools for any arithmetic.")
    response = model.invoke([system] + state["messages"])
    return {"messages": [response]}   # partial state update

# --- Node 2: executes any tool the model asked for ---
tool_node = ToolNode(tools)

# --- Wire the graph ---
graph = StateGraph(AgentState)
graph.add_node("agent", agent)
graph.add_node("tools", tool_node)

graph.add_edge(START, "agent")
graph.add_conditional_edges(
    "agent",
    tools_condition,                 # router function
    {"tools": "tools", "__end__": END},
)
graph.add_edge("tools", "agent")     # loop back after a tool runs

app = graph.compile()

What each piece does:

  • StateGraph(AgentState) — creates a graph that understands your state schema.
  • add_node("agent", agent) — registers a node. The name string is used in edges.
  • add_edge(START, "agent") — execution always begins at the agent.
  • add_conditional_edges("agent", tools_condition, ...) — after the agent, call the router. The prebuilt tools_condition returns "tools" if the agent emitted tool calls, otherwise "__end__" (stop).
  • add_edge("tools", "agent") — after a tool runs, feed the result back to the agent so it can keep reasoning. This edge is what creates the loop.
  • compile() — validates the graph (no orphaned nodes) and returns a runnable app.

Step 5: Run it

result = app.invoke({"messages": [HumanMessage("What is 12 + 30, then multiply the result by 2?")]})

for msg in result["messages"]:
    role = msg.type
    content = msg.content if not getattr(msg, "tool_calls", None) else f"tool_calls: {[tc['name'] for tc in msg.tool_calls]}"
    print(f"{role}: {content}")

Expected output (roughly):

human: What is 12 + 30, then multiply the result by 2?
ai: tool_calls: ['add_numbers']
tool: 42.0
ai: tool_calls: ['multiply_numbers']
tool: 84.0
ai: 12 + 30 = 42, and 42 × 2 = 84.

The agent reasoned there were two steps, called the tools in sequence, and only stopped (reached END) once it had everything it needed. That loop — reason → call tool → observe → reason again — is the essence of an agent, and LangGraph made it a first-class, inspectable graph.

Step 6 (optional): watch it run, step by step

Use stream() instead of invoke() to see each node fire, which is great for debugging:

for event in app.stream({"messages": [HumanMessage("What is 100 / 5?")]}, stream_mode="updates"):
    for node_name, update in event.items():
        print(f"--> {node_name}: {update}")

What we learned

  • Nodes are plain functions returning partial updates to state.
  • Reducers (add_messages) decide how updates merge into existing state.
  • Conditional edges give the agent the ability to route itself.
  • Looping is just an edge that points back to an earlier node.
