Scenario Workshop: Thirty Judgment Exercises

This chapter is a workshop, not a lecture. Instead of introducing new facts, it puts you in the position the exam cares about most: a short workplace situation, four plausible answers, and the need to pick the one that reflects sound judgment. Every scenario below is newly written for this book. Work them in order, cover the answers, and commit to a choice before you read the rationale. The goal is not to memorize thirty correct letters. It is to build a habit of noticing what a situation is missing, because that habit transfers to questions you have never seen.

Learning objectives

  • Apply a repeatable decision routine to unfamiliar scenario questions.
  • Recognize the six themes that organize the exam's judgment items.
  • Distinguish a technically possible action from a permissible and sensible one.
  • Recognize the common shapes of wrong answers before you read them.
  • Explain why each distractor in a four-option question is wrong.
  • Use a scoring guide to turn practice results into a focused study plan.

Key concepts

Scenario questions test decisions, not definitions. A recall question asks what a feature is; a scenario question asks whether, when, and how to use it. The correct option is usually the one that adds a missing safeguard, a clarifying step, or a check on evidence. The distractors are usually plausible actions that skip one of those steps. They are tempting precisely because they look productive: they produce text, save time, or use a capable tool.

A repeatable judgment routine

When you meet an unfamiliar situation, run the same short routine every time:

  1. Name the goal the person in the scenario is actually trying to reach.
  2. Identify what is missing: information, permission, verification, or context.
  3. Look for the option that supplies the missing piece with the least disruption.
  4. Reject options that trade a real requirement for speed or convenience.
  5. Check that the chosen action is both capable and appropriate.

The order matters. Starting with the goal stops you from fixing an attractive but irrelevant problem. Naming the gap converts a fuzzy feeling that "something is off" into a specific deficit you can look for in the options. Checking capability and appropriateness separately protects you from the most common trap in this exam type: seeing that a tool can do something and assuming that doing it is therefore fine.

Exam note: The phrase "best first move" points to the step that removes the root problem, not the step that produces the most immediate output.

The anatomy of a distractor

Wrong answers are not random. They tend to fall into a handful of recurring shapes, and learning to spot the shape is faster than evaluating each option from scratch. Absolute language is one signal: words such as "always," "never," and "indefinitely" usually mark an option that ignores legitimate variation. Wrong-surface answers address a real concern with the wrong instrument, such as changing models when the real problem is the prompt. Skipped-verification answers accept output because it looks finished. Over-privileged answers grant more access than a task needs. Polished-but-wrong answers describe an attractive result while quietly dropping a required check. Finally, capability-without-policy answers assume that because a feature exists, using it is permitted.

None of these signals is a rule that lets you answer without thinking. They are prompts to slow down. When an option uses an absolute word, ask whether the scenario truly supports that strength. When an option swaps one tool for another, ask what the underlying gap actually is. Slow, deliberate reading beats pattern matching on its own.

Common mistake: Choosing an option because it sounds responsible in general, without checking that it fixes the specific gap in the scenario.

Theme map

The thirty exercises are grouped into six themes. This table shows what each theme is really testing, so you can see the pattern behind the surface details.

Theme Core judgment tested Typical missing piece
Prompting and context Making a request specific and usable Audience, goal, constraints, format
Verification and bias Deciding what to trust An independent check or balanced evidence
Models and features Matching capability to need Right-sized tool and output controls
Projects and connectors Scoping shared knowledge and data access Least privilege and correct scope
Governance and privacy Acting within policy and law Redaction, retention, approval, audit
Workflow design Building a safe repeatable process Oversight, fallback, measurement

Use the table as a diagnostic index. If you consistently miss items in one row, the problem is usually a concept gap rather than a reading error. Return to the underlying idea, then repeat only that checkpoint. Practising the whole set again often feels productive but rarely fixes a single weak area as efficiently.

The routine can be kept as a compact checklist you reuse during practice:

GOAL   - What is the person actually trying to accomplish?
GAP    - What is missing: context, proof, permission, or control?
FIT    - Which option closes the gap without creating a new risk?
CAN    - Is the action technically possible?
SHOULD - Is it allowed, proportionate, and reviewable?

Try it: Before answering any scenario, write one word for the gap (context, proof, permission, control). That word usually points straight at the correct option.

How the themes show up

The same few judgments reappear in different clothing. In prompting scenarios, the recurring need is to turn intent into something testable: a defined audience, a bounded question, an explicit constraint. In verification scenarios, the recurring need is an independent check, because a confident tone and a formal citation are not evidence. A related idea is balance: if every example points one way, the output will lean that way too.

Model and feature scenarios ask you to fit the tool to the demand rather than reach for the biggest option. Simple, high-volume work favors a smaller model; ambiguous, high-consequence work favors stronger reasoning; changing source material favors retrieval over memorization. Project and connector scenarios move the same logic into data access: keep shared context as narrow as the audience, grant the least access that works, and refresh stale sources before relying on them.

Governance and privacy scenarios add the question of whether an action is allowed at all. Redaction, retention, approval, and audit trails are not obstacles to good work; they are the conditions that make the work trustworthy. Workflow scenarios pull everything together into a repeatable process, where automation handles the ordinary path and humans handle the exceptions, with measurement to show whether the design is working.

Scoring guide

Raw scores matter less than patterns. Use this guide after each checkpoint of five.

Correct out of five Reading Recommended action
5 Theme is secure Move on; revisit only during final review
4 Solid with one slip Re-read the rationale for the missed item
3 Partial grasp Rework the theme map and repeat the set
2 or fewer Fragile understanding Review the underlying concepts, then retry

A score of four deserves more attention than it first appears. A single miss often marks a specific blind spot, such as overlooking retention requirements or treating confidence as proof. Read that rationale closely and name the gap you failed to see. A score of three means the theme is partly understood but not yet reliable, which is exactly the state in which a question can go either way under time pressure.

Scoring tip: A correct answer reached by guessing is still unfinished learning. If you cannot explain why each distractor is wrong, mark the item for review.

Worked scenario

A team lead asks an assistant to draft a customer message about a billing change. The assistant produces a polished paragraph that includes a precise refund figure. The figure sounds plausible, but nobody on the team has checked it against the billing system. The deadline is tight, and sending quickly would be convenient. There is also a second detail: the draft was composed using a general assistant rather than the approved internal tool, and the message will go to customers whose account data appears in the source notes.

Apply the routine. The goal is an accurate, trustworthy customer message. The gap is larger than it first appears. There is a proof gap, because the refund figure is unverified. There is a control gap, because an external message carries consequences. There is also a permission gap, because account data was placed into an unapproved environment. Capability is not the issue; the assistant can write the message. Appropriateness is the issue.

The best action is to verify the figure against the authoritative billing record, move the work into an approved environment, and route the draft through a human reviewer before sending. Three tempting shortcuts fail. Trusting precision as evidence of accuracy mistakes presentation for verification. Rounding the number changes how certain the claim looks without establishing whether it is true. Skipping review because the prose reads well ignores the fact that fluency and correctness are independent qualities.

Notice what the correct decision did not require. It required no new technical knowledge and no clever prompt. It required noticing what was missing and refusing to trade it for speed. That is the whole skill this chapter practices. Now imagine the same situation with one fact changed: the figure has already been confirmed against the billing system, and the tool is approved. The proof and permission gaps close. Human review of the final wording still remains, because a customer-facing message warrants a check, but the urgency of the intervention drops. This is why the routine must be reapplied rather than memorized: changing one fact can change which gap matters most.

Exam note: When a scenario contains two problems, the strongest answer usually addresses both. An option that fixes only the visible one is a partial answer dressed as a complete one.

Common mistakes

  • Treating a confident, polished answer as a verified answer.
  • Choosing the fastest option when the scenario centers on a safeguard.
  • Assuming a tool's capability makes its use appropriate.
  • Fixing the symptom in the prompt when the real problem is missing evidence.
  • Overlooking the difference between project-scoped and broadly shared context.
  • Granting broad access now with the intention of tightening it later.
  • Ignoring retention, redaction, or audit requirements until the final option.
  • Using a self-report from the assistant as independent verification.
  • Measuring activity, such as prompt counts, instead of outcomes.
  • Picking an answer because it sounds reasonable without explaining the distractors.

Chapter summary

  • Scenario questions reward a consistent decision routine over memorized facts.
  • The six themes are prompting and context, verification and bias, models and features, projects and connectors, governance and privacy, and workflow design.
  • Most correct answers add context, verification, least privilege, oversight, or measurement.
  • Most distractors trade a genuine requirement for speed, convenience, or false confidence.
  • Wrong answers often contain absolute language, swap the wrong tool, or skip a required check.
  • Review wrong answers by naming the missing piece you failed to notice, then reapply the routine to a changed scenario.

Checkpoint questions

Answer all five items in a checkpoint before reading the answers.

Checkpoint 1 — Prompting and context

Q1. An analyst asks an assistant to "improve this report" and receives a generic rewrite. What is the best first move?

A. Ask the assistant to infer the audience from the file name.

B. State the audience, purpose, and desired format before requesting revisions.

C. Accept the first draft and rewrite most of it manually.

D. Switch to a larger model to compensate for the vague request.

Q2. A coordinator pastes a two-hundred-page manual into a prompt and gets a weak answer. What change is most likely to help?

A. Paste the entire manual again with a request to read carefully.

B. Ask for a summary of the whole manual before asking the question.

C. Supply only the relevant section plus a precise, bounded question.

D. Reduce the question to a single word to shorten the reply.

Q3. During a long session, a later answer ignores a constraint agreed earlier. What should the analyst do?

A. Assume every earlier detail is retained indefinitely.

B. Start a fresh session with no reference to earlier decisions.

C. Restate the key constraint in the current turn and cite the earlier decision.

D. Repeat the full conversation verbatim in every turn.

Q4. A request refers to "the quarter" when two different date ranges are possible. What is the safest response?

A. Let the assistant choose whichever meaning seems more common.

B. Define the term and state the exact date range before proceeding.

C. Ask for both answers and choose one afterward without a criterion.

D. Omit all dates to keep the prompt short.

Q5. Which prompt structure is most reliable for a recurring team task?

A. A single imperative sentence with no constraints.

B. A long list of unrelated background details.

C. A structured prompt covering role, context, constraints, and output format.

D. The identical prompt used regardless of input variation.

Checkpoint 2 — Verification and bias

Q6. An assistant reports a very precise statistic that a reviewer finds suspicious. What should happen next?

A. Publish it because precision is a sign of accuracy.

B. Cross-check the figure against the original source before using it.

C. Round the number to reduce its apparent precision.

D. Replace the statistic with a vague adjective.

Q7. An output keeps favoring one option because the supplied examples all point that way. What is the likely fix?

A. Add balanced examples spanning the full range of cases.

B. Add more of the same examples to reinforce the pattern.

C. Ignore the pattern because the assistant is neutral by design.

D. Lower the verbosity setting to reduce the bias.

Q8. A draft includes a citation that cannot be located in any real source. What is the correct treatment?

A. Keep it because a formal citation looks credible.

B. Verify each citation and remove any that cannot be confirmed.

C. Replace the reference with a generic label.

D. Trust cited claims more than uncited ones by default.

Q9. A reviewer accepts the assistant's first answer and stops considering alternatives. What is the main problem?

A. It saves time and should be preferred.

B. No disconfirming evidence was sought before deciding.

C. The same model should be asked to confirm its own answer.

D. The review step should be shortened further.

Q10. An assistant produces a draft with legal or financial consequences. What level of checking is appropriate?

A. Treat it exactly like a low-stakes internal draft.

B. Require source verification and review by a qualified human.

C. Trust it more because the writing is confident.

D. Rely only on the assistant's own confidence rating.

Checkpoint 3 — Models and features

Q11. A team needs simple, repetitive classification of thousands of records. What is the sensible model choice?

A. Use the largest available model for every request.

B. Select the smallest model that clears the accuracy requirement.

C. Always use the most expensive model to be safe.

D. Avoid models and classify every record manually.

Q12. Answers must draw on a private knowledge base that changes weekly. Which approach fits best?

A. Fine-tune once on a static snapshot and never refresh it.

B. Use retrieval so responses draw on current source documents.

C. Assume pretraining already contains the private facts.

D. Raise the randomness setting to improve factual recall.

Q13. Downstream code needs a strictly formatted JSON response. What should the analyst request?

A. JSON-like text and hope the parser is forgiving.

B. Structured output against a defined schema, then validate it.

C. Prose that will be converted with pattern matching.

D. No specific format because the code can adapt.

Q14. A dataset is far larger than one request can hold. What is the correct handling?

A. Silently truncate the input and answer from part of it.

B. Process the data in chunks and combine the results.

C. Increase randomness to cover more of the input.

D. Ask the model to guess the missing portion.

Q15. A nuanced contract requires careful reasoning over conflicting clauses. Which choice is most appropriate?

A. Pick the fastest model to meet the deadline.

B. Use a model with stronger reasoning for the analysis.

C. Use the cheapest model and accept lower quality.

D. Reduce the task to a simple keyword search.

Checkpoint 4 — Projects and connectors

Q16. A connector will read from an internal repository. How should its access be configured?

A. Grant access to all data to avoid future requests.

B. Limit permissions to the minimum the task requires.

C. Share one set of credentials across the entire team.

D. Disable logging so the connector runs faster.

Q17. Reference material should be available only to one department. Where should it live?

A. In every user's general context.

B. In a project shared only with that department.

C. Pasted manually into each individual prompt.

D. Nowhere, relying on the assistant to remember it.

Q18. Answers from a connected source are clearly out of date. What is the first check?

A. Assume connected sources are always current.

B. Check the sync schedule and refresh the index before trusting results.

C. Lower confidence equally in every answer.

D. Abandon connectors entirely in favor of general search.

Q19. A task depends on live availability information. How should a connector be selected?

A. Use whichever connector happens to be enabled.

B. Match the connector to the specific data the task needs.

C. Ask the model to estimate the missing information.

D. Skip connectors and hard-code assumptions.

Q20. A proposed connector could expose confidential records. What is the right prerequisite?

A. Connect everything and restrict access after an incident.

B. Apply data-loss controls and review scope before enabling it.

C. Rely on the model to hide sensitive content on its own.

D. Turn off security logging for that connector.

Checkpoint 5 — Governance and privacy

Q21. A source draft contains customer identifiers. What should happen before using an assistant?

A. Send it unchanged because the document is internal.

B. Remove or mask direct identifiers first.

C. Anonymize only after the output is published.

D. Assume nothing is stored and skip redaction.

Q22. Policy sets a maximum retention period for prompts. What is the correct response?

A. Keep every prompt indefinitely for convenience.

B. Apply the configured retention settings and delete as required.

C. Assume retention is another team's responsibility.

D. Store prompts in a personal folder with no limits.

Q23. A tool can perform an action, but policy forbids it. What should the analyst do?

A. Perform it because the capability exists.

B. Decline and follow policy despite the technical ability.

C. Perform it without documenting the decision.

D. Ask the assistant whether the action is permitted.

Q24. A regulated decision must be traceable later. What should the workflow record?

A. Discard prompts and outputs after each use.

B. Keep inputs, outputs, and reviewer decisions in an audit trail.

C. Treat the model's internal logs as the only record.

D. Skip review because the output appears reasonable.

Q25. A confidential strategy document needs analysis. Which environment is appropriate?

A. Any convenient assistant that accepts pasted text.

B. An approved environment with suitable confidentiality controls.

C. A broad shared channel to gather more opinions.

D. A version with the title removed but all details intact.

Checkpoint 6 — Workflow design

Q26. An assistant drafts messages that go directly to customers. What control belongs in the workflow?

A. Send automatically to improve response time.

B. Route drafts through human approval before sending.

C. Trust the assistant fully for all customer messages.

D. Remove review to reduce operating cost.

Q27. A routine daily report is a good automation candidate. How should it be designed?

A. Automate every case with no checks to save time.

B. Automate the normal path and flag anomalies for review.

C. Keep all steps manual to eliminate any risk.

D. Automate only the final formatting step.

Q28. A team wants to know whether the assistant is actually helping. How should success be judged?

A. Assume it works because adoption is high.

B. Define quality and time metrics and sample outputs regularly.

C. Count only the number of prompts submitted.

D. Remove measurement to avoid extra work.

Q29. The assistant performs poorly on unusual inputs. What should the workflow include?

A. Force a confident answer for every input.

B. Define a fallback path that escalates low-confidence cases.

C. Delete unusual inputs from the queue.

D. Lower the quality bar for edge cases.

Q30. A successful pilot is ready to expand across an organization. What is the best rollout approach?

A. Enable it everywhere at once with no oversight.

B. Expand in stages with monitoring, training, and escalation paths.

C. Keep the pilot permanently limited to one team.

D. Remove all controls once early results look positive.

Answers and rationale

Q1 — B. Vague requests produce generic output because the assistant has no basis for choosing tone, depth, or structure. Naming the audience, purpose, and format gives the rewrite a target and makes the result judgeable. A shifts a decision the analyst owns onto the tool, and a file name is weak evidence of intent. C spends manual effort correcting a draft that was never aimed at a goal. D assumes a larger model can infer detail that was never supplied.

Q2 — C. Targeted context plus a bounded question fits the material to the task and keeps attention on the relevant passage. A repeats the same mistake at greater length. B adds a summary step that still leaves the eventual answer unguided and may introduce its own errors. D makes the question too vague to produce anything useful, trading one failure for another.

Q3 — C. Restating the constraint re-anchors the current turn and makes the requirement explicit again. A overestimates how reliably earlier detail is retained over a long exchange. B discards useful history and forces the work to restart. D wastes effort by resending everything each time and still does not highlight which item matters now.

Q4 — B. Defining the term and date range removes the ambiguity before any work begins. A delegates a decision that belongs to the requester and leaves the output potentially useless. C produces two answers with no stated criterion for choosing between them. D removes information the task depends on, which is the opposite of clarification.

Q5 — C. A structured prompt covering role, context, constraints, and format is repeatable and checkable across varying inputs. A omits the guidance that prevents drift and inconsistent results. B adds noise rather than signal, burying the instruction. D ignores legitimate variation, so a prompt that worked once may fail whenever conditions change.

Q6 — B. An independent check against the original source resolves the suspicion and establishes whether the figure is real. A confuses precision with accuracy, which are separate qualities. C changes presentation without establishing truth and can mislead just as easily. D removes the detail rather than confirming it, avoiding the question instead of answering it.

Q7 — A. Balanced examples counter a skewed evidence base and give the output a fairer range to draw from. B deepens the same bias by adding more of the same signal. C assumes a neutrality that the supplied examples have already distorted. D adjusts an unrelated output setting that has no bearing on which examples dominate.

Q8 — B. Verifying references and dropping those that cannot be confirmed protects the credibility of the whole draft. A trusts appearance over evidence and risks repeating a fabrication. C hides the problem by relabeling it without checking anything. D sets a dangerous default that rewards invented citations whenever they are dressed formally.

Q9 — B. Seeking disconfirming evidence is the core of sound review, because a first answer can be fluent and wrong. A mistakes speed for correctness. C asks a source to validate itself, which adds no independent signal. D weakens the very check that the situation calls for, compounding the original lapse.

Q10 — B. High consequences justify both source verification and review by a qualified human before anything is acted on. A ignores the difference in stakes between a draft and a binding decision. C treats confidence as evidence when it is only a stylistic property of the writing. D substitutes a self-report for the independent check the situation demands.

Q11 — B. Right-sizing cost and latency while meeting the accuracy bar is the efficient choice for repetitive work at volume. A and C overspend without any quality gain for a simple task. D rejects automation that suits the task well and keeps people doing mechanical work. The guiding idea is sufficiency, not maximum capability.

Q12 — B. Retrieval keeps answers tied to current documents and avoids baking last week's facts into the system. A freezes a snapshot that begins aging immediately. C assumes private knowledge that general pretraining cannot contain. D increases randomness, which affects variety rather than factual grounding, so staleness remains.

Q13 — B. A defined schema with validation gives downstream code a dependable contract it can parse without guesswork. A invites intermittent parsing failures when formatting drifts. C applies fragile pattern matching to prose that was never structured. D assumes a flexibility the consuming code may not actually have.

Q14 — B. Chunking the input and combining the results covers the full dataset without silent loss. A answers from partial data while appearing complete, which is worse than admitting a limit. C changes sampling behavior but does not expand capacity. D asks the model to invent content for the missing portion, corrupting the analysis.

Q15 — B. Stronger reasoning fits a task whose difficulty lies in weighing conflicting clauses. A prioritizes speed over a quality the scenario explicitly demands. C accepts avoidable errors on consequential text. D discards precisely the nuance that makes careful analysis necessary, reducing a judgment task to a lookup.

Q16 — B. Least privilege limits the damage of error, misuse, or a compromised account while still allowing the work. A over-grants permanently for hypothetical future needs. C destroys individual accountability and widens exposure across the team. D removes the record needed to detect and investigate problems later.

Q17 — B. A department-scoped project keeps the material with the intended audience and out of other contexts. A exposes it organization-wide and defeats the restriction. C is error-prone and unsustainable at any scale. D loses the shared context entirely and forces everyone to reconstruct it from memory.

Q18 — B. Checking the sync schedule addresses the most likely cause of staleness before the results are trusted. A ignores the evidence presented in the scenario. C treats every answer as equally doubtful instead of repairing the source. D abandons a useful tool over a problem that may have a simple fix.

Q19 — B. The connector must expose the exact data the task requires, so selection starts from the requirement. A accepts whatever is already available and hopes it fits. C substitutes a guess for live information in a task defined by timeliness. D builds an assumption into the process where a real data source was available.

Q20 — B. Controls and a scope review before activation prevent exposure rather than documenting it after the fact. A reacts only once harm has occurred. C assumes a model will enforce policy on its own, which it cannot be relied upon to do. D removes the logging needed to understand any later incident.

Q21 — B. Masking identifiers before processing reduces privacy risk at the earliest and most effective point. A assumes internal use is risk free, which the scenario gives no basis for. C protects the data too late, after the output has already been produced. D relies on an unverified assumption about storage behavior.

Q22 — B. Applying configured retention settings turns a written policy into actual practice. A and D ignore the limit entirely and create indefinite accumulation. C assumes an ownership that the scenario does not transfer, leaving the requirement unmet. Policy that nobody implements is not a control.

Q23 — B. Capability does not override policy, so the action should be declined despite being technically possible. A confuses what can be done with what should be done, the central distinction of this theme. C adds concealment to the violation. D hands an ethical and policy decision to a tool that cannot own the consequences.

Q24 — B. An audit trail preserving inputs, outputs, and human decisions makes a regulated outcome traceable later. A destroys the evidence that a review ever occurred. C trusts incomplete internal records that were not designed for accountability. D skips the human review that gives the trail its meaning.

Q25 — B. An approved environment with confidentiality controls matches the sensitivity of the document. A ignores its classification entirely. C spreads the material further under the guise of gathering opinions. D strips only a label while keeping the substance exposed, which changes nothing about the actual risk.

Q26 — B. Human approval before external sending catches errors while they are still cheap to fix. A and C remove the safeguard from a context where mistakes reach customers directly. D trades trust for a small saving and places the cost on recipients instead. Speed is not the primary value in an external message.

Q27 — B. Automating the normal path while flagging anomalies balances efficiency with control. A removes all detection precisely where unusual cases need attention. C forgoes available efficiency and keeps people on mechanical work. D automates too little to change the workload, so the design delivers almost no benefit.

Q28 — B. Defined quality and time metrics combined with sampled review measure real impact rather than impressions. A uses popularity as proof of value. C counts activity, which can rise even when output quality falls. D eliminates the evidence needed to justify the program or improve it over time.

Q29 — B. A fallback path with escalation handles cases the assistant cannot serve well without forcing a bad answer. A demands false confidence on inputs where confidence is least warranted. C discards valid work instead of routing it. D normalizes poor outcomes for the cases where quality matters most.

Q30 — B. Staged expansion with monitoring, training, and escalation paths manages risk as exposure grows. A removes control at the moment it matters most. C captures no further value from a proven approach. D relaxes safeguards just as the number of users and the variety of cases increase.
