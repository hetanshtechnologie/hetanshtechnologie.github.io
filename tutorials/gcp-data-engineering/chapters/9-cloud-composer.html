9. Cloud Composer in Practice

Chapter 9

What is Cloud Composer?

Cloud Composer is Google Cloud's fully managed Apache Airflow service. You create an environment — which provisions the Airflow scheduler, webserver, workers, metadata database, and Redis cache — and you focus on writing DAGs. Google handles upgrades, scaling, and infrastructure, and it integrates natively with GCP (IAM, networking, Secret Manager, logging, monitoring).

Environment Components

  • Webserver: the Airflow UI — DAG list, graph views, logs, connections, variables, triggers.
  • Scheduler: decides which tasks are ready to run; scheduler parallelism is your main tuning lever.
  • Workers: execute tasks; can scale based on queue pressure.
  • Metadata database (Cloud SQL): stores DAG and task state.
  • Redis: the Celery message broker coordinating workers.
  • Cloud Storage bucket: where DAGs, plugins, requirements, and data live.
# Create a Composer environment
gcloud composer environments create composer-prod \
  --location=us-central1 \
  --image-version=composer-2.22.0-airflow-2.7.3 \
  --node-count=3 \
  --environment-size=MEDIUM

Deploying DAGs

Every environment has a GCS bucket; DAG files go into the dags/ folder and the scheduler picks them up within a few minutes.

# Find the DAG bucket
gcloud composer environments describe composer-prod \
  --location=us-central1 \
  --format="value(config.dagGcsPrefix)"

# Sync DAGs from your repo
gcloud composer environments storage dags import \
  --environment=composer-prod --location=us-central1 \
  --source=./dags/
CI/CD pattern: commit DAGs to git; on merge, a pipeline validates with airflow dags list and deploys with gsutil rsync. Rollbacks are a redeploy of the previous commit. Keep DAG code in version control — it is application code, not configuration.

Connections, Variables, and Secrets

  • Prefer the Google Secret Manager backend so secrets live in Secret Manager, not Airflow's metadata DB.
  • For GCP integrations, use the default connection, which uses the environment's service account + Application Default Credentials.
  • Use Airflow Variables sparingly for non-secret config; prefer explicit DAG parameters.
# Referencing a connection in DAG code
from airflow.hooks.base import BaseHook
conn = BaseHook.get_connection("my_source_db")

Service Accounts and IAM

  • The environment runs under a service account. Grant it exactly the roles DAGs need (BigQuery Job User, Dataproc Editor, Storage Object Admin, etc.).
  • Use separate environments (dev/staging/prod) with separate projects and service accounts for isolation.
  • For regulated data, add IAM conditions or VPC Service Controls boundaries.

Running Dataproc Jobs from Composer

The classic production pattern: Airflow creates a temporary Dataproc cluster, submits the job, then deletes the cluster.

from airflow.providers.google.cloud.operators.dataproc import (
    DataprocCreateClusterOperator,
    DataprocDeleteClusterOperator,
    DataprocSubmitPySparkJobOperator,
)

CLUSTER_CONFIG = {
    "master_config": {"num_instances": 1, "machine_type_uri": "n2-standard-4"},
    "worker_config": {"num_instances": 4, "machine_type_uri": "n2-standard-8"},
}

create_cluster = DataprocCreateClusterOperator(
    task_id="create_cluster",
    project_id="my-data-project",
    region="us-central1",
    cluster_name="ephemeral-{{ ds_nodash }}",
    cluster_config=CLUSTER_CONFIG,
    delete_on_error=True,
)

submit_job = DataprocSubmitPySparkJobOperator(
    task_id="submit_pyspark",
    project_id="my-data-project",
    region="us-central1",
    main="gs://my-bucket/jobs/sales_agg.py",
    arguments=["--date={{ ds }}"],
    cluster_name="ephemeral-{{ ds_nodash }}",
)

delete_cluster = DataprocDeleteClusterOperator(
    task_id="delete_cluster",
    project_id="my-data-project",
    region="us-central1",
    cluster_name="ephemeral-{{ ds_nodash }}",
    trigger_rule="all_done",
)

create_cluster >> submit_job >> delete_cluster

Running BigQuery and dbt from Composer

  • BigQueryInsertJobOperator for SQL steps in DAGs.
  • dbt: run it from a worker image with dbt installed, via KubernetesPodOperator, a Dataproc job, or a Cloud Run job triggered by Composer. Package dbt in a container for reproducibility.
  • Dataflow: DataflowStartFlexTemplateOperator for Beam pipelines.

Scheduling Data-Interval Jobs Correctly

Airflow runs a run for data interval {{ ds }} after that interval ends. A schedule="0 6 * * *" DAG processes the previous day's data at 06:00. Always name partition paths from the context ({{ ds }}, {{ ds_nodash }}), never from datetime.now().

Timezone pitfall: if you build partition paths with datetime.now() inside a DAG, you mismatch the data interval and create data leaks across partitions. Derive dates from the Airflow context. Also set catchup=False on new DAGs to avoid surprise backfills.

Monitoring and Alerting

  • Use the Airflow UI for task state, DAG duration, and logs.
  • Cloud Monitoring provides Composer-specific metrics (DAG runs, task state, scheduler health) — build alerting policies on DAG/task failures.
  • Logs go to Cloud Logging; enable data lineage (Dataplex) to track what pipelines produce.
  • Add DAG-level SLA and timeout policies so long-running jobs page the team.

Environment Tuning and Troubleshooting

  • Scheduler too slow: increase scheduler parallelism, or split large environments.
  • Task timeouts: align task execution_timeout with actual runtimes; investigate long-running tasks.
  • DAG import errors: a DAG that fails to parse shows red in the UI; fix the top-of-file import error first.
  • Worker starvation: if tasks queue but never start, workers may be under-provisioned or a Celery deadlock needs an environment restart.
Composer 2/3 note: Composer 2 introduced autoscaling workers and IP address auto-allocation; Composer 3 continues the Kubernetes-native approach. Check the current image version when creating environments and keep DAG code portable so Airflow upgrades are painless.

Configure a Slack or email alert on failure, trigger a backfill for two past days, and confirm idempotent reruns. Document scheduler settings you changed.
