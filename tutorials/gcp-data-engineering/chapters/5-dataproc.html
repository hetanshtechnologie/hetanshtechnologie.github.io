5. Dataproc & Managed Spark

Chapter 5

What is Dataproc?

Dataproc is Google Cloud's managed service for Apache Spark, Hadoop, Flink, Presto/Trino, and related open-source data processing frameworks. It gives you clusters of virtual machines pre-installed with these engines, managed for you — you create a cluster, submit jobs, and let it scale or shut down. You pay for the underlying VMs plus a small managed service fee.

Dataproc is the natural home on GCP for workloads that already run on open-source tools (especially those migrating from AWS EMR, as we'll cover in Chapter 13).

When to Use Dataproc vs Dataflow vs BigQuery

ToolBest ForModel
BigQuerySQL analytics, warehouse workloads, BIServerless SQL
DataflowStreaming and batch pipelines with Beam (portable code, unified model)Serverless, autoscaling
DataprocOpen-source Spark/Hadoop/Flink workloads, ML with PySpark, migrating EMR jobsManaged VMs, full engine control

Choose Dataproc when you have existing Spark code, need specific engine versions, use ML libraries that require Spark, or want control over cluster configuration. Choose Dataflow for new unified batch+stream pipelines. Choose BigQuery when SQL is enough.

Cluster Types

  • Standard cluster: a long-running cluster of master + worker VMs, used for many jobs. Simple but can waste money when idle.
  • Single node cluster: one VM runs both master and worker roles — ideal for development and small jobs.
  • Ephemeral (transient) clusters: created per job, deleted when the job finishes. The cost-efficient default for scheduled batch jobs.
  • Autoscaling clusters: workers scale up and down based on utilization. Requires careful sizing of secondary worker pools.
# Create an ephemeral cluster and run a job in one step
gcloud dataproc jobs submit pyspark \
  --cluster=my-cluster \
  --region=us-central1 \
  gs://my-bucket/etl.py

# Cluster itself is created via:
gcloud dataproc clusters create my-cluster \
  --region=us-central1 \
  --master-machine-type n2-standard-4 \
  --worker-machine-type n2-standard-8 \
  --num-workers 4

Job Submission

Dataproc supports several job types: PySpark, Spark (Scala/Java), Spark SQL, Hadoop MapReduce, Hive, Pig, Flink, Trino/Presto, and shell. Jobs can be submitted:

  • Via the gcloud CLI or console (for manual runs).
  • Via the REST API from Cloud Composer/Airflow (the production pattern).
  • As Workflow Templates — predefined job sequences with dependencies, parameters, and orchestration, which Composer/Airflow can trigger.
# Submit Spark SQL job
gcloud dataproc jobs submit spark-sql \
  --cluster=my-cluster --region=us-central1 \
  --file=gs://my-bucket/queries.sql

Components and Customization

  • Optional components: Jupyter, Zeppelin, Docker, Anaconda, Presto, Flink, Zookeeper, etc. — enabled at cluster creation.
  • Initialization actions: scripts that run on cluster VMs at startup (install packages, mount drives, configure clients).
  • Custom images: pre-built images with your libraries for faster, reproducible startup.
# Enable Jupyter notebook component
gcloud dataproc clusters create ml-cluster \
  --region=us-central1 \
  --optional-components=JUPYTER \
  --enable-component-gateway

Integrating with BigQuery and GCS

Dataproc natively reads and writes Google services:

  • GCS: the gs:// filesystem is available out of the box — Spark jobs read/write files directly (no copying to HDFS).
  • BigQuery: the Spark BigQuery connector (com.google.cloud.spark.bigquery) lets Spark DataFrames read and write BigQuery tables with the Storage Read/Write API. This is how you bridge "Spark processing" and "warehouse analytics".
  • Pub/Sub: the Spark Pub/Sub connector enables streaming ingestion.
# PySpark: read from BigQuery
df = spark.read.format("bigquery").option("table", "myproj.analytics.orders").load()
# write back
df.write.format("bigquery").option("table", "myproj.analytics.orders_processed").mode("append").save()

Cost Management

  • Prefer ephemeral clusters for scheduled jobs — pay only while jobs run.
  • Use preemptible (spot) workers for fault-tolerant, cost-sensitive workloads — they can be reclaimed, so design jobs to tolerate it.
  • Right-size VMs: monitor CPU/memory with Cloud Monitoring and adjust.
  • Use secondary worker pools (scaled-down spot nodes without HDFS) for pure compute.
  • Turn off idle standard clusters via scheduled autoscaling.
Cost math example: An ephemeral cluster with 1 master (n2-standard-4) + 4 workers (n2-standard-8), running 2 hours/day: roughly 5 vCPUs master + 32 worker vCPUs × 2h/day × ~30 days — a small fraction of leaving a 24x7 cluster running. Ephemeral clusters commonly cut Dataproc bills by 60-90%.

High Availability and Reliability

  • HA clusters add multiple masters so driver/coordination failures don't stop the cluster.
  • Job retries: design Spark jobs as idempotent so a retried run is safe.
  • Cloud Monitoring + Logging: cluster metrics, job status, and logs in one place; alert on job failures.
  • Workflow templates provide retry and failure policies at the sequence level.

Dataproc Serverless

Dataproc Serverless runs Spark batch workloads without managing clusters at all: you submit a job with a runtime and resource limits, and Google provisions compute for you. No cluster creation or deletion — ideal for teams that want the Spark API without cluster operations. Choose between managed clusters (control) and serverless (simplicity).

Migration Note for AWS Users

If you are coming from AWS: Dataproc is the managed equivalent of EMR (covered in detail in Chapter 13). Cluster-level concepts, Spark job code, and Hive tables port over directly — the main change is the console/CLI/API and networking (VPC, IAM, service accounts instead of instance roles).

Practice Task: Using Dataproc's free tier budget: (1) create a single-node cluster with Jupyter enabled, (2) run a small PySpark job that reads a public CSV from GCS, does a group-by, and writes Parquet back to GCS, (3) run the same data through the Spark BigQuery connector into a BigQuery table, (4) submit the same job via a Workflow Template and via a simple curl to the API. Document cluster create time, job time, and what the cluster cost by the hour.
