Let's check in on the costing aspect

You have now run a model in Foundry, built an agent, and stood up a function app to back it with live data. All of that costs money, and this is the moment to check what you are paying for. This chapter breaks down the cost drivers of this section, shows how to estimate a bill, and explains the free grants that cover a course project like yours.

The Cost Drivers in This Section

Your setup has three distinct things that can generate charges:

ComponentWhat you pay forCost model
Foundry model deploymentsInput and output tokensPer 1,000 or 1 million tokens
Azure FunctionsExecution time and number of executionsPer execution and GB-second on Consumption
Storage accountData held, operations, and transfersPer GB-month and per operation

Where the Money Actually Goes

For a tool-backed agent, the balance is not what you might guess:

  • Model tokens dominate. Every tool call adds an extra model round-trip: the model decides to call the tool, then processes the tool result and writes the final answer. A question that triggers a tool call consumes roughly twice the tokens of a plain answer.
  • Function executions are cheap. On the Consumption plan you get a generous free grant each month, and each lightweight order lookup costs only fractions of a cent when it runs.
  • Storage is nearly free at this scale. A few megabytes of code and runtime state cost essentially nothing.

The agent's token usage is the hidden multiplier in this section. Each OpenAPI tool call means more prompt tokens (the tool definitions and the conversation so far) and more completion tokens (the tool arguments and the follow-up answer). Budgeting for an API-backed agent means budgeting for token-hungry conversations.

A Worked Example

Suppose a support conversation uses about 2,000 input tokens and 400 output tokens per turn, and a typical exchange takes three turns with one tool call in the middle:

Billable itemQuantityRough cost
Input tokens (6,000 total)6KFractions of a cent
Output tokens (1,200 total)1.2KFractions of a cent
Function executions (1 lookup)1Under the free grant

Repeat that conversation a thousand times a day and the token line becomes real money, while the function app line stays near zero. The lesson: when scaling a tool-backed agent, optimize the model conversations first.

Free Grants That Cover This Course

  • Azure Functions Consumption plan includes a monthly free grant of executions and GB-seconds. Your lab traffic stays well inside it.
  • Foundry offers a monthly free grant on many model deployments, enough for course-scale usage.
  • Storage accounts have a small monthly free tier for the first GB.

Check the current free grant amounts and per-tier rates in the Azure pricing pages for the region you deployed to, because both change over time and vary by region.

Keep a rough mental model: model tokens are the big lever, function execution is a rounding error at course scale, and storage is negligible. When the bill surprises you, look at token usage first.

How to Keep an Eye on It

  • Use the cost analysis page in the portal to see spend grouped by resource and service.
  • Set an alert on the subscription so any unexpected spike triggers an email.
  • Watch token usage in Foundry's monitoring for your model deployments.
  • Remember that the function app keeps running and the storage account keeps storing, even when nobody is chatting; idle resources still carry a tiny baseline.

Summary

The cost of this section is driven almost entirely by model tokens, with function execution and storage well inside free grants at course scale. Estimating a bill means estimating conversations, not server load. The next chapter cleans the lab up so nothing continues to accrue.
