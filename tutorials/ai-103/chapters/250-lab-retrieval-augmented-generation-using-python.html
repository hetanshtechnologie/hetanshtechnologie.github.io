Lab - Retrieval Augmented Generation - Using Python

You have a working search index and a deployed chat model — two systems that do not yet know each other. This lab connects them in Python. You will query the index from code, use an embedding model to enable semantic retrieval, and then build the grounded prompt that produces a RAG answer. When you finish, a single Python script will implement the entire pipeline from question to sourced answer.

What You Will Need

  • The Azure AI Search service and rag-index from the previous labs, with the admin key.
  • A deployed chat model and a deployed embedding model in Foundry, with endpoint and key.
  • Python 3.9 or newer with the azure-search-documents and openai packages installed.
pip install azure-search-documents openai

Step 1: Query the Index from Python

Exercise 1: Run a keyword search with the SDK

  1. Create a folder named ai103-lab250 and open it in VS Code.
  2. Create search.py with the search client. Set these environment variables first:
$env:AZURE_SEARCH_ENDPOINT = "https://ai103-rag-search.search.windows.net"
$env:AZURE_SEARCH_KEY = "YOUR_SEARCH_ADMIN_KEY"
$env:AZURE_OPENAI_ENDPOINT = "https://YOUR-RESOURCE.openai.azure.com/"
$env:AZURE_OPENAI_KEY = "YOUR_KEY"
  1. Paste the script:
import os
from azure.core.credentials import AzureKeyCredential
from azure.search.documents import SearchClient

search_client = SearchClient(
    endpoint=os.environ["AZURE_SEARCH_ENDPOINT"],
    index_name="rag-index",
    credential=AzureKeyCredential(os.environ["AZURE_SEARCH_KEY"]),
)

results = search_client.search(search_text="return policy", top=3, include_total_count=True)

print("Total matches:", results.get_count())
for hit in results:
    print("-", hit["title"], "| score:", round(hit["@search.score"], 3))
  1. Run it:
python search.py

The titles and scores come straight from the index you built. If you see zero results, your indexer may not have completed — check the indexer status as you did in the previous lab.

Step 2: Embed the Query for Semantic Search

Keyword search finds exact terms. Semantic search needs the query converted to a vector, then compared against the content_vector field. The embedding model does that conversion.

Exercise 2: Vector search with an embedding model

Create vector_search.py. Replace YOUR_EMBEDDING_DEPLOYMENT with your embedding deployment name:

import os
from azure.core.credentials import AzureKeyCredential
from azure.search.documents import SearchClient
from azure.search.documents.models import VectorizedQuery
from openai import AzureOpenAI

search_client = SearchClient(
    endpoint=os.environ["AZURE_SEARCH_ENDPOINT"],
    index_name="rag-index",
    credential=AzureKeyCredential(os.environ["AZURE_SEARCH_KEY"]),
)

openai_client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2025-01-01-preview",
)

question = "What is the procedure for returning damaged goods?"

embedding = openai_client.embeddings.create(
    model="YOUR_EMBEDDING_DEPLOYMENT",
    input=[question],
).data[0].embedding

vector_query = VectorizedQuery(
    vector=embedding,
    k_nearest_neighbors=3,
    fields="content_vector",
)

results = search_client.search(
    search_text=None,
    vector_queries=[vector_query],
    top=3,
)

for hit in results:
    print("-", hit["title"], "| score:", round(hit["@search.score"], 3))

python vector_search.py

Ask the same question but phrase it differently — "I bought something and it arrived broken, what do I do?" — and run again. The vector search still finds the same policy, which is exactly what keyword search would struggle with.

The vector dimension of content_vector was set when you created the index. If your embedding model returns a different number of dimensions, the request fails with a dimension-mismatch error. Recreate the index with matching dimensions and re-run the indexer, then retry.

Step 3: Build the Full RAG Answer

Retrieval is only half the pipeline. The retrieved text must reach the chat model inside a prompt, with instructions that keep the answer grounded in the provided context.

Exercise 3: Grounded question answering end to end

Create rag.py that retrieves, augments, and generates in one flow. Replace YOUR_CHAT_DEPLOYMENT and YOUR_EMBEDDING_DEPLOYMENT:

import os
from azure.core.credentials import AzureKeyCredential
from azure.search.documents import SearchClient
from azure.search.documents.models import VectorizedQuery
from openai import AzureOpenAI

search_client = SearchClient(
    endpoint=os.environ["AZURE_SEARCH_ENDPOINT"],
    index_name="rag-index",
    credential=AzureKeyCredential(os.environ["AZURE_SEARCH_KEY"]),
)

openai_client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2025-01-01-preview",
)

def retrieve_chunks(question: str, top: int = 3):
    embedding = openai_client.embeddings.create(
        model="YOUR_EMBEDDING_DEPLOYMENT",
        input=[question],
    ).data[0].embedding

    vector_query = VectorizedQuery(
        vector=embedding,
        k_nearest_neighbors=top,
        fields="content_vector",
    )

    hits = search_client.search(
        search_text=question,
        vector_queries=[vector_query],
        top=top,
        select=["title", "content"],
    )
    return [h["content"] for h in hits]

question = "What is the return procedure for damaged items?"

context = "\n\n".join(retrieve_chunks(question))

response = openai_client.chat.completions.create(
    model="YOUR_CHAT_DEPLOYMENT",
    messages=[
        {
            "role": "system",
            "content": (
                "Answer using only the provided context. If the context does not "
                "contain the answer, say you do not know. Never invent details."
            ),
        },
        {
            "role": "user",
            "content": f"Context:\n{context}\n\nQuestion:\n{question}",
        },
    ],
)

print(response.choices[0].message.content)

python rag.py

Ask a question whose answer is genuinely in your uploaded documents. The model answers from the context. Now ask a question that is not in the documents — the model should refuse or say it does not know, rather than inventing an answer.

This version also passes the raw question as search_text, making it a hybrid search: keyword matching and vector similarity run together and the results are merged. Hybrid retrieval is a strong default for RAG and is what production systems typically use.

Step 4: Label Your Sources

Grounded answers are more trustworthy when they are traceable. Have the model cite which document it used:

def retrieve_with_titles(question: str, top: int = 3):
    embedding = openai_client.embeddings.create(
        model="YOUR_EMBEDDING_DEPLOYMENT",
        input=[question],
    ).data[0].embedding

    vector_query = VectorizedQuery(
        vector=embedding,
        k_nearest_neighbors=top,
        fields="content_vector",
    )

    hits = search_client.search(
        search_text=question,
        vector_queries=[vector_query],
        top=top,
        select=["title", "content"],
    )
    return [(h["title"], h["content"]) for h in hits]

question = "Are refunds available on sale items?"

blocks = []
sources = []
for title, content in retrieve_with_titles(question):
    blocks.append(content)
    sources.append(title)

context = "\n\n".join(blocks)

response = openai_client.chat.completions.create(
    model="YOUR_CHAT_DEPLOYMENT",
    messages=[
        {
            "role": "system",
            "content": (
                "Answer using only the provided context. End your reply with a "
                "line listing the source document names you used."
            ),
        },
        {"role": "user", "content": f"Context:\n{context}\n\nQuestion:\n{question}"},
    ],
)

print(response.choices[0].message.content)

Summary

You completed the RAG pipeline in Python: keyword and vector retrieval against the search index, embedding the query with a deployed embedding model, augmenting the prompt with retrieved context, and generating a grounded answer that refuses to guess when the context is silent. From here, the pattern scales into full applications — richer chunking, reranking, and conversation memory — but the core loop is the one you just built.
