Using the CloudXeus Invoice Intelligence Agent

An agent is only worth what it does in practice. This chapter puts the CloudXeus Invoice Intelligence Agent to work: you will run realistic requests against it, read the traces to see exactly how it reached its answers, and handle the failures that surface. By the end you will have a repeatable test script and a shortlist of improvements grounded in observed behavior.

Testing with Realistic Requests

Start with a set of requests that cover the agent's three jobs: extraction, explanation, and knowledge-based answers.

RequestWhat it tests
"Here is an invoice. What is the total amount?"Tool call and field extraction
"Summarize this invoice in two lines."Tool call plus summarization
"What is our invoice approval policy?"Knowledge base retrieval
"Which of these two invoices is larger?"Multiple tool calls and comparison
"What is the due date?" (document has no due date)Honest refusal instead of invention

Exercise 1: Drive the agent from Python

Create a file named use_agent.py that sends messages to the agent through the project client and prints the reply:

import os

from azure.ai.projects import AIProjectClient
from azure.identity import DefaultAzureCredential

project = AIProjectClient.from_connection_string(
    conn_str=os.environ["PROJECT_CONNECTION_STRING"],
    credential=DefaultAzureCredential(),
)

AGENT_ID = "YOUR_AGENT_ID"

thread = project.agents.create_thread()
project.agents.create_message(
    thread_id=thread.id,
    role="user",
    content="Here is an invoice. What is the total amount?",
    attachments=[],
)

run = project.agents.create_run(
    thread_id=thread.id,
    agent_id=AGENT_ID,
)

while project.agents.get_run(thread.id, run.id).status in (
    "queued", "in_progress", "requires_action"
):
    import time
    time.sleep(2)

messages = project.agents.list_messages(thread_id=thread.id)
for message in messages.data:
    if message.role == "assistant":
        for part in message.content:
            if part.type == "text":
                print(part.text.value)

Run it, then repeat with each request from the table. Record what the agent got right and where it struggled.

Inspecting the Trace

Tracing shows you the reasoning path behind every answer. When you open a run in the portal, look for four checkpoints:

  • The model input: what the agent actually saw, including the tool description.
  • The tool call: which tool was invoked, with what arguments.
  • The tool result: the JSON returned by the extraction endpoint.
  • The final answer: how the model used that result in its reply.

When an answer is wrong, the trace tells you which layer is at fault. If the tool returned the wrong value, the problem is extraction — check Document Intelligence or the tool logic. If the tool returned a good value but the agent stated it wrongly, the problem is the model or the prompt.

Handling Edge Cases and Errors

Real usage surfaces cases the happy path never touches. Test and handle these deliberately:

  • Not an invoice: the tool should return an error the agent can restate honestly, such as "this document could not be read as an invoice."
  • Empty extraction: when a field is missing, the agent must say so rather than guess.
  • Low confidence: the extraction result includes confidence scores; the prompt instructs the agent to flag values below the threshold.
  • Timeout: large documents take time; the tool and the run both need timeouts that produce a friendly response.
  • Multiple documents: if the tool accepts only one file per call, the agent should loop or the tool should support batches.

Do not train a model to lie gracefully. If a document cannot be processed, the agent should say exactly that. Covering up a failed extraction with a plausible-sounding guess is the failure mode most damaging to trust.

Refining the System Prompt

After a test round, refine the prompt based on what you observed. Common adjustments:

  • If the agent answers policy questions from memory instead of retrieval, strengthen the retrieval rule: "For any question about invoice policy, retrieve from the knowledge base first and answer only from what you retrieve."
  • If the agent rounds totals, state the precision rule explicitly: "Report amounts exactly as extracted, with two decimal places."
  • If the agent invents a missing due date, add a concrete fallback: "If due_date is null, answer: the invoice does not list a due date."

Each change is one rule, tested the same way, measured against the same request table.

Automating the Test Round

Once the request set stabilizes, turn it into a repeatable script that runs all requests, collects the replies, and flags any answer containing an invented field. This becomes your regression harness: run it after every prompt change, tool change, or model update — including the model updates you learned to manage in an earlier chapter.

Summary

You tested the CloudXeus Invoice Intelligence Agent across extraction, summarization, retrieval, comparison, and refusal cases, read the traces to locate faults, and refined the system prompt one rule at a time. The agent is now exercised and inspectable. The remaining chapters of this section add the safety and orchestration layers around it, starting with Azure AI Content Safety.
