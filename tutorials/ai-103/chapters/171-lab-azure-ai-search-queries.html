Lab - Azure AI Search - Queries

The index is populated and searchable. Now you will ask it questions. In this lab you query the docs-index with keyword search, apply filters and selections, read result scores, and then call the same service from Python using the official SDK. By the end you will have reusable query patterns for any RAG application.

What You Need Before Starting

  • The search service name, admin key, and resource group variables from earlier labs.
  • The populated docs-index with a non-zero document count.
  • Python 3.9 or later with a virtual environment, and the search package installed: pip install azure-search-documents

Step 1 - Run a Keyword Search

The simplest query sends a $search term to the index's search action. Start with a term that appears in your documents:

az rest --method post `
  --uri "https://$searchName.search.windows.net/indexes/docs-index/search?api-version=2023-11-01" `
  --headers "api-key=$adminKey" `
  --body '{"search": "azure", "top": 5}'

Each hit is a JSON document. Look at the @search.score value on each result — it is a relative measure of how strongly the document matched. Higher is better, and scores are only meaningful within one query, not across different queries.

The default query syntax is simple: terms are combined with an implicit OR, phrases can be quoted, and +/- force inclusion or exclusion. The full Lucene syntax adds proximity, wildcards, and regex. Switch with "queryType": "full" when you need that power.

Step 2 - Add Filters and Select Fields

Most real queries combine a search term with metadata filters. The example below narrows results to a specific source file and returns only the fields the application needs:

az rest --method post `
  --uri "https://$searchName.search.windows.net/indexes/docs-index/search?api-version=2023-11-01" `
  --headers "api-key=$adminKey" `
  --body '{
    "search": "embedding",
    "filter": "metadata_storage_name eq '\''chapter1.pdf'\''",
    "select": "id,title,content,metadata_storage_name",
    "top": 10
  }'

Because the filter runs before ranking, it is an effective way to restrict a large index to a relevant slice — for example, only documents from one product line or one date range.

Step 3 - Query from Python

Application code should not shell out to az rest. Use the azure-search-documents SDK instead. Save the following as search_docs.py and fill in your own service name and key:

from azure.core.credentials import AzureKeyCredential
from azure.search.documents import SearchClient

service_name = "YOUR_SEARCH_SERVICE_NAME"
index_name = "docs-index"
api_key = "YOUR_ADMIN_KEY"

endpoint = f"https://{service_name}.search.windows.net"

client = SearchClient(
    endpoint=endpoint,
    index_name=index_name,
    credential=AzureKeyCredential(api_key)
)

query = "how do I reset the device"

results = client.search(
    search_text=query,
    top=5,
    select=["title", "content", "metadata_storage_name"],
)

for doc in results:
    print(doc["@search.score"], doc["metadata_storage_name"])
    print(doc["content"][:200])
    print("-" * 60)

Run it and you should see a ranked list of matching documents with their source file names and the opening characters of the matching content.

The admin key grants full control of the search service. For application code that only queries, create a query key in the Azure portal or via az search query-key create and use that instead. Never ship an admin key in client code.

Step 4 - Use a Query Key

Create a query key, then swap it into your Python script to prove read-only access works:

az search query-key create `
  --service-name $searchName `
  --resource-group $rg `
  --name app-reader

Update the api_key variable in search_docs.py with the returned value and re-run the script. The results are identical, but the credential now only allows reads.

For RAG you will usually query with search_text for the user's question and combine it with a vector query for meaning-based matching. That hybrid pattern is covered in the enrichment section of the course; the keyword patterns here are the foundation it builds on.

Troubleshooting

SymptomLikely causeFix
403 on searchWrong key for the operationQuery keys cannot write; use the admin key for az rest examples.
Empty result setTerm not in any documentTry a broader term or check documentCount on the index.
Invalid filter expressionMismatched quotes or wrong field nameSingle-quote string literals inside filters and verify the field is filterable.
Module not foundSDK not installedRun pip install azure-search-documents in the active environment.

Summary

You ran keyword searches with the REST API, combined them with metadata filters, and queried the same index from Python with the official SDK using both an admin key and a query key. You can now retrieve ranked results from your own data — the retrieval half of RAG. The next chapter explains how AI enrichment adds meaning-based fields to this index.
