Lab - Enabling Continuous Evaluation on an Agent - Adding Application Insights

Continuous evaluation scores a sample of your production agent traffic against evaluators on an ongoing basis, so you can watch response quality drift before it becomes a problem. The prerequisite is telemetry plumbing: the agent must emit traces, and those traces must land somewhere queryable. In this lab you will create an Application Insights resource, connect it to your Foundry project, and verify that agent traces arrive. With the plumbing in place, the next chapter's lab builds the continuous evaluation on top of it.

Objectives

  • Create an Application Insights resource in Azure.
  • Connect the resource to your Foundry project.
  • Confirm the agent emits traces that Application Insights receives.
  • Run a quick query to prove the telemetry is stored.

Prerequisites

  • A Foundry project with an agent that has at least one published version.
  • Azure CLI (az) installed and signed in, or portal access to create the resource.

Step 1: Create the Application Insights Resource

Application Insights is a standard Azure resource. Create it in the same region as your Foundry project so telemetry travels a short, fast path.

Create App Insights with the Azure CLI

Open a terminal and run the following, replacing the placeholders:

az resource create \
  --resource-group YOUR-RESOURCE-GROUP \
  --resource-type "Microsoft.Insights/components" \
  --name ai103-insights \
  --location eastus2 \
  --properties "{\"Application_Type\":\"web\"}"

Or, if you prefer the portal: search for Application Insights, click Create, choose the same resource group and region as your Foundry project, name it ai103-insights, and create it.

The resource's instrumentation key or connection string identifies it to writers. You rarely need it by hand when connecting through Foundry — the portal links the resources for you — but note that it is visible on the resource's Overview or Properties page.

Step 2: Connect Foundry to Application Insights

Add the connection to your project

  1. Open your Foundry project and go to the Connections section.
  2. Click New connection and choose Application Insights.
  3. Select the ai103-insights resource you created (or enter the connection string manually).
  4. Give the connection a name such as appinsights-prod and create it.

This connection is what lets Foundry write agent telemetry into Application Insights. Without it, traces stop at the portal's internal store and are not queryable in Application Insights — which means no durable history and no continuous evaluation data.

Step 3: Generate Some Agent Traffic

Telemetry has nothing to capture until the agent runs. Open your agent in the Foundry playground and have a short conversation — two or three turns is enough. Then, if your workflow from earlier chapters is still published, run it once as well. Every model call, tool invocation, and workflow step is a trace candidate.

Create the traffic

  1. Open the agent's playground and send a message such as What is the status of my order AC-88231?
  2. Send one follow-up message.
  3. Run the intake-pipeline workflow once with a test message.

Step 4: Verify the Traces Arrive

Wait a minute for telemetry to flush, then check Application Insights.

Query the telemetry

  1. Open the ai103-insights resource in the Azure portal.
  2. Go to Logs and run this query:
traces
| where timestamp > ago(1h)
| project timestamp, message
| order by timestamp desc
  1. If you see rows, the plumbing works — your agent's activity is now stored and queryable.
  2. Run a second query that looks at how the platform categorizes events:
dependencies
| where timestamp > ago(1h)
| summarize count() by type, target

If nothing appears, the usual suspects are: the agent ran before the connection was created, the connection points at a different resource, or telemetry has not finished flushing. Re-run the traffic after verifying the connection, then wait a couple of minutes before querying again.

KQL queries like the ones above are the everyday way to inspect AI workloads. If you ever need to answer "what happened with this customer yesterday," the trace log lets you reconstruct the exact prompts, responses, and tool calls that occurred.

Step 5: Confirm the Connection on the Agent

Finally, make sure the agent itself is set to emit telemetry to this connection. In the agent's configuration, look for the telemetry or monitoring setting and confirm it references the Application Insights connection you created.

The next chapter's lab assumes exactly this state: an Application Insights resource connected to the project, and an agent emitting traces into it. Everything you built here is the foundation for creating and running the continuous evaluation itself.

Summary

You created an Application Insights resource, connected it to your Foundry project, generated real agent and workflow traffic, and verified with KQL queries that the telemetry arrives. The agent's behavior is now recorded in a durable, queryable store. With the instrumentation in place, you are ready for the next lab, where you will create the continuous evaluation and start measuring response quality on an ongoing basis.
