Lab - Giving the Agent Memory Memory Stores and the Memory Search Tool

In the previous lab you watched an agent forget everything the moment a session ended. In this lab you will fix that by giving the agent real memory. You will create a memory store, connect it to your agent, and enable the memory search tool so the agent can look up persisted facts on its own. When you finish, the agent will remember details across completely separate conversations.

Objectives

  • Create a memory store backed by an Azure AI Search index.
  • Connect the store to an agent in the Foundry portal.
  • Enable the memory search tool on the agent.
  • Verify that facts persist across separate conversations.

Prerequisites

  • The convo-demo agent from the previous lab, or any prompt agent in your project.
  • An Azure AI Search service, or permission to create one in your subscription.
  • Contributor access to your Foundry project.

Step 1: Create an Azure AI Search Service

A memory store in Foundry is backed by an Azure AI Search index. The search service provides the durable storage and the semantic search that lets the agent find relevant memories by meaning rather than by exact keyword.

Provision the search service

  1. Open the Azure portal and create a new AI Search resource in the same region as your Foundry project.
  2. Choose a tier. The free tier is enough for learning; the basic tier is fine for development.
  3. After deployment, note the service name and the admin key shown under Settings > Keys.

You could create the service from the command line as well. The equivalent az command is:

az search service create \
  --name YOUR-SEARCH-NAME \
  --resource-group YOUR-RESOURCE-GROUP \
  --sku basic \
  --location eastus2

Step 2: Create a Memory Store in Foundry

Back in the Foundry portal, you will wrap that search service into a memory store.

Add the memory store

  1. In your project, open Agents and select the agent you created in the previous lab.
  2. Find the Memory or Memory stores area in the agent configuration.
  3. Choose to create a new memory store backed by your Azure AI Search service.
  4. Enter the search service name and admin key from Step 1, or select the service from the picker if it appears.
  5. Give the store a name such as customer-memories and create it.

If your search service already contains data, you can reuse an existing index as the memory store. The agent will search that index with its memory search tool. For this lab, an empty store is ideal — the agent will populate it as it converses.

Step 3: Enable the Memory Search Tool

The memory store is only useful if the agent can reach it. Enabling the memory search tool gives the agent the ability to decide, during a conversation, when it needs to look up stored memories.

Attach the tool to the agent

  1. In the agent's Tools section, click Add tool.
  2. Select the memory search tool and bind it to the customer-memories store.
  3. Set a friendly description, for example: "Search the customer memory store for facts the user has shared before."
  4. Save the agent. The tool list should now show the memory search tool.

Descriptions matter enormously for tool selection. The model reads your description to decide whether to call the tool. A vague description leads to the tool being ignored, while a precise one that names when to use it makes the agent call it at the right moments.

Step 4: Verify Memory Across Conversations

Now test the full cycle: store a fact in one conversation and retrieve it in another.

Test persistence

  1. Start a new conversation with the agent and say: My name is Alex and I prefer vegetarian meals. Remember that.
  2. Open a completely new conversation (as if the user returned days later) and ask: What do you know about me?
  3. The agent should search the memory store, find the stored fact, and answer with Alex and the vegetarian preference.
  4. Return to the first conversation and say: I now eat meat sometimes. Update your records.
  5. Open a new conversation again and confirm the updated preference is returned — memory was both stored and updated.

Whether the agent automatically stores new facts depends on the memory mode you enabled. Some configurations let the agent write memories autonomously during the conversation; others only let it read. For a production agent, think carefully about what should be auto-saved versus what must be explicitly confirmed, because anything the agent writes to the store becomes retrievable later.

Step 5: Inspect What Was Stored

Your memory store is a real search index, so you can examine its contents directly:

  1. Open the Azure AI Search resource in the Azure portal.
  2. Open the Indexes blade and select the index behind the memory store.
  3. Use the Search explorer tab and run a query for vegetarian.
  4. You will see the stored document with the fact and its metadata (user, timestamp, source conversation).

Every stored memory typically carries metadata — which user it belongs to, when it was written, and which conversation it came from. When you build your own retrieval layer, always filter on the user field first so one user's memories never surface in another user's conversation.

Summary

You provisioned an Azure AI Search service, created a memory store around it, connected it to your agent, and enabled the memory search tool. The agent can now persist facts in one conversation and retrieve them in another, and you verified the stored documents in the search explorer. Memory has moved from the transcript to a durable store — the single most important step in making agents feel continuous.
