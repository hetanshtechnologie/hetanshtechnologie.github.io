Review of Guardrails and controls

This chapter reviews the guardrails and controls you have met in this section: what guardrails are, the harm categories content filters enforce, how severity thresholds work, the difference between direct and indirect prompt injection, and how prompt shields detect them. Answer the eight questions below from memory first, then check the answer key at the bottom.

Questions

  1. What is the main difference between guardrails and prompt instructions?

    1. Prompt instructions are written by Microsoft; guardrails are written by developers.
    2. Guardrails are deterministic services that return hard verdicts, while prompt instructions depend on the model following them. (correct)
    3. Guardrails only work for image content.
    4. There is no difference; the terms are interchangeable.

  2. Which of the following is NOT one of the main harm categories screened by content filters?

    1. Hate and fairness
    2. Sexual content
    3. Violence
    4. Misspelled words (correct)

  3. In Azure's content filtering, what does the severity score represent?

    1. How certain the filter is that content is harmful.
    2. How severe the detected content is, on a scale with a configurable threshold per category. (correct)
    3. The cost of processing the request.
    4. The number of times a category has fired.

  4. What is indirect prompt injection?

    1. An attack where instructions are hidden inside retrieved documents or tool output. (correct)
    2. An attack where the user directly asks the model to ignore its system prompt.
    3. A filter that checks for copyrighted material.
    4. A method of blocking content by IP address.

  5. What does the prompt shield's verdict look like?

    1. A single yes/no answer with no detail.
    2. A per-type verdict such as attackType: "jailbreak" with a threat ID. (correct)
    3. A rewritten version of the safe prompt.
    4. An HTTP status code only.

  6. Where should prompt shields be applied in an agent pipeline?

    1. Only on the model's final output.
    2. Only on the user's message.
    3. On both user messages and retrieved or tool content that enters the prompt. (correct)
    4. Nowhere; the model's training is enough.

  7. When a content filter blocks a model request, what should your application do?

    1. Retry the request with a different model.
    2. Handle it as an expected outcome: return a friendly message and log the block. (correct)
    3. Return the raw error to the user.
    4. Disable the filter for that user.

  8. What is a blocklist used for in addition to content filters?

    1. To replace the severity model entirely.
    2. To match specific company-policy words and phrases independently of the severity model. (correct)
    3. To reduce latency of requests.
    4. To store user preferences.

Answer Key

QuestionAnswerKey idea
1BGuardrails enforce boundaries deterministically; prompts merely request behaviour.
2DThe main harm categories are hate, sexual, violence, and self-harm.
3BSeverity scores the content, and each category has a configurable threshold.
4AIndirect injection hides instructions in retrieved content, not the user message.
5BPrompt shields return per-type attack detection with a threat ID.
6CBoth user input and untrusted retrieved content must be screened.
7BFilter blocks are expected events; handle them gracefully and log them.
8BBlocklists match exact company-specific terms.

Summary

Guardrails layer deterministic safety checks around the model: content filters score harm categories with configurable severity thresholds, and prompt shields detect direct and indirect injection attempts. You saw how blocks appear in code, how to tune thresholds on real traffic, and where to apply shields so both user input and retrieved content are protected. If any answer surprised you, re-read the guardrails chapters before moving on. The next chapter introduces the model router, which decides which model handles which request.
