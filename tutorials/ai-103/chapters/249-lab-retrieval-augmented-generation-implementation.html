Lab - Retrieval Augmented Generation - Implementation

The previous labs built the pieces: a storage account holding documents and an empty search index. This lab wires them together. You will define a data source that points the search service at your blobs, create an indexer that copies and transforms the documents, run it, and verify that your knowledge base is genuinely searchable.

The Three Objects of Indexing

Indexing on Azure AI Search is configured with three cooperating objects:

ObjectRole
Data sourceDescribes where documents live and how to connect (blob container + credentials)
IndexDescribes the target schema (created in the previous lab)
IndexerThe job that reads from the data source and writes into the index

For plain text documents, the built-in blob parser reads each file's content, so no skillset is required. Embedding can be added either with a custom skill or by a separate step; for this lab the focus is on getting text into the index.

Step 1: Create the Data Source

Exercise 1: Connect the search service to your blobs

Create datasource.json using the connection string you saved in the Blob lab:

{
  "name": "rag-blob-source",
  "type": "azureblob",
  "credentials": {
    "connectionString": "YOUR_BLOB_CONNECTION_STRING"
  },
  "container": {"name": "ragdocs"},
  "dataChangeDetectionPolicy": {"@odata.type": "#Microsoft.Azure.Search.HighWaterMarkChangeDetectionPolicy", "highWaterMarkColumnName": "metadata_storage_last_modified"}
}

Submit it to the search service:

curl -X PUT "https://ai103-rag-search.search.windows.net/datasources/rag-blob-source?api-version=2023-11-01" \
  -H "Content-Type: application/json" \
  -H "api-key: YOUR_SEARCH_ADMIN_KEY" \
  --data "@datasource.json"

The change-detection policy tells the indexer to re-ingest only blobs whose last_modified timestamp moved forward. It makes later re-runs incremental instead of reprocessing every file, which keeps indexing fast as your knowledge base grows.

Step 2: Create the Indexer

The indexer maps source blob fields to index fields. Blob indexers expose built-in metadata fields such as metadata_storage_name, and the file's text is available through the special field content.

Exercise 2: Define the mapping job

Create indexer.json:

{
  "name": "rag-indexer",
  "dataSourceName": "rag-blob-source",
  "targetIndexName": "rag-index",
  "fieldMappings": [
    {"sourceFieldName": "content", "targetFieldName": "content"},
    {"sourceFieldName": "metadata_storage_name", "targetFieldName": "title"}
  ],
  "parameters": {
    "configuration": {
      "parsingMode": "text",
      "dataToExtract": "contentAndMetadata"
    }
  },
  "schedule": {"interval": "PT1H"}
}

The parsingMode: text configuration tells the indexer that the blobs are plain text. For PDFs and Word files, use parsingMode: default or the document-specific modes so the indexer can extract the embedded text.

Step 3: Run and Monitor the Indexer

Exercise 3: Start the job and check its health

Create the indexer and run it on demand (the hourly schedule in the definition is a safety net):

curl -X PUT "https://ai103-rag-search.search.windows.net/indexers/rag-indexer?api-version=2023-11-01" \
  -H "Content-Type: application/json" \
  -H "api-key: YOUR_SEARCH_ADMIN_KEY" \
  --data "@indexer.json"

curl -X POST "https://ai103-rag-search.search.windows.net/indexers/rag-indexer/run?api-version=2023-11-01" \
  -H "api-key: YOUR_SEARCH_ADMIN_KEY"

Wait about a minute, then check the indexer status:

curl -X GET "https://ai103-rag-search.search.windows.net/indexers/rag-indexer/status?api-version=2023-11-01" \
  -H "api-key: YOUR_SEARCH_ADMIN_KEY"

You want to see lastResult.status equal to success with an itemCount matching the number of blobs you uploaded.

An indexer that stays at zero documents usually failed silently on every file. Check lastResult.errors and lastResult.warnings — a common cause is a wrong connection string or a container name typo in the data source. Fix the data source and re-run the indexer; there is nothing else to reset.

Step 4: Verify the Index Is Searchable

Now query the index exactly as the RAG application will — with a keyword search over the content field:

curl -X POST "https://ai103-rag-search.search.windows.net/indexes/rag-index/docs/search?api-version=2023-11-01" \
  -H "Content-Type: application/json" \
  -H "api-key: YOUR_SEARCH_ADMIN_KEY" \
  --data '{"search": "return policy", "top": 3}'

The response lists the documents whose content matches the query, with relevance scores. If you see hits that obviously relate to your uploaded files, the retrieval half of the RAG pipeline is now working end to end.

This search call is exactly what the Python lab later in this section will make programmatically. The pieces you just built — data source, indexer, index — are the same ones that production RAG applications use, just driven here through the management API.

Summary

You connected the search service to Blob Storage with a data source, defined an indexer that maps blob content into the index, ran it, checked its status, and queried the populated index. The knowledge base is now real: documents on disk have become searchable records.
