Building the CloudXeus Invoice Intelligence Agent

With the remote tool ready, you can build the agent that uses it. The CloudXeus Invoice Intelligence Agent is an agent that answers questions about invoices — extracting fields from uploaded documents, summarizing what it finds, and answering follow-up questions in natural language. This chapter creates that agent: choosing the model, writing the system prompt, attaching the tool and the knowledge base, and creating it both in the Foundry portal and through code.

Choosing the Model and Agent Type

Start from the simplest agent shape that does the job. The invoice agent needs to call a remote tool and hold a short conversation, so a lightweight chat model with tool-calling support is a good baseline — for example a small GPT model deployed in your Foundry project. You do not need multi-agent orchestration yet; a single agent with a tool and a knowledge base covers the workflow.

Agent type is a design decision, not a default. A single agent is right when one persona handles the whole request. Multi-agent designs earn their complexity only when the steps need different roles, different knowledge, or different guardrails — which is why workflows appear later in this section.

Writing the System Prompt

The system prompt sets the agent's rules. A good prompt for this agent covers four things:

  • Role: what the agent is and who it serves.
  • Capability boundary: what it can and cannot do — it extracts and explains invoices, it does not create or modify them.
  • Tool discipline: call the invoice tool when a document must be analyzed, and use the knowledge base for questions about invoice policy.
  • Output behavior: answer with the extracted values clearly, flag low-confidence data, and refuse to invent fields that were not extracted.

A concise version:

You are CloudXeus Invoice Intelligence, an assistant for the CloudXeus
accounts team. You extract and explain information from invoices.

Rules:
1. When the user uploads or references an invoice document, call the
   analyze-invoice tool and base your answer on its output.
2. When a question is about invoice policy or procedures, retrieve from
   the knowledge base instead of guessing.
3. If a required field was not extracted, say so explicitly. Never
   invent an invoice number, date, or amount.
4. If the extraction confidence is low, mention it and recommend a
   manual check.
5. Answer concisely. Quote exact values you were given; never round or
   change numbers.

Write the prompt as explicit rules your model can follow line by line. "Be accurate" is not a rule; "if a required field was not extracted, say so explicitly" is.

Attaching the Tool and Knowledge Base

An agent is a model plus the resources it can use. For this agent you attach two:

  • The remote tool — registered from the OpenAPI specification you wrote in the previous chapter, so the model knows it can call analyze-invoice.
  • The knowledge base — cloudxeus-docs, so policy and procedure questions can be answered from retrieval rather than from the model's general knowledge.

Every tool you attach is an additional attack surface. A remote tool that accepts arbitrary document uploads should enforce size limits and validation before the extraction call, as discussed in the previous chapter.

Creating the Agent in the Foundry Portal

In Microsoft Foundry, create the agent from the portal:

  1. Open your project and navigate to Agents.
  2. Click Create and name it cloudxeus-invoice-intelligence.
  3. Select the chat model deployment from your project.
  4. Paste the system prompt into the instructions field.
  5. Add the analyze-invoice remote tool from the OpenAPI connection.
  6. Add the cloudxeus-docs knowledge base under the agent's knowledge resources.
  7. Enable tracing and, if available, attach the content safety configuration you will build later.
  8. Save the agent.

Creating the Agent via Code

The same definition is reproducible from Python with the Azure AI Foundry SDK. Install it, then create the agent from a connection string:

pip install azure-ai-projects
import os

from azure.ai.projects import AIProjectClient
from azure.identity import DefaultAzureCredential

project = AIProjectClient.from_connection_string(
    conn_str=os.environ["PROJECT_CONNECTION_STRING"],
    credential=DefaultAzureCredential(),
)

agent = project.agents.create_agent(
    model="gpt-4o-mini",
    name="cloudxeus-invoice-intelligence",
    instructions=(
        "You are CloudXeus Invoice Intelligence, an assistant for the "
        "CloudXeus accounts team. Extract and explain information from "
        "invoices using the analyze-invoice tool, and answer policy "
        "questions from the knowledge base. Never invent fields."
    ),
    tools=[{"type": "openapi", "openapi": "YOUR_OPENAPI_TOOL_ID"}],
    tool_resources={
        "knowledge": [{"knowledge_base": "cloudxeus-docs"}]
    },
)

print("Agent created:", agent.id)

The exact tool and resource shapes evolve with the SDK, and the portal always shows you the current options. Treat the code above as the structure to adapt: a project client, an agent definition, tools, and tool resources.

Enabling Tracing and Guardrails

Turn on the observability and safety layers before you use the agent, not after:

  • Tracing records each conversation: the prompt, the tool calls, the retrieval hits, and the model output. This is how you will diagnose wrong answers in the next chapter.
  • Content safety screens input and output. You will build the content safety configuration in a later chapter and attach it to this agent.

Summary

You created the CloudXeus Invoice Intelligence Agent: you picked a model, wrote a rule-based system prompt, attached the remote tool and knowledge base, and created the agent in both the portal and code. Tracing is enabled so every answer can be inspected. In the next chapter you will use the agent — testing it with realistic invoice questions and reading the traces it produces.
