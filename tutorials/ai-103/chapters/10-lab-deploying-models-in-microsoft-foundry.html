Lab - Deploying Models in Microsoft Foundry

This lab puts the previous chapter's concepts into practice. You will deploy a real model in Microsoft Foundry, inspect its endpoint, send test requests from the portal playground and from the command line, and then clean up. Completing this lab gives you the endpoint, deployment name, and key that every later coding chapter will reuse.

What You Will Need

  • An Azure free account with a Microsoft Foundry resource (from the earlier labs).
  • A Foundry project inside that resource.
  • Your resource's endpoint and one access key, found under Keys and Endpoint in the Azure portal.

Before you start, decide whether to use a free-tier or pay-as-you-go deployment and keep an eye on it. If your region offers no free tier for the model you pick, the pay-as-you-go option still costs almost nothing for the handful of test requests in this lab — but delete the deployment when you finish, as instructed in the final step.

Step 1: Open Your Project in Foundry

Exercise 1: Deploy a chat model and test it

  1. Open the Foundry portal and navigate to your project.
  2. In the left menu, open the Model catalog. Filter the list to chat models and choose a general-purpose model that is available in your region.
  3. Open the model's card and read the model card summary — note the context length and the supported languages.
  4. Click Deploy (sometimes labeled Deploy to endpoint).
  5. Enter a deployment name such as ai103-chat-deploy. This exact string is what your code will reference, so type it carefully.
  6. Choose the region closest to you and the smallest capacity or tier available. Leave content filtering at its default for now.
  7. Click Deploy and wait for the status to change to Ready. This can take from a few seconds to a couple of minutes.
  8. From the deployments page, open the new deployment. Note the Endpoint URL and the Deployment name — both are needed for the next steps.

If the model card shows no Deploy button or the deployment fails, the model is probably unavailable in your region or under your quota. The fix is usually a different region or a different model family — not a different resource. Try a small sibling model if a large one refuses to deploy.

Step 2: Test from the Playground

Before touching code, test the deployment in the Foundry playground. The playground lets you send a chat request and see the response immediately, which makes it the fastest way to confirm the deployment works:

  1. In your project, open the Playground area.
  2. Select your deployment from the model dropdown.
  3. Send a simple prompt such as "Explain what a token is in one sentence."
  4. Adjust the temperature slider and send the same prompt again. Notice how the same input can produce different wording — that is sampling in action.

The playground is the same model endpoint your code will use, so a good playground result is a strong signal that the deployment itself is healthy. If the playground works but your code fails, the bug is almost always in the code or the connection values — not the deployment.

Step 3: Call the Deployment with curl

Next, verify the endpoint from outside the portal using curl. Replace the placeholder values with your own endpoint, key, and deployment name. On Windows PowerShell, put the JSON body in a file to avoid quoting problems:

# request-body.json
{
  "messages": [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "List three uses of generative AI in customer support."}
  ],
  "temperature": 0.7,
  "max_tokens": 150
}
# Call the deployment (Windows PowerShell)
curl.exe https://YOUR_ENDPOINT/openai/deployments/YOUR_DEPLOYMENT_NAME/chat/completions?api-version=2024-06-01 `
  -H "api-key: YOUR_KEY" `
  -H "Content-Type: application/json" `
  -d "@request-body.json"

On macOS or Linux the same request works with a single line:

curl https://YOUR_ENDPOINT/openai/deployments/YOUR_DEPLOYMENT_NAME/chat/completions?api-version=2024-06-01 \
  -H "api-key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"system","content":"You are a helpful assistant."},{"role":"user","content":"Hello, model!"}],"max_tokens":50}'

A healthy response includes a choices array with your model's text and a usage block with token counts. If you see an authentication error, double-check the key; if you see a 404, verify the deployment name and API version.

Step 4: Inspect the Response

Spend a moment reading the full response JSON. Every field teaches you something:

  • id and model identify which deployment and model served the request.
  • choices[0].message.content holds the generated text your application will use.
  • choices[0].finish_reason tells you why generation stopped — reaching a length limit (length), stopping naturally (stop), or stopping on a content filter.
  • usage reports prompt and completion tokens, which is how your cost is calculated.

If finish_reason is length, the model hit its maximum output cap and the answer is cut off. Your application should detect this and either raise the cap or tell the user the response was truncated — silent truncation produces misleading content.

Step 5: Clean Up

Once you have confirmed the deployment works, delete it unless you are immediately continuing to the next chapter. This stops any recurring cost:

  1. Open the Deployments page in your project.
  2. Select your deployment and choose Delete (or Stop if your platform offers pausing).
  3. Confirm the deletion. The model card in the catalog is unaffected — you can redeploy anytime.
# Or delete via Azure CLI if you prefer
az cognitiveservices account deployment delete \
  --resource-group rg-ai103-rg \
  --name YOUR_RESOURCE_NAME \
  --deployment-name ai103-chat-deploy

Summary

You deployed a chat model to a named endpoint in Foundry, tested it in the playground, verified it from the command line, learned to interpret the response JSON, and cleaned up afterwards. This deployment cycle — create, test, inspect, delete — is the exact workflow you will repeat throughout the course. Next you will review what you learned about model deployment.
