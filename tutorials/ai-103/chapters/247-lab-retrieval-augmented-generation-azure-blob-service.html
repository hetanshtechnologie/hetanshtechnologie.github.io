Lab - Retrieval Augmented Generation - Azure Blob service

Every RAG pipeline starts with the same ingredient: a place to store the documents that will become the knowledge base. In this lab you will create an Azure Blob Storage account, upload a few sample documents, and confirm they are reachable — the storage foundation the following labs will connect to Azure AI Search.

Why Blob Storage

Azure Blob Storage is object storage for unstructured content. It is the natural home for the raw material of RAG — PDFs, Word files, text, and markdown — because it is cheap, scales without limits, and is a first-class data source for Azure AI Search indexers. Documents land in a container inside a storage account, and every file gets a URL you can reference later.

What You Will Need

  • An Azure subscription with an owner or contributor role.
  • The Azure CLI (az) installed and signed in with az login.
  • A resource group to keep this lab's resources together.
az login
az account set --subscription "YOUR_SUBSCRIPTION_ID"

Step 1: Create the Storage Account and Container

Exercise 1: Provision storage with the CLI

Choose a resource group (create one if needed) and run these commands. Replace the placeholder names with values that are unique — storage account names must be globally unique:

az group create --name "ai103-rag-rg" --location "eastus"

az storage account create \
  --name "ai103ragstore" \
  --resource-group "ai103-rag-rg" \
  --location "eastus" \
  --sku Standard_LRS \
  --kind StorageV2

az storage container create \
  --account-name "ai103ragstore" \
  --name "ragdocs" \
  --auth-mode login

If the container creation reports that the account's resource group does not exist or you see a "missing resource group" error, verify the first two commands ran without errors and that your default subscription is the correct one.

Using --auth-mode login creates the container with your Entra identity instead of a shared key. It is the recommended default for new storage resources and avoids handling account keys.

Step 2: Upload Sample Documents

The knowledge base needs realistic content. Prepare two or three small text files, such as a fictional company policy and a product FAQ. For example, create policy.txt and faq.md in a local folder, then upload them:

Exercise 2: Upload documents to the container

az storage blob upload \
  --account-name "ai103ragstore" \
  --container-name "ragdocs" \
  --name "policy.txt" \
  --file "policy.txt" \
  --auth-mode login

az storage blob upload \
  --account-name "ai103ragstore" \
  --container-name "ragdocs" \
  --name "faq.md" \
  --file "faq.md" \
  --auth-mode login

List the blobs to confirm both files are in place:

az storage blob list \
  --account-name "ai103ragstore" \
  --container-name "ragdocs" \
  --auth-mode login \
  --output table

You should see two rows: faq.md and policy.txt, each with a size and a last-modified timestamp.

Step 3: Capture the Connection Details

The next labs need to reach this storage from Azure AI Search. Two values matter: the storage account name (you have it) and a connection string or key that the search service can use. Record the connection string now:

az storage account show-connection-string \
  --name "ai103ragstore" \
  --resource-group "ai103-rag-rg" \
  --query connectionString

A connection string is a credential. Treat it like a password: never paste it into code that is committed to a repository, and revoke it if it leaks. For this course you can keep it in a local notes file; in production, use managed identity between the search service and storage instead of a shared key.

Managed identity is the production-grade alternative to connection strings. You grant the search service's system-assigned identity the Storage Blob Data Reader role on the storage account, and the indexer authenticates without any secret. It is a little more setup now and much safer later — but for these labs the connection string keeps the focus on RAG itself.

Step 4: Verify the Files Are Publicly Addressable

Indexers connect to blobs through their HTTPS endpoints. Your files are private by default, which is exactly what you want. Reachability is handled by the credentials you supply to the indexer, not by making the container public. Confirm the container's access level is private:

az storage container show-permission \
  --account-name "ai103ragstore" \
  --name "ragdocs" \
  --auth-mode login

The output should show publicAccess: None. That is the secure baseline you want before any indexing happens.

Summary

You created a storage account and a ragdocs container, uploaded two sample documents, captured the connection string the next labs will reuse, and verified the container is private. Your knowledge base now has a home. In the next lab you will create the Azure AI Search service that will index these documents and make them searchable.
