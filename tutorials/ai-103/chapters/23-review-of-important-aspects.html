Review of important aspects

Before moving into agents, this chapter stops to consolidate everything you have done since the first API call. The goal is not new material; it is a map of the concepts and a checklist of the skills you should have before the section quiz.

What You Have Learned So Far

  • Making API calls: the OpenAI SDK, the endpoint and key from Foundry, and the chat completions pattern of system and user messages.
  • Controlling behaviour: the system prompt as the main lever, sampling parameters for creativity, max_tokens for length, and response_format for structure.
  • Reasoning effort: reasoning models think before answering, and low/medium/high trade latency and cost against accuracy.
  • Multi-modal input: images travel as base64 data URIs in the message, letting the model describe, transcribe, and compare what it sees.
  • Tools: function calling with schemas, the tool-call loop, and two concrete tools — web search and code execution.

Common Mistakes and How to Avoid Them

  • Hard-coding keys in scripts. Use environment variables so secrets never land in git.
  • Forgetting the model name is a deployment name. The model field must match your deployment, not the base model family.
  • Overlooking finish_reason. A value of length means the answer was cut off, not finished.
  • Adjusting temperature and top_p together. Tune one at a time for predictable results.
  • Sending huge images. Resize first; large images cost time and tokens.
  • Trusting tool arguments blindly. Validate arguments before executing anything.
  • Running generated code without sandboxing. Contain it and set timeouts.

If you can reproduce any lab in this section from memory — write the client setup, send a chat message, add a system prompt, force JSON, send an image, and wire one tool — you are ready for what comes next.

Checklist Before You Move On

  • I can find the endpoint and key for a deployment in Foundry.
  • I can send a chat message from Python and read the response.
  • I can change role and behaviour with a system prompt.
  • I can produce JSON output and parse it in my code.
  • I know when to use a reasoning model and how to set its effort.
  • I can send an image to a vision-capable model.
  • I can build a tool-call loop with a schema and a Python function.

Summary

You have covered the complete lifecycle of talking to a deployed model: authentication, prompting, sampling, reasoning, vision, and tools. These are the raw ingredients of every larger system you will build. The quiz that follows checks that the fundamentals are solid before you move on to agents.
