Lab - Retrieval Augmented Generation - Building the search index

The search service and the index schema are ready, but the cloudxeus-docs index still has no documents. This lab connects to the search service from Python, creates the index from the schema file, reads the chunks produced in the data preparation lab, generates an embedding for every chunk, and uploads the documents in batches.

Install the SDK

The azure-search-documents package drives the search service from Python. It should already be in your virtual environment from the overview lab; if not:

pip install azure-search-documents openai

Configure the Clients

Create scripts/create_index.py and start with configuration values. Put your search endpoint and key and your Foundry embedding deployment name into environment variables or a small config block:

import os
import json
import urllib.request
from pathlib import Path

from azure.core.credentials import AzureKeyCredential
from azure.search.documents import SearchClient
from openai import AzureOpenAI

SEARCH_ENDPOINT = os.getenv("SEARCH_ENDPOINT", "https://YOUR_SEARCH_ENDPOINT.search.windows.net")
SEARCH_KEY = os.getenv("SEARCH_KEY", "YOUR_SEARCH_ADMIN_KEY")
INDEX_NAME = "cloudxeus-docs"

embedding_client = AzureOpenAI(
    api_key=os.getenv("AZURE_OPENAI_KEY", "YOUR_KEY"),
    azure_endpoint=os.getenv("AZURE_OPENAI_ENDPOINT", "YOUR_ENDPOINT"),
    api_version="2024-06-01",
)
EMBEDDING_DEPLOYMENT = "text-embedding-3-small"

The AzureOpenAI client points at your Foundry model deployment. Use the same embedding model here that the index schema's dimensions field expects; text-embedding-3-small produces 1536 dimensions by default.

Build the Index from the Schema

The schema JSON you wrote in the previous lab can create the index directly through the search REST API. A PUT request to the index endpoint creates or updates the index definition:

def create_index_from_schema() -> None:
    with Path("scripts/index_schema.json").open(encoding="utf-8") as fh:
        schema = json.load(fh)
    name = schema["name"]
    url = f"{SEARCH_ENDPOINT}/indexes/{name}?api-version=2023-11-01"
    request = urllib.request.Request(
        url,
        data=json.dumps(schema).encode("utf-8"),
        method="PUT",
        headers={"Content-Type": "application/json", "api-key": SEARCH_KEY},
    )
    with urllib.request.urlopen(request) as response:
        print("HTTP", response.status)
    print("Index ready:", name)

Generate Embeddings

Each chunk needs a vector so vector search can compare meaning. The embedding call is a simple API call; we process chunks in batches so the calls are efficient:

def embed_texts(texts: list[str]) -> list[list[float]]:
    response = embedding_client.embeddings.create(
        model=EMBEDDING_DEPLOYMENT,
        input=texts,
    )
    return [item.embedding for item in response.data]

Upload Documents

Read the chunk file, attach a vector to every chunk, and push them to the index in batches:

def load_documents() -> list[dict]:
    docs = []
    with Path("data/chunks.jsonl").open(encoding="utf-8") as fh:
        for line in fh:
            docs.append(json.loads(line))
    return docs

docs = load_documents()
search_client = SearchClient(SEARCH_ENDPOINT, INDEX_NAME, AzureKeyCredential(SEARCH_KEY))
BATCH = 50

for i in range(0, len(docs), BATCH):
    batch = docs[i:i + BATCH]
    vectors = embed_texts([d["content"] for d in batch])
    for d, vec in zip(batch, vectors):
        d["content_vector"] = vec
    search_client.upload_documents(batch)
    print(f"Uploaded {i + len(batch)}/{len(docs)}")

Run and Verify

Exercise — Populate the Index

  1. Complete the script by calling the functions in order at the bottom: create the index, load the documents, upload them.
  2. Run python scripts/create_index.py from the project root.
  3. Watch the progress lines count up to the total number of chunks.
  4. In the portal, open Indexes > cloudxeus-docs and confirm the document count matches.

The first embedding call pays a one-time cost to load the model, so it may take a few seconds. Later calls in the same script are faster.

If you already created the index with the CLI in the previous lab, the PUT request above will update it in place. If the schema changed, re-run the upload so the stored vectors match the new schema.

Summary

Your index now holds every CloudXeus chunk together with its embedding. The pipeline you just ran is the indexing half of RAG, and it can be re-run any time the source documents change. The next lab shows the retrieval half: querying this index from Python.
