Introduction to Microsoft Foundry

Microsoft Foundry is the cloud platform that brings all the pieces of generative AI together in one place. Instead of stitching together raw virtual machines, model APIs, and storage services yourself, Foundry gives you a unified workspace for building, deploying, evaluating, and monitoring AI applications. This chapter explains what Foundry is, why it exists, and the mental model you need to navigate it.

What Microsoft Foundry Is

Microsoft Foundry is an end-to-end development platform for AI applications built on the Azure cloud. At its core it provides three things: a catalog of models you can deploy in seconds, a set of tools for building applications on top of those models, and the infrastructure that makes those applications production-ready. It is often described as a "studio" or "workspace" because you spend most of your time in a web portal, but everything you create there is backed by real Azure resources you can also manage programmatically.

Foundry is not a single product so much as a coherent layer over many Azure services. Model inference, data storage, evaluation, monitoring, and security are all exposed through a consistent interface, which dramatically reduces the amount of glue code you have to write.

The naming can be confusing because Microsoft has used several related names over time. You may see "Azure AI Foundry," "Microsoft Foundry," or "AI Foundry" referring to the same platform. When in doubt, follow the guidance in this course and look for the Azure AI Foundry portal in your Azure account.

Why Organizations Need a Platform

Raw access to a model API is easy. Running that access safely and at scale in a business is hard. Organizations need a platform because of the challenges that appear once an AI application leaves the demo stage:

  • Security: Who is allowed to call which model? How do you keep keys and data private?
  • Governance: Which models can be used, and what content is filtered or blocked?
  • Cost control: How do you track spending per team, per project, and per request?
  • Consistency: How do you keep every team using the same model versions and settings?
  • Quality: How do you measure whether the model's answers are good enough to ship?
  • Observability: How do you see failures, latency, and usage across all applications?

Microsoft Foundry answers each of these with a built-in feature, which is why enterprises adopt it rather than wiring models directly into their code.

Core Components of Foundry

When you open Foundry you will encounter a small set of recurring concepts. Understanding these now will make every later chapter easier:

ComponentWhat it does
ResourceThe top-level Azure container holding all your AI work in a region.
ProjectA workspace within the resource that organizes models, data, and evaluations for one effort.
Model catalogThe gallery of models you can deploy, from Microsoft and many partners.
DeploymentA specific model made available at your own endpoint with your own settings.
ConnectionsLinks from your project to data sources, APIs, and other Azure services.
EvaluationTools that score how well a model performs on your data and your criteria.

What You Can Build with Foundry

The platform supports the full lifecycle of an AI application. In rough order, you can:

  1. Deploy a model from the catalog to your own endpoint.
  2. Connect your data and build a retrieval pipeline so the model answers from your documents.
  3. Orchestrate the model with tools and workflows to build agents that take actions.
  4. Evaluate the results with automated metrics and human review.
  5. Monitor the live application for cost, latency, errors, and content-safety issues.
  6. Iterate by adjusting prompts, switching models, or fine-tuning on your own data.

Every one of these steps is covered in this course, and each one is a separate tool inside the Foundry portal.

Keep a simple mental model: Foundry is the factory floor. The resource is the building, the project is the assembly line, the model catalog is the parts shelf, and deployments are the machines producing output. When you understand which part you are looking at, the portal stops feeling overwhelming.

Foundry vs. Calling a Model API Directly

You can build a working AI application by calling a model API directly from your code — many developers do. What Foundry adds on top of that raw call is management. Versioned deployments, access control, usage tracking, safety filters, and evaluation tooling all come included, so your application does not have to reinvent them. For learning, both approaches work; for production, the platform approach saves enormous time and reduces risk.

The code you write is still the same style of API call. Foundry does not replace your programming language or framework — it hosts and manages the model behind a standard endpoint that your code talks to just like any other service.

Do not confuse the Foundry portal with your application. The portal is a management console where you configure deployments and monitor usage. The actual serving happens through REST endpoints that your application code calls. Both matter, but they are separate layers.

Summary

Microsoft Foundry is a complete platform for building AI applications: it hosts models, organizes work into projects, and provides the security, cost, quality, and monitoring features that production systems require. It sits between your application code and raw model APIs, adding management without changing how you program. In the next chapter you will create the Azure free account you need to use it.
