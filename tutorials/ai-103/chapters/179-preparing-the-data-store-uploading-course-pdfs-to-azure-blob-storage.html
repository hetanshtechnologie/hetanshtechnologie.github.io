Preparing the Data Store Uploading Course PDFs to Azure Blob Storage

Every knowledge assistant needs a source of truth. For the capstone, that source is the course itself: a set of PDF documents the assistant will answer from. This chapter prepares the data store — gathering the PDFs, creating blob storage, uploading the files, and verifying the container. When you finish, your course material is safely in Azure and ready for the knowledge-base chapters that follow.

What You Are Preparing

The data store has three layers:

  • Local source folder — your original PDFs, kept as the master copy.
  • Storage account — the Azure service that hosts blob containers.
  • Blob container — the named folder inside storage that holds the PDFs.

Everything downstream — chunking, embedding, indexing — reads from this container. Choose its contents carefully because it defines the assistant's entire knowledge boundary.

Step 1 - Gather the Source PDFs

Collect the documents the assistant should know. For this course, five to ten chapters or articles are enough to produce meaningful answers while keeping costs tiny. Put them in a single local folder named course-docs.

Prefer clean, text-based PDFs. Scanned or image-only pages will not extract text with the default parser and will be skipped during indexing. If your documents are scanned, you will need OCR enrichment, which the course covers but the capstone keeps simple.

Step 2 - Set Up the Variables

Start a PowerShell terminal, sign in, and set the variables the commands will reuse. You can reuse the storage account from the ingestion lab or create a fresh one:

$rg = "rg-ai103"
$storageName = "saai103<yourname>"
$containerName = "docs"

az login

Storage account names must be globally unique and use only lowercase letters and numbers. If the name is taken, append a few characters and retry.

Step 3 - Create the Storage Account and Container

Create the storage account (or skip this command if you are reusing one) and the container:

az group create --name $rg --location eastus

az storage account create `
  --name $storageName `
  --resource-group $rg `
  --location eastus `
  --sku Standard_LRS

az storage container create `
  --name $containerName `
  --account-name $storageName

The container creation command above uses your signed-in identity, so it requires the Azure CLI to have permission on the storage account. If you prefer explicit credentials, fetch the connection string and pass --connection-string instead:

$conn = az storage account show-connection-string `
  --name $storageName `
  --resource-group $rg `
  --query connectionString -o tsv

az storage container create --name $containerName --connection-string $conn

Step 4 - Upload the PDFs

Upload every file in course-docs to the container in one batch command:

$conn = az storage account show-connection-string `
  --name $storageName `
  --resource-group $rg `
  --query connectionString -o tsv

az storage blob upload-batch `
  --destination $containerName `
  --source ./course-docs `
  --connection-string $conn

Each file becomes a blob whose name matches the local file name. The batch command is idempotent — re-running it after adding new files uploads only what is missing or changed.

Step 5 - Verify the Upload

Confirm every document made it into the container:

az storage blob list `
  --container-name $containerName `
  --connection-string $conn `
  --query "[].{name:name, size:properties.contentLength}" -o table

You should see one row per PDF with a non-zero size. If a file is missing, check that it is actually inside the course-docs folder and that the file names contain no characters that could confuse the indexer.

Consider organizing files into subfolders such as concepts/, labs/, and reference/. Blob paths become part of the file name in search metadata, so a clean structure makes filters and citations more readable later.

Step 6 - Note the Access Method

The upload used the connection string for simplicity. For the capstone's agent, prefer managed identity so no secret travels with code — the assistant's identity will be granted read access to this container in the permissions chapter. Record the container name, account name, and resource group; you will need them for the knowledge-base and permission steps.

Summary

You gathered the course PDFs, created a storage account and container, uploaded the files in one batch, and verified them with a listing. Your data store is ready and every downstream step will read from this container. The next chapter explains how this store becomes a knowledge source and a knowledge base for agentic retrieval.
