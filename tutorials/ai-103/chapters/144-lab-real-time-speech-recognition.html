Lab - Real-Time Speech Recognition

In this lab you will move from transcribing a file to listening to a live microphone. Realtime recognition streams audio to the Speech service as you speak and returns partial results along the way, updating a caption as each new phrase is finalized. This is the pattern behind live dictation and voice assistants, and it uses the same Speech SDK you already know — the difference is in how the audio is captured and how results arrive.

Realtime vs. One-Shot Recognition

The previous lab used recognize_once(), which is a request–response call: record a short utterance, get one final result. Realtime recognition is event-driven. You start a recognizer, it raises events throughout the session, and you subscribe to those events:

  • Recognizing: fired as partial, intermediate results arrive while you are still speaking.
  • Recognized: fired when a phrase is finalized.
  • SessionStarted / SessionStopped: mark the lifetime of the listening session.

This event model is what makes captions feel live: the partial text updates every fraction of a second, and the final text replaces the partial as soon as the service commits to it.

Exercise: Live dictation from your microphone

Step 1 — Reuse your Speech resource

This lab needs the same resource as the previous one. Confirm your key and region are available as environment variables:

echo $env:YOUR_SPEECH_KEY
echo $env:YOUR_SPEECH_REGION

If they are not set, set them again before running the script.

Step 2 — Create the realtime script

Create realtime_dictation.py with the following code. It captures from the default microphone, prints partial results as they arrive, and keeps listening until you press Enter.

import os
import threading
import time

import azure.cognitiveservices.speech as speechsdk

SPEECH_KEY = os.environ.get("YOUR_SPEECH_KEY", "")
SPEECH_REGION = os.environ.get("YOUR_SPEECH_REGION", "")

speech_config = speechsdk.SpeechConfig(
    subscription=SPEECH_KEY,
    region=SPEECH_REGION,
)
speech_config.speech_recognition_language = "en-US"
speech_config.enable_dictation()

audio_config = speechsdk.audio.AudioConfig(use_default_microphone=True)
recognizer = speechsdk.SpeechRecognizer(
    speech_config=speech_config,
    audio_config=audio_config,
)

def on_partial(evt):
    print("\rpartial: " + evt.text, end="", flush=True)

def on_recognized(evt):
    print("\rfinal:   " + evt.text)

def on_canceled(evt):
    details = speechsdk.CancellationDetails(evt)
    print(f"\ncanceled: {details.reason} — {details.error_details}")

recognizer.recognizing.connect(on_partial)
recognizer.recognized.connect(on_recognized)
recognizer.canceled.connect(on_canceled)

def stop_when_enter_pressed():
    input("\nPress Enter to stop listening...\n")
    recognizer.stop_continuous_recognition()

print("Listening... speak now.")
recognizer.start_continuous_recognition()

threading.Thread(target=stop_when_enter_pressed, daemon=True).start()

while recognizer.state != speechsdk.RecognizerState.Stopped:
    time.sleep(0.5)

print("\nSession finished.")

Step 3 — Run and speak

python realtime_dictation.py

Read a few sentences aloud. You should see partial text updating on the line as you speak, then a final line once each phrase settles. Press Enter to stop.

Why Partial Results Matter

Partial results are the reason a realtime experience feels instant. A user does not wait for the service to decide the whole sentence is done; they watch the text appear word by word. Your application can choose how to treat partials — render them in a lighter style to signal they are provisional, and replace them with the final result when Recognized arrives.

If your default microphone captures a lot of ambient noise, recognition accuracy drops. Try setting the audio config to a known microphone by name, or record a quieter sample and confirm the phrase list from the previous lab still helps with any domain terms.

Continuous vs. Single Recognition

Notice the two different calls this lab uses. start_continuous_recognition() keeps the session open, firing events until you stop it. That is what you want for dictation, captions, or an always-on voice interface. recognize_once(), by contrast, returns after a single utterance. If you are building a wake-word or push-to-talk experience, the once pattern gives you a simple loop; if you want open listening, go continuous.

Continuous recognition holds an open connection to the Speech service the entire time it listens, and it bills for the time the connection is active. In a real product, stop the recognizer when the user is not speaking and restart it on demand, rather than leaving it running indefinitely.

Summary

Realtime recognition turns the Speech SDK into a live captioning machine. You subscribed to the recognizing, recognized, and canceled events, captured audio from the default microphone, and ran a continuous session that streams partial results as you speak.
