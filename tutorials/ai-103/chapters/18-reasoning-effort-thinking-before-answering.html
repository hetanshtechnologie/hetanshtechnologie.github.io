Reasoning Effort Thinking Before Answering

So far the models you have used produce an answer almost immediately. There is another family of models that pause first: they generate an internal chain of reasoning and only then produce the visible answer. This chapter explains what reasoning effort is, when it helps, and how to configure it.

Thinking Before Answering

A standard chat model predicts the next token directly. A reasoning model instead spends time producing intermediate "thinking" tokens that explore the problem before committing to a final answer. For math, logic, multi-step planning, and code debugging, this extra deliberation produces measurably more accurate results.

You can observe the same effect in people: the person who pauses to work the problem on paper usually beats the person who blurts out the first guess. Reasoning models formalize that pause inside the model.

Standard Models vs Reasoning Models

AspectStandard modelReasoning model
How it answersPredicts the answer directlyGenerates hidden reasoning, then answers

LatencyFastSlower, scales with problem difficulty
Cost per taskLowerHigher because of extra reasoning tokens
Examples in Foundrygpt-4o, gpt-4o-minio1, o3, o4-mini-class models

Model families evolve quickly. When you open the model catalogue in Foundry you will find the current list of reasoning-capable models; the naming pattern is usually an o-series rather than a g-series.

Configuring Reasoning Effort

Reasoning models let you trade thinking time against speed. The API exposes a reasoning_effort parameter with three common levels:

  • low — minimal reasoning, fastest, for easy or well-scoped tasks.
  • medium — balanced default for typical problems.
  • high — extensive reasoning for hard problems that deserve the latency.
response = client.chat.completions.create(
    model="YOUR_REASONING_DEPLOYMENT",
    reasoning_effort="medium",
    messages=[
        {"role": "user", "content": "Prove that the square root of 2 is irrational."}
    ],
)
print(response.choices[0].message.content)

Reasoning effort is a property of the model's API surface. A standard chat model such as gpt-4o-mini ignores or rejects this parameter; you need a reasoning model deployment to see the effect.

Choosing the Right Level

The "right" level is the smallest amount of reasoning that still gives correct answers:

Task typeRecommended effort
Simple factual recalllow
Summaries, extraction, everyday chatlow or medium
Analysis, planning, moderate codemedium
Competition math, proof, intricate multi-step debugginghigh

Cost and Latency Trade-Offs

Every reasoning token you generate costs money and takes time. Billing counts the hidden reasoning tokens as well as the visible answer, and the total response time grows with the amount of thinking. A fast chat model might answer in a second; a high-effort reasoning model can take much longer on a hard question. Design your application to use the cheapest adequate level, and route simple requests to standard models when possible.

Inspecting the Thinking

With some SDK versions you can inspect the reasoning portion of a response. Depending on the model and provider policy, it may be returned in a dedicated field or deliberately hidden. The visible answer is always in message.content; reasoning, when exposed, lives in a separate field and is not meant to be treated as a user-facing explanation.

Do not build business logic around the wording of the hidden reasoning. It is a working scratchpad, not a guarantee. Validate the final answer in your code just as you would with any model.

Practical Guidance

  • Start with a standard model for the bulk of your workload.
  • Route hard reasoning tasks to a reasoning model with medium effort.
  • Raise to high only when medium provably fails.
  • Set a generous token budget for reasoning models, since thinking consumes tokens.
  • Measure both accuracy and latency before locking in a configuration.

Summary

Reasoning models think before they answer, trading latency and cost for higher accuracy on hard tasks. The reasoning_effort parameter lets you choose how much thinking happens, and the right level is the smallest one that produces correct results.
