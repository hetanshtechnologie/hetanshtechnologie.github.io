OpenAI - Understanding the Model Lineup

OpenAI does not offer one single model. It offers a family of models, each designed for a different kind of job. Choosing the right model is one of the most important decisions you will make, because it drives quality, speed, and cost. This chapter introduces the main model families, explains how to read their names, and gives you a practical framework for choosing one.

How to Read Model Names

OpenAI model names follow a loose pattern: a family name, a version number, and often a size or capability suffix. For example, a name like gpt-4o-mini tells you it belongs to the GPT-4 generation ("4"), is optimised ("o") for speed and low cost, and is the smaller ("mini") variant of that family.

  • Family: the base model line, such as GPT or a dedicated reasoning line.
  • Version: the generation, which generally becomes more capable with each release.
  • Size marker: terms like mini or small indicate a lighter, cheaper, faster variant.
  • Date codes: some names carry a date, indicating when the model was released or snapshotted.

Model names and versions change frequently. A name that is current when you read this chapter may be deprecated or superseded by the time you sit down to build. Always check the model catalog in your platform of choice — Microsoft Foundry, Azure AI Foundry, or the OpenAI platform — for the current list before you commit to a name in code.

Choosing Between General and Reasoning Models

The two families you will most often compare are the general-purpose chat models and the reasoning models:

  • General chat models respond quickly and handle the vast majority of tasks well — answering questions, drafting text, translating, and writing straightforward code. They are the default choice.
  • Reasoning models spend extra computation thinking before they answer. They shine on problems where a superficial answer is wrong — complex arithmetic, tricky logic, competitive programming — but they are slower and more expensive.

Start with a general-purpose model. If your task is genuinely hard — for example, a multi-step maths problem where quick answers are usually wrong — switch to a reasoning model. Do not pay reasoning overhead for simple requests; it is wasted cost and latency.

Embedding Models and Why They Matter

Embedding models do not generate text at all. They take text as input and output a list of numbers — a vector — that captures the text's meaning. Texts with similar meaning end up with similar vectors, which makes embeddings the foundation of semantic search and retrieval augmented generation. You used exactly this idea earlier in the course when you built search indexes for RAG.

A Simple Selection Framework

  1. Start with the smallest general-purpose model you expect to do the job.
  2. Test it on your real prompts. If quality is clearly insufficient, move up a size.
  3. If the task is inherently multi-step reasoning, try a reasoning model.
  4. If you need search or RAG, add an embedding model for the retrieval side.
  5. Match the modality — add a vision-capable model if images are involved.

Summary

OpenAI's lineup spans general-purpose chat models, dedicated reasoning models, multi-modal models, embeddings, and image and audio generators. Names encode generation, optimisation, and size. The practical skill is matching a model to a task: default to small general models, escalate size or reasoning only when needed, and pull in embeddings and vision models for their specific jobs.
