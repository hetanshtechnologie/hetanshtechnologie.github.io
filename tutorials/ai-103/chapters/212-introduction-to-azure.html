Introduction to Azure

Before you deploy a single model, you need a place to run it. That place is Microsoft Azure, a public cloud platform. This chapter explains what the cloud actually is, how Azure organizes its services, and the core vocabulary — regions, subscriptions, and resource groups — that you will use in every Azure task that follows.

What Cloud Computing Means

Cloud computing is the delivery of computing resources — servers, storage, networking, databases, and software — over the internet, on demand, with pay-as-you-go billing. Instead of buying and maintaining physical hardware, you rent capacity from a provider who operates enormous data centers around the world. The two defining characteristics are elasticity and self-service: you can scale resources up or down as your needs change, and you can provision new resources yourself through a portal or API without waiting for a hardware purchase.

This model is a natural fit for AI workloads. Training and serving models requires bursts of specialized hardware — GPUs, for example — that would be wasteful to own for occasional use. On the cloud you spin up capacity when you need it and release it when you do not.

What Microsoft Azure Is

Azure is Microsoft's public cloud platform. It offers hundreds of services across computing, storage, networking, databases, security, and — most relevant to this course — artificial intelligence. What makes Azure distinctive for AI is the combination of three things:

  • Managed AI services such as Azure OpenAI Service and Azure AI Foundry that package advanced models behind simple interfaces.
  • Enterprise integration with Microsoft's identity, security, and management tools, so organizations can govern AI the way they govern everything else.
  • Data platform integration with storage and databases, which makes patterns like retrieval-augmented generation practical.

Regions and Availability Zones

Azure runs in regions, geographic areas that contain one or more data centers. Each region is an independent failure boundary, so choosing where your resources live matters for latency, compliance, and resilience.

  • Latency: placing resources close to your users reduces response time — important for interactive AI applications.
  • Compliance: some organizations must keep data within a specific country or region for legal reasons.
  • Availability: running the same service in more than one region protects you if a whole region experiences an outage.

Inside a region, Azure uses availability zones — physically separate data centers connected by fast networks — so that a single facility failure does not take down your service. Not every region has zones, and not every service uses them, but the option exists for workloads that need high availability.

For this course, the specific region rarely matters. Choose one near you that offers the model you want to deploy. The course will remind you to pick the same region consistently, because some AI models are only available in certain regions.

Subscriptions

A subscription is the billing and access boundary of your Azure usage. When you create an Azure account, you get a subscription attached to it. All resources you create inside that subscription are billed to it, and permissions are managed relative to it. If an organization uses Azure, it typically has several subscriptions — one per department, project, or environment — so costs and permissions stay separated.

Resource Groups

Resources in Azure are grouped into resource groups. A resource group is simply a logical container that holds related resources so you can manage them together. You might put all the components of one application in a single resource group, which lets you:

  • See everything for a project in one place.
  • Apply permissions to the whole group at once.
  • Delete the entire group to clean up all its resources together.

Resource groups have a region assigned to them (where metadata is stored), but the resources inside a group can live in any region. A resource can belong to only one group, and a group can hold many resources.

Resources and Services

Two words you will see constantly are service and resource. A service is a category of capability — for example, "Azure AI Foundry" or "Azure Storage." A resource is an individual, billable instance of a service that you create — for example, a specific storage account named myblogstorage. When you deploy to Azure, you are creating resources: each one gets a name, a region, a resource group, and a set of configuration options.

The Azure Portal

Azure is managed primarily through the Azure portal, a web interface at portal.azure.com. From the portal you can create, configure, monitor, and delete resources, browse what you have, and view billing. The portal is the graphical front end; underneath it, everything is driven by the same REST APIs that the Azure CLI and automation tools call. You will spend a good amount of time in the portal during the labs, so the next chapters give you a proper tour.

Why Azure for AI

Azure is a strong fit for the AI work in this course for practical reasons. The Azure OpenAI Service hosts the same model families you practiced with on the OpenAI platform, but inside your own subscription with your own access controls and an enterprise support contract. Microsoft Foundry layers on top of that: a single workspace where you browse the model catalog, deploy models, experiment in a playground, build evaluation flows, and later connect data and agents. That combination — capable models plus a management platform plus enterprise governance — is why the rest of the course is built on it.

Summary

Azure is a public cloud platform organized into regions, subscriptions, and resource groups, managed through the Azure portal. Resources are billable instances of services, and the platform is a natural home for AI because of its managed model services, enterprise controls, and data integration.
