Lab - Building Your First AI Agent - The OpenAI SDK

In this lab you will turn the concepts from the previous chapter into a working program. You will build a small but complete AI agent using the OpenAI Python SDK, configure it against an Azure-hosted model deployment, and drive a full conversation from start to finish. By the end of the exercise you will have a reusable script that creates an assistant, opens a conversation thread, submits a message, and reads back the model's final answer.

Objectives

This lab walks through the four stages that every agent application shares:

  • Setting up a Python environment with the SDK installed.
  • Pointing the SDK at your Azure OpenAI resource with an endpoint and key.
  • Creating an assistant object that holds the model name and system instructions.
  • Running a thread-based conversation and polling for the final result.

Prerequisites

Before you begin, make sure you have the following ready:

  • Python 3.10 or later installed on your machine.
  • A deployed model in Microsoft Foundry or Azure OpenAI that your key can access. You will need the deployment name, the endpoint URL, and the API key.
  • Your credentials stored somewhere safe. You will place them in a local .env file that is never committed to source control.

Keep your API key secret. Any code you share, push, or publish must not contain the key itself. Read it from an environment variable or a .env file, and make sure that file is listed in your .gitignore.

Step 1: Create the project environment

Create a new folder for the project and install the packages you need. The OpenAI SDK is the only runtime dependency for this lab.

Set up the project

  1. Open a terminal and create a directory for the lab.
  2. Create a virtual environment so packages stay isolated from the rest of your system.
  3. Install the OpenAI SDK and the dotenv helper for reading credentials.
mkdir my-first-agent
cd my-first-agent
python -m venv .venv
.venv\Scripts\activate
pip install openai python-dotenv

On macOS or Linux the activation command is source .venv/bin/activate.

Step 2: Store your credentials

Create a file named .env in the project folder. Fill in the values from your Azure OpenAI resource. The endpoint looks similar to https://your-resource.openai.azure.com/ and the deployment name is the model name you chose when you deployed it in Foundry.

AZURE_OPENAI_ENDPOINT=https://YOUR_RESOURCE.openai.azure.com/
AZURE_OPENAI_API_KEY=YOUR_KEY
AZURE_OPENAI_DEPLOYMENT=YOUR_DEPLOYMENT_NAME

If you are using the Microsoft Foundry model catalog, the deployment name shown in the playground is the exact string your code must use. It is rarely the same as the base model name, so copy it carefully.

Step 3: Write the agent script

Create a file named agent.py. The script loads the credentials, creates the client, and builds an assistant with a clear set of system instructions. The assistant holds the personality and rules; the thread holds the conversation history.

Create the assistant and start a thread

import os
from dotenv import load_dotenv
from openai import AzureOpenAI

load_dotenv()

client = AzureOpenAI(
    api_key=os.getenv("AZURE_OPENAI_API_KEY"),
    api_version="2024-10-21",
    azure_endpoint=os.getenv("AZURE_OPENAI_ENDPOINT"),
)

assistant = client.beta.assistants.create(
    name="Travel Planner",
    instructions=(
        "You are a travel planning assistant. Help the user build a "
        "day-by-day itinerary. Ask for their destination, budget, and "
        "travel dates before making suggestions."
    ),
    model=os.getenv("AZURE_OPENAI_DEPLOYMENT"),
)

thread = client.beta.threads.create()
print(f"Assistant created: {assistant.id}")
print(f"Thread created: {thread.id}")

Step 4: Send a message and wait for the answer

Agents run asynchronously. Sending a message into the thread does not produce an immediate answer; it creates a run that the service executes on its own timeline. Your code must poll the run until it reaches a terminal state, then read the messages back from the thread.

Complete the conversation loop

import time

client.beta.threads.messages.create(
    thread_id=thread.id,
    role="user",
    content="Plan a 3-day trip to Lisbon for two people.",
)

run = client.beta.threads.runs.create(
    thread_id=thread.id,
    assistant_id=assistant.id,
)

while run.status in ("queued", "in_progress", "requires_action"):
    run = client.beta.threads.runs.retrieve(
        thread_id=thread.id, run_id=run.id
    )
    time.sleep(1)

messages = client.beta.threads.messages.list(thread_id=thread.id)
for message in messages.data:
    for block in message.content:
        if block.type == "text":
            print(f"{message.role}: {block.text.value}")
            print("---")

Step 5: Run and verify

Run the script from the terminal and confirm that the output contains both the user question and the assistant's itinerary.

python agent.py

Experiment with the design:

  • Change the system instructions and observe how the tone of the answer changes.
  • Send a second user message into the same thread to see the assistant remember the earlier request.
  • Lower the temperature parameter when creating the assistant to get more predictable output.

The list of messages includes every turn in the thread, oldest first. The assistant's last message is usually the final element, but scanning all blocks and printing each one is a useful way to watch the conversation unfold during debugging.

Summary

You have now built your first AI agent program: an assistant with system instructions, a thread to hold the dialogue, an asynchronous run, and a polling loop that retrieves the result. This four-part pattern — assistant, thread, message, run — is the foundation you will build on in the rest of this section, where you will add tools, host agents in the Foundry Agent Service, and eventually invoke them as production services.
