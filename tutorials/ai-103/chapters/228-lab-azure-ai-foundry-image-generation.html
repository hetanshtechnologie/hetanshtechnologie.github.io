Lab - Azure AI Foundry - Image Generation

Text models generate words; image models generate pixels. In Azure AI Foundry you can deploy an image-generation model such as a DALL-E family model or another vision-capable model, describe the scene you want in plain language, and receive back a set of images. In this lab you will generate images in the playground, refine your prompt to steer the result, and learn the response shape your code will parse later.

What You Will Need

  • An image-generation model deployed in your Foundry project. If you do not have one yet, deploy a DALL-E family model from the catalog following the same steps as the chat model lab.
  • The playground open with that image model selected.
  • An understanding that image models have their own content-safety rules and may decline certain prompts.

Image generation consumes far more compute per request than chat. Double-check the pricing tier of your deployment and keep your experiments brief. Delete the deployment when you finish the lab to avoid standing charges.

How Text-to-Image Generation Works

An image model takes your description — the prompt — and renders a fresh image that matches it. Unlike a text model, it produces no stream of tokens you can read; it returns one or more image URLs (or base64-encoded image data) plus a generation timestamp. Your application downloads the image from that URL and displays or stores it.

Image prompts are a skill of their own. The best results name the subject, the setting, the style, the composition, the lighting, and the mood. Each added detail narrows the space of possible images the model can paint.

Step 1: Generate a First Image

Exercise 1: Describe a scene and generate it

  1. Open the playground and select your image model.
  2. Enter the prompt "A small wooden cabin on a mountain lake at sunset."
  3. Click Send or the generate button and wait for the images to appear.
  4. Repeat with "The same cabin, drawn as a children's book illustration."

The second prompt shows the power of style words: same subject, completely different art direction.

Step 2: Steer with Detailed Prompts

Compare these three prompts to see how specificity changes the result:

A cat
A fluffy ginger cat sitting on a windowsill, morning light
A fluffy ginger cat sitting on a windowsill, morning light streaming in,
pixel art style, 8-bit game aesthetic, simple flat colors
  1. Send all three and compare the images side by side.
  2. Note how the generic prompt returns an average, unspecific image while the detailed prompts produce images that actually follow the constraints.

If an image model keeps missing an element, check your prompt for ambiguity rather than assuming the model is broken. "A dog and a cat" is easier for the model than "a pet" — name everything you actually want to see.

Step 3: Inspect the Response Payload

The image playground lets you peek at what the API actually returned. Expand the developer or response view and look for the result structure:

{
  "created": 1712345678,
  "data": [
    {
      "url": "https://...generated-image-1.png",
      "revised_prompt": "A fluffy ginger cat sitting on a windowsill..."
    }
  ]
}
  • data — an array, because one prompt can return multiple images.
  • url — where your code can download the generated image.
  • revised_prompt — the safety-rewritten version of your prompt that the model actually used.

Many providers automatically rewrite prompts to remove harmful or copyrighted content before generation. The revised_prompt field shows you the final wording. If your image looks different from what you typed, check this field first.

Step 4: Test Parameters for Image Generation

Image models accept generation parameters that parallel the text parameters you saw earlier:

  • Size: the pixel dimensions of the output, such as 1024x1024, 1792x1024, or 1024x1792. Larger sizes cost more tokens.
  • Number of images (n): how many variants to return in one call.
  • Quality: standard vs. higher-quality rendering, with a corresponding token cost.
# JSON request shape for image generation
{
  "prompt": "A fluffy ginger cat on a windowsill, pixel art style",
  "size": "1024x1024",
  "n": 1,
  "quality": "standard"
}
  1. Generate the same prompt at two different sizes and compare the detail.
  2. Request n: 2 and notice the API returns two variants in a single call.

Summary

You generated images from text, saw how prompt specificity changes the art, inspected the response payload with its URLs and revised prompt, and tested size and count parameters. Image generation is now on your toolkit — later chapters will call the same endpoint from Python. Next you move from Foundry to the theory of prompts with prompt engineering fundamentals.
