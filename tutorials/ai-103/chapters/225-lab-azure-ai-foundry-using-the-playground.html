Lab - Azure AI Foundry - Using the playground

The playground is the fastest way to talk to a deployed model before writing a single line of code. It is a browser-based chat surface that sits directly on top of your endpoint, so the request you send and the response you see are identical to what your application code will produce. In this lab you will chat with your deployment, inspect the request the playground builds, and save conversations for later reuse.

What You Will Need

  • A deployed chat model from the previous lab (ai103-chat-deploy or your own name).
  • The project in Azure AI Foundry that owns the deployment.
  • No code is required — everything in this lab happens in the browser.

Step 1: Open the Playground

Exercise 1: Start a chat with your deployment

  1. Sign in to Azure AI Foundry and open your project.
  2. From the left menu choose Playground.
  3. If a chat session appears automatically, check the model dropdown in the top bar. Otherwise click New chat.
  4. Select your deployed model from the dropdown so the session uses ai103-chat-deploy rather than a default model.
  5. Type "Hello. What can you help me with?" and press Enter.

The playground never charges for the setup screen itself — you only consume tokens when you send a message. Treat it as a free diagnostic tool to confirm a deployment is healthy before you build on top of it.

Step 2: Ask Practical Questions

Send a few prompts that exercise different abilities of the model. Watch how the same model handles each one:

  • A factual question: "What is a token in a large language model?"
  • A creative task: "Write a two-line poem about cloud computing."
  • A translation: "Translate 'good morning, how are you' into Spanish."
  • A summarization: "Summarize in one sentence: tokens are text fragments that models process one at a time."

You should notice the model adapts its style to the request. This happens without any code because the chat API formats every user message into the same underlying request structure.

Step 3: Inspect What the Playground Sends

The playground exposes the raw request so you can learn exactly what your application will send later:

  1. Next to the chat window, expand Developer view (or the View code tab, depending on your portal version).
  2. Look for a JSON payload that contains a messages array.
  3. You will see entries with roles such as system, user, and assistant — the system message you can edit in the setup panel, followed by each turn you typed.
{
  "messages": [
    {
      "role": "system",
      "content": "You are an AI assistant that helps people find information."
    },
    {
      "role": "user",
      "content": "What is a token in a large language model?"
    }
  ],
  "temperature": 0.7,
  "top_p": 0.95,
  "max_tokens": 800
}

The messages array is the heart of every chat-completion request. Each message pairs a role with content. The model answers based on the entire history in the array, which is why keeping the conversation going means appending messages rather than starting over.

Step 4: Save and Reuse a Conversation

When you reach a useful exchange, you do not have to lose it:

  1. Use the Save button in the chat session toolbar and give the session a name such as prompt-ideas.
  2. Return to the main Chat area later and reopen the saved session from the history panel.
  3. Use the Copy or Share option to keep the prompt text for use in a later lab.

A saved chat contains whatever text you and the model exchanged. If you tested with personal or sensitive data, delete the session from history when you finish the lab. The playground is a tool, not a vault.

Step 5: Compare Output Variability

Resend the exact same prompt two or three times. Because the model samples from a probability distribution, the wording usually shifts between runs even though the meaning stays similar. Then move the temperature slider:

  • Set temperature near 0 and resend. The model becomes far more deterministic.
  • Set temperature near 1 and resend. Outputs become more varied and occasionally surprising.

This hands-on feel for temperature will pay off in the next lab, where you tune model parameters deliberately.

Summary

You opened the playground, held a multi-turn conversation, inspected the JSON request the playground constructs, saved a session, and observed how temperature changes output. You now understand the request shape the rest of the course is built on. Next you will tune model parameters and watch them change behavior in real time.
