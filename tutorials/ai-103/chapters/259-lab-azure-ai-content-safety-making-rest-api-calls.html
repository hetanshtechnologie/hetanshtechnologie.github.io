Lab - Azure AI Content Safety - Making REST API calls

The Content Safety SDKs wrap a plain REST API. Understanding that API is valuable because it lets you call the service from any language, debug what the SDK sends, and integrate with tools that only speak HTTP. In this lab you will call the text analysis endpoint directly using the command line and a small Python request, reading the JSON responses yourself.

The Moderation Endpoint

Text moderation lives at a fixed path under your resource endpoint:

POST {ENDPOINT}/contentsafety/text:analyze?api-version=2024-02-15-preview

The request needs two headers:

  • Ocp-Apim-Subscription-Key — your resource key.
  • Content-Type — application/json.

The body is JSON containing the text to analyze.

Calling from the Command Line

On Windows, PowerShell's Invoke-RestMethod makes the call straightforward:

$endpoint = "YOUR_ENDPOINT"
$key = "YOUR_KEY"

$body = @{
    text = "Your sample text to moderate."
} | ConvertTo-Json

$uri = "$endpoint/contentsafety/text:analyze?api-version=2024-02-15-preview"

$headers = @{
    "Ocp-Apim-Subscription-Key" = $key
    "Content-Type" = "application/json"
}

$response = Invoke-RestMethod -Uri $uri -Method Post -Headers $headers -Body $body
$response.categoriesAnalysis | ForEach-Object {
    Write-Output "$($_.category): severity $($_.severity)"
}

On Linux or macOS you can use curl instead:

curl -X POST "https://YOUR_ENDPOINT/contentsafety/text:analyze?api-version=2024-02-15-preview" \
  -H "Ocp-Apim-Subscription-Key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"Your sample text to moderate."}'

PowerShell converts the double-quoted JSON to a hashtable and back, which is fine. Just do not add extra backslashes or quoting inside text — keep the string clean so the service receives valid JSON.

Reading the JSON Response

Whichever tool you use, the response has the same shape:

{
  "blocklistsMatch": [],
  "categoriesAnalysis": [
    { "category": "Hate", "severity": 0 },
    { "category": "Sexual", "severity": 0 },
    { "category": "Violence", "severity": 0 },
    { "category": "SelfHarm", "severity": 0 }
  ]
}
  • categoriesAnalysis — one object per category with its severity.
  • blocklistsMatch — terms from your blocklists that appeared, empty when nothing matched.

Calling from Python with Requests

The SDK is convenient, but sometimes you want a plain HTTP client. Python's requests library keeps the call explicit:

import requests

endpoint = "YOUR_ENDPOINT"
key = "YOUR_KEY"
text = "Your sample text to moderate."

url = f"{endpoint}/contentsafety/text:analyze?api-version=2024-02-15-preview"
headers = {
    "Ocp-Apim-Subscription-Key": key,
    "Content-Type": "application/json",
}
payload = {"text": text}

response = requests.post(url, headers=headers, json=payload)
response.raise_for_status()

for item in response.json()["categoriesAnalysis"]:
    print(f"{item['category']}: severity {item['severity']}")

Install the library first if needed: pip install requests.

Watch the HTTP status code. A 200 means the analysis ran; a 401 means a bad key; a 429 means you hit a rate limit. Reading status codes before parsing the body saves you confusing debugging later.

Verifying Error Handling

Confirm that errors surface clearly by deliberately sending a bad request:

  1. Use an incorrect key and observe the 401 Unauthorized response.
  2. Send an empty text field and read the validation error in the response body.

Understanding these failure modes helps you build robust retry logic in your own applications.

Summary

The Content Safety service is a straightforward HTTP API. You called the text analysis endpoint from PowerShell, curl, and Python's requests library, and you parsed the same JSON response each time. With this foundation you can integrate Content Safety into any stack, with or without the official SDK.
