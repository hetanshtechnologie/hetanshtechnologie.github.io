Lab - Wiring CloudXeus's agent to the Speech MCP Server

In this lab you will connect CloudXeus — the recurring assistant agent from this course — to the Azure Speech MCP server, then hand the agent a conversation in which it must transcribe audio and speak its reply. The lab has two halves: first you configure an MCP client to reach the speech server, then you observe the agent selecting and calling the speech tools on its own.

How the Pieces Connect

The wiring has three parts. CloudXeus is your agent, defined by a system prompt and backed by a model. The Azure Speech MCP server is a hosted endpoint that exposes speech tools. Between them sits the MCP client, which connects the agent to the server, lists the tools, and relays tool calls. When the client starts, the agent discovers the speech tools and can use them for the rest of the session.

Exercise: Connecting CloudXeus to the speech tools

Step 1 — Gather the endpoint and credentials

You need three values:

  • The Azure Speech MCP server URL (for example https://speechmcp.example.azure.com) as instructed in your course workspace.
  • Your Speech key and region from the resource you created earlier.
  • The client configuration file for your MCP client, typically named claude_desktop_config.json for Claude Desktop or the equivalent for your agent runtime.

Step 2 — Register the speech MCP server

Add an entry to your MCP client configuration. The exact shape depends on the client, but it generally looks like this:

{
  "mcpServers": {
    "azure-speech": {
      "type": "sse",
      "url": "https://speechmcp.example.azure.com/sse",
      "env": {
        "AZURE_SPEECH_KEY": "PASTE_YOUR_KEY_HERE",
        "AZURE_SPEECH_REGION": "eastus"
      }
    }
  }
}

Restart the MCP client so it performs the handshake and pulls the tool list from the server.

Step 3 — Confirm the tools are visible

Open your agent client and ask it to list its available tools. You should see the speech tools such as speech recognition and synthesis. If the tools do not appear, check the server URL and that the environment variables reached the server process.

Step 4 — Load the CloudXeus persona

Seed the agent with the CloudXeus system prompt used earlier in the course — the assistant persona that answers with a friendly, structured tone. This keeps the demonstration consistent with the agent you have already built.

Step 5 — Let the agent use the tools

Send the agent a task that exercises both directions of the voice arc, for example:

There is a voicemail audio file at path /tmp/message.wav.
Transcribe it, then summarize the key point and
deliver your summary as spoken audio saved to
/tmp/summary.mp3.

Watch the transcript of tool calls. A correct run will show the agent calling the recognition tool first, reading the resulting text, and then calling the synthesis tool to produce the audio. Open /tmp/summary.mp3 and verify you hear the summary read aloud.

Observing the Tool Selection

The interesting part of this lab is not the code — there is very little — but the reasoning trail. The agent had to decide that transcription was required even though the word "transcribe" never appears in the request; it inferred that an audio file needs listening. Then it had to choose synthesis to deliver the answer in the same modality the user implied. Each of those decisions is a tool call you can inspect in the session log.

Try a variation: change the request to "summarize the voicemail in a chat message instead." The same agent will call recognition but skip synthesis, proving that the model is choosing tools based on the requested output modality, not just running a fixed script.

Troubleshooting the Connection

  • Tools not listed: confirm the server URL and the SSE/streamable endpoint path; a typo here silently yields no tools.
  • Authentication errors on tool calls: verify the Speech key and region inside the server environment, not the client environment.
  • Agent calls the wrong tool: improve the system prompt's descriptions of each tool so the model can distinguish recognition from synthesis.
  • Audio file not found: the agent process must have access to the file path it passes to the tool; use absolute paths.

Summary

You registered the Azure Speech MCP server with your MCP client, verified that CloudXeus discovered the speech tools, and watched the agent transcribe a voicemail and then synthesize a spoken summary without you writing any pipeline code. Speech is now a modality CloudXeus can reason about. In the next chapter you will look at the Voice Live API, which takes speech interaction one step further into realtime conversation.
