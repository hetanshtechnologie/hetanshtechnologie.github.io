Lab - Content Understanding with Agents

In this lab you will connect your Content Understanding analyzer to an agent so the agent can read documents on its own. You will create an agent in Microsoft Foundry, register your document analyzer as a tool it can call, and then test the full loop: upload a document, have the agent extract the fields, and get an answer that is grounded in what it read.

What You Need Before Starting

  • A Microsoft Foundry project with an agent-capable model deployed (any chat model you deployed earlier works).
  • Your Content Understanding resource and a published analyzer — the invoice-analyzer from the earlier lab is ideal.
  • A test document (the same invoice you used in the Python lab).
  • The Azure CLI (az) installed and signed in, plus the role assignments required to connect the services.

Step 1 - Give the Agent Access to Content Understanding

Before the agent can call the analyzer, its identity must be allowed to use the Content Understanding resource. In the Azure portal, open the Content Understanding resource and add a role assignment:

  1. Select Access control (IAM) > Add role assignment.
  2. Choose the Cognitive Services User role.
  3. Assign it to the service principal that represents your Foundry agent (in many setups this is the project's managed identity).
  4. Save the assignment and wait a minute for it to propagate.

If you skip this step, the agent will be able to see the tool but every call will fail with an authorization error. When in doubt, check the resource's activity log or the agent's trace output for the failing call.

Step 2 - Add the Analyzer as a Tool

In the Foundry portal, open the agent editor and go to the tools section. Choose to add a new tool and select the option that connects to Content Understanding. Complete the setup:

  1. Pick the Content Understanding resource and project.
  2. Select the published analyzer you want to expose (for example invoice-analyzer).
  3. Give the tool a clear name and description, such as:
Name: extract_invoice_fields
Description: Extracts vendor, invoice number, dates, and total from an
invoice PDF or image. Use this when the user shares an invoice and asks
questions about its contents.

Save the tool and confirm it appears in the agent's tool list.

The tool description is instruction to the model, not documentation for humans. Be specific about when to call it and what it returns — the agent decides whether to invoke the tool based on this text.

Step 3 - Test the Tool in the Chat

Open the agent's chat interface and run this full loop:

  1. Type "I received an invoice. Can you tell me the total and the due date?"
  2. Attach your invoice file to the message.
  3. Send the message and watch the agent work.
  4. Look for the tool call in the trace: the agent should invoke extract_invoice_fields, receive the JSON, and then answer using the values in it.

The exact attachment mechanism depends on your Foundry setup — some agent experiences accept file uploads directly, while others expect the document to be stored and referenced by URL. If upload is not available, store the file in a container and describe where the agent can find it.

Step 4 - Inspect the Tool Trace

Open the trace or run details for your conversation. You should see a sequence like this:

[user]  I received an invoice. Can you tell me the total and the due date?
[agent] Calling tool extract_invoice_fields(file=invoice.pdf)
[tool]  {"vendor": "ACME Supplies Ltd.", "invoice_number": "INV-1042",
         "issue_date": "2026-07-01", "due_date": "2026-07-31",
         "total_amount": 1249.75}
[agent] The invoice from ACME Supplies Ltd. totals $1,249.75 and is due
        on July 31, 2026.

Notice that the agent did not invent the numbers — it answered from the tool output. This is grounded behavior: the model used the analyzer's structured result instead of guessing.

Step 5 - Probe the Failure Path

Test what happens when extraction cannot work. Attach a file the analyzer cannot read (for example, a binary file renamed to .pdf) and ask the same question. A well-configured agent should say it could not extract the fields rather than fabricate an answer. If your agent instead makes up numbers, add a line to its system prompt: "When a tool fails or returns low confidence, say so and ask for a better file."

Troubleshooting

SymptomLikely causeFix
Tool exists but calls failMissing role assignment on Content UnderstandingGrant the agent's identity the Cognitive Services User role.
Agent never calls the toolTool description is vagueRewrite the description with a clear trigger condition and output summary.
Agent answers without using the toolLow grounding in the system promptInstruct the agent to extract document contents via the tool before answering.
Analyzer not listed when adding the toolAnalyzer not published, or wrong projectPublish the analyzer and confirm the resource is attached to the project.

Summary

You granted your agent access to Content Understanding, registered your invoice analyzer as a callable tool, and watched the agent extract and reason over a real document. The tool trace demonstrated grounded, non-hallucinated answers — the model used the analyzer's structured output. This pattern generalizes to any analyzer: give the agent a tool, describe it well, and let the model decide when to use it.
