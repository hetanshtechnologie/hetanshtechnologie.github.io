Lab - Python - Analyze an Invoice with Azure Content Understanding

In this lab you move from the portal to Python. You will define an invoice analyzer through the Content Understanding REST API, submit an invoice document for analysis, and work with the returned JSON. When you finish you will have a reusable script that extracts invoice data — vendor, invoice number, due date, and totals — from any document you point it at.

What You Need Before Starting

  • Python 3.9 or newer with pip, as configured earlier in the course.
  • The Content Understanding resource you created in the previous lab.
  • Its endpoint URL and API key, copied from Keys and Endpoint in the Azure portal.
  • An invoice to test with. A PDF or image of a one-page invoice works best.
  • The requests library, installed with pip install requests.

Store the endpoint and key in environment variables, not in the script. Never commit credentials to a repository or share them in screenshots.

Step 1 - Set Environment Variables

Open a terminal in VS Code and set the connection values. Replace the placeholders with your own:

$env:CONTENT_UNDERSTANDING_ENDPOINT = "https://YOUR_RESOURCE.cognitiveservices.azure.com/"
$env:CONTENT_UNDERSTANDING_KEY = "YOUR_KEY"

On macOS or Linux the equivalent commands are export CONTENT_UNDERSTANDING_ENDPOINT="..." and export CONTENT_UNDERSTANDING_KEY="...".

Step 2 - Create the Analyzer Definition

The analyzer is defined as JSON. Save the following as analyzer.json. It describes a document analyzer that performs OCR, captures layout, and extracts five invoice fields:

{
  "name": "invoice-analyzer",
  "contentType": "document",
  "description": "Extracts key fields from one-page invoices",
  "config": {
    "ocr": true,
    "language": "en",
    "layout": true
  },
  "fields": {
    "vendor": { "type": "string", "method": "extract", "description": "Company issuing the invoice" },
    "invoice_number": { "type": "string", "method": "extract", "description": "Unique invoice identifier" },
    "issue_date": { "type": "date", "method": "extract", "description": "Date the invoice was issued" },
    "due_date": { "type": "date", "method": "extract", "description": "Payment due date" },
    "total_amount": { "type": "number", "method": "extract", "description": "Grand total including tax" }
  }
}

Write clear description text for every field. The description tells the extraction model what to look for, and the more specific it is, the more reliable the extraction tends to be.

Step 3 - Register the Analyzer

Use the REST API to create the analyzer on your resource. In a terminal run:

$body = Get-Content -Raw analyzer.json
$headers = @{ "Content-Type" = "application/json"; "Ocp-Apim-Subscription-Key" = $env:CONTENT_UNDERSTANDING_KEY }
Invoke-RestMethod -Method Put `
  -Uri "$env:CONTENT_UNDERSTANDING_ENDPOINT/models/invoice-analyzer?api-version=2024-12-01-preview" `
  -Headers $headers -Body $body

A successful call returns the analyzer definition with an id and status READY. In this course's exercises you will do the equivalent work in Python, so let's build the full script now.

Step 4 - Write the Python Analyzer Script

4.1 - Create the project folder

Create a folder named ai103-lab159 and add a file called analyze_invoice.py.

4.2 - Paste the script

Paste the code below. It registers the analyzer if it does not exist, then sends an invoice for analysis and prints the extracted fields.

import json
import os
import requests

ENDPOINT = os.environ["CONTENT_UNDERSTANDING_ENDPOINT"]
KEY = os.environ["CONTENT_UNDERSTANDING_KEY"]
API_VERSION = "2024-12-01-preview"
MODEL_NAME = "invoice-analyzer"

ANALYZER_DEFINITION = {
    "contentType": "document",
    "description": "Extracts key fields from one-page invoices",
    "config": {"ocr": True, "language": "en", "layout": True},
    "fields": {
        "vendor": {"type": "string", "method": "extract",
                   "description": "Company issuing the invoice"},
        "invoice_number": {"type": "string", "method": "extract",
                           "description": "Unique invoice identifier"},
        "issue_date": {"type": "date", "method": "extract",
                       "description": "Date the invoice was issued"},
        "due_date": {"type": "date", "method": "extract",
                     "description": "Payment due date"},
        "total_amount": {"type": "number", "method": "extract",
                         "description": "Grand total including tax"},
    },
}


def ensure_analyzer():
    url = f"{ENDPOINT}/models/{MODEL_NAME}?api-version={API_VERSION}"
    response = requests.put(url, headers={
        "Content-Type": "application/json",
        "Ocp-Apim-Subscription-Key": KEY,
    }, json=ANALYZER_DEFINITION)
    response.raise_for_status()
    print(f"Analyzer ready: {response.json().get('id')}")


def analyze_document(file_path):
    url = f"{ENDPOINT}/models/{MODEL_NAME}:analyze?api-version={API_VERSION}"
    with open(file_path, "rb") as fh:
        response = requests.post(url, headers={
            "Ocp-Apim-Subscription-Key": KEY,
        }, files={"file": fh})
    response.raise_for_status()
    return response.json()


if __name__ == "__main__":
    ensure_analyzer()
    result = analyze_document("invoice.pdf")
    document = result["content"]["documents"][0]
    print(json.dumps(document["fields"], indent=2))

4.3 - Run the script

Place your invoice file in the folder as invoice.pdf (or update the filename) and run:

python analyze_invoice.py

Understanding the Response

The analysis response mirrors the portal output. The part you will use most is the fields object inside the first document:

{
  "invoice_number": {
    "valueString": "INV-1042",
    "confidence": 0.98,
    "regions": [{ "pageNumber": 1, "polygon": [10, 20, 60, 20, 60, 40, 10, 40] }]
  },
  "total_amount": {
    "valueNumber": 1249.75,
    "confidence": 0.95,
    "regions": [{ "pageNumber": 1, "polygon": [...] }]
  }
}
  • valueString, valueNumber, or valueDate — the extracted value, whose shape depends on the field type.
  • confidence — how confident the model is about the extraction.
  • regions — the page and polygon where each value was found.

Add a quick guard to your pipeline: when a field's confidence is below a threshold such as 0.8, send that document to a review queue instead of trusting the value.

Error Handling Quick Reference

ErrorLikely causeFix
401Wrong or missing keyRe-check the environment variable and the resource key.
404 on analyzeThe analyzer name does not matchUse the exact MODEL_NAME you registered.
415 unsupported mediaUnsupported file formatSubmit PDF, PNG, or JPG.
400 invalid requestMalformed analyzer JSON or bad field typeValidate analyzer.json against the documented schema.

Summary

You registered an invoice analyzer through the REST API, submitted a document from Python, and read typed field values with confidence scores from the response. This is the same call pattern you will reuse for image analyzers in the coming labs, and the structured output you produced is exactly the input your future RAG index and agents will consume.
