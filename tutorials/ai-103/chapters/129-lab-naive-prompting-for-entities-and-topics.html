Lab - Naive Prompting for Entities and Topics

In this lab you will write your first text-analysis prompts. The word naive is deliberate: you will simply ask the model to find entities and topics and let it choose its own output format. This is the fastest way to analyze text with an LLM, and it also exposes the inconsistency that motivates the structured-JSON lab that follows.

Prerequisites

  • The project folder from the resources-download chapter, or the dependencies installed in your ai103-language folder.
  • A deployed chat model in Microsoft Foundry. Note its deployment name.
  • Your endpoint and key as environment variables (AZURE_OPENAI_ENDPOINT, AZURE_OPENAI_KEY).

Step 1: Build a Reusable Chat Client

Exercise 1: Create the client helper

Create naive_prompt.py:

import os

from dotenv import load_dotenv
from openai import AzureOpenAI

load_dotenv()

client = AzureOpenAI(
    azure_endpoint=os.getenv("AZURE_OPENAI_ENDPOINT"),
    api_key=os.getenv("AZURE_OPENAI_KEY"),
    api_version="2024-06-01",
)

DEPLOYMENT = "YOUR_DEPLOYMENT_NAME"


def ask(system: str, text: str) -> str:
    response = client.chat.completions.create(
        model=DEPLOYMENT,
        messages=[
            {"role": "system", "content": system},
            {"role": "user", "content": text},
        ],
    )
    return response.choices[0].message.content

Run the script to confirm it imports cleanly:

python naive_prompt.py

Step 2: Extract Entities with a Naive Prompt

Exercise 2: Ask the model for entities

Append a sample document and a plain-language request to the same file:

if __name__ == "__main__":
    document = (
        "Acme Robotics shipped its new inspection drone to Frankfurt on "
        "March 12. CEO Dana Whitfield announced the launch at the plant "
        "near Berlin, with a retail price of 2,400 euros."
    )
    entities = ask(
        "You are a text analysis assistant.",
        f"Find the entities in this text:\n{document}",
    )
    print(entities)
  1. Run the script and study the output. The model should list people, places, dates, organizations, and prices — but notice exactly how it formats them. Lists, line breaks, bullets, and wording are all chosen freely by the model.
  2. Run it again with a different document, such as a sentence about a support ticket or a product review. Confirm the model adapts to the new content.

This is the naive approach at its most useful: zero effort, sensible results, works on any text. It is also at its most fragile — there is no guarantee the format matches what your code expects.

Step 3: Detect Topics with a Naive Prompt

Exercise 3: Ask the model for topics

Add a topic-detection call next to the entity call:

    topics = ask(
        "You are a text analysis assistant. Label the topics in the text.",
        (
            "Our billing portal rejected my payment three times today. "
            "The error page never shows a reason and the retry button "
            "loops back to the same failure."
        ),
    )
    print(topics)
  1. Run the script. The model should return thematic labels such as "billing", "payments", or "customer support".
  2. Ask for a specific number of topics: change the system prompt to "Label the topics in the text. Return exactly two topic labels." Notice how the output changes.
  3. Compare the entity output with the topic output side by side. The entity output is item-level facts; the topic output is a whole-document theme.

Step 4: Observe the Inconsistency

Run each prompt three times in a row and compare the outputs. You will see the real weakness of naive prompting:

  • The model may switch between a comma-separated line, a bulleted list, or a numbered list for the same request.
  • Entity labels may change from PERSON to name to nothing at all.
  • Topic phrasing varies even when the meaning stays the same.

None of these differences matter to a human reading the output. All of them matter to a program trying to parse it. That gap between human-readable and machine-usable output is exactly what the next lab fixes.

Keep naive_prompt.py — you will reuse the ask() helper and the same sample document in the next lab, which rebuilds these exact requests in a strict JSON format.

Summary

You prompted a chat model to extract entities and label topics using plain-language requests, observed how the model adapts to different documents and instructions, and demonstrated that naive output format varies run to run. That variability is the motivation for the next lab, where you will force the model into structured JSON.
