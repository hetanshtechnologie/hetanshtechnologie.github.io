Lab - Enabling Continuous Evaluation on an Agent -Creating the evaluation

In the previous lab you connected your agent to Application Insights so that live traffic produces trace data. That telemetry is only useful if something examines it. This lab builds the second half of continuous evaluation: you will create an evaluation flow in Microsoft Foundry that pulls recent chat data, scores it with built-in evaluators such as groundedness and relevance, and produces a quality dashboard you can watch over time. By the end you will have a running evaluation that re-scores your agent on new data automatically.

What You Need Before Starting

  • Your Foundry project with the support agent deployed from earlier labs.
  • The agent connected to Application Insights, as completed in the previous lab.
  • At least a handful of real or generated chat messages recorded in that workspace, because an evaluation needs data to score.
  • A chat model deployment in the project that the evaluation can use as a judge (for example gpt-4o-mini).

If your agent has little real traffic yet, send it a few test questions first — for example a product question, a pricing question, and an out-of-scope question. Each conversation will be captured by Application Insights and become candidate data for the evaluation.

How the Evaluation Flow Works

A continuous evaluation flow in Foundry does three things in a loop: it reads a batch of recent conversations, runs one or more evaluators over them, and records the scores so you can view trends. The evaluators themselves are typically LLM-as-a-judge style prompts — a judge model reads the question, the retrieved context, and the answer, then scores a quality dimension on a scale. This is why you need a judge model deployment in addition to your agent's own model.

The steps you will follow in the portal are:

  1. Create a new evaluation flow for your agent.
  2. Choose the data source: the traces stored in your Application Insights workspace.
  3. Pick the evaluators you want to run, such as groundedness, relevance, and coherence.
  4. Configure the judge model and the score scale.
  5. Define thresholds and alerts, then start the evaluation.

Creating the Evaluation

Step 1 - Open the Evaluation page

In your Foundry project, open Evaluation from the left menu. On the Continuous evaluations tab, click Create evaluation.

Step 2 - Select the target and data source

Choose your support agent as the target application. For the data source select the Application Insights workspace you connected in the previous lab. Foundry will map each conversation into a record with fields such as the user question and the assistant's answer.

Step 3 - Pick the evaluators

Add built-in evaluators from the catalog. A useful starting set for a grounded support agent:

EvaluatorWhat it measures
GroundednessWhether the answer is supported by the supplied context
RelevanceWhether the answer addresses the user's question
CoherenceWhether the answer reads as logical and connected
FluencyWhether the language is natural and grammatical

Step 4 - Configure the judge model

For each evaluator, select the judge model deployment (for example gpt-4o-mini) and the prompt that defines the scoring rubric. The default prompts give a score from 1 to 5; you can keep them or tighten the rubric to match your product.

Step 5 - Define thresholds and alerts

Set a threshold, such as alert when groundedness drops below 3.5. This turns the evaluation into a safety net: you get notified when quality degrades instead of discovering it in user complaints.

Step 6 - Start the evaluation

Click Create and start. Foundry runs the evaluation against the current data and schedules it to run on the interval you selected. After a few minutes, open the evaluation to see the score dashboard.

Evaluating a Single Record Programmatically

You can also score individual conversations from code before you invest in a continuous flow. This is a quick way to prototype evaluator prompts. Install the evaluation SDK and run a one-off check with your own rubric:

pip install azure-ai-evaluation

from azure.ai.evaluation import RelevanceEvaluator, GroundednessEvaluator
from azure.identity import DefaultAzureCredential

credential = DefaultAzureCredential()

relevance = RelevanceEvaluator(
    azure_ai_project={
        "subscription_id": "YOUR_SUBSCRIPTION_ID",
        "resource_group_name": "YOUR_RESOURCE_GROUP",
        "project_name": "YOUR_PROJECT_NAME",
    },
    credential=credential,
    model_config={
        "type": "azure_openai",
        "azure_endpoint": "https://YOUR_ENDPOINT.openai.azure.com/",
        "api_key": "YOUR_KEY",
        "azure_deployment": "gpt-4o-mini",
    },
)

result = relevance(
    query="What is the refund policy?",
    response="We refund unused licenses within 30 days of purchase.",
)

print(result)

Use the interactive chat trace view of one conversation to understand why a low score happened before you change anything. A low groundedness score usually means the retrieved context was missing or the model answered from memory.

Interpreting the Results

The dashboard groups scores by evaluator and shows the distribution over time. Treat it as a health gauge:

  • A stable high average means the agent is holding its quality bar.
  • A declining trend often follows a change: a new system prompt, a different embedding model, or updated source documents.
  • A spike of low scores usually points at a specific data problem, such as a batch of documents that fail to index.

Evaluations judge, they do not fix. When an alert fires, use the trace data to locate the failing conversations, then adjust the prompt, the retrieval, or the data — and let the next scheduled run confirm the improvement.

Summary

Continuous evaluation turns live telemetry into a quality signal. In this lab you created an evaluation flow, selected data from Application Insights, chose built-in evaluators, configured a judge model, and set thresholds that alert you when quality drops.
