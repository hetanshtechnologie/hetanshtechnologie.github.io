Evaluators - The Measuring Instruments of AI Quality

Operational monitoring tells you that your model is running. It cannot tell you whether the model's answers are any good. To measure quality you need evaluators — the instruments that score AI output against a standard. In this chapter you will learn what evaluators are, the categories they measure, and how to pick the right ones for a workload. In the lab that follows you will wire continuous evaluation into an agent using Application Insights.

What an Evaluator Is

An evaluator is a component that takes an input — typically a prompt, the model's response, and sometimes reference context — and produces a score or a verdict. Evaluators come in two broad flavors:

  • AI-assisted evaluators: A model (often a separate one) judges the response against a rubric and returns a score with an explanation. Flexible and good at qualitative judgments like coherence.
  • Code or metric-based evaluators: Deterministic calculations such as string similarity, word counts, or fact-matching. Fast, cheap, and perfectly reproducible, but limited to measurable qualities.

Evaluators do not judge "good" in the abstract. They judge a response against the specific criteria you choose. The same response can score high on fluency and low on groundedness at the same time — which is exactly why you should use several evaluators together rather than one catch-all.

Common Evaluation Dimensions

Foundry offers evaluators that target different aspects of response quality:

EvaluatorWhat it measures
GroundednessWhether the answer stays supported by the retrieved source material, without inventing facts
RelevanceWhether the response actually answers the user's question
CoherenceWhether the response flows logically from one point to the next
FluencyWhether the language is natural, grammatical, and readable
SimilarityHow close the response is to a reference (ground-truth) answer
Retrieval scoreHow well the RAG pipeline retrieved the documents the answer needed

Safety dimensions form a second family — measures for harmful content, jailbreak attempts, and protection against leaking personal information. For any customer-facing system, quality and safety evaluators belong together.

When to Evaluate

Evaluation has value at different points in the lifecycle, and each point answers a different question:

  • Prompt development: Run a small set of test prompts through candidate system prompts and compare scores. This is how you know prompt A is better than prompt B, instead of just feeling like it is.
  • Release checks: Before publishing a new agent version or model, run the regression set and confirm the scores have not dropped.
  • Continuous evaluation: Score a sample of production traffic on an ongoing basis and watch for drift — the model or the data changing under you.

The same dataset of representative prompts is your measurement stick everywhere. Keep a golden set of 20 to 50 prompts with expected characteristics, and run every candidate prompt or model against it. Without a fixed measurement, you cannot tell whether an improvement is real.

Designing a Good Evaluation Set

The quality of an evaluation is only as good as the data you feed it. Keep these rules in mind:

  • Represent real usage: Use prompts that mirror what actual users ask, including edge cases and messy phrasing.
  • Include reference context: Groundedness and retrieval evaluators need the source documents to compare against.
  • Cover failure modes: Deliberately include tricky cases — off-topic questions, vague questions, requests for ungrounded facts.
  • Label important items: Flag high-risk categories so you can filter results by them later.

A golden set that only contains easy, well-formed questions will report rosy scores that collapse the moment real traffic arrives. Make the set uncomfortable: half of it should be the questions you hope users never ask.

Choosing the Right Evaluators

Match the evaluators to the failure modes your workload cares about:

  • For a RAG assistant that must not hallucinate: groundedness and relevance are non-negotiable.
  • For a summarization pipeline: coherence, fluency, and similarity to a reference summary.
  • For a customer-facing chatbot: add safety dimensions on top of quality ones.
  • For a search-backed workflow: monitor the retrieval score so you know when the index or the query is the weak link.

AI-assisted evaluators cost tokens and add latency, so score a sample rather than every request. Continuous evaluation typically rates a fraction of production traffic — enough to detect drift, cheap enough to run forever.

Summary

Evaluators are the instruments that measure AI quality, in two families: AI-assisted judges for qualitative dimensions and code-based metrics for deterministic ones. They cover groundedness, relevance, coherence, fluency, similarity, and retrieval quality, plus safety dimensions. You apply them during prompt development, at release, and continuously in production, always against a fixed evaluation set.
