Capstone Project Overview Building the CloudXeus AI Course Assistant

Everything in this course leads to one deliverable: a working knowledge assistant. The capstone project asks you to build the CloudXeus AI Course Assistant, an agent that answers questions about this course from the course's own documents. It is not a toy demo. You will combine blob storage, a search index, embeddings, a chat model, and an agent — the exact stack used in production RAG applications — and make it answer real questions with citations.

The Goal

CloudXeus is a learner who wants to study the AI-103 course efficiently. The assistant's job is to answer their questions about the material — what a term means, how a lab is done, where a concept is explained — strictly from the course documents. It must:

  • Retrieve the most relevant passages for each question.
  • Answer only from those passages, not from the model's training knowledge.
  • Cite the source file so the learner can verify and read more.
  • Stay conversational and respond helpfully when the documents lack an answer.

Why This Project

The capstone deliberately reuses every arc of the course. Retrieval Augmented Generation provides the retrieval-and-grounding pattern, Azure AI Search provides the index, skillsets provide the chunking and vectors, Foundry provides the models and the agent runtime, and the OpenAPI and tool patterns let the assistant behave like a real product. If you can build this assistant, you can build most knowledge-assistant applications on Azure.

There is no single correct architecture for a RAG assistant. The course teaches the most common production pattern; the capstone asks you to assemble it correctly and explain the choices you made. If you build it differently but with the same guarantees — grounded answers, current data, citations — that is a valid solution too.

The Architecture

The project uses five pieces that work together:

ComponentRole in the assistant
Azure Blob StorageHolds the raw course PDFs, the source of truth
Azure AI SearchIndexes chunked content and answers retrieval queries
Embedding modelVectorizes chunks at index time and the question at query time
Chat modelWrites the final grounded answer
Foundry project and agentOrchestrates retrieval and generation, holds the assistant persona

Data flows in one direction. PDFs land in storage, a skillset-indexer pipeline chunks and embeds them into the search index, and the agent queries that index for every learner question.

How a Question Flows Through the System

  1. A learner asks the assistant, for example: "What is hybrid search and why does RAG use it?"
  2. The agent decides the question needs the knowledge base and composes a search.
  3. The search service returns the top matching chunks with source metadata.
  4. The chunks are added to the prompt as context, and the chat model writes an answer.
  5. The answer cites the file the information came from.

Keep this flow in mind when things go wrong. If the answer is wrong, the fault is usually one of three places: the chunk (bad split), the retrieval (bad query or ranking), or the generation (model ignoring context). The chapters ahead help you isolate each stage.

What You Will Build, Step by Step

  • Data store: upload the course PDFs to blob storage.
  • Knowledge base: create a search index over the course content.
  • Models: deploy the embedding and chat models the assistant needs.
  • Permissions: assign the identities that let services read each other securely.
  • The assistant: wire the agent to the index and test grounded conversations.

Success Criteria

Before you call the project done, confirm the assistant passes these checks:

  • A definitional question (e.g., "what is a token?") returns a correct answer with a source.
  • A procedural question (e.g., "how do I run the indexer?") returns steps found in the documents.
  • A question outside the documents is answered honestly as unknown rather than guessed.
  • Answers stay grounded: nothing is invented, and every claim traces to a retrieved chunk.

The capstone runs paid services. A corpus of five to ten PDFs keeps embedding and storage costs trivial, and inference costs are a few cents per session. When you finish the project, delete the resource group so nothing keeps accruing charges.

Summary

The capstone assembles the whole course into one product: the CloudXeus AI Course Assistant, a grounded knowledge agent over the course documents. It reuses storage, search, skillsets, models, and the agent runtime, and it succeeds only when answers are correct, grounded, and cited.
