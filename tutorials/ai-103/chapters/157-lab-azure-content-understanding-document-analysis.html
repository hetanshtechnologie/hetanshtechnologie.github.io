Lab - Azure Content Understanding - Document Analysis

In this lab you will work with Azure Content Understanding end to end for the first time. You will create the resource, define a document analyzer in the Foundry portal, upload a sample document, and examine the structured output it produces. By the end you will have seen the OCR, layout, table, and field layers from the previous chapter in action — and you will know exactly what the portal and the API call produce.

What You Need Before Starting

  • An active Azure subscription and the ability to create new resources.
  • Access to Microsoft Foundry (the AI Foundry portal) and the resource group where your other course resources live.
  • A sample document to analyze. You can use any contract, form, or invoice PDF you have at hand; a one-page form with clear labels works best.
  • A text editor to save the JSON output you copy from the portal.

If you do not have a document handy, print a simple table from a spreadsheet to PDF, or scan a filled-out paper form. The classic choice for this lab is an invoice, because it exercises OCR, layout, tables, and fields all at once.

Step 1 - Create the Content Understanding Resource

Content Understanding runs as an Azure resource, like the other services in this course. To create it:

  1. Sign in to the Azure portal and select Create a resource.
  2. Search for Content Understanding and select the service.
  3. Choose your subscription and the resource group you use for this course.
  4. Give the resource a unique name, such as cu-course-<yourname>.
  5. Select a region where the service is available, then create the resource.
  6. Once deployed, open the resource and navigate to Keys and Endpoint. Note the endpoint URL and one of the keys — you will use them in the next lab.

Treat the resource key like a password. Do not paste it into chat windows, public repositories, or shared screenshots. For the portal-based parts of this lab you will not need the key at all, but you will need it when you call the API from code.

Step 2 - Open Content Understanding in Foundry

Microsoft Foundry hosts the analyzers for Content Understanding. From the AI Foundry portal:

  1. Select your project, or create a new project that points at the Content Understanding resource you just created.
  2. In the left navigation, find the Content Understanding section (sometimes listed under Build or Models + endpoints, depending on the portal layout).
  3. On the analyzers page you will see prebuilt analyzers that ship with the service, alongside a button to create a new one.

Step 3 - Create a Document Analyzer

3.1 - Start a new analyzer

Click Create analyzer. Choose Document as the content type. The analyzer editor opens with a configuration panel.

3.2 - Configure the capabilities

In the capabilities section, enable OCR (read) and Layout. Leave tables enabled so the analyzer reconstructs any tables it finds. This configuration gives you text, structure, and tables.

3.3 - Define one field

In the fields section, add a field named document_title of type string. This single field is enough to demonstrate how custom fields appear in the output.

3.4 - Save and publish

Give the analyzer a name such as lab-doc-analyzer, then click Save. After saving, click Publish so the analyzer becomes callable. The published analyzer gets a version number that future API calls will reference.

Step 4 - Analyze a Document

With the analyzer published, you can test it against a real file from the portal:

  1. In the analyzer detail view, open the Test tab.
  2. Upload your sample document. PDF, PNG, and JPG files are all acceptable.
  3. Click the button to run the analysis.
  4. When the analysis finishes, the portal shows the extracted content in a structured viewer.

Take a moment to switch between the visual view and the raw view in the test results. The visual view overlays the recognized content on the original page image, which makes it obvious whether the analyzer found the right regions. The raw view shows the actual JSON your application would receive.

Step 5 - Read the Output

The result contains the layers described earlier. The JSON will look similar to this structure:

{
  "content": {
    "id": "analysis-0001",
    "formatVersion": "1.0",
    "documents": [
      {
        "id": "doc1",
        "content": "SAMPLE INVOICE\nACME Supplies Ltd.\nInvoice #1042 ...",
        "span": { "offset": 0, "length": 1200 },
        "regions": [ { "pageNumber": 1, "polygon": [...], "offset": 0, "length": 1200 } ],
        "fields": {
          "document_title": {
            "valueString": "SAMPLE INVOICE",
            "confidence": 0.99,
            "regions": [ { "pageNumber": 1, "polygon": [...] } ]
          }
        }
      }
    ],
    "pages": [
      {
        "pageNumber": 1,
        "width": 612,
        "height": 792,
        "words": [ { "text": "SAMPLE", "span": { "offset": 0, "length": 6 } } ],
        "lines": [...]
      }
    ],
    "tables": [ ... ],
    "paragraphs": [ ... ]
  }
}

Note how the pieces fit together: the top-level content object holds the whole document, pages carries the OCR text with word spans, paragraphs and tables add structure, and fields holds the specific values you requested, each with a confidence score.

What to Look For in the Results

  • Reading order: paragraphs should follow the natural top-to-bottom flow of the page.
  • Table reconstruction: if your document has a table, its cells should line up with the original grid, including a header row.
  • Field confidence: your document_title field should carry a high confidence score if the title is clear on the page.
  • Coordinates: each region includes a polygon of points so you can locate extracted values on the original page.

Troubleshooting

SymptomLikely causeFix
No analyzer page appears in FoundryThe Content Understanding resource is not connected to the projectAttach the resource to the project in the project settings.
Upload fails with an unsupported typeFile format outside the supported listConvert to PDF, PNG, or JPG and retry.
Fields come back emptyThe field definition or document content does not matchCheck the field type and the wording on the page; try a clearer label.
Tables are missingTables were disabled in the capabilitiesEdit the analyzer and enable the table capability, then re-publish.

Summary

You created a Content Understanding resource, built a document analyzer with OCR, layout, and a custom field, and analyzed a real document. You saw how text, geometry, structure, and extracted fields combine into a single JSON result. The next lab removes the portal from the equation: you will perform the same kind of analysis in Python, calling the analyzer you published here through its REST API.
