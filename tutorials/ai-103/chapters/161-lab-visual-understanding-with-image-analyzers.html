Lab - Visual Understanding with Image Analyzers

In this lab you will analyze images with Azure Content Understanding. You will register an image analyzer that produces captions, dense captions, tags, and OCR, then run it against sample photos from Python and inspect the structured results. When you finish, you will have a script that can describe any image you give it.

What You Need Before Starting

  • Python 3.9 or newer with the requests library installed.
  • Your Content Understanding endpoint and API key from the earlier labs.
  • Two or three sample images — a photo of a scene, a product shot, and an image that contains some visible text (such as a sign or screenshot).
  • The environment variables CONTENT_UNDERSTANDING_ENDPOINT and CONTENT_UNDERSTANDING_KEY set in your terminal.

Step 1 - Register an Image Analyzer

Unlike the prebuilt document analyzers, the image analyzer in this lab is custom, so you define which capabilities you want. The analyzer below requests a caption, dense captions, tags, people detection, and OCR:

{
  "contentType": "image",
  "description": "Describes scenes, labels regions, and reads text from images",
  "config": {
    "returnDetails": true,
    "modelKind": "gpt-4o-mini"
  },
  "fields": {
    "caption": { "type": "string", "method": "caption", "description": "Short sentence describing the scene" },
    "denseCaptions": { "type": "string", "method": "denseCaptions", "description": "Captions for image regions" },
    "tags": { "type": "array", "method": "tag", "description": "Relevant concepts in the image" },
    "ocr": { "type": "string", "method": "ocr", "description": "Text read from the image" },
    "people": { "type": "array", "method": "people", "description": "Detected persons with bounding boxes" }
  }
}

Capabilities vary by model and by the Content Understanding API version you use. If a capability is not accepted by your API version, check the portal's analyzer editor — the same capabilities you enable in the UI correspond to the fields shown here.

Step 2 - Write the Analysis Script

2.1 - Create the project

Create a folder named ai103-lab161 and add analyze_image.py with the code below. It registers the analyzer, analyzes an image file, and prints a readable summary.

import json
import os
import requests

ENDPOINT = os.environ["CONTENT_UNDERSTANDING_ENDPOINT"]
KEY = os.environ["CONTENT_UNDERSTANDING_KEY"]
API_VERSION = "2024-12-01-preview"
MODEL_NAME = "image-scene-analyzer"

ANALYZER = {
    "contentType": "image",
    "description": "Describes scenes, labels regions, and reads text from images",
    "config": {"returnDetails": True, "modelKind": "gpt-4o-mini"},
    "fields": {
        "caption": {"type": "string", "method": "caption",
                    "description": "Short sentence describing the scene"},
        "denseCaptions": {"type": "string", "method": "denseCaptions",
                          "description": "Captions for image regions"},
        "tags": {"type": "array", "method": "tag",
                 "description": "Relevant concepts in the image"},
        "ocr": {"type": "string", "method": "ocr",
                "description": "Text read from the image"},
        "people": {"type": "array", "method": "people",
                   "description": "Detected persons with bounding boxes"},
    },
}


def ensure_analyzer():
    url = f"{ENDPOINT}/models/{MODEL_NAME}?api-version={API_VERSION}"
    response = requests.put(url, headers={
        "Content-Type": "application/json",
        "Ocp-Apim-Subscription-Key": KEY,
    }, json=ANALYZER)
    response.raise_for_status()
    print(f"Analyzer ready: {response.json().get('id')}")


def analyze_image(file_path):
    url = f"{ENDPOINT}/models/{MODEL_NAME}:analyze?api-version={API_VERSION}"
    with open(file_path, "rb") as fh:
        response = requests.post(url, headers={
            "Ocp-Apim-Subscription-Key": KEY,
        }, files={"file": fh})
    response.raise_for_status()
    return response.json()


def summarize(result):
    fields = result["content"]["documents"][0]["fields"]
    print("Caption:", fields["caption"]["valueString"])
    print("Tags:", ", ".join(fields["tags"]["valueArray"]))
    print("OCR:", fields["ocr"]["valueString"] or "(no text found)")
    people = fields.get("people", {})
    print("People detected:", len(people.get("valueArray", [])))


if __name__ == "__main__":
    ensure_analyzer()
    result = analyze_image("scene.jpg")
    summarize(result)

2.2 - Run the script

Save your photo as scene.jpg (or update the filename) and run:

python analyze_image.py

Expect output along the lines of:

Analyzer ready: image-scene-analyzer
Caption: A busy outdoor market with colorful stalls and shoppers.
Tags: market, outdoor, shopping, people
OCR: FRESH PRODUCE
People detected: 4

Step 3 - Test with a Text-Heavy Image

Run the same script against an image that contains visible text, such as a photographed sign or a screenshot:

python -c "import analyze_image as a; a.ensure_analyzer(); print(a.analyze_image('sign.jpg'))"

Compare the ocr field across the two images. You will notice that the analyzer reads text that a caption-only model would ignore entirely — a strong reason to enable OCR on any image analyzer that feeds a search index.

Inspecting the Raw JSON

To see the full structured response, save it to a file:

python -c "import analyze_image as a; a.ensure_analyzer(); open('result.json','w').write(a.analyze_image('scene.jpg').__str__())"

Open result.json and look for the polygons attached to each people detection and dense caption. Those coordinates let an application draw boxes on the original image or crop a region for a downstream model.

For a quick interactive check, upload the same image in the Content Understanding section of the Foundry portal and enable the same capabilities. Comparing portal and API output for the same image is a fast way to confirm your field definitions behave as expected.

Troubleshooting

SymptomLikely causeFix
400 on analyzer registrationUnsupported capability for the API versionRemove the capability or bump the api-version.
Empty OCR fieldThe image contains no recognizable textUse an image with clearly legible text and test again.
404 on analyzeAnalyzer name mismatchConfirm MODEL_NAME matches the registered name.
Slow responsesLarge images or heavier model kindsDownscale the image or choose a lighter model kind.
