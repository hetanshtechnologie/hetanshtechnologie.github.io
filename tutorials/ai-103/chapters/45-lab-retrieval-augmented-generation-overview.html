Lab - Retrieval Augmented Generation - Overview

This is the overview lab for a five-part series that builds a complete Retrieval Augmented Generation application for CloudXeus. In this chapter you will not write the real logic yet. Instead you will set up the project structure, install the Python packages you will need, and verify that your environment can talk to the Azure services. Later labs turn the setup into working code: data preparation, search indexing, querying, and finally the full retrieve-and-generate loop.

What You Will Build

By the end of the series you will have a CloudXeus knowledge assistant that answers support questions from the company's own documents. The assistant will:

  • Find the most relevant passages in a set of CloudXeus manuals and FAQs.
  • Ground every answer in those passages instead of the model's training data.
  • Return the source document and section for each answer so users can verify it.

The Architecture

The build uses these components:

  • Source documents: PDF and text files that contain CloudXeus product knowledge.
  • Data preparation scripts: Python code that extracts, cleans, and chunks the documents.
  • An embedding model deployment in Foundry that turns text into vectors.
  • Azure AI Search: the index that stores chunks and their vectors and answers retrieval queries.
  • A chat model deployment in Foundry that writes the final grounded answer.

You already deployed both models earlier in the course; this series focuses on the data side and the retrieval glue.

Prerequisites

  • A Microsoft Foundry project with a chat model deployment (for example a GPT model) and a text embedding model deployment.
  • An Azure subscription where you can create an Azure AI Search resource.
  • Python 3.10 or later and Visual Studio Code (or your preferred editor).
  • Your Foundry project connection string and model deployment names.

Exercise 1 — Create the Project Skeleton

  1. Open a terminal and create a working folder called cloudxeus-rag.
  2. Create a Python virtual environment and activate it.
  3. Create a requirements.txt file with the following packages:
openai>=1.30
azure-search-documents>=11.6
azure-identity>=1.16
pypdf>=4.0
  1. Install the packages with pip install -r requirements.txt.

Project Layout

Create the folder structure now so later labs can drop files into known places:

cloudxeus-rag/
|-- data/
|   |-- source/        # original documents
|   `-- chunks.jsonl   # produced by the data prep lab
|-- scripts/
|   |-- prepare_data.py
|   |-- create_index.py
|   |-- search_index.py
|   `-- rag_assistant.py
`-- requirements.txt

Verify Your Environment

Exercise 2 — Check the Installation

  1. Create scripts/check_env.py with this content:
import sys
import importlib.metadata as metadata
import openai
import pypdf

print("Python:", sys.version.split()[0])
print("openai:", openai.__version__)
print("azure-search-documents:", metadata.version("azure-search-documents"))
print("pypdf:", pypdf.__version__)
print("All imports OK")
  1. Run it: python scripts/check_env.py.
  2. You should see version numbers and the message All imports OK.

If you are on Windows, activate the virtual environment with venv\Scripts\activate. On macOS or Linux use source venv/bin/activate.

Search tiers and embedding calls cost money. Use the Free tier of Azure AI Search for this course if it is available in your region, and keep document counts small. Delete the search resource after the labs to avoid surprise bills.

Summary

You have created the CloudXeus RAG project skeleton, installed the Python packages, and verified the environment. In the next lab you prepare the data: extracting, cleaning, and chunking the CloudXeus support documents so they are ready to be embedded and indexed.
