Azure AI Foundry - Exploring the models

Before deploying anything, it pays to know what you can deploy. The model catalog in Microsoft Foundry is the doorway to every model available on the platform — OpenAI models, Microsoft models, and open models from many providers. This chapter shows you how to explore the catalog, read a model card, and compare models so you can pick the right one for a task.

Opening the Model Catalog

From your project's home in the Foundry portal, click Model catalog in the left menu. You will see a gallery of model entries, each shown as a card with the model's name and its provider. The catalog is large, so the first skill is filtering — narrow the list before you scroll.

Filtering the Catalog

Use the filter controls to focus the list:

  • Collection / provider: show only OpenAI models, only Microsoft models, or a specific provider such as Meta or Mistral.
  • Task type: narrow to chat completion, embeddings, image generation, or another task. For this course, chat completion is the filter you will use most.
  • Modalities: text, image, audio, or multimodal inputs.
  • Deployment type: which families can be deployed as managed endpoints.

When you are looking for "a model to chat with," filter by chat completion first. It removes embedding and image models from the list and leaves the models whose API you already know.

Reading a Model Card

Clicking a model card opens its model card — the authoritative summary of what that model is and what it is good at. Read it before deploying, and pay attention to these details:

  • Model description: what the provider designed it for and any stated limitations.
  • Context window: the maximum number of tokens the model can consider in one request. Larger windows mean you can feed it longer documents.
  • Input and output types: text, images, or both; what the model can accept and produce.
  • Languages: which languages the model handles well.
  • Version and date: which model version you would deploy, and whether it is current.
  • Deployment options: whether the model supports standard (pay-as-you-go) or provisioned deployment, and whether a free tier exists.

Model cards are the model's documentation. Just as you would not call an unfamiliar library function without reading its docs, you should not deploy an unfamiliar model without reading its card — the card is where providers disclose limitations that matter for production use.

Comparing Models

When several models could do the same job, compare them on the axes that matter for your task. A useful mental table looks like this:

FactorWhat to look forWhy it matters
Context windowTokens per requestLong documents need large windows or a RAG pipeline
ModalitiesText only vs. vision vs. imagesImage questions need a multimodal model
CostPrice per million tokensLarge workloads multiply small price differences
SpeedOutput tokens per secondInteractive UX needs faster models
AvailabilityRegions and quotaUnavailable in your region means no deployment
SpecializationSmall vs. large, chat vs. reasoningMatch the model class to the task complexity

A common pattern in practice: start with a strong general-purpose chat model for development, and only move to a larger or specialized model when the task demands it. Smaller models are faster and cheaper; larger ones are better at complex reasoning.

Try It: Exploring the Catalog

Spend five minutes in the catalog before the next chapter. Open Model catalog, apply the chat completion filter, and browse until you find a general-purpose model that is available in your region. Open its model card and note its context window, its pricing shape (free tier vs. per token), and whether it supports standard deployment. You will deploy exactly this model in the next lab.

Availability is regional and changes over time. If the model you picked in the catalog later fails to deploy, the first suspect is region availability — switch regions, or pick the sibling model the error message suggests.

Summary

The model catalog is where all deployments begin: filter by task and provider, read the model card, and compare context window, cost, speed, and availability. For your first deployment you need a chat-completion model available in your region with a free or low-cost tier. In the next chapter you will learn exactly what happens when you deploy it.
