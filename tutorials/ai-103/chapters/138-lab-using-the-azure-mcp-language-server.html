Lab - Using the Azure MCP Language Server

In the previous chapter you learned what the Azure Language MCP server is. In this lab you will use a live one: connect a real MCP client, call the translate_text and analyze_sentiment tools directly, and then let a chat model drive the same tools as an agent. By the end you will have moved from service-specific SDK calls to a model-facing tool catalog.

Prerequisites

  • A deployed Azure Language MCP server with its URL and access key. If you did not deploy one, complete the MCP deployment lab before continuing.
  • Your Python environment with the MCP SDK and an HTTP client installed:
pip install mcp httpx

Keep the server running for the whole lab. If it has scaled to zero, requests will fail with a connection error — restart it or redeploy and note the new endpoint and access key.

Step 1: Connect and Call the Translation Tool

Exercise 1: Translate text through MCP

Create mcp_use_server.py:

import asyncio

from mcp import ClientSession
from mcp.client.sse import sse_client

SERVER_URL = "http://YOUR_SERVER_FQDN/sse"
ACCESS_KEY = "YOUR_GENERATED_KEY"


async def call_tool(session: ClientSession, name: str, args: dict) -> str:
    result = await session.call_tool(name, args)
    lines = [
        block.text for block in result.content if block.type == "text"
    ]
    output = "\n".join(lines)
    if result.isError:
        output = f"(tool error) {output}"
    return output


async def main():
    read, write = await sse_client(SERVER_URL, headers={
        "Authorization": f"Bearer {ACCESS_KEY}",
    })
    async with ClientSession(read, write) as session:
        await session.initialize()

        print(call_tool and "translating...")
        translation = await call_tool(session, "translate_text", {
            "text": "The quarterly report is ready for review.",
            "to": "fr",
        })
        print("French:", translation)

        detection = await call_tool(session, "detect_language", {
            "text": "El informe está listo para revisión.",
        })
        print("Detected:", detection)


asyncio.run(main())
  1. Run the script. The first call should return a French translation, and the second should identify the language as Spanish.
  2. If translate_text is missing from your server's catalog, run the tools-listing script first and adjust the names to match your deployment.

This single MCP call replaced what would otherwise be an SDK call with its own authentication, endpoint, and response parsing. The server handled all of that — your client only spoke MCP.

Step 3: Wire the Tools into an Agent

Exercise 3: Let the model call the server

Assemble the pieces from this lab and the LangChain agent labs. Connect to the server, wrap each discovered tool in a LangChain StructuredTool, bind them to your Foundry chat model, and ask a question that requires translation:

import asyncio

from dotenv import load_dotenv
from langchain.agents import AgentExecutor, create_tool_calling_agent
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.tools import StructuredTool
from langchain_openai import AzureChatOpenAI
from mcp import ClientSession
from mcp.client.sse import sse_client

load_dotenv()

SERVER_URL = "http://YOUR_SERVER_FQDN/sse"
ACCESS_KEY = "YOUR_GENERATED_KEY"


def make_langchain_tool(session: ClientSession, mcp_tool):
    async def _run(**kwargs):
        result = await session.call_tool(mcp_tool.name, kwargs)
        return "\n".join(
            block.text for block in result.content if block.type == "text"
        )

    return StructuredTool.from_function(
        name=mcp_tool.name,
        description=mcp_tool.description,
        func=_run,
    )


async def run():
    read, write = await sse_client(SERVER_URL, headers={
        "Authorization": f"Bearer {ACCESS_KEY}",
    })
    async with ClientSession(read, write) as session:
        await session.initialize()
        tools = await session.list_tools()
        langchain_tools = [make_langchain_tool(session, t) for t in tools.tools]

        model = AzureChatOpenAI(
            azure_endpoint="YOUR_ENDPOINT",
            api_key="YOUR_KEY",
            api_version="2024-06-01",
            deployment_name="YOUR_DEPLOYMENT_NAME",
        )
        prompt = ChatPromptTemplate.from_messages([
            ("system", "Use the tools you have access to when they help."),
            ("human", "{input}"),
            ("placeholder", "{agent_scratchpad}"),
        ])
        agent = create_tool_calling_agent(
            model.bind_tools(langchain_tools), langchain_tools, prompt
        )
        executor = AgentExecutor(agent=agent, tools=langchain_tools)

        result = await executor.ainvoke({
            "input": "Translate 'see you at the conference' into Italian.",
        })
        print(result["output"])


asyncio.run(run())
  1. Run the agent script. The model should select the translation tool, the call goes through MCP to your server, and the agent answers with the Italian text.
  2. Ask a question that does not need tools, such as "What is 9 times 9?" — the agent should answer directly, proving it only uses the server when relevant.
  3. Ask a question that needs sentiment analysis instead, and confirm the model picks the matching tool from the catalog.

The adapter snippet is a pattern, not a verbatim recipe — the exact LangChain APIs shift between versions. The invariant is the idea: wrap each MCP tool in a callable your model framework can bind, with every call routed through the MCP session.

Step 4: Troubleshoot Common Failures

  • Connection refused: the server is stopped, scaled to zero, or the FQDN is wrong.
  • 401/403 at connect: the access key is missing, wrong, or not being sent as a bearer token.
  • Tool not found: the tool name does not exist on your server version — run the listing script and match names exactly.
  • Invalid arguments: the schema from tools/list is the contract; compare your argument names and types against it.
  • Azure-side errors: the server relays errors from the underlying service, so the tool result usually names the real cause.

Your agent now reaches the Azure language services through a public endpoint guarded only by the access key. Keep that key out of source control and regenerate it if it ever leaks. In production, prefer Azure AD token authentication and endpoint restrictions over a shared static key.
