Lab - Python - Using a model to generate an image

In this lab you will generate images programmatically for the first time. You will send a text description to an image model deployed in Microsoft Foundry, receive a brand-new picture, save it to disk, and experiment with the parameters that control its size and quality.

Image Generation vs. Chat Completions

Image generation uses a different part of the API than chat. Instead of calling the chat completions endpoint, you call the image generation endpoint, which is exposed in the same SDK through the images client. The request is simpler — a prompt plus a few options — and the response contains either a URL to the finished image or the image bytes themselves.

AspectChat completionImage generation
SDK callclient.chat.completions.create(...)client.images.generate(...)
Key inputMessages (system, user)A text prompt
ResponseMessage text and token usageImage URL or base64-encoded bytes

What You Need Before Starting

  • Python 3.9 or newer and VS Code.
  • An image model deployed in Foundry, for example gpt-image-1 or dall-e-3.
  • Your endpoint URL and API key as environment variables.
  • The openai and requests packages installed.
pip install openai requests

An image deployment is separate from your chat deployment. Even if you already have a chat model deployed, you still need a dedicated deployment of an image-capable model for the calls in this lab. Confirm the deployment is ready in the Foundry portal before running the scripts.

Step 1: Generate Your First Image

Exercise 1: Create and save an image

  1. Create a folder named ai103-lab243 and open it in VS Code.
  2. Create generate.py and set your environment variables:
$env:AZURE_OPENAI_ENDPOINT = "https://YOUR-RESOURCE.openai.azure.com/"
$env:AZURE_OPENAI_KEY = "YOUR_KEY"
  1. Paste this script and replace YOUR_IMAGE_DEPLOYMENT with your image deployment name:
import base64
import os
from openai import AzureOpenAI

client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2025-01-01-preview",
)

result = client.images.generate(
    model="YOUR_IMAGE_DEPLOYMENT",
    prompt="A small red lighthouse on a rocky coast at sunrise, painterly style",
    size="1024x1024",
    quality="standard",
    n=1,
)

item = result.data[0]

if item.url:
    print("Image URL:", item.url)
else:
    raw = base64.b64decode(item.b64_json)
    with open("lighthouse.png", "wb") as f:
        f.write(raw)
    print("Saved lighthouse.png")
  1. Run the script:
python generate.py

Depending on the deployment, the result either prints a URL or writes the image file directly. Open the image and check that it matches the prompt.

Step 2: Always Save the Image to Disk

A URL is temporary — the file can be deleted or expire. For a durable result, download the bytes and store them locally. If the response gave you a URL, fetch it with requests and write the content to a file:

Exercise 2: Download the image when the response is a URL

Extend generate.py so that URL responses are downloaded automatically:

import base64
import os
import requests
from openai import AzureOpenAI

client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2025-01-01-preview",
)

result = client.images.generate(
    model="YOUR_IMAGE_DEPLOYMENT",
    prompt="A tiny coral reef with a clownfish, underwater photograph style",
    size="1024x1024",
    quality="standard",
    n=1,
)

item = result.data[0]

if item.url:
    response = requests.get(item.url, timeout=60)
    response.raise_for_status()
    with open("reef.png", "wb") as f:
        f.write(response.content)
    print("Saved reef.png from URL")
else:
    with open("reef.png", "wb") as f:
        f.write(base64.b64decode(item.b64_json))
    print("Saved reef.png from base64 data")

python generate.py

Handling both cases — URL and inline bytes — makes your script robust across deployments. Some models return URLs, others return base64; supporting both means the script works wherever you point it.

Step 3: Tune Size and Quality

The size and quality parameters change what the model produces and how much it costs:

  • size controls resolution, for example 1024x1024, 1024x1792, or 1792x1024.
  • quality trades detail against speed and price. standard is fast and cheaper; hd adds detail for premium results.

Exercise 3: Compare quality settings

Modify generate.py to generate a landscape-orientation image at high definition:

result = client.images.generate(
    model="YOUR_IMAGE_DEPLOYMENT",
    prompt="A dramatic mountain lake with autumn forest, hd quality",
    size="1792x1024",
    quality="hd",
    n=1,
)

python generate.py

Generate the same prompt at standard quality and compare the two files. The detail difference is easiest to see in textures such as leaves or water.

Image generation costs considerably more tokens per call than a short chat exchange, and hd raises the price further. Stick to standard quality during the lab unless a model card specifically encourages hd, and check the Foundry metrics page afterward to see the token impact.

Handling a Blocked Prompt

Image models are paired with content filters, and a prompt that trips a filter returns an error instead of a picture. A small, reusable guard makes this obvious:

try:
    result = client.images.generate(
        model="YOUR_IMAGE_DEPLOYMENT",
        prompt="A serene garden pond at dusk",
        size="1024x1024",
        quality="standard",
        n=1,
    )
    print("Generated successfully")
except Exception as exc:
    print("Generation failed:", exc)

Summary

You generated an image from a text prompt, saved the result to disk whether the response returned a URL or inline bytes, experimented with size and quality, and added error handling for blocked prompts. The images.generate pattern — prompt, size, quality — is all you need to turn any text description into a picture.
