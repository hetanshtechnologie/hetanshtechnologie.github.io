Azure AI Language service

You have already seen text analysis done two ways in this course: by prompting a general-purpose model and by calling the dedicated Azure AI Language service. This chapter zooms into the service itself. The Azure AI Language service is a collection of pre-trained natural language processing capabilities hosted in Azure and exposed through stable REST endpoints and software development kits. Instead of writing a prompt and hoping the model behaves, you call a purpose-built endpoint for each task — detect language, extract key phrases, score sentiment, pull out entities, redact personal information, or summarize a document — and receive a fixed, documented response shape every time.

What the Azure AI Language Service Is

Azure AI Language is a family of language technologies that sit behind one resource. You provision a single resource in Azure, get one endpoint and a set of keys, and then access every feature through that same connection. The models behind each feature are trained specifically for their job, which makes them fast, predictable, and inexpensive at high volume. They return structured JSON — codes, scores, spans, and lists — rather than free-form prose, so your application code can parse the results without negotiating formats.

The service is managed through three entry points:

  • Azure portal for creating the resource, viewing keys, and monitoring usage.
  • Language Studio for trying every capability in the browser without writing code.
  • REST API and SDKs for building the feature into your applications.

Prebuilt Capabilities

The prebuilt features cover the most common text-analysis jobs. The ones you will use in this section are:

CapabilityWhat it returnsTypical use
Language detectionLanguage code, name, and confidence scoreRouting documents to the right pipeline
Key phrase extractionA ranked list of salient phrasesTagging, search indexing, topic surfacing
Sentiment analysisPositive, neutral, or negative scores per document and sentenceMeasuring customer feedback at scale
Named entity recognitionEntities with types and character offsetsExtracting people, places, organizations, dates, and amounts
Personally identifiable information (PII) detectionPersonal data spans by category, plus redacted textScrubbing documents before storage or sharing
Text summarizationExtractive or abstractive summariesCondensing long reports and transcripts

Beyond these, the service also offers custom named entity recognition, custom text classification, question answering, conversational language understanding, and orchestration workflows. Most of those are built with Azure AI Language Studio by labeling your own data, so they are worth knowing about even though this course works with the prebuilt endpoints.

Prebuilt vs. Custom Models

Every capability in the table above exists as a prebuilt model: Microsoft trains it, and it works out of the box on the text you send. No training data is required from you. The same service family also supports custom models, which you build in Language Studio by uploading labeled examples. Custom models are the right tool when your domain uses vocabulary the prebuilt models do not know, or when you need entity types that do not exist in the standard taxonomy, such as part numbers or internal team names.

A pragmatic strategy is to start with the prebuilt model, measure its accuracy against a small labeled sample of your own data, and invest in custom training only where the prebuilt result falls short. Most teams never need the custom tier for the common tasks covered in this section.

Language Studio

Language Studio is the web portal for the service, available at https://language.cognitive.azure.com/. It lets you try any feature against your own text or a sample, see the full JSON response, and in some cases export the request for reuse. The browser experience is not a mock — it calls the exact same endpoints your code will call. Every lab in this section therefore has a companion studio step that shows you the result visually before you reproduce it in code.

When you open Language Studio, you connect it to a Language resource. If you do not have one yet, the portal walks you through creating it. The next chapter shows how to create that resource deliberately from the portal and the command line so you understand exactly what is being provisioned.

Calling the Service

All features are accessible through the same REST base URL. For example, the language detection endpoint is:

POST https://YOUR_ENDPOINT.cognitiveservices.azure.com/text/analytics/v3.1/languages

Every request carries one of your keys in the Ocp-Apim-Subscription-Key header and a JSON body containing a documents array. The response mirrors that structure, returning one result per document, in the same order. The Python SDK wraps these calls in client methods such as detect_language, extract_key_phrases, and recognize_entities, so you rarely touch the raw HTTP layer in application code.

When to Choose the Service over an LLM

Because you have already worked with LLM prompting for text analysis, it is useful to name exactly where the boundary sits:

ConsiderationAzure AI Language serviceLLM prompting
Output contractFixed schema per featureYou define through the prompt and JSON mode
CustomizationRequires custom trainingAny task you can describe
ExplanationsNone — codes, scores, and spans onlyFree-text reasoning available
Billing unitPer text recordPer token in and out
LatencyLow and single-passHigher, token-by-token generation
Best fitHigh-volume, well-specified jobsNovel tasks, judgment, tone, nuance

Neither approach dominates. Language detection, PII redaction, and prebuilt entity extraction are textbook service jobs — fixed schema, huge volume, no explanation needed. Tasks that need judgment, reasoning, or audience-aware tone are better served by a model. A healthy pipeline often uses both: the service cleans and structures the text, and an LLM interprets it.

Summary

The Azure AI Language service provides pre-trained, purpose-built language capabilities behind one resource, one endpoint, and one set of keys. Its prebuilt features return stable, parseable structures at high volume and low latency, and Language Studio lets you try them without writing code.
