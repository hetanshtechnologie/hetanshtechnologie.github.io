Using Azure Document Intelligence

Knowing what Azure Document Intelligence does is different from putting it to work. This chapter is the practical middle step: you will provision a Document Intelligence resource, call it from Python with the official SDK, analyze an invoice, and read the extracted fields out of the response. This is the same pattern the CloudXeus invoice agent will rely on in the coming chapters.

Provisioning the Resource

Create a Document Intelligence resource with the Azure CLI. The kind is FormRecognizer and the free tier is plenty for the labs in this course:

az cognitiveservices account create \
    --name cloudxeus-docintel \
    --resource-group cloudxeus-docs-rg \
    --kind FormRecognizer \
    --sku F0 \
    --location eastus

Fetch the endpoint and one of the keys, then store them as environment variables:

$env:DOCUMENT_INTELLIGENCE_ENDPOINT = "https://cloudxeus-docintel.cognitiveservices.azure.com/"
$env:DOCUMENT_INTELLIGENCE_KEY = "YOUR_KEY"

Treat the key like a password. The labs read it from environment variables, and you should never commit it to source control or paste it into shared documents.

Installing the Python SDK

The SDK package is azure-ai-documentintelligence. Install it in your lab environment:

pip install azure-ai-documentintelligence

The SDK's DocumentIntelligenceClient mirrors the REST API: you call begin_analyze_document with a model ID and a document, then wait for the polling operation to finish.

Analyzing an Invoice

Exercise 1: Extract fields from an invoice with the prebuilt model

Create a folder named ai103-lab189 with a file called analyze_invoice.py containing:

import os

from azure.ai.documentintelligence import DocumentIntelligenceClient
from azure.core.credentials import AzureKeyCredential

endpoint = os.environ["DOCUMENT_INTELLIGENCE_ENDPOINT"]
key = os.environ["DOCUMENT_INTELLIGENCE_KEY"]

client = DocumentIntelligenceClient(
    endpoint=endpoint,
    credential=AzureKeyCredential(key),
)

with open("invoice.pdf", "rb") as fh:
    poller = client.begin_analyze_document(
        model_id="prebuilt-invoice",
        analyze_request=fh,
        content_type="application/pdf",
    )

result = poller.result()

for document in result.documents:
    fields = document.fields
    print("Vendor:", fields.get("VendorName").value_string if fields.get("VendorName") else None)
    print("Invoice ID:", fields.get("InvoiceId").value_string if fields.get("InvoiceId") else None)
    print("Issue date:", fields.get("InvoiceDate").value_date if fields.get("InvoiceDate") else None)
    print("Due date:", fields.get("DueDate").value_date if fields.get("DueDate") else None)
    print("Total:", fields.get("InvoiceTotal").value_currency if fields.get("InvoiceTotal") else None)

Place an invoice file named invoice.pdf in the folder and run:

python analyze_invoice.py

If everything is configured correctly, the script prints the five fields. Try it with a scanned invoice as well — the prebuilt model runs OCR internally, so the same code works.

Reading the Response

The analysis result is richer than a single field value. Useful things to read from it:

  • fields — the extracted named fields, each with a value and a confidence score.
  • pages — the OCR output per page: lines, words, and their polygon coordinates.
  • tables — detected cell grids with content and location, including multi-page tables.
  • key_value_pairs — label/value relationships found on forms.

Build a simple confidence check into the pipeline: when a field's confidence drops below a threshold such as 0.8, mark the document for human review instead of trusting the extracted value.

Handling the Polling Pattern

Document analysis is asynchronous — the call returns quickly, and the result becomes available after the service finishes processing. The SDK hides this behind the poller object. For long documents, you may want to control the wait explicitly rather than blocking on the default polling:

poller = client.begin_analyze_document(
    model_id="prebuilt-invoice",
    analyze_request=fh,
    content_type="application/pdf",
    polling_interval=5,
)
result = poller.result(timeout=300)

polling_interval sets how often the client checks status; timeout sets the maximum wait in seconds. In a production pipeline, consider running the analysis in a job queue rather than blocking a request thread.
