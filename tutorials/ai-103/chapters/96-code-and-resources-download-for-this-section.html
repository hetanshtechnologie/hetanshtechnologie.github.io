Code and resources download for this section

This section combined Azure observability, evaluation, safety guardrails, and model routing. The hands-on parts — connecting Application Insights, creating an evaluation, testing content filters, and building a model router — are built from a handful of scripts and configuration snippets. This chapter explains what the section's download contains and how to lay out your project folder so every example just works.

The resources for this section are a single ZIP file containing these files:

FileWhat it demonstrates
continuous_eval.pyScoring a conversation with built-in evaluators from Python

Downloading the Resources

  1. Download the ZIP file for this section from the course download page.
  2. Extract it into a folder named ai103-observability on your machine.
  3. Open that folder in VS Code with File > Open Folder.

Set Up the Project Folder

After extraction, your folder should look like this:

ai103-observability/
  continuous_eval.py
  completeness_prompt.txt
  diagnostics_setup.sh
  content_filter_test.py
  prompt_shield.py
  router.py
  routes.yaml
  requirements.txt
  .env.example

Install the required packages once, in this folder's terminal:

pip install -r requirements.txt

Credentials Without Hard-Coding

The Python scripts read credentials from environment variables. Set them in the terminal before running any script, using the values from your Foundry project and your Azure OpenAI resource:

$env:AZURE_OPENAI_ENDPOINT = "https://YOUR-RESOURCE.openai.azure.com/"
$env:AZURE_OPENAI_KEY = "YOUR_KEY"
$env:CONTENT_SAFETY_ENDPOINT = "https://YOUR-CONTENT-SAFETY.cognitiveservices.azure.com/"
$env:CONTENT_SAFETY_KEY = "YOUR_KEY"

The .env.example file is a template only. Copy it to .env, fill in your values, and make sure .env is listed in your .gitignore so credentials never reach a repository. Never commit real keys.

How the Files Fit the Section

Each file maps to a specific chapter, so you can follow along:

  • continuous_eval.py supports the continuous evaluation lab — it is the one-off scoring example from that chapter.
  • completeness_prompt.txt and diagnostics_setup.sh are the prompt and CLI snippets from the completeness and diagnostics chapters.
  • content_filter_test.py and prompt_shield.py correspond to the content filter and prompt shield examples.
  • router.py and routes.yaml are the model router lab output and its lecture configuration.

The download gives you ready-to-run versions of every script in this section. Set up the folder, install the requirements, configure the environment variables, and each example is executable against your own deployments.
