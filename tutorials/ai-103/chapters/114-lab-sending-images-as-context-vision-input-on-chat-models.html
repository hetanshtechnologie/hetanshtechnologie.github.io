Lab - Sending Images as Context - Vision Input on Chat Models

In this lab you will teach a deployed chat model to look at a picture. Chat models that support vision accept images as part of the conversation context: alongside the text message you send, you attach one or more images, and the model considers everything together when it composes its answer. This is the same capability that powers features such as "describe this screenshot" or "read the text from this document photo." By the end of the lab you will have a Python script that loads a local image, sends it to a Foundry deployment, and prints the model's description of what it sees.

What You Need Before Starting

  • Python 3.9 or newer and VS Code, from the earlier chapters.
  • A vision-capable chat model deployed in Microsoft Foundry, such as gpt-4o or gpt-4o-mini.
  • Your endpoint URL and API key for that deployment, stored as environment variables.
  • A sample image file, for example sample_building.jpg from the section download.

Not every chat model can accept images. Older text-only models will reject an image attachment or simply ignore it. If your deployment errors when you send the image, switch to a model family that is documented as supporting vision input.

Installing the OpenAI Python SDK

Your Python code talks to the deployment through the openai package, the same client library you used in earlier labs. If you have not installed it in your current environment yet, open a terminal in VS Code and run:

pip install openai

Preparing an Image for the API

The chat API does not accept a file path directly. You must read the image bytes and encode them so the model can receive them. The standard approach is to:

  1. Open the image file in binary mode.
  2. Base64-encode the bytes into a string.
  3. Wrap that string in a data URI such as data:image/jpeg;base64,AAAA....

Python's base64 module and a one-line format string do all of this for you.

Send the Image to the Chat Model

Step 1 - Create the project folder

Create a folder named ai103-lab114 and open it in VS Code. Inside it, create a new Python file called vision_chat.py. Copy sample_building.jpg from the section download into the same folder.

Step 2 - Set your environment variables

In the integrated terminal, set your endpoint and key. Replace the placeholder values with the ones from your Foundry deployment:

$env:AZURE_OPENAI_ENDPOINT = "https://YOUR-RESOURCE.openai.azure.com/"
$env:AZURE_OPENAI_KEY = "YOUR_KEY"

Step 3 - Paste the script

Paste the following code into vision_chat.py. Replace YOUR_DEPLOYMENT_NAME with the name of your vision-capable deployment:

from openai import AzureOpenAI
import os
import base64

client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2025-01-01-preview",
)

with open("sample_building.jpg", "rb") as image_file:
    image_data = base64.b64encode(image_file.read()).decode("utf-8")

response = client.chat.completions.create(
    model="YOUR_DEPLOYMENT_NAME",
    messages=[
        {"role": "system", "content": "You answer questions about images in a few concise sentences."},
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "Describe what you see in this image."},
                {
                    "type": "image_url",
                    "image_url": {"url": f"data:image/jpeg;base64,{image_data}"},
                },
            ],
        },
    ],
)

print(response.choices[0].message.content)

Step 4 - Run the script

python vision_chat.py

You should see a natural-language description of the building photo printed to the console.

Why the Message Content Is a List

Notice that the user message in the previous step is not a simple string. Its content is an array of parts, and each part has a type. The array can hold any mix of text parts and image parts, which lets you ask detailed questions while the image is right there in the context:

  • A text part carries the instruction or question.
  • An image_url part carries the picture, either as a data URI or as a public web URL.

Order matters: the parts are read in the order you list them, so place the question before the image if you want the model to interpret them in that order.

Sending More Than One Image

You can attach multiple images in a single request by adding more image_url parts. The model can then compare pictures, which is useful for tasks like checking two documents or spotting differences. A short example:

messages=[
    {"role": "system", "content": "You compare images and summarize differences."},
    {
        "role": "user",
        "content": [
            {"type": "text", "text": "Compare these two images."},
            {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{first_image}"}},
            {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{second_image}"}},
        ],
    },
]

Understanding the Response

The response structure is identical to a text-only chat response. The useful fields are:

  • response.choices[0].message.content — the model's description or answer.
  • response.usage.prompt_tokens — tokens consumed by your text and the encoded image.
  • response.usage.completion_tokens — tokens in the generated answer.

Image tokens can be significant: a large picture is converted into many tokens, which affects both latency and cost. Using the smallest image that still contains the details you need keeps requests fast and cheap.

Troubleshooting Common Errors

Error you may seeMost likely causeFix
404 or model not foundThe deployment name does not match.Check the model argument against the exact deployment name in Foundry.
400 Invalid imageThe image format or data URI is malformed.Confirm the file is JPEG or PNG and that the MIME type in the data URI matches the file.
Model does not support visionThe deployment is a text-only model.Deploy a vision-capable model such as gpt-4o and use its name.
Image too largeThe encoded image exceeds the API limit.Resize or compress the image before sending it.

If your image is a public web URL, you can pass it directly as {"type": "image_url", "image_url": {"url": "https://example.com/photo.jpg"}} without any base64 encoding. Local files, and anything sensitive, should always be sent as a data URI instead.

Summary

You have sent your first image to a chat model and received a text description in return. You learned to base64-encode a local file, attach it as an image_url part inside a message array, send multiple images in one call, and read the token usage from the response.
