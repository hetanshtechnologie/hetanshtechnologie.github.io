Introduction to LangChain

So far you have called models directly with the OpenAI SDK and configured agents inside Microsoft Foundry. This chapter introduces LangChain, a framework that sits on top of model APIs and gives you reusable building blocks for composing generative AI applications. LangChain is one of the most widely used orchestration frameworks, and understanding it prepares you for the agent labs that follow. We will look at what problem it solves, its core abstractions, and how it connects to your Foundry deployments.

What Problem LangChain Solves

Raw model calls work, but production applications repeat the same plumbing: constructing prompts, managing conversation history, retrying calls, parsing output, connecting retrieval, and wiring tools. Hand-written, this code tends to be copy-pasted across every feature and becomes hard to maintain. LangChain packages that plumbing into composable components, so you assemble an application from parts instead of writing each integration from scratch.

That brings three concrete benefits:

  • Composition: chains combine prompts, models, and parsers into a single pipeline you can reuse.
  • Portability: models and tools are interchangeable — swap a deployment without rewriting the surrounding logic.
  • Tooling: built-in integrations for retrieval, memory, output parsing, and tracing, which you would otherwise build yourself.

LangChain is a framework, not a model. It still calls your Foundry deployments under the hood. What it adds is structure around those calls, and that structure is what makes larger applications manageable.

Installing LangChain

LangChain is distributed as several Python packages. For the examples in this section you need the core package plus the OpenAI integration, which works with Azure OpenAI endpoints:

pip install langchain langchain-openai openai

To point LangChain at a Foundry deployment, you configure an Azure OpenAI chat model with your endpoint, key, and deployment name. The deployment name is passed as the model identifier:

from langchain_openai import AzureChatOpenAI
import os

chat = AzureChatOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2025-01-01-preview",
    model="YOUR_DEPLOYMENT_NAME",
    temperature=0.2,
)

The Core Building Blocks

LangChain applications are assembled from a small set of components. You will meet all of them in this section:

ComponentRole
ModelsWrappers around chat and embedding deployments
MessagesStructured system, user, assistant, and tool turns
PromptsTemplates that turn variables into formatted instructions
Output parsersConvert model text into structured data such as JSON
ChainsSequences of steps that call models and transform results
ToolsFunctions the model can request, with schemas the model can read
MemoryConversation state carried across turns

A First LangChain Call

Once the chat model is configured, invoking it is straightforward. LangChain keeps the familiar message structure:

from langchain_core.messages import HumanMessage, SystemMessage

messages = [
    SystemMessage(content="You are a concise travel assistant."),
    HumanMessage(content="Suggest one day itinerary in Barcelona."),
]

response = chat.invoke(messages)
print(response.content)

chat.invoke(...) is synchronous and returns a single response. LangChain also offers stream for token-by-token output and ainvoke for asynchronous code. Starting with invoke keeps debugging simple.

Composing a Chain

The real power shows up when you connect components. A minimal chain takes a user input, formats a prompt from it, calls the model, and passes the result through an output parser — all in one expression:

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_template(
    "You are a helpful assistant. Answer in two sentences: {question}"
)

chain = prompt | chat | StrOutputParser()

answer = chain.invoke({"question": "What is the water cycle?"})
print(answer)

The pipe operator (|) is LangChain's way of composing: the prompt produces a formatted message, the model produces an AI response, and the parser extracts plain text. Each stage's output is the next stage's input, and the whole pipeline is a single callable.

Keep the chain design in mind for the coming labs. LangChain agents are built from the same components — a model, prompts, tools, and memory — but add a decision loop so the model can call tools and keep working until it finishes.

LangChain and Foundry Together

LangChain and Microsoft Foundry complement each other rather than compete. Foundry gives you managed deployments, guardrails, evaluation, and observability; LangChain gives you a flexible framework for composing prompts, tools, and memory around those deployments. A common production shape is: Foundry hosts the model and the safety layer, while LangChain wires the application logic and connects retrieval and tools.

Summary

LangChain is an orchestration framework that packages the repeated plumbing of generative AI into composable components. You installed it, configured a chat model against a Foundry deployment, made a first call, and composed a prompt-model-parser chain with the pipe operator.
