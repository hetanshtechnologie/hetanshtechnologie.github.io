Lab - Ingesting documents from Azure Blob Storage

Every search pipeline starts with a home for the raw documents. In this lab you will create a storage container, upload course documents to it, and provision the Azure AI Search service that will later index them. When you finish, you will have a populated data store and a search service ready for the data-source lab that follows.

What You Need Before Starting

  • An Azure subscription and the Azure CLI (az) installed and signed in.
  • A resource group for this course, or permission to create one.
  • Two or three documents to index — PDFs of chapters or articles work well. Keep them plain text-based PDFs for now.
  • An environment variable holding your resource group name so the commands stay reusable.

Run the commands below from a PowerShell terminal in VS Code. All placeholders in angle brackets, such as <yourname>, must be replaced with your own unique values.

Step 1 - Set Your Resource Group

Set a variable for the resource group so later commands can reference it. Use an existing group or create one:

$rg = "rg-ai103"
az group create --name $rg --location eastus

Step 2 - Create a Storage Account

The storage account holds your documents in blob containers. Names must be globally unique and use only lowercase letters and numbers:

$storageName = "saai103<yourname>"
az storage account create `
  --name $storageName `
  --resource-group $rg `
  --location eastus `
  --sku Standard_LRS

Step 3 - Create a Container and Upload Documents

Create a container named docs and upload your PDFs into it. First grab the account's connection string:

$conn = az storage account show-connection-string `
  --name $storageName `
  --resource-group $rg `
  --query connectionString -o tsv

az storage container create --name docs --connection-string $conn

az storage blob upload-batch `
  --destination docs `
  --source ./course-docs `
  --connection-string $conn

Point --source at the local folder containing your PDFs. When the batch completes, every file is in the docs container.

Verify the upload by listing blobs in the container:

az storage blob list --container-name docs --connection-string $conn --query "[].{name:name}" -o table

Step 4 - Provision Azure AI Search

Create the search service that will index and query the documents. The service name must be globally unique:

$searchName = "srch-ai103-<yourname>"
az search service create `
  --name $searchName `
  --resource-group $rg `
  --sku Basic `
  --location eastus

The Free tier is fine for learning but cannot run some advanced features and skillsets used later. The Basic tier gives you room for the enrichment steps ahead. Remember which tier you choose — upgrading later requires recreating the service.

Step 5 - Record the Search Service Details

Fetch the service's endpoints and admin key. You will need them in the data-source lab:

$searchHost = az search service show `
  --name $searchName `
  --resource-group $rg `
  --query "properties.endpoints[0]" -o tsv

az search admin-key show --resource-group $rg --service-name $searchName

Write-Output "Search host: $searchHost"

Store the host URL and the admin key somewhere safe, like a local .env-style file that is not committed to source control.

The admin key grants full control of the search service. For programmatic clients you will later use a query key or managed identity instead. For the labs ahead the admin key is the simplest way to configure everything.

Step 6 - Review the Flow

You now have three resources that fit together:

ResourcePurpose
Storage accountHolds the raw PDFs in the docs container.
Azure AI SearchWill store the searchable index and answer queries.
Your local folderSource of the documents you uploaded.

Nothing has been indexed yet — the search service is empty. Creating the connection from the container to the search service is exactly what the next lab does.

Troubleshooting

SymptomLikely causeFix
Storage name already in useName is not uniqueAppend more characters to the name and retry.
Search service name invalidName contains invalid charactersUse only lowercase letters, numbers, and hyphens.
Upload-batch finds no filesWrong source pathCheck that --source points to a folder containing files.
Quota exceeded on tierSelected SKU not available in regionTry another region or a different SKU.

Summary

You created a storage account, uploaded documents into a docs container, provisioned an Azure AI Search service, and recorded the endpoint and key. Your data is staged and your search service is ready. The next lab connects the two by defining a data source — the first component of the indexing pipeline.
