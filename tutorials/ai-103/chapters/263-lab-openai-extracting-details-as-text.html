Lab - OpenAI - Extracting details as text

Before we dive into JSON schemas, it is worth seeing what happens when you simply ask a model to extract details and reply as free-form text. This lab walks you through an extraction task using the Responses API without any structured-output constraints. You will see exactly why that approach is unreliable, which motivates the structured techniques in the following labs.

The Extraction Task

We will ask the model to pull structured facts out of a short customer email:

email_text = """
Hi there,
My name is Priya Patel and I ordered a blue wireless
mouse on March 3rd. It has not arrived yet. Can you
check the status? My order number is 58492.
Thanks,
Priya
"""

Extracting with a Plain Prompt

Step 1 — Create the script

Create a file named extract_plain.py:

from openai import OpenAI

client = OpenAI(api_key="YOUR_API_KEY")

email_text = """
Hi there,
My name is Priya Patel and I ordered a blue wireless
mouse on March 3rd. It has not arrived yet. Can you
check the status? My order number is 58492.
Thanks,
Priya
"""

response = client.responses.create(
    model="gpt-4o-mini",
    instructions="Extract the customer name, product, order number, and issue from the message.",
    input=email_text,
)

print(response.output_text)

Step 2 — Run it a few times

python extract_plain.py

Run the script two or three times and compare the outputs.

What You Will Notice

The answers are usually informative but not consistent. You may see variations like:

  • The order number formatted as 58492, #58492, or order 58492.
  • The name written as Priya Patel or wrapped in an extra sentence such as "The customer is Priya."
  • Extra commentary explaining the extraction, mixed in with the facts.
  • Field order changing between runs.

None of these outputs are wrong, which is exactly the problem: a parser would need to handle every variation.

This variability is not a bug. The model is doing what you asked — producing helpful text. The lesson is that "helpful text" is the wrong target when your code needs fixed fields. You must change the request itself, not the parser.

Forcing JSON Shape in the Prompt

A common intermediate step is to demand JSON inside the prompt. It improves the odds, but still leaves room for error:

response = client.responses.create(
    model="gpt-4o-mini",
    instructions=(
        "Extract these fields and reply only as JSON with keys "
        "name, product, order_number, and issue."
    ),
    input=email_text,
)

print(response.output_text)

Try it and notice that the output is usually valid JSON — but occasionally the model adds markdown code fences, wraps the object in a sentence, or drops a key. The format is still not contractually guaranteed.

Parsing the Text Result

If you must handle free-form output, you can attempt JSON parsing with a fallback, but this only patches the symptom:

import json
import re

text = response.output_text

match = re.search(r"\{.*\}", text, re.DOTALL)
if match:
    data = json.loads(match.group(0))
    print(data.get("name"))
    print(data.get("order_number"))
else:
    print("No JSON object found in the response.")

This works often and breaks quietly. The structured-output labs that follow remove the need for this kind of guesswork entirely.

Summary

You extracted details with a plain prompt and saw the output vary in format, ordering, and extra commentary. Prompt-level requests for JSON improve consistency but do not guarantee it. This experiment sets up the next two labs, where schemas enforce the shape at the API level.
