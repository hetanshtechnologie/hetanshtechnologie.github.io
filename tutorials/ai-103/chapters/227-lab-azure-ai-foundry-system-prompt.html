Lab - Azure AI Foundry - System prompt

A system prompt is the instruction block that runs before the user says anything. It sets the model's role, rules, tone, and constraints for the whole conversation. It is the single highest-leverage text in any chat application: the same user message produces very different answers depending on what the system prompt says. In this lab you will write, test, and refine system prompts in the playground.

What You Will Need

  • The playground open with your deployed chat model selected.
  • The System prompt (or Setup) panel visible next to the chat area.
  • A fixed test question you will ask against several different system prompts.

What a System Prompt Does

The system message and the user messages both travel in the same messages array, but they play different roles:

AspectSystem messageUser message
PurposeSets rules, role, and toneDelivers the actual task or question
PersistenceApplies to the whole conversationApplies to that turn
OriginWritten by you, the developerTyped by the end user
ExampleYou are a patient math tutor for beginners.Explain fractions to me.

Think of the system prompt as the job description and the user message as the day's task. A crisp job description makes every task easier, no matter who types it.

Step 1: Baseline Without a System Prompt

Exercise 1: Capture a baseline answer

  1. Clear the system prompt box so it contains only the default text (or nothing).
  2. Ask the test question "Explain why the sky is blue."
  3. Note the length, tone, and level of detail in the answer.

Keep that answer in mind. Now add a system prompt and the exact same question should come back in a very different voice.

Step 2: Add a Role and Rules

  1. Replace the system prompt with:
You are a patient science teacher for elementary school students.
Use simple words and short sentences.
Explain with a small analogy.
Never use more than 60 words.
  1. Resend the same question "Explain why the sky is blue."
  2. Compare with the baseline: the length, vocabulary, and structure should all shift to match the role.

Write rules as short imperative sentences: "Use simple words," "Answer in JSON," "If unsure, say you do not know." Imperatives are easier for models to follow than long paragraphs.

Step 3: Enforce an Output Format

System prompts are the cleanest way to force structured output. Try this one:

You answer customer support questions.
Always reply in JSON with exactly these fields:
  "category"  : one of billing, technical, or other
  "sentiment" : positive, neutral, or negative
  "answer"    : a short reply to the customer
Do not add anything outside the JSON object.

Ask "I was charged twice for my subscription, what do I do?". The model should return a JSON object with the three fields, which your application could parse directly without any string scraping.

Step 4: Combine Multiple Rules

Real applications combine role, tone, constraints, and format in a single system prompt. Build one that packs several concerns together and then test it with a question that should trigger each rule:

You are a travel concierge for a hotel chain.
- Tone: friendly and concise.
- Always end your reply with a question.
- If the user asks about prices, say prices vary by season.
- Keep every reply under three sentences.

Ask "What is there to do near the hotel?" and then "How much is a room?". Watch the model switch between the rules depending on the topic.

Step 5: Handle the Failure Case

A good system prompt also defines what the model should NOT do — and what to say when it cannot help:

You are a support bot for a bank.
You may only discuss account services listed on the help page.
If a question is outside that scope, reply:
  "I can only help with account services. Please contact a human agent."
Never invent fees, policies, or deadlines.

Ask "Can I get a discount on my car loan?". The model should refuse politely instead of inventing a policy — the behavior you want before you ever add a separate guardrail.

A system prompt is instructions, not a guarantee. Models can still contradict it, especially when the user's message is aggressive or the prompt is vague. System prompts reduce the risk; they do not remove it.

Summary

You wrote and tested system prompts that set a role, enforce a tone, force a JSON format, combine multiple rules, and define a refusal path. You saw the same user question produce completely different answers purely from the system text. This skill carries directly into the Python labs, where the system message becomes the first element of every request. Next, you will work with image generation in the playground.
