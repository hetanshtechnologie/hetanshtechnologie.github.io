Lab - Conversational Language Understanding - Adding Utterances

Your project now has intents and entities, but the model has not seen any real user language yet. In this lab you will teach it how people actually speak by adding utterances — example sentences that express a given intent. You will also label the entities that appear inside those sentences so the model learns to extract them from new input. By the end of this lab your project will contain a realistic training set, ready for training in the next chapter.

Prerequisites

  • The CLU project you created in the Language Studio getting-started lab.
  • The intents from the Adding Intents lab (for example BookFlight and GetHelp).
  • The entities from the Adding Entities lab (for example City and Date).
  • Access to Language Studio with the correct Azure AI Language resource selected.

What Makes a Good Utterance

An utterance is one example of how a user might express an intent. The model does not read rules; it learns patterns from your examples. That means the quality and variety of your utterances directly control how well the model generalizes to sentences it has never seen. Good utterances share several properties:

  • They sound natural. Write the way real users type or speak, including casual phrasing and minor grammar mistakes.
  • They vary. Use different sentence structures, word orders, synonyms, and lengths so the model does not overfit to a single template.
  • They stay on intent. Every utterance must clearly belong to exactly one intent, or it will confuse the classifier.
  • They include realistic entity values. Put dates, cities, names, and other entity mentions where users would naturally put them.

There is no fixed minimum, but plan for at least 15 to 30 utterances per intent as a starting point. Fewer than about ten examples per intent usually produces an unstable classifier that changes behavior after every retrain.

Step 1: Add Utterances to an Intent

Exercise 1: Enter example sentences

In Language Studio, open your CLU project and select Data labeling from the left menu.

  1. Select the intent you want to populate, for example BookFlight.
  2. In the Utterance box, type an example sentence such as Book a round trip to Madrid next Tuesday and press Enter. The sentence appears in the list below.
  3. Repeat with several more examples, varying the verbs, cities, and dates: I need a flight to London on Friday, Find me cheap flights to Rome tomorrow morning, Can you book a business class trip to Paris for next week.
  4. Repeat the process for each intent, including GetHelp with questions like What can I do here? and Help me with this app.

Step 2: Label Entities Inside Utterances

Exercise 2: Tag entity mentions

An utterance is not only a classification example — it is also the place where the model learns to find entities.

  1. Open the utterance Book a round trip to Madrid next Tuesday in the editor.
  2. Select the word Madrid. A small menu appears; choose the City entity you created earlier.
  3. Select next Tuesday and label it with your Date entity.
  4. Go through every utterance you added and label every entity mention. Consistency matters — the same kind of value must always receive the same label.
  5. Use the entity list on the left to jump between mentions and verify that none are missing.

Selecting text inside an utterance pops up the label menu immediately, so you can label quickly while you are still in the flow of adding examples. Working utterance by utterance is faster than labeling everything later.

Step 3: Review for Balance and Noise

Before you train, scan the whole project:

  • Confirm that no utterance is assigned to the wrong intent.
  • Check that no entity label was applied inconsistently.
  • Remove near-duplicate utterances that differ only in one word and replace them with genuinely different phrasings.
  • Make sure every intent has roughly similar numbers of examples so the classifier is not biased toward one intent.

Do not add utterances that could belong to two intents. A sentence like I want to go somewhere is too vague. If you cannot decide the intent yourself, the model will not be able to either — delete it or give it a clear home in a single intent.

Step 4: Adding Utterances Through the Authoring API

Large projects are usually maintained through the API instead of the portal. The authoring API accepts a payload that contains the utterances for each intent. A JSON document that adds utterances looks like this:

{
  "projectKind": "Conversation",
  "intents": [
    {
      "category": "BookFlight",
      "utterances": [
        { "text": "Book a round trip to Madrid next Tuesday" },
        { "text": "I need a flight to London on Friday" }
      ]
    }
  ]
}

You would send that JSON to the import endpoint of your language resource, with your key in the request header. The portal uses the same mechanism behind the scenes.

The authoring API requires the endpoint and key of your Azure AI Language resource, not the prediction endpoint. Keep the authoring key secret and rotate it if it is ever exposed.

Summary

You populated your CLU project with natural, varied example utterances and labeled every entity mention inside them. You also reviewed the data for balance and noise, and saw how the same operations are exposed through the authoring API. Your project is now ready to be trained, which is exactly what you will do in the next chapter.
