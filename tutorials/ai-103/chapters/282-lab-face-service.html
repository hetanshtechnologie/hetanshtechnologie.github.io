Lab - Face service

In this lab you will create an Azure AI Face resource, obtain its endpoint and key, and call the detection and analysis operations for real. You will use the REST API directly, which makes the request and response structure visible and gives you a foundation for the Python version in the next chapter.

What You Need Before Starting

  • An Azure subscription with permissions to create resources.
  • The Azure CLI installed and signed in, or access to the Azure portal.
  • A photo with one or two clear faces, stored locally.

Create the Face Resource

Step 1 - Sign in to the Azure CLI

az login

Follow the browser prompt and select the subscription you want to use.

Step 2 - Create a resource group

az group create --name rg-ai103 --location eastus

Step 3 - Create the Face account

Create a Cognitive Services multi-service account. This kind of account exposes the Face API under the Face sub-endpoint, and it also gives you room to reuse the same account for other vision services later in the course:

az cognitiveservices account create \
    --name cs-ai103 \
    --resource-group rg-ai103 \
    --kind CognitiveServices \
    --sku S0 \
    --location eastus

Step 4 - Fetch the endpoint and a key

az cognitiveservices account show --name cs-ai103 --resource-group rg-ai103
az cognitiveservices account keys list --name cs-ai103 --resource-group rg-ai103

Copy the properties.endpoint value and one of the keys. Store them in environment variables so your commands stay clean:

$env:AZURE_FACE_ENDPOINT = "https://cs-ai103.cognitiveservices.azure.com/"
$env:AZURE_FACE_KEY = "YOUR_KEY"

Detect Faces in an Image

Detection is a single POST to the /face/v1.0/detect endpoint. The following PowerShell request sends a public image URL and asks for the age and glasses attributes:

Step 5 - Call detect with a URL

$body = @{ url = "https://example.com/your-photo.jpg" } | ConvertTo-Json

$response = Invoke-RestMethod `
    -Uri "$env:AZURE_FACE_ENDPOINT/face/v1.0/detect?returnFaceAttributes=age,glasses,emotion" `
    -Method Post `
    -Headers @{ "Ocp-Apim-Subscription-Key" = $env:AZURE_FACE_KEY } `
    -ContentType "application/json" `
    -Body $body

$response | ConvertTo-Json -Depth 5

The result is an array of faces. Each element contains faceRectangle with the pixel coordinates, a faceId, and the attributes you requested.

If you use curl instead, the equivalent command is:

curl -X POST "https://cs-ai103.cognitiveservices.azure.com/face/v1.0/detect?returnFaceAttributes=age,glasses" -H "Ocp-Apim-Subscription-Key: $env:AZURE_FACE_KEY" -H "Content-Type: application/json" --data-raw "{\"url\":\"https://example.com/your-photo.jpg\"}"

Send the Image as Raw Bytes

Public URLs are convenient but often not available — many applications hold images in local storage or in a database. The detect endpoint also accepts the raw image bytes directly in the request body, with a binary content type:

$imageBytes = [System.IO.File]::ReadAllBytes("C:\temp\face.jpg")

$response = Invoke-RestMethod `
    -Uri "$env:AZURE_FACE_ENDPOINT/face/v1.0/detect?returnFaceRectangle=true" `
    -Method Post `
    -Headers @{ "Ocp-Apim-Subscription-Key" = $env:AZURE_FACE_KEY } `
    -ContentType "application/octet-stream" `
    -Body $imageBytes

$response | ConvertTo-Json -Depth 5

When you pass image bytes directly you cannot also pass a JSON body, so all configuration travels in the query string. Keep images under the size limit documented for the service — for the detection endpoint that is 6 MB for the binary body — and re-encode very large files before sending them.

Observing the Response Shape

Regardless of whether you send a URL or bytes, the response follows the same shape. A single face produces something like this (values shown are illustrative):

[
  {
    "faceId": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
    "faceRectangle": {
      "top": 64,
      "left": 120,
      "width": 180,
      "height": 180
    },
    "faceAttributes": {
      "age": 32.0,
      "glasses": "NoGlasses",
      "emotion": {
        "happiness": 0.97,
        "neutral": 0.01,
        "anger": 0.0,
        "surprise": 0.0,
        "sadness": 0.0,
        "fear": 0.0,
        "disgust": 0.0
      }
    }
  }
]

Clean Up the Resource

Once you have confirmed detection works, you can keep the account for the next chapters or delete it to avoid further charges:

az cognitiveservices account delete --name cs-ai103 --resource-group rg-ai103
az group delete --name rg-ai103 --yes

Summary

You created a Cognitive Services account, discovered the Face endpoint and its subscription key, and made working detect calls using both a public image URL and raw image bytes. You have also seen the structure of the JSON response, including the bounding box, the face ID, and the requested attributes. The next chapter reimplements the same workflow in Python, which is the language most of your integration work will use.
