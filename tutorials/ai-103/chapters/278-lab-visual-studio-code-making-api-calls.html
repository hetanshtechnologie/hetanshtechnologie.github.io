Lab - Visual Studio Code - Making API calls

The Python labs gave you one way to talk to your Computer Vision resource. Before the remaining REST labs, this short lab sets up a second, faster way: making API calls directly from Visual Studio Code. With the REST Client extension you can write HTTP requests in a plain text file and send them with one click — no Python script required. It is ideal for exploring an API, testing a single request, and reading raw responses.

What You Need

  • Visual Studio Code installed.
  • Your Computer Vision endpoint and key.
  • An image file or image URL to analyze.

Set Up the REST Client Extension

Exercise 1: Install and prepare REST Client

  1. Open Visual Studio Code.
  2. Open the Extensions view (Ctrl+Shift+X) and search for REST Client by Huachao Mao. Click Install.
  3. Create a new folder for this section of the course, for example ai103-vision.
  4. In that folder, create a new file called vision.http. The .http extension is what REST Client looks for.
  5. At the top of the file, define variables for your endpoint and key so the requests stay readable:
@endpoint = https://YOURNAME.cognitiveservices.azure.com/
@key = YOUR_KEY
@imageUrl = https://upload.wikimedia.org/wikipedia/commons/1/1e/Cat_and_dog.jpg

Keep the key in the @key variable so it appears once, not in every request. If you share the file, replace the key with a placeholder and instruct anyone else to fill in their own value.

Write Your First Request

Below the variables, add a request that asks for a caption and tags. In REST Client syntax, the variables are referenced as {{variable}}:

### Analyze image - caption and tags
POST {{endpoint}}computervision/imageanalysis:analyze?api-version=2024-02-01&features=caption,tags
Content-Type: application/json
Ocp-Apim-Subscription-Key: {{key}}

{
  "url": "{{imageUrl}}"
}

Send the Request

Exercise 2: Send and inspect the response

  1. Place your cursor anywhere inside the request block, starting at the POST line.
  2. Click the Send Request link that appears directly above the POST line, or press Ctrl+Alt+R.
  3. A response pane opens beside the editor. Confirm the status is 200 OK and read the JSON body.
  4. Locate the captionResult and tagsResult blocks. Compare them with the output your Python script produced in the earlier labs — they come from the same endpoint.
  5. Change features to objects and send the request again. Watch the response change to object bounding boxes.

Every block in the file that starts with a method line (POST, GET) becomes a separate sendable request. Use the ### comment lines to give each one a label so the file stays readable as it grows.

Sending a Local Image File

You can also analyze a file on your disk by referencing it as a local file URL. REST Client reads the file and sends its bytes in the request body:

### Analyze a local image - caption
POST {{endpoint}}computervision/imageanalysis:analyze?api-version=2024-02-01&features=caption
Content-Type: application/octet-stream
Ocp-Apim-Subscription-Key: {{key}}

< C:\path\to\test.jpg

REST Client sends the local file over the internet to your Azure endpoint, and the endpoint logs the request. Do not point this workflow at sensitive images unless the endpoint and its data handling satisfy your security requirements.

Reading an Error Response

When a request fails, REST Client still shows you the response — usually with a status code and an error JSON block that explains what went wrong. Common ones you will meet:

  • 401 Unauthorized: the key variable is wrong or empty.
  • 404 Not Found: the endpoint variable is incomplete or the path is misspelled.
  • 429 Too Many Requests: the resource's rate limit was reached; wait before retrying.
  • 400 Bad Request: often a malformed body or an unsupported feature name.

Keep the variables and the requests in separate concerns: change the endpoint and key in one place at the top, and you never have to hunt through every request to update them.

Summary

You set up the REST Client extension, wrote your first .http file, and sent caption, tags, and object detection requests directly from Visual Studio Code. This workflow is the foundation for the next two labs, where you will make raw REST API calls to generate captions and exercise the other vision features without writing Python.
