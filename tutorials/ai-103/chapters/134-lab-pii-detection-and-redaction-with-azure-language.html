Lab - PII Detection and Redaction with Azure Language

Personal information — names, addresses, phone numbers, bank details — appears in support tickets, contracts, and logs whether you want it there or not. Azure AI Language's PII detection finds those values and its redaction feature masks them so documents can be stored, shared, or sent to an LLM without leaking personal data. In this lab you will detect PII, inspect its categories, and produce redacted text.

Prerequisites

  • An Azure AI Language resource with its endpoint and key. You can create it in the portal or reuse the service created for your Foundry project.
  • Python with the text analytics SDK installed:
pip install azure-ai-textanalytics azure-core python-dotenv

Step 1: Set Up the Client

Exercise 1: Create the analysis client

Create lang_pii.py:

import os

from azure.ai.textanalytics import TextAnalyticsClient
from azure.core.credentials import AzureKeyCredential
from dotenv import load_dotenv

load_dotenv()

client = TextAnalyticsClient(
    endpoint=os.getenv("AZURE_LANGUAGE_ENDPOINT"),
    credential=AzureKeyCredential(os.getenv("AZURE_LANGUAGE_KEY")),
)

Run the file once to confirm the imports and client construction succeed.

Step 2: Detect PII in a Document

Exercise 2: Find and inspect personal information

Append the detection logic:

document = (
    "Customer Dana Whitfield called about order 4821. Contact them at "
    "dana.whitfield@example.com or +1 555 010 2233. The delivery "
    "address is 12 Linden Street, Berlin, and payment was charged to "
    "card ending 4412."
)

result = client.recognize_pii_entities(documents=[document])
doc = result[0]
if doc.is_error:
    print("Error:", doc.error.code, doc.error.message)
else:
    print(f"Redacted text:\n{doc.redacted_text}\n")
    for entity in doc.entities:
        print(
            f"{entity.category:16s} {entity.text!r:40s} "
            f"confidence={entity.confidence_score:.2f}"
        )
  1. Run the script. The output shows two things: the fully redacted text and the list of detected entities with categories and confidence scores.
  2. Note the entity offsets — each entity carries a text value and a span into the original document, so you can locate exactly where the PII sits.

Categories are granular: names, phone numbers, email addresses, credit-card numbers, street addresses, and more are distinguished. Because each entity reports a category, you can choose to keep some categories and redact others — for example, mask phone numbers but keep names.

Step 3: Redact Only Selected Categories

Exercise 3: Filter which categories get redacted

Use the categories_filter parameter to redact only the values you choose:

phone_only = client.recognize_pii_entities(
    documents=[document],
    categories_filter=["PhoneNumber", "Email"],
)
doc_phone = phone_only[0]
print("Redacted with phone and email only:")
print(doc_phone.redacted_text)
  1. Run the script. The name and address should now survive while the phone number and email are masked.
  2. Change the filter to ["CreditCard"] and rerun. Only the card ending in 4412 should be hidden.

Category filtering is the tool for the "comply with the data-protection rule but keep the useful business context" problem. Many pipelines redact financial identifiers while deliberately preserving names and addresses for customer-service lookup.

Step 4: Redact a Batch of Documents

Exercise 4: Process several documents at once

The SDK accepts a list of documents in a single call:

batch = [
    "Emergency contact: Sam Rivera, sam.rivera@example.net, 555-0199.",
    "Policy PR-2233 lapsed on 2026-01-31; renewal due.",
    "Technician visited unit 7 at 9 Linden Street at 14:30.",
]

results = client.recognize_pii_entities(documents=batch)
for i, doc in enumerate(results):
    if doc.is_error:
        print(f"Doc {i + 1} failed: {doc.error.message}")
    else:
        print(f"Doc {i + 1}: {doc.redacted_text}")
  1. Run the script and verify each document is redacted independently.
  2. Add a document with no PII, such as "The quarterly report is due on Friday", and confirm it passes through unchanged with an empty entities list.

Sending personal data to the service means that data is processed in Azure. For production use, confirm your compliance requirements and understand the region where your Language resource lives. Where full control is needed, run the service in your approved region and use managed identity authentication instead of keys.

Step 5: Use the Redacted Text Downstream

The redacted output is plain text, so it drops naturally into the next stage of a pipeline — for example, as the input to a chat model or a search index. A common pattern is: detect PII, redact the document, then hand the redacted text to your LLM, which never sees the personal data.

redacted = doc.redacted_text
print("Send to LLM:", redacted[:80], "...")

Summary

You detected PII in documents with Azure AI Language, inspected the entity categories and confidence scores, redacted only selected categories, processed a batch, and learned how redacted text feeds safely into downstream systems. Next you will use the same client for the simpler job of detecting which language a document is written in.
