Lab - OpenAI - Structured Output - Trying to use the Responses API

Structured outputs are available in both the Responses API and the Chat Completions API, but they work differently in each. This lab focuses on the Responses API: you will attach a JSON schema to a call and verify the model honors it exactly. We will also show the helper-based approach that makes writing schemas simpler.

Passing a Schema in the Responses API

With client.responses.create, structured output is enabled by supplying a text field inside the output array. The text field carries the schema, the request for the model, and how strict the output should be.

Step 1 — Create the script

Create a file named structured_response.py:

from openai import OpenAI

client = OpenAI(api_key="YOUR_API_KEY")

schema = {
    "type": "object",
    "properties": {
        "customer": {
            "type": "object",
            "properties": {
                "name": {"type": "string"},
                "email": {"type": "string"}
            },
            "required": ["name", "email"],
            "additionalProperties": False
        },
        "order_number": {"type": "string"},
        "issue": {"type": "string"}
    },
    "required": ["customer", "order_number", "issue"],
    "additionalProperties": False
}

email_text = """
Hi, I am Raj. My email is raj@example.com. Order 77123
was supposed to arrive on Friday but never showed up.
"""

response = client.responses.create(
    model="gpt-4o-mini",
    input=email_text,
    output=[
        {
            "type": "text",
            "name": "order_issue",
            "text": {
                "format": {
                    "type": "json_schema",
                    "name": "order_issue",
                    "schema": schema,
                    "strict": True
                }
            }
        }
    ],
)

print(response.output[0].content[0].text)

Step 2 — Run it

python structured_response.py

The output should be a compact JSON object matching your schema exactly.

Verifying the Contract

Now that the schema is enforced, your application can parse the output directly without defensive parsing:

import json

payload = json.loads(response.output[0].content[0].text)
print("Customer:", payload["customer"]["name"])
print("Email:", payload["customer"]["email"])
print("Order:", payload["order_number"])
print("Issue:", payload["issue"])

Because the model was required to produce every key, indexing into the dictionary is safe. Run the script several times and confirm the output never changes shape.

Read the response from response.output[0].content[0].text, not output_text. When you request structured output, the answer lives in that content item as raw JSON. Using the wrong accessor yields the plain-text fallback or empty output, which confuses many first attempts.

Enforcing Values with Enums

Schemas can restrict fields to a fixed set of allowed values using enum. This is ideal for issue types in a support ticket:

schema = {
    "type": "object",
    "properties": {
        "issue_type": {
            "type": "string",
            "enum": ["shipping", "refund", "product_question", "other"]
        },
        "summary": {"type": "string"}
    },
    "required": ["issue_type", "summary"],
    "additionalProperties": False
}

Now issue_type can only be one of the four listed values, which makes downstream routing trivial.

Common Pitfalls

  • Missing additionalProperties: False: without it, the model may add fields you did not declare.
  • Forgotten required fields: a field listed only in properties is optional unless it also appears in required.
  • Wrong response accessor: remember the structured text sits in output[0].content[0].text.
  • Schema too loose: types like "anyOf" with conflicting shapes can trigger validation errors. Keep each field's type concrete.

Design your schema from the perspective of the consuming code, not the model. Ask: what exact keys and types does my application branch on? Those become the required, typed properties.

Summary

You enabled structured output on the Responses API by attaching a strict JSON schema, parsed the guaranteed JSON safely, and added enum constraints. The Responses API gives you schema-enforced output in a single call — the next lab shows the Chat Completions API variant of the same idea.
