Lab - Creating the CloudXeus Agents

CloudXeus is the fictional company used through the rest of this course: a cloud services provider that receives customer requests, support tickets, and sales inquiries around the clock. In this lab you will create the two agents that power its intake pipeline — IntakeAgent, which reads and summarizes incoming customer messages, and ResolverAgent, which drafts replies for the teams that follow up. These agents are the building blocks you will assemble into a workflow in the next labs.

Objectives

  • Define the role of each CloudXeus agent.
  • Create IntakeAgent and ResolverAgent as prompt agents in the Foundry portal.
  • Write clear instructions that keep each agent focused.
  • Validate both agents in the playground with realistic sample messages.

Prerequisites

  • A Foundry project with contributor access.
  • At least one deployed chat model, such as gpt-4o-mini, to attach to both agents.

Step 1: Create IntakeAgent

IntakeAgent is the front door. It receives raw customer messages — a sentence or a paragraph, possibly messy — and produces a clean, structured summary of what the customer needs. Its job is to understand, not to answer.

Create and configure IntakeAgent

  1. In your Foundry project, open Agents and click Create.
  2. Choose Prompt agent, name it IntakeAgent, and select your chat model deployment.
  3. Paste the instructions below and save the agent.
You are IntakeAgent at CloudXeus, a cloud services provider.
Read the customer's message and summarize it into a concise
intake record. Always cover:
- the customer's core request or issue
- the product or service mentioned (if any)
- any urgency or deadline the customer mentions
- any account or order number the customer provides
Do not solve the problem. Do not add facts that are not present.
If a field is missing, state that it is missing.

Notice what the instructions deliberately omit: they do not ask IntakeAgent to reply kindly to the customer or to offer solutions. Keeping the role narrow makes the agent's output predictable, which matters when its output feeds the next step of a workflow.

Step 2: Create ResolverAgent

ResolverAgent plays the opposite role: it takes a clean intake summary and the customer's original message, and it drafts a professional reply for a CloudXeus support representative to review.

Create and configure ResolverAgent

  1. Click Create again and choose Prompt agent.
  2. Name it ResolverAgent and select the same model deployment.
  3. Paste the instructions below and save.
You are ResolverAgent at CloudXeus. You receive a customer's
original message plus an intake summary. Draft a professional,
empathetic reply for a support representative to review.
- Acknowledge the customer's concern clearly.
- Reflect the details from the intake summary accurately.
- Ask for any information the summary shows is missing.
- Do not promise refunds, timelines, or fixes unless the
  intake summary explicitly confirms them.
- Keep the reply under 120 words.

Step 3: Test IntakeAgent

Every agent is only as good as its instructions, and the playground is where you prove them. Test IntakeAgent with a message that looks like real customer noise:

Run a realistic intake

  1. Open IntakeAgent's chat panel.
  2. Paste this message and send it:
Hi, I'm Priya from Meridian Retail. Our virtual machine
in eastus has been down for almost 2 hours now and our
billing dashboard depends on it. This is urgent, we are
losing sales. Our account number is AC-88231.
  1. Check that the response covers the request, the product (virtual machine), the urgency (2 hours, losing sales), and the account number (AC-88231).
  2. If any field is missing or invented, refine the instructions and test again.

Step 4: Test ResolverAgent

Run a resolution draft

  1. Open ResolverAgent's chat panel.
  2. Paste the customer message from Step 3 followed by the intake summary IntakeAgent produced.
  3. Verify the draft reply acknowledges the concern, reflects the details, and does not invent a fix timeline or a refund.

Notice that ResolverAgent is designed to let a human review the draft. Do not remove that guardrail for this course: in production, auto-sending a model-generated reply with promises baked in is a fast way to create contractual liability. Keep a human in the loop until you have evaluation data that proves otherwise.

Step 5: Save the Agent Versions

Once both agents behave correctly, save a version of each so the workflow labs can reference stable snapshots.

  1. In each agent's editor, click Save and then Publish to create a version.
  2. Note the published version number for each agent.
  3. Confirm both agents appear on the Agents list with a published version.

Publishing creates an immutable version you can point a workflow at. If you edit the agent later, the workflow keeps using the version it was bound to until you deliberately update the binding. This separation is what makes production workflows stable.

Summary

You created the two CloudXeus agents that will power the intake pipeline: IntakeAgent, a focused summarizer of customer messages, and ResolverAgent, a careful drafter of replies. You validated each agent's instructions against realistic input, confirmed they neither add nor omit critical facts, and published versions for reuse. In the next lab you will connect these agents into a workflow in the Foundry portal.
