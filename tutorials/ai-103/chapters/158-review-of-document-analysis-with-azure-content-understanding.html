Review of document analysis with Azure Content Understanding

You have now built and used a document analyzer: you created a Content Understanding resource, configured capabilities, published an analyzer, and inspected the layered output. This review makes sure the concepts stick before you move to Python. Answer the questions below, then compare your answers with the key at the end.

Questions

  1. What is the primary job of the OCR layer in a document analyzer?

    1. To read the characters on the page and report them with their positions. (correct)
    2. To decide whether a document is a contract or an invoice.
    3. To assign a confidence score to extracted fields.
    4. To connect the resource to a Microsoft Foundry project.

  2. Which layer reconstructs rows and columns from scattered text on a page?

    1. Field extraction.
    2. OCR.
    3. Table detection. (correct)
    4. Semantic ranking.

  3. In a custom document analyzer, fields are:

    1. Fixed and identical for every analyzer.
    2. Named data points you define, each with a type such as string or number. (correct)
    3. Only usable for images, never documents.
    4. Calculated automatically by the resource key.

  4. Why does each recognized word carry a span or polygon in the output?

    1. So the text can be compressed for storage.
    2. So applications know exactly where content sits on the page and can correlate it with fields. (correct)
    3. To encrypt the document content.
    4. To satisfy billing requirements.

  5. When a field is extracted with a low confidence score, the recommended practice is to:

    1. Ignore the field completely and delete it from the analyzer.
    2. Route the value to human review rather than accepting it automatically. (correct)
    3. Increase the page resolution and run again.
    4. Switch to a prebuilt analyzer, since custom ones cannot be trusted.

  6. What happens when you publish an analyzer?

    1. The resource is deleted from the subscription.
    2. The analyzer becomes callable, usually with a version, and can be invoked from the portal or the API. (correct)
    3. The analyzer is converted into a chat model deployment.
    4. Nothing; publishing only renames the analyzer.

  7. Which of these is NOT a content type supported by Azure Content Understanding?

    1. Documents.
    2. Images.
    3. Audio.
    4. Database dumps. (correct)

  8. Why is reading order important in layout analysis?

    1. It makes the extracted text flow the way a human reads the page, which matters when the text is later indexed or summarized. (correct)
    2. It determines which OCR engine is used.
    3. It is only cosmetic and has no effect on output.
    4. It decides whether the document is billable.

Answer Key

1AOCR recognizes characters and reports text together with spatial metadata such as bounding boxes.

4BSpans and polygons locate content on the page and tie field values to their source regions.
5BLow-confidence extractions belong in a human review queue, not in automated processing.

If you missed more than two questions, revisit the previous two chapters before continuing. The next lab drops the portal and drives the same analyzer from Python, so a solid mental model of the layered output will make the code easier to follow.

Summary

Document analysis is a layered pipeline: OCR produces text and geometry, layout gives it structure, tables restore grids, and custom fields extract the values your application needs. The JSON output carries all four layers, so downstream systems can consume both the raw content and the structured extractions. With that foundation, you are ready to call the analyzer programmatically.
