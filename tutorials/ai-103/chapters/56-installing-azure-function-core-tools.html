Installing Azure Function Core tools

You can build functions entirely in the portal, but professional development happens locally: write the code, run it on your machine, debug it, and publish when it works. The Azure Functions Core Tools is the CLI that makes this possible. This lab installs Core Tools, verifies it, and scaffolds a first local project.

What Core Tools Provides

Core Tools bundles everything you need for local Functions development:

  • func init to scaffold a new function app project.
  • func new to add functions from templates.
  • func start to run the app locally with a real HTTP host.
  • func azure functionapp publish to deploy to Azure.
  • func extensions install to manage binding extensions.

Prerequisites

  • Node.js and npm (for the npm installation) or winget on Windows.
  • Python 3.10 or later (the worker runtime we will use) installed and on your PATH.
  • The Core Tools major version should match the Functions runtime version your project targets; version 4 matches the current v4 runtime.

Install with npm

The npm package installs Core Tools globally. On some systems you need elevated rights, which the unsafe-perm flag handles:

npm install -g azure-functions-core-tools@4 --unsafe-perm true

Install with winget (Windows)

Alternatively, install the packaged build with the Windows package manager:

winget install Azure.FunctionsCoreTools

Verify the Installation

Open a fresh terminal and check the version. A 4.x output means the tools are ready:

func --version

If your terminal was open before the install, restart it so the new PATH entry is picked up. If func is still not found, the npm global bin folder is not on your PATH; add it and try again.

Scaffold Your First Local Project

Exercise — Create and Run a Function Locally

  1. Create a project folder and initialize a Python function app:
mkdir cloudxeus-orders-api
cd cloudxeus-orders-api
func init --worker-runtime python --model v2
  1. Add an HTTP-triggered function named hello:
func new --name hello --template "HTTP trigger" --authlevel anonymous
  1. Start the local host:
func start
  1. In a second terminal, call your function:
curl "http://localhost:7071/api/hello?name=CloudXeus"
  1. You should receive a JSON greeting. Stop the host with Ctrl+C.

The --model v2 flag selects the current Python programming model, where a function is declared with a decorator in code instead of a separate function.json file. It keeps all HTTP routing details in one file, which pairs well with the OpenAPI tools you will add later.

Summary

Core Tools is installed and verified, and you have run your first local Azure Function over HTTP. In the next lab you use this setup to build the real CloudXeus orders API, add OpenAPI metadata, and publish it so a Foundry agent can call it as a tool.
