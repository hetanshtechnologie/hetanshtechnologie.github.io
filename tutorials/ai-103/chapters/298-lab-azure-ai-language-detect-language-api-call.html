Lab - Azure AI Language - Detect Language - API Call

Language Studio is a friendly front end, but your applications will call the service directly. In this lab you will make a raw REST API call for language detection using curl, inspect the JSON response, and learn to diagnose the common failure modes. This is the same request the browser made on your behalf in the first lab of this section — now you send it yourself.

What You Need

  • The endpoint and key from your Azure AI Language resource (previous chapter).
  • A terminal with curl available. On Windows, use curl.exe from Command Prompt or PowerShell.

The Language Detection Endpoint

Language detection uses the following path on the text analytics API:

POST https://YOUR_ENDPOINT.cognitiveservices.azure.com/text/analytics/v3.1/languages

Two details matter in that URL:

  • YOUR_ENDPOINT is the base URL of your resource, for example https://lang-ai103-demo.cognitiveservices.azure.com. Note there is no trailing slash.
  • v3.1 is the API version in the path. Azure pins the behavior of each released version, so applications stay stable even as the service evolves.

Every request must carry two things: your key in the Ocp-Apim-Subscription-Key header, and a JSON body with a documents array.

Your First Request

Exercise 1: Detect the language of one sentence

From your terminal, run the following request. Replace YOUR_ENDPOINT and YOUR_KEY with the values from your resource:

curl -X POST "https://YOUR_ENDPOINT.cognitiveservices.azure.com/text/analytics/v3.1/languages" \
  -H "Ocp-Apim-Subscription-Key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d "{\"documents\": [{\"id\": \"1\", \"text\": \"El servicio de atención al cliente fue excelente.\"}]}"

You should see a JSON response similar to this:

{
  "documents": [
    {
      "id": "1",
      "detectedLanguage": {
        "name": "Spanish",
        "iso6391Name": "es",
        "confidenceScore": 1.0
      },
      "warnings": []
    }
  ],
  "errors": []
}
  1. Confirm the iso6391Name is es and the confidence is 1.0.
  2. Change the text to an English sentence and run again. The code should switch to en.

The -d flag in curl sends a request body, and -X POST sets the HTTP method. The escaped quotes inside \" are the JSON quotes. When you write this in Python with the requests library, the JSON handling is much cleaner — that is one reason applications prefer SDKs.

Send a Batch of Documents

The same endpoint accepts up to ten documents per request. Each document must have a unique id; the service returns results in the same order.

Exercise 2: Detect languages for five documents

Save the following body to a file named batch.json:

{
  "documents": [
    {"id": "1", "text": "The invoice was sent by email this morning."},
    {"id": "2", "text": "Die Lieferung erfolgt morgen per Kurier."},
    {"id": "3", "text": "La réunion commence à dix heures."},
    {"id": "4", "text": "Prazo de entrega é de cinco dias úteis."},
    {"id": "5", "text": "Tilauksesi on valmis noudettavaksi."}
  ]
}

Then send it with curl using the @filename syntax:

curl -X POST "https://YOUR_ENDPOINT.cognitiveservices.azure.com/text/analytics/v3.1/languages" \
  -H "Ocp-Apim-Subscription-Key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d @batch.json
  1. Read the response. Document 1 is English (en), 2 is German (de), 3 is French (fr), 4 is Portuguese (pt), and 5 is Finnish (fi).
  2. Notice that every result keeps its original id, so your code can match results back to inputs even if the order changed.

The @batch.json form tells curl to read the request body from a file. This avoids fragile escaping on the command line and is the pattern you should use for anything longer than a single line.

Reading the Response

The response has three top-level blocks worth understanding:

  • documents — one entry per input document, each containing detectedLanguage and warnings.
  • errors — empty when everything succeeds. If a document exceeds the size limit, it appears here instead of in documents.
  • modelVersion — the model version used to produce the results, useful for auditing and reproducibility.

Inside detectedLanguage, the confidenceScore is a number from 0 to 1. Values near 1.0 are trustworthy; lower values indicate the text is short, mixed, or ambiguous.

Error Handling

When something goes wrong, the service returns an HTTP status code with an error body. Learn to recognize the common ones:

StatusMeaningFix
401UnauthorizedKey is wrong or has a stray space. Re-copy it from Keys and Endpoint.
404Not foundEndpoint URL is malformed, or the API version is wrong. Check the full URL.
429Too many requestsYou exceeded the rate or quota of your tier. Wait and retry.
400Bad requestThe JSON body is invalid, or a document is too large.

An error in one document does not fail the whole batch. Check the errors array separately from documents — a partially successful call is still a 200 OK response, and your code must handle both blocks.

Summary

You made a raw REST API call for language detection, sent both a single document and a batch, and learned to read the response and diagnose failures. The next lab does the same job in Python with the official SDK, where the HTTP layer disappears behind client methods.
