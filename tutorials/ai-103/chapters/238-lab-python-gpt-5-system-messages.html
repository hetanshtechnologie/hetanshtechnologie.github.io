Lab - Python - GPT 5 - System Messages

The playground labs let you type a system prompt into a box. In a real application, that system prompt is the first element of the messages array your Python code sends. This lab moves system messages into code: you will build a chat client that applies a fixed system message, tests how different system messages change the same question, and handles a multi-turn conversation.

What You Will Need

  • The reusable ask() function (or the AzureOpenAI client) from the previous lab.
  • Your endpoint URL, key, and deployment name.
  • An understanding of roles: system for instructions, user for input, assistant for model replies.

Where the System Message Goes

The system message is just a message with the role system placed at the front of the array. Everything after it — user questions and assistant answers — plays out under its rules:

messages = [
    {"role": "system", "content": "You are a concise assistant. Never exceed 40 words."},
    {"role": "user", "content": "Explain what a token is."},
]

There is no separate field for the system prompt in the chat-completions API — it travels inside the messages array exactly like everything else. When you saw a "System prompt" box in the playground, the playground was building this array for you.

Step 1: Write a System-Message Script

Exercise 1: Build a fixed-role assistant

  1. Create system_chat.py in ai103-lab.
  2. Reuse the client setup from the previous lab, but drive the conversation with a function that always prefixes the same system message.
  3. Run it and compare two questions under one system message.
import os
from openai import AzureOpenAI

SYSTEM_PROMPT = (
    "You are a strict technical writer for a software manual. "
    "Use simple words. Never write more than three sentences. "
    "Never mention pricing."
)

client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2024-06-01",
)


def ask(question, deployment="ai103-chat-deploy"):
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": question},
    ]
    response = client.chat.completions.create(
        model=deployment,
        messages=messages,
        temperature=0.3,
        max_tokens=150,
    )
    return response.choices[0].message.content


if __name__ == "__main__":
    print(ask("What is a database?"))
    print()
    print(ask("How much does a database cost?"))

The second question tests the "never mention pricing" rule: even though the user directly asks about cost, the system message should steer the answer away from figures.

System messages shape behavior but are not enforcement. A user who rephrases the same question cleverly might still get a pricing answer. That is exactly why later chapters add explicit guardrails on top of prompting.

Step 2: Compare System Prompts Head to Head

The same question answered under two different system messages proves how much the system text matters. Update the script to loop over system prompts:

def ask_with_system(system_prompt, question, deployment="ai103-chat-deploy"):
    messages = [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": question},
    ]
    response = client.chat.completions.create(
        model=deployment,
        messages=messages,
        temperature=0.0,
        max_tokens=150,
    )
    return response.choices[0].message.content


prompts = {
    "tutor": "You are a patient tutor for a 10-year-old. Keep it friendly and simple.",
    "executive": "You are a CEO writing to investors. Be formal and concise.",
}

question = "Explain cloud computing."
for name, prompt in prompts.items():
    print(f"--- system: {name} ---")
    print(ask_with_system(prompt, question))
    print()

Set temperature=0.0 in this experiment so any differences between the two outputs come from the system message alone, not from random sampling.

Step 3: Carry a Multi-Turn Conversation

A system message applies to the whole conversation, which only matters if you keep the history. Build a loop that appends each exchange to the array:

messages = [
    {"role": "system", "content": "You are a friendly travel guide. Keep answers short."},
]

while True:
    user_text = input("You: ")
    if user_text.lower() in ("quit", "exit"):
        break

    messages.append({"role": "user", "content": user_text})

    response = client.chat.completions.create(
        model="ai103-chat-deploy",
        messages=messages,
        temperature=0.5,
        max_tokens=120,
    )

    assistant_text = response.choices[0].message.content
    print("Bot:", assistant_text)

    messages.append({"role": "assistant", "content": assistant_text})
  1. Run the script and ask "What should I eat in Paris?"
  2. Then ask "And where should I stay?" — the model answers using context from the first exchange.
  3. Type quit to stop the loop.

The conversation history grows with every turn, which also grows the token cost. Production apps cap the history to a sliding window — keeping the newest N messages and dropping the oldest — to control cost and stay inside the model's context window.

Step 4: Enforce a Structured Output

Finish by having the system message force JSON, exactly as you did in the playground but now from Python:

system_json = (
    "You extract flight details into JSON with exactly these fields: "
    'airline, origin, destination, price. '
    "Respond with the JSON object only, no extra text."
)

reply = ask_with_system(
    system_json,
    "Please book the Delta flight from Seattle to Chicago that costs $189.",
)
print(reply)

The output should be a parseable JSON object that your code could feed straight to json.loads():

{"airline": "Delta", "origin": "Seattle",
 "destination": "Chicago", "price": 189}

When parsing model output, wrap json.loads in a try/except and retry once or twice before failing. A tiny formatting slip is common, and a one-line retry handles most of them without showing the user an error.

Summary

You moved the system prompt into Python code, proved how different system messages change the same question, ran a multi-turn conversation that maintains history, and forced structured JSON output from code. The system message is now a first-class part of your program rather than a box in the portal.
