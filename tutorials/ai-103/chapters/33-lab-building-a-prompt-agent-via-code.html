Lab - Building a prompt agent via code

The portal is a great way to explore, but teams manage their agents as code. Defining an agent in code means the agent can be versioned in source control, reviewed in a pull request, and rebuilt reproducibly. In this lab you will build a prompt agent with the Azure AI Projects SDK, registering the same kind of agent you created in the portal — but this time from a Python script.

Objectives

  • Install the Azure AI Projects SDK and prepare the connection to your Foundry project.
  • Define an agent with model, name, and instructions entirely in code.
  • Verify the agent appears in your Foundry project after the script runs.

Prerequisites

You need the same project access as the previous lab, plus Python installed. You will also need the project's connection string, which you can copy from the Foundry portal under your project's settings.

The connection string contains a secret used to reach your project. Treat it like a key: store it in a .env file, never in source control, and never print it to the console.

Step 1: Install the SDK and prepare credentials

Create a project folder, install the required packages, and store the connection string in a .env file.

Set up the environment

mkdir agent-from-code
cd agent-from-code
python -m venv .venv
.venv\Scripts\activate
pip install azure-ai-projects azure-identity python-dotenv

Create a .env file with your project's connection string:

PROJECT_CONNECTION_STRING=YOUR_PROJECT_CONNECTION_STRING

Step 2: Write the agent definition script

The SDK connects to your Foundry project using your Azure credentials, then registers the agent through the project's agent operations. Keep the instructions in the script so the whole definition lives in one place.

Create create_agent.py

import os
from dotenv import load_dotenv
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient

load_dotenv()

project_client = AIProjectClient.from_connection_string(
    credential=DefaultAzureCredential(),
    conn_str=os.getenv("PROJECT_CONNECTION_STRING"),
)

agent = project_client.agents.create_agent(
    model="YOUR_DEPLOYMENT_NAME",
    name="trip-planner",
    description="Helps customers plan day-by-day travel itineraries.",
    instructions=(
        "You are a travel planning assistant for a small agency. "
        "Before recommending anything, ask for the destination, budget, "
        "number of travelers, and preferred dates. Keep answers under "
        "150 words and end with one clarifying question. Never invent "
        "specific hotel or flight prices."
    ),
    temperature=0.5,
)

print(f"Agent created: {agent.id}")
print(f"Agent name: {agent.name}")

Use DefaultAzureCredential when possible. It tries several sign-in methods in order — your Azure CLI login, Visual Studio, and others — which means the same script works in a developer machine and in a CI pipeline with only configuration changes.

Step 3: Run the script and verify

Run the script from the terminal:

python create_agent.py

Then verify the result in two places:

  • The console prints the agent ID and name.
  • In the Foundry portal, open Agents in your project and confirm trip-planner is listed.

Confirm the agent is registered

  1. Open the Microsoft Foundry portal and navigate to your project.
  2. Select Agents in the left navigation.
  3. Find the agent named trip-planner. You may need to refresh the list.
  4. Open it and confirm the instructions you wrote in code appear in the portal editor.

An agent created through code is the same object as one created in the portal. Because everything is stored in the Foundry project, you can switch seamlessly between the portal editor and your codebase — the source of truth is whatever you edit last.

Step 4: Make the definition reproducible

A single script is fine for learning, but a team wants the definition tracked. Save the instruction prompt in a separate plain-text file, for example agent_instructions.txt, and read it into the script. Now the prompt can be reviewed and diffed like any other file.

with open("agent_instructions.txt", encoding="utf-8") as handle:
    instructions = handle.read()

Every time you run this script it creates another agent with the same name. For a lab that is harmless, but in a shared project you will soon end up with duplicate agents. Later in this section you will see how to make registration idempotent by reusing an existing agent or cleaning up after yourself.

Summary

You registered a prompt agent programmatically using the Azure AI Projects SDK: connection first, agent definition second, verification third. The pattern scales — the same script shape works when agents gain tools, file search, or custom functions. In the next chapter you will face the duplication problem directly and make your registration flow safe to run again.
