Lab - Azure AI Text Translation - API Call

In the previous chapter you translated text through the Python SDK. That SDK is really a thin wrapper around the Translator REST API, and in this lab you will call that API directly to see exactly how requests are shaped. Calling the REST endpoint by hand is useful for debugging, for writing integrations in languages without an SDK, and for understanding what the client libraries do for you.

Exercise: Calling the Translator REST API

Step 1 — Gather your request details

Every call needs three pieces of information from your resource:

  • Endpoint — for example https://YOUR-NAME.cognitiveservices.azure.com/
  • Subscription key — sent in the Ocp-Apim-Subscription-Key header
  • Region — sent in the Ocp-Apim-Subscription-Region header

Your key is a credential. Anyone who holds it can use your resource and spend your quota. Treat it like a password: keep it out of shared files, and rotate it if it ever leaks.

Step 2 — Send a translation with curl

Open a terminal and run the following command, replacing the placeholders. The query string names the API version and lists the target languages, while the JSON body holds the text to translate.

curl -X POST "https://YOUR_TRANSLATOR_ENDPOINT/translator/text/v3.0/translate?api-version=3.0&to=es&to=de&to=fr" \
  -H "Ocp-Apim-Subscription-Key: YOUR_TRANSLATOR_KEY" \
  -H "Ocp-Apim-Subscription-Region: YOUR_TRANSLATOR_REGION" \
  -H "Content-Type: application/json" \
  -d '[{"text": "Good morning, the weather is lovely today."}]'

The response is JSON. Each item in the array matches one input text, and the translations array contains one entry per target language. You should also see a detectedLanguage block because no source language was supplied.

Step 3 — Read the response

A typical response looks like this:

[
  {
    "detectedLanguage": { "language": "en", "score": 1.0 },
    "translations": [
      { "text": "Buenos d\u00edas, el clima es hermoso hoy.", "to": "es" },
      { "text": "Guten Morgen, das Wetter ist heute sch\u00f6n.", "to": "de" },
      { "text": "Bonjour, il fait beau aujourd'hui.", "to": "fr" }
    ]
  }
]

Driving the API from Python

You can call the same endpoint from Python with the standard requests library. Install it first with pip install requests, then run this script:

import requests

endpoint = "https://YOUR_TRANSLATOR_ENDPOINT/translator/text/v3.0/translate"
params = {"api-version": "3.0", "to": ["es", "de", "fr"]}
headers = {
    "Ocp-Apim-Subscription-Key": "YOUR_TRANSLATOR_KEY",
    "Ocp-Apim-Subscription-Region": "YOUR_TRANSLATOR_REGION",
    "Content-Type": "application/json",
}
body = [{"text": "Good morning, the weather is lovely today."}]

response = requests.post(endpoint, params=params, headers=headers, json=body)
response.raise_for_status()
data = response.json()
for translation in data[0]["translations"]:
    print(translation["to"], "->", translation["text"])

The requests library encodes the query parameters and JSON body for you, but you still manage the headers and the response parsing yourself — exactly the work the SDK automates.

Supplying a Source Language

When you know the source language, include a from parameter such as &from=en in the query string. This skips the detection step and can make results more consistent for mixed or technical content. When the source is unknown, let the service detect it automatically as you did in Step 2.

Understanding HTTP Status Codes

A successful call returns 200. Common failures include 400 for a malformed request, 401 for a missing or invalid key, and 429 when you exceed the rate limit. When a call fails, inspect the error body — it usually names the exact problem, such as a bad language code or an empty text field.

Summary

You issued a raw REST call to the Translator endpoint with curl, inspected the JSON response, and then recreated the same request from Python with requests. Now that you have seen both layers — SDK and REST — you understand what the client library hides and when it is worth dropping down to the API directly.
