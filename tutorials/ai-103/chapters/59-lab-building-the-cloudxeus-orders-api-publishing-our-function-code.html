Lab - Building the CloudXeus Orders API - Publishing our Function code

Your orders API works on your machine, but an agent in the cloud cannot reach localhost. This lab takes the function app and deploys it to Azure: you create a resource group, a storage account, and a function app, publish the code, and verify the live endpoints respond.

What the Deployment Needs

An Azure Function app is more than a folder of code. It needs a few supporting resources:

ResourceWhy it is required
Resource groupOrganizes all of the related resources in one container
Storage accountHolds function code and runtime state (queues, tables, blobs)
Function appThe hosting plan and configuration that runs your functions

The Azure CLI creates all three for you. Make sure you are signed in before you begin.

az login

You can use the subscription you have been using for the course; check it if you manage more than one:

az account show

Choose Names

Pick a resource group name and a unique function app name. Function app names become part of a public URL, so they must be globally unique. Use a short base such as cloudxeus and add your initials or a number:

$RESOURCE_GROUP = "rg-cloudxeus-orders"
$STORAGE_ACCOUNT = "stcloudxeusorders001"
$FUNCTION_APP = "func-cloudxeus-orders-001"
$LOCATION = "eastus"

Storage account names allow only lowercase letters and digits. Replace stcloudxeusorders001 with something unique to you, because the same names are shared across all Azure customers.

Create the Resources

Exercise — Provision and Publish the Function App

  1. Create the resource group:
az group create --name $RESOURCE_GROUP --location $LOCATION
  1. Create the storage account:
az storage account create --name $STORAGE_ACCOUNT `
  --resource-group $RESOURCE_GROUP `
  --location $LOCATION `
  --sku Standard_LRS
  1. Create the function app on the Consumption plan with the Python runtime:
az functionapp create --name $FUNCTION_APP `
  --resource-group $RESOURCE_GROUP `
  --storage-account $STORAGE_ACCOUNT `
  --consumption-plan-location $LOCATION `
  --runtime python `
  --runtime-version 3.11 `
  --functions-version 4
  1. Publish your local project to the function app:
func azure functionapp publish $FUNCTION_APP

The publish step uploads your code, installs the Python packages from requirements.txt on the remote host, and registers the functions. When it finishes, the output prints the deployed function URLs.

Run the publish command from inside the cloudxeus-orders-api project folder so Core Tools finds function_app.py and your dependencies. Publishing from any other directory deploys an empty app.

Verify the Live Endpoints

Use the deployed URL returned by the publish step. The pattern is:

curl "https://$FUNCTION_APP.azurewebsites.net/api/orders/ORD-1001"
curl "https://$FUNCTION_APP.azurewebsites.net/api/orders?email=ada@example.com"
curl -X POST "https://$FUNCTION_APP.azurewebsites.net/api/orders/ORD-1002/cancel"

You should receive the same JSON responses you saw locally. If a request returns a 404 for a valid order, the first build may still be compiling; wait a moment and retry.

In this lab the functions still use AuthLevel.ANONYMOUS, so anyone with the URL can call them. That is temporary: a later chapter replaces the anonymous access with function keys so the API is usable by your agent and nobody else.

Summary

The orders API is now live in Azure: a resource group, storage account, and Consumption-plan function app were created, your code was published with one command, and the three endpoints respond over the public internet.
