Lab - Retrieval Augmented Generation - Azure Search service

Your documents now sit in Blob Storage. This lab adds the search layer: Azure AI Search, the service that makes those documents findable. You will provision the service, check its search capabilities, and define the index that will hold the retrieved content in the next lab.

What Azure AI Search Provides

Azure AI Search is a managed search service that supports the retrieval half of RAG. It stores your indexed content and answers similarity queries against it. For a RAG pipeline you care about two capabilities:

  • Vector search: finding documents by semantic similarity using embeddings.
  • Keyword (lexical) search: exact term matching for names, codes, and numbers.

Combining both, with a semantic ranker to reorder results, is the most reliable retrieval setup for RAG.

Step 1: Create the Search Service

Exercise 1: Provision Azure AI Search

Continue in the same resource group from the previous lab and run:

az search service create \
  --name "ai103-rag-search" \
  --resource-group "ai103-rag-rg" \
  --location "eastus" \
  --sku basic

Note two things from the output: the service endpoint (something like https://ai103-rag-search.search.windows.net) and the admin key you can fetch next:

az search admin-key show \
  --service-name "ai103-rag-search" \
  --resource-group "ai103-rag-rg" \
  --query primaryKey

Record the endpoint and key — the index and indexer in the following labs need them.

If the basic tier is unavailable in your region, try a different region or use the free tier if your subscription qualifies. Basic and free both support vector and semantic search, which is all this course needs.

Step 2: Confirm Semantic Search Is Available

Semantic search on Azure AI Search works by attaching a semantic configuration to an index, naming which fields hold the title and content. It also requires the service tier to support the feature. Verify your tier supports it:

az resource show \
  --ids "/subscriptions/YOUR_SUBSCRIPTION_ID/resourceGroups/ai103-rag-rg/providers/Microsoft.Search/searchServices/ai103-rag-search" \
  --query "properties.semanticSearch"

A value of free or standard means semantic ranking is enabled. An empty value means the tier does not support it — in that case the labs still work with keyword and vector search alone.

Step 3: Define the Index

An index is the schema of your searchable content. For the documents in the next lab, a useful index declares fields for the source file, the chunked text, and the vector embedding:

Exercise 2: Review the index schema

Create index.json in your lab folder. This is the document the next lab will submit to the search service:

{
  "name": "rag-index",
  "fields": [
    {"name": "id", "type": "Edm.String", "key": true, "searchable": false},
    {"name": "content", "type": "Edm.String", "searchable": true, "retrievable": true},
    {"name": "title", "type": "Edm.String", "searchable": true, "retrievable": true},
    {"name": "metadata_storage_name", "type": "Edm.String", "searchable": true, "retrievable": true},
    {"name": "content_vector", "type": "Collection(Edm.Single)", "searchable": true,
     "dimensions": 1536, "vectorSearchProfile": "rag-profile"}
  ],
  "vectorSearch": {
    "algorithms": [
      {"name": "rag-hnsw", "kind": "hnsw",
       "hnswParameters": {"metric": "cosine"}}
    ],
    "profiles": [
      {"name": "rag-profile", "algorithm": "rag-hnsw"}
    ]
  }
}

The important pieces: id is the document key, content holds the chunked text, content_vector holds a 1536-dimension embedding (the size produced by many embedding models), and the HNSW profile configures vector similarity search.

The vector dimension must match the embedding model you use. If you plan to embed with a model that returns a different vector size — some return 3072 — adjust dimensions accordingly. An index created with the wrong dimension will reject the documents you try to push into it.

Step 4: Create the Index from the Command Line

Submit the schema to the service. Azure AI Search uses its own REST API, so the call is a PUT request with an admin key in the header:

curl -X PUT "https://ai103-rag-search.search.windows.net/indexes/rag-index?api-version=2023-11-01" \
  -H "Content-Type: application/json" \
  -H "api-key: YOUR_SEARCH_ADMIN_KEY" \
  --data "@index.json"

On Windows PowerShell, curl is an alias for Invoke-WebRequest in older versions. If you get a parse error, use curl.exe explicitly or run the command from a bash terminal.

The index is just a schema — creating it costs nothing and stores nothing yet. Recreating it later is cheap and is actually the normal way to fix a schema mistake, so do not be shy about deleting and re-creating the index as you iterate.

Summary

You provisioned an Azure AI Search service, verified that semantic search is enabled, and defined the rag-index schema with text, metadata, and vector fields. The search service now exists as an empty container ready to be filled. In the next lab you will connect it to your Blob Storage container and run the indexing job that populates it.
