Review on model deployment

This review chapter tests your understanding of everything covered so far: the difference between a model and a deployment, the settings you choose when deploying, billing and quota, and how applications talk to a deployed endpoint. Try to answer each question from memory before checking the answer key at the bottom.

Questions

Question 1

Which of the following best describes what a deployment is?

A. The training run that produced the model's weights
B. A running instance of a model, bound to computing capacity at an endpoint
C. A copy of the model stored in the model catalog
D. A dataset used to evaluate the model

Correct answer: B.

Question 2

Your application code references a deployment by a name. What happens if you point that deployment at a new version of the same model?

A. Your application breaks because the endpoint changes.
B. You must redeploy and update every caller.
C. Your application keeps working unchanged, now served by the new version.
D. The old deployment is deleted automatically.

Correct answer: C.

Question 3

Which scenario is the best fit for provisioned capacity rather than pay-as-you-go?

A. A prototype that receives a few test requests
B. A production feature with steady, predictable, high-volume traffic
C. A one-off batch of ten documents
D. A student lab running for a single afternoon

Correct answer: B.

Question 4

Your deployment fails with a quota error. Which action is most likely to resolve it?

A. Restarting the Azure portal
B. Increasing the temperature setting
C. Requesting a quota increase or deploying in a region with available capacity
D. Calling the endpoint more slowly

Correct answer: C.

Question 5

In a chat completion response, what does finish_reason equal when the model reached the maximum output length?

A. stop
B. length
C. filter
D. error

Correct answer: B.

Question 6

Where in a chat completion response can you find the token counts used to calculate your cost?

A. In the usage block
B. In the system message
C. In the HTTP response headers only
D. Token counts are not returned

Correct answer: A.

Question 7

What is the difference between fine-tuning a model and deploying it?

A. They are the same operation with different names.
B. Deployment trains on your data; fine-tuning serves the model as-is.
C. Fine-tuning trains the model on your data first; deployment then serves the result as an endpoint.
D. Fine-tuning only works for image models.

Correct answer: C.

Question 8

Why is the deployment name chosen by the developer rather than taken from the model name?

A. So the model publisher can change it remotely
B. So application code can remain stable while the underlying model or version changes
C. So the name never needs to be unique
D. So billing is separated by model

Correct answer: B.

Summary

This review checked your understanding of the deployment lifecycle: what a deployment is, the choices you make when creating one, how billing and quota work, and how responses carry the information your code needs. If you missed any questions, re-read the model deployment chapters before moving on. In the next chapter you will learn how to debug deployments when things go wrong.
