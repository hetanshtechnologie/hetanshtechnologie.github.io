Lab - Creating a Microsoft Foundry Resource

In this lab you will provision a Microsoft Foundry resource in your Azure subscription — the cloud home for every model, project, and deployment you build for the rest of this course. A Foundry resource is the container that holds your Azure AI projects, model deployments, fine-tuned models, and evaluation runs. By the end of the lab you will have a working resource, know where to find its endpoint and keys, and understand the choices you made while creating it.

Prerequisites

Before you begin, confirm you have the following:

  • An active Azure account. If you do not have one yet, complete the next chapter on creating an Azure free account first.
  • A subscription you are allowed to create resources in. Your free account creates one automatically.
  • Permission to create resources in that subscription. On a personal account this is always true; on a corporate account you may need the Contributor role from an administrator.
  • A stable internet connection and a modern browser for the Azure portal.

Creating a Microsoft Foundry resource itself does not incur charges. Costs begin when you deploy models, run evaluations, or consume paid inference. Everything in this lab is free to create, so do not worry about surprise bills while you are learning.

What the Resource Provides

A Microsoft Foundry resource is a regional, top-level container in Azure. Inside it you can create one or more projects, and each project organizes a unit of work — the models you deploy, the data you connect, the evaluations you run, and the connections to supporting services. Think of the resource as your organization's AI workspace and the project as a specific application or team's sandbox within it.

Creating the resource also gives you an endpoint URL and a set of keys. Applications authenticate against that endpoint when they call the models you deploy. Some Azure AI resources reuse a single key-and-endpoint pair across everything inside them, which is why keeping those values secret and rotating them regularly is important.

Step-by-Step: Create the Resource in the Portal

Exercise 1: Create a Foundry resource through the Azure portal

  1. Open a browser and go to the Azure portal at https://portal.azure.com. Sign in with the account that owns your subscription.
  2. Use the search bar at the top of the page and type Foundry. Select AI Foundry from the results, then click Create.
  3. Choose your subscription from the dropdown, then create a new resource group or select an existing one. A resource group is a logical folder that keeps related resources together. Give it a meaningful name such as rg-ai103-rg.
  4. Give the resource a globally unique name, for example ai103-workspace-<yourname>. Only letters, numbers, and hyphens are allowed.
  5. Pick a region that is close to you. Keep in mind that not every region hosts every model; if you later cannot find a model, switching regions is often the fix.
  6. Choose the pricing tier. For this course the free tier or the lowest standard tier is sufficient. You can upgrade later without recreating the resource.
  7. Review your selections and click Review + create, then Create. Azure validates your configuration and deploys the resource. The deployment usually takes less than a minute.
  8. When the deployment finishes, click Go to resource. You should see the resource overview page with an Explore AI Foundry or Launch studio button that opens the web portal where you manage projects and models.

The region you choose matters more than most other settings. Model availability varies by region, so if you are building for production, check that the models you plan to use are offered in the region you select before you commit.

Create the Resource with Azure CLI

If you prefer automation or you are setting up several environments, the Azure CLI is a faster and repeatable way to create the same resource. First sign in, then create the resource group and the Foundry resource with two commands.

# Sign in to Azure
az login

# Create a resource group (adjust the region if needed)
az group create --name rg-ai103-rg --location eastus

# Create the Microsoft Foundry resource
az cognitiveservices account create --resource-group rg-ai103-rg \
  --name ai103-workspace-demo \
  --kind AIServices \
  --sku F0 \
  --location eastus

The --kind AIServices value creates the multi-service resource that Microsoft Foundry uses. The --sku F0 value requests the free tier where available. After the command completes, fetch the endpoint and keys that your code will need later:

# List endpoints for the resource
az cognitiveservices account show --resource-group rg-ai103-rg \
  --name ai103-workspace-demo --query "properties.endpoint"

# Show the access keys
az cognitiveservices account keys list --resource-group rg-ai103-rg \
  --name ai103-workspace-demo --query "[key1, key2]"

Verify the Resource Is Working

Do not move on until you can confirm the resource answers requests. A quick check saves you from debugging connection problems later:

  • In the Azure portal, navigate to your resource and open the Keys and Endpoint page. Note the endpoint URL and both key values.
  • Open the Microsoft Foundry web portal from the resource overview and confirm you can sign in and see an empty project list or a welcome screen.
  • Optionally run a health check with a simple API request using your endpoint and key. The example below lists the deployed models in your resource:
curl -H "Api-Key: YOUR_KEY" \
  "https://YOUR_ENDPOINT/models?api-version=2024-02-01"

If you see an empty JSON array [] in the response, the resource is working correctly — it simply has no model deployments yet. Deploying models is the subject of the model deployment lab later in the course.

Clean Up When You Are Done

Leaving resources around is harmless while they are free, but a tidy subscription is easier to manage and audit. When you no longer need this resource, delete the whole resource group to remove everything inside it in one step:

az group delete --name rg-ai103-rg --yes --no-wait

Deleting a resource group deletes every resource inside it permanently. Only delete the resource group when you are certain you no longer need any of its contents. There is no undo for this operation.

Summary

In this lab you created a Microsoft Foundry resource using both the Azure portal and the Azure CLI, retrieved its endpoint and keys, verified it responds to API requests, and learned how to remove it when finished. The resource is your gateway to every model deployment in this course. In the next chapter you will compare large language models with small language models and learn how to choose between them.
