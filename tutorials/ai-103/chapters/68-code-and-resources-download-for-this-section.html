Code and resources download for this section

Every lab in this section built on a small set of files: the Python function app, its configuration, the OpenAPI document, and a few test scripts. Rather than retyping them, you can download the finished resources for this section and use them as a starting point. This chapter explains what the download contains and how to make it run with your own names and keys.

What Is in the Download

The resources for this section are a single ZIP file containing the orders API project and the tooling around it:

FileWhat it provides
function_app.pyThe three HTTP functions for the orders API
requirements.txtThe Python packages the function app needs
host.jsonRuntime configuration for the function host
local.settings.jsonLocal settings template for running and publishing
cloudxeus-orders-api.openapi.jsonThe OpenAPI spec for the orders API
test_orders.ps1A PowerShell script that exercises all three endpoints
README.mdQuick-start notes for the section

Downloading and Extracting

  1. Download the ZIP file for this section from the course download page.
  2. Extract it into a folder named cloudxeus-orders-api.
  3. Open that folder in VS Code with File > Open Folder.

Set Up the Project Folder

After extraction, your folder should look like this:

cloudxeus-orders-api/
  function_app.py
  requirements.txt
  host.json
  local.settings.json
  cloudxeus-orders-api.openapi.json
  test_orders.ps1
  README.md

Install the Python dependencies in this folder's terminal so the functions can run locally:

pip install -r requirements.txt

Replace the Placeholders

Before publishing, search the files for these placeholders and replace them with your own values:

PlaceholderReplace with
YOUR_FUNCTION_APPYour globally unique function app name
YOUR_RESOURCE_GROUPThe resource group you created
YOUR_STORAGE_ACCOUNTYour storage account name
YOUR_FUNCTION_KEYThe function key used in the connection and tests

Treat local.settings.json and any file that holds a key as sensitive. Add them to your .gitignore if you push the project to a repository, and never commit real keys.

Run the Full Loop

With the placeholders filled in, the standard flow is:

func start

In a second terminal, run the test script against the local host:

.\test_orders.ps1 -BaseUrl "http://localhost:7071/api"

Once everything passes locally, publish and repeat the tests against the public URL:

func azure functionapp publish YOUR_FUNCTION_APP

If you prefer to type the code by hand, the lab chapters contain the same files verbatim. Typing them is a better way to learn the v2 model, but the download saves time when you want to redo the section quickly.

Summary

The section download gathers the complete orders API project, the OpenAPI spec, and a test script into one folder. After installing dependencies and replacing the four placeholders, the full loop from local testing through publishing works exactly as the labs described.
