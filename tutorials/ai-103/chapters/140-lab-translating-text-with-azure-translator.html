Lab - Translating Text with Azure Translator

Azure Translator is the dedicated translation service in the Azure AI family. Where the chat-model lab translated by prompting, Translator is a purpose-built REST API tuned on massive amounts of parallel text — fast, cheap at scale, and supporting dozens of languages. In this lab you will translate text with HTTP requests, handle multi-language and multi-target calls, and compare the service with the prompt-based approach you built earlier.

Prerequisites

  • An Azure Translator resource with its key and region. You can create it in the portal, or create a single-service resource named Translator in your resource group.
  • Python with the httpx (or requests) library installed:
pip install httpx python-dotenv

Step 1: Make Your First Translation Call

Exercise 1: Translate one sentence with a REST call

Create translator.py:

import os

import httpx
from dotenv import load_dotenv

load_dotenv()

KEY = os.getenv("AZURE_TRANSLATOR_KEY")
REGION = os.getenv("AZURE_TRANSLATOR_REGION")
ENDPOINT = os.getenv(
    "AZURE_TRANSLATOR_ENDPOINT",
    "https://api.cognitive.microsofttranslator.com",
)


def translate(text: str, to: list[str]) -> list[dict]:
    url = f"{ENDPOINT}/translate?api-version=3.0" + "".join(
        f"&to={lang}" for lang in to
    )
    headers = {
        "Ocp-Apim-Subscription-Key": KEY,
        "Ocp-Apim-Subscription-Region": REGION,
        "Content-Type": "application/json",
    }
    response = httpx.post(url, headers=headers, json=[{"text": text}])
    response.raise_for_status()
    return response.json()


result = translate(
    "The inspection drone maps pipe surfaces before corrosion becomes critical.",
    ["de", "fr", "ja"],
)
for entry in result[0]["translations"]:
    print(f"{entry['to']}: {entry['text']}")
  1. Run the script. You should see German, French, and Japanese translations, one per target language.
  2. Note the structure of the response: a list of entries (one per input text), each holding a translations list keyed by the to code.

Three key details make Translator calls work: the resource key in the Ocp-Apim-Subscription-Key header, the resource region in the Ocp-Apim-Subscription-Region header (required for the multi-service regional pricing and for access in your region), and the request body as a JSON array of {"text": ...} objects.

Step 2: Translate a Batch of Texts

Exercise 2: One call, several inputs

Send multiple source strings in a single request:

batch_texts = [
    "The sensor array reports every 30 seconds.",
    "Alerts are grouped by severity on the dashboard.",
    "Operators can acknowledge alarms with one click.",
]

batch_url = f"{ENDPOINT}/translate?api-version=3.0&to=es"
headers = {
    "Ocp-Apim-Subscription-Key": KEY,
    "Ocp-Apim-Subscription-Region": REGION,
    "Content-Type": "application/json",
}
response = httpx.post(
    batch_url,
    headers=headers,
    json=[{"text": t} for t in batch_texts],
)
response.raise_for_status()
for i, entry in enumerate(response.json(), start=1):
    print(f"{i}: {entry['translations'][0]['text']}")
  1. Run the script. The service returns one entry per input, in the same order — no interleaving, no prompt parsing.
  2. Batching also cuts request overhead: one HTTP round trip replaces three.

Step 3: Detect the Source Language Automatically

Exercise 3: Let Translator guess the source

Omit the from parameter and ask for a detected-language response:

auto_url = (
    f"{ENDPOINT}/translate?api-version=3.0&to=en"
    "&includeSentenceLength=false"
)
mixed = ["Bonjour, comment allez-vous ?", "Guten Morgen", "おはようございます"]
response = httpx.post(
    auto_url,
    headers=headers,
    json=[{"text": t} for t in mixed],
)
response.raise_for_status()
for entry in response.json():
    detected = entry.get("detectedLanguage", {})
    print(f"{detected.get('language', '?')} -> {entry['translations'][0]['text']}")
  1. Run the script. Each input is auto-detected (French, German, Japanese) and translated to English.
  2. Ask for the confidence score by adding includeAlignment or by sending a very short, ambiguous string — a single word like "love" — and observe the detected-language confidence vary.

Step 4: Compare with the Chat-Model Translation

Translate the same sentence three ways — with the chat model from the translation-prompting lab, with Translator in one target language, and with Translator in several targets — and compare them on the axes that matter in production:

AspectChat-model promptingAzure Translator
Register and audienceControllable via promptNot offered; one faithful version
BillingPer token (input + output)Per character translated
Response shapeProse you must parse or constrainFixed JSON with one entry per input
Multiple targetsOne target per prompt (or repeat)Many to parameters in one call
Best forAdaptive, styled, low-volume workBulk, multi-language, high-volume work

A common production pattern is a hybrid: Translator handles the bulk throughput at low cost, while a chat model is reserved for the small subset of content that needs an audience-specific or branded translation.

Step 5: Handle Errors

  • 401 Unauthorized: the key header is missing or wrong.
  • 403 or 400 with quota messages: the resource is out of quota or the region header is missing — a very common first-time mistake.
  • 400 on language codes: the to value is not a valid language code; validate codes against the supported-language endpoint before batch runs.
# List supported languages (no key required)
lang_url = f"{ENDPOINT}/languages?api-version=3.0&scope=translation"
lang_response = httpx.get(lang_url)
lang_response.raise_for_status()
print(list(lang_response.json()["translation"].keys())[:10], "...")

Summary

You translated text with the Azure Translator REST API, sent batches and multiple target languages in single calls, used automatic source-language detection, and compared the service with prompt-based translation on cost, shape, and flexibility. Translator is the high-volume complement to the chat model's adaptive translation — and a fine close to this text-analysis section.
