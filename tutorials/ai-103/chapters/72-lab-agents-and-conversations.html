Lab - Agents and Conversations

In this lab you will create an agent and study how it behaves across multiple turns of a conversation. You will see firsthand the difference between a stateless model call and an agent that keeps conversation history, and you will prove that — without any memory features enabled — the agent can only "remember" what appears in the message history you send it. This lab sets the foundation for the next chapter, where you will add persistent memory.

Objectives

  • Create a prompt agent in the Microsoft Foundry portal.
  • Carry out a multi-turn conversation in the agent playground.
  • Inspect how conversation history is passed to the model with each turn.
  • Call the same model from Python while managing history manually.

Prerequisites

  • A Microsoft Foundry project where you have contributor access.
  • At least one deployed chat model, such as gpt-4o or gpt-4o-mini.
  • Python 3.9 or newer with the openai package installed.
  • Your endpoint URL and key available as environment variables.

Step 1: Create the Agent

Start in the Foundry portal, inside your project.

Create a prompt agent

  1. From the left menu, open Agents.
  2. Click Create and choose Prompt agent.
  3. Name the agent convo-demo and select your deployed chat model.
  4. Paste the following instructions and save:
You are a helpful assistant. Keep answers short. If the user
mentions their name or a preference, acknowledge it. Ask one
clarifying question when a request is ambiguous.

Step 2: Have a Multi-Turn Conversation

Open the chat panel for your new agent and run a conversation that depends on earlier turns:

Chat across several turns

  1. Send: My name is Alex and I prefer vegetarian meals.
  2. Send: What was my name again? — the agent answers correctly because the earlier turns are part of the conversation history.
  3. Send: Suggest a dinner. — the agent should respect the vegetarian preference stated in turn one.
  4. Send: Actually, I no longer eat vegetarian food. — note how the follow-up answers now reflect the change.

Inside the playground, history is managed for you. Every message you send is appended to the conversation, and the full transcript is included in each model call. The agent is not remembering anything — it is simply re-reading the transcript each turn. That distinction is the entire point of this lab.

Step 3: Watch What Happens When History Is Dropped

Now start a new conversation in the playground (use the New conversation button) and send What was my name? first. The agent has no idea, because the previous conversation was never persisted — it existed only inside the old chat session.

This is the fundamental limitation of conversation-only memory. It works beautifully within a session and evaporates the moment the session ends. Persisting facts beyond the session requires a memory store, which is the topic of the next chapter.

Step 4: Manage Conversation History from Python

When you build real applications you own the history yourself. The pattern is simple: keep a list of messages, append the user's turn, send the whole list to the model, and append the model's reply. Create a file chat_history.py with the following code:

from openai import AzureOpenAI
import os

client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2025-01-01-preview",
)

history = [
    {"role": "system", "content": "Keep answers short."},
    {"role": "user", "content": "My name is Alex and I prefer vegetarian meals."},
]

response = client.chat.completions.create(
    model="YOUR_DEPLOYMENT_NAME",
    messages=history,
)
reply = response.choices[0].message.content
print("Assistant:", reply)

history.append({"role": "assistant", "content": reply})
history.append({"role": "user", "content": "What was my name?"})

response = client.chat.completions.create(
    model="YOUR_DEPLOYMENT_NAME",
    messages=history,
)
print("Assistant:", response.choices[0].message.content)

Run the script

  1. Replace YOUR_DEPLOYMENT_NAME with your model deployment's name.
  2. Confirm your endpoint and key are set in the environment variables AZURE_OPENAI_ENDPOINT and AZURE_OPENAI_KEY.
  3. Run the script. The second answer should correctly recall the name "Alex" because the full transcript was included in the call.
  4. Comment out the line that appends the assistant reply, re-run, and observe the behavior change — the model only sees what you deliberately put into history.

Note that this manual history is still session-scoped. If you restart the script, the name is forgotten again. Moving that transcript — or the important facts inside it — into durable storage is exactly what memory stores do.

Summary

You created an agent, verified that multi-turn behavior inside a session comes from re-reading the transcript, and confirmed that closing the session erases everything. You also reproduced the same conversation from Python by managing the message list yourself. The gap you observed — forgetting across sessions — is precisely the gap that persistent memory stores fill in the next lab.
