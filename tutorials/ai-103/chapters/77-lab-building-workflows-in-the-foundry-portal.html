Lab - Building Workflows in the Foundry Portal

With IntakeAgent and ResolverAgent created in the previous lab, you are ready to assemble them into an actual workflow. In this lab you will build a workflow in the Foundry portal that captures a customer message, lets IntakeAgent summarize it, hands the summary to ResolverAgent, and returns the draft reply. This is the first workflow you have built, and it introduces the node canvas and the way data flows between steps.

Objectives

  • Create a new workflow in the Foundry portal.
  • Add input, agent, and output nodes to the canvas.
  • Connect nodes so data flows from the customer message to the final reply.
  • Run the workflow with a sample message and inspect the results.

Prerequisites

  • IntakeAgent and ResolverAgent with published versions from the previous lab.
  • Contributor access to your Foundry project.

Step 1: Create the Workflow

Start a new workflow

  1. In your Foundry project, open the Workflows section from the left menu.
  2. Click Create and choose a blank workflow.
  3. Name it intake-pipeline.
  4. An empty canvas opens with a toolbar of node types on the side.

The canvas is your flowchart editor. You drag nodes onto it and connect them with edges. Each edge carries the output of the source node into the target node, and the target node can reference that data in its settings.

Step 2: Add the Input Node

The workflow needs an entry point that receives the customer message from whoever triggers it.

Configure the input

  1. Drag an Input node onto the canvas.
  2. Open its settings and add a field named customer_message of type string.
  3. Add a description so callers know what to provide: "The raw message sent by the customer."
  4. Mark the field as required.

Step 3: Add the IntakeAgent Node

Connect IntakeAgent to the input

  1. Drag an Agent node onto the canvas.
  2. In its settings, select the IntakeAgent version you published.
  3. Draw an edge from the Input node to the Agent node.
  4. Map the input so the customer message is passed as the agent's user input. In the agent node's settings, set the user message to $\{inputs.customer_message} or use the field-mapping picker to bind the workflow input to the agent prompt.

Foundry uses placeholder expressions in the shape $\{path.to.data} to reference earlier outputs. When in doubt, use the picker: select the source node, then the field, and the portal fills the expression for you.

Step 4: Add the ResolverAgent Node

ResolverAgent needs both the original message and IntakeAgent's summary to write a good reply.

Connect ResolverAgent

  1. Drag a second Agent node onto the canvas and select the ResolverAgent version.
  2. Draw an edge from the IntakeAgent node to the ResolverAgent node.
  3. In ResolverAgent's settings, compose its user message from both sources, for example:
Original customer message:
$\{inputs.customer_message}

Intake summary:
$\{nodes.intake_agent.output}

The exact node identifier for IntakeAgent may be shown as its workflow node name, such as nodes.<agent_node_name>. Use the portal's expression picker to insert the correct path instead of guessing it.

Step 5: Add the Output Node

Expose the results

  1. Drag an Output node onto the canvas.
  2. Add an output field named intake_summary and bind it to IntakeAgent's output.
  3. Add an output field named draft_reply and bind it to ResolverAgent's output.
  4. Draw edges from both agent nodes into the Output node.
  5. Save the workflow.

Check every edge and binding before running. The most common first-time mistakes are an edge that was never drawn, and a binding that points at the wrong node. The canvas shows unresolved bindings with a warning icon — do not ignore it.

Step 6: Run the Workflow

Test the pipeline end to end

  1. Click Run on the workflow editor.
  2. Provide a test value for customer_message, for example:
Hi, our blob storage account is showing a 403 error since this
morning. We cannot upload our daily backups. Account BA-44590,
not urgent but we do need help by end of day. - Sam.
  1. Start the run and watch each node execute in turn.
  2. When the run completes, open the run details and inspect the outputs: intake_summary should be a clean summary, and draft_reply should be a professional follow-up that reflects the summary.
  3. If the reply reads oddly, review the binding on the ResolverAgent node first — it is the one most likely to have been misconfigured.

Each run records per-node duration and status. Use the run history to see which step consumed the most time and tokens — usually the agent nodes — and to compare how output quality changes after you refine instructions.

Summary

You built your first workflow in the Foundry portal: an input node feeds a customer message into IntakeAgent, whose summary flows into ResolverAgent, and both outputs are exposed through an output node. You ran the pipeline with a realistic message and verified the results. The next labs will tighten this pipeline: capturing IntakeAgent's output as structured data, and adding conditional routing.
