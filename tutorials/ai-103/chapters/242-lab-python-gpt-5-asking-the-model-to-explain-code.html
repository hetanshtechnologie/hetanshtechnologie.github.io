Lab - Python - GPT 5- Asking the model to explain code

Large language models are trained on enormous amounts of source code, which makes them surprisingly good at reading it back to you. In this lab you will treat the model as a code explainer: you will feed it functions and snippets, ask for plain-English explanations, and use prompts to control how deep and how structured the explanation is.

Why Ask a Model to Explain Code

Code explanation is one of the most practical everyday uses of a chat model. It helps in several situations:

  • You inherit a project and need to understand a function quickly.
  • A colleague wrote something terse and you want it restated in plain words.
  • You are reviewing a snippet and want a second opinion on what it does.
  • You are learning a new language or library and need the idioms explained.

The model is not a substitute for reading code, but it compresses the time to first understanding dramatically — as long as you ask it well.

Designing a Good Explainer Prompt

Raw code dump, vague question: the model will answer, but the answer is hit-or-miss. Add structure to the request and you get reliable, consistent explanations. A strong explainer prompt specifies:

  • The audience: beginner, intermediate, or expert.
  • The output shape: bullet points, a paragraph, or a line-by-line walkthrough.
  • The focus: overall purpose, specific lines, or hidden pitfalls.

Put the explainer role and rules in a system message, then place the code in the user message. Keeping code out of the system prompt means the instructions stay stable while the code changes freely between requests.

Step 1: Explain a Simple Function

Exercise 1: Explain a small function

  1. Create a folder named ai103-lab242 and open it in VS Code.
  2. Create explain.py and set your environment variables:
$env:AZURE_OPENAI_ENDPOINT = "https://YOUR-RESOURCE.openai.azure.com/"
$env:AZURE_OPENAI_KEY = "YOUR_KEY"
  1. Paste this script and replace YOUR_DEPLOYMENT_NAME with your chat deployment:
import os
from openai import AzureOpenAI

client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2025-01-01-preview",
)

code = """
def group_by(items, key):
    result = {}
    for item in items:
        k = item[key]
        result.setdefault(k, []).append(item)
    return result
"""

messages = [
    {
        "role": "system",
        "content": (
            "You are a patient senior developer who explains code to a "
            "junior colleague. Explain the purpose first, then describe "
            "what each line does. Use plain language and avoid jargon."
        ),
    },
    {"role": "user", "content": f"Please explain this function:\n\n{code}"},
]

response = client.chat.completions.create(
    model="YOUR_DEPLOYMENT_NAME",
    messages=messages,
)

print(response.choices[0].message.content)
  1. Run the script:
python explain.py

You should get a purpose-first explanation. Notice that the answer also touches on why setdefault is used — the model explains intent, not just syntax.

Step 2: Control the Level of Detail

The same snippet can produce a one-line summary or a line-by-line lecture depending on the instructions. This control is what makes the system prompt so valuable.

Exercise 2: Ask for a line-by-line walkthrough

Create walkthrough.py. Reuse the same code string but change the system message:

messages = [
    {
        "role": "system",
        "content": (
            "You explain code line by line. For each line, quote it and then "
            "explain what it does and why it is needed. Start with a single "
            "sentence that states the overall purpose of the function."
        ),
    },
    {"role": "user", "content": f"Walk me through this function:\n\n{code}"},
]

response = client.chat.completions.create(
    model="YOUR_DEPLOYMENT_NAME",
    messages=messages,
)

print(response.choices[0].message.content)

python walkthrough.py

Compare the two outputs side by side. The request stayed almost identical; only the system instructions changed, and the response changed with them.

Step 3: Explain a Snippet That Has a Bug

Explaining code is also a quick debugging sanity check. Ask the model to explain a snippet that contains a subtle bug — its explanation often reveals the flaw because the model has to reason about what the code actually does.

Exercise 3: Find the bug through explanation

Create find_bug.py and pass this function, which intends to sum a list of numbers:

buggy_code = """
def total(values):
    total = 0
    for v in values:
        total = v
    return total
"""

messages = [
    {
        "role": "system",
        "content": (
            "You are a code reviewer. Explain what this function does, "
            "then point out any behavior that does not match its apparent "
            "intent, and suggest a corrected version."
        ),
    },
    {"role": "user", "content": f"Review this function:\n\n{buggy_code}"},
]

response = client.chat.completions.create(
    model="YOUR_DEPLOYMENT_NAME",
    messages=messages,
)

print(response.choices[0].message.content)

python find_bug.py

The model should identify that total = v overwrites the accumulator instead of adding to it.

The model's explanation can be confidently wrong, especially for obscure or very new APIs. Treat explanations as a fast first draft and verify with the documentation or a quick test — never paste generated code into production without understanding it yourself.

Summary

You used a chat model as a code explainer in three ways: a purpose-first explanation of a simple function, a line-by-line walkthrough driven by the system prompt, and a review of a buggy snippet that revealed its flaw. The key skill is prompt control — the same code produces different depths of explanation depending on the instructions.
