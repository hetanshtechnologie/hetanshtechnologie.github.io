Lab - Retrieval Augmented Generation - Searching the index from Python

The index now holds all the CloudXeus chunks and their vectors. This lab shows how to query it from Python: plain keyword search, vector search, and the hybrid combination that most RAG systems rely on. You will also learn to read the score that tells you how strongly each chunk matched.

The Three Search Modes

  • Keyword search matches the query terms against the text fields and scores by relevance. Great for exact names and codes.
  • Vector search embeds the query and returns chunks whose embeddings are nearest. Great when the question uses different words than the document.
  • Hybrid search runs both and merges the results. This is the usual default for RAG.

Set Up the Search Client

import os
from azure.core.credentials import AzureKeyCredential
from azure.search.documents import SearchClient
from azure.search.documents.models import RawVectorQuery
from openai import AzureOpenAI

SEARCH_ENDPOINT = os.getenv("SEARCH_ENDPOINT", "https://YOUR_SEARCH_ENDPOINT.search.windows.net")
SEARCH_KEY = os.getenv("SEARCH_KEY", "YOUR_SEARCH_ADMIN_KEY")
INDEX_NAME = "cloudxeus-docs"

client = SearchClient(SEARCH_ENDPOINT, INDEX_NAME, AzureKeyCredential(SEARCH_KEY))

embedding_client = AzureOpenAI(
    api_key=os.getenv("AZURE_OPENAI_KEY", "YOUR_KEY"),
    azure_endpoint=os.getenv("AZURE_OPENAI_ENDPOINT", "YOUR_ENDPOINT"),
    api_version="2024-06-01",
)
EMBEDDING_DEPLOYMENT = "text-embedding-3-small"

def embed_query(text: str) -> list[float]:
    response = embedding_client.embeddings.create(model=EMBEDDING_DEPLOYMENT, input=text)
    return response.data[0].embedding

Keyword Search

def keyword_search(query: str, top: int = 3):
    results = client.search(search_text=query, top=top)
    for r in results:
        print(r["score"], "-", r["title"], "-", r["content"][:120], "...")

Vector Search

Vector search builds a RawVectorQuery from the query embedding and asks the service to compare it against the stored content_vector field:

def vector_search(query: str, top: int = 3):
    vector_query = RawVectorQuery(vector=embed_query(query), k=top, fields="content_vector")
    results = client.search(search_text=None, vector_queries=[vector_query], top=top)
    for r in results:
        print(r["score"], "-", r["title"], "-", r["content"][:120], "...")

The same embedding model must produce both the stored vectors and the query vector. Mixing models corrupts the similarity comparison, so keep EMBEDDING_DEPLOYMENT identical to the one used during indexing.

Hybrid Search

Hybrid search supplies both the keyword text and the vector query in one request, and the service fuses the two result sets:

def hybrid_search(query: str, top: int = 3):
    vector_query = RawVectorQuery(vector=embed_query(query), k=top, fields="content_vector")
    results = client.search(search_text=query, vector_queries=[vector_query], top=top)
    for r in results:
        print(r["score"], "-", r["title"], "-", r["content"][:120], "...")

Reading the Results

Every result has a score and the retrievable fields: title, source, and content. The score measures match strength; higher is better, but scores are only comparable within a single query, not across queries.

Two tuning knobs matter most:

  • top: how many chunks you return. Three to five is a common default for feeding an LLM.
  • Filters: you can narrow results, for example to one product or document family, using the filterable fields like source.

Summary

You can now query the CloudXeus index three ways. Keyword search handles exact terms, vector search captures meaning, and hybrid search combines both. Retrieval is the heart of RAG, so the next lab plugs this search into a chat model to build the full retrieve-and-answer loop.
