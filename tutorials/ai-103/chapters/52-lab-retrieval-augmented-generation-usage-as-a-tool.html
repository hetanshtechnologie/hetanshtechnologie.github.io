Lab - Retrieval Augmented Generation - Usage as a tool

So far the RAG assistant answers a single question end to end. In a real product, retrieval is one capability among many: the model should decide when a question needs the knowledge base and when it needs a different tool or just a conversation. This lab wraps the CloudXeus retrieval into a callable tool and teaches the chat model to invoke it through function tool calling, turning your RAG pipeline into a reusable component of a larger agent.

From Function to Tool

Function tool calling works by declaring a JSON schema that describes the function. The model reads the schema, decides the call is needed, and returns a structured request. Your code performs the actual search and sends the results back as a tool message.

The Tool Schema

Define the search function with its parameters in scripts/rag_tool.py:

TOOL_SPEC = {
    "type": "function",
    "function": {
        "name": "search_cloudxeus_docs",
        "description": "Search the CloudXeus knowledge base and return the most "
                       "relevant passages for a question.",
        "parameters": {
            "type": "object",
            "properties": {
                "query": {
                    "type": "string",
                    "description": "The user's question or search text."
                },
                "top_k": {
                    "type": "integer",
                    "description": "How many passages to return. Default 4."
                }
            },
            "required": ["query"]
        }
    }
}

The Retrieval Implementation

The function behind the tool is the hybrid search from the earlier lab, packaged as a plain Python callable. Add the search client, embed_query, and their imports from the search lab at the top of the file:

import json
from azure.search.documents.models import RawVectorQuery

def search_cloudxeus_docs(query: str, top_k: int = 4) -> str:
    vector = embed_query(query)
    vector_query = RawVectorQuery(vector=vector, k=top_k, fields="content_vector")
    results = client.search(search_text=query, vector_queries=[vector_query], top=top_k)

    passages = []
    for r in results:
        passages.append(f"Document: {r['title']}\n{r['content']}")
    return "\n\n".join(passages) if passages else "No relevant passages found."

The Tool Calling Loop

The loop sends the user message with the tool schema declared, then handles the model's request. When the model asks to call the tool, your code runs it and hands the result back as a tool message:

def chat_with_tool(user_message: str):
    messages = [
        {"role": "system",
         "content": "You are the CloudXeus support assistant. Use "
                    "search_cloudxeus_docs when you need information, "
                    "then answer from the retrieved text."},
        {"role": "user", "content": user_message},
    ]
    response = chat_client.chat.completions.create(
        model=CHAT_DEPLOYMENT,
        messages=messages,
        tools=[TOOL_SPEC],
        tool_choice="auto",
    )
    message = response.choices[0].message

    if message.tool_calls:
        for call in message.tool_calls:
            args = json.loads(call.function.arguments)
            result = search_cloudxeus_docs(**args)
            messages.append(message)
            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "content": result,
            })
        response = chat_client.chat.completions.create(
            model=CHAT_DEPLOYMENT, messages=messages, tools=[TOOL_SPEC]
        )

    print(response.choices[0].message.content)

The pattern is always the same: declare the tool, let the model ask, execute the tool yourself, return the output as a tool message, and give the model a second chance to answer. This loop generalizes to any number of tools.

Test the Agent

Exercise — Use Retrieval as a Tool

  1. Create scripts/rag_tool.py combining the schema, the search function, and the chat loop (plus the client setup from the previous labs).
  2. Add a test call: chat_with_tool("How do I reset the EdgeCam 300?").
  3. Run the script. The model should invoke search_cloudxeus_docs and then answer from the returned passages.
  4. Try a general question, such as Hello, how are you?. The model should chat directly without calling the tool.

Troubleshooting

  • The tool is never called: improve the tool's description so the model understands when it applies.
  • Malformed arguments: the model occasionally invents parameters; validate them and retry once with a corrected request.
  • The answer is still generic: check whether the retrieval actually returned good passages, and increase top_k.
  • Slow responses: each tool round trip adds latency; keep the schema small and the search fast.

Summary

Retrieval is now a first-class tool: the model decides when to consult the knowledge base and answers from what it retrieves. You can combine this tool with others, such as an orders API, in one agent. The next chapters show exactly that, using OpenAPI tools and Azure Functions to connect agents to real services.
