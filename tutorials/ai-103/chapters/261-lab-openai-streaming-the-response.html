Lab - OpenAI - Streaming the response

Waiting for a model to finish before showing anything makes an application feel slow, especially for long answers. Streaming fixes this: the API sends the answer in fragments as the model generates it, and your interface can render text as it arrives. In this lab you will stream a response with the OpenAI Python SDK and display the output incrementally.

Why Stream

  • Users see the first words in a fraction of the time it takes to complete a full answer.
  • Long responses feel responsive instead of frozen.
  • You can stop a generation early by interrupting the stream.
  • Network and model latency is hidden behind incremental progress.

The trade-off is that the caller must handle a stream of events instead of a single finished object.

Streaming with the Responses API

Step 1 — Create the streaming script

Create a file named stream_response.py:

from openai import OpenAI

client = OpenAI(api_key="YOUR_API_KEY")

stream = client.responses.create(
    model="gpt-4o-mini",
    instructions="You write short, clear paragraphs.",
    input="Explain how solar panels work in simple terms.",
    stream=True,
)

for event in stream:
    if event.type == "response.output_text.delta":
        print(event.delta, end="", flush=True)

print()

Step 2 — Run it

python stream_response.py

You should see the answer appear word by word in the terminal instead of all at once.

How the Stream Works

Setting stream=True changes the return type. Instead of a completed response object, the call yields a sequence of event objects. Each event has a type field that tells you what happened:

  • response.output_text.delta — a chunk of new assistant text. Append event.delta to your running output.
  • response.completed — the generation finished successfully.
  • response.failed — something went wrong mid-generation.

Each event is a snapshot of a moment in time, not the full answer. Your application is responsible for concatenating the delta fragments in order. That is why the loop above prints immediately with flush=True rather than buffering.

Collecting the Full Text

Streaming apps usually need both the incremental display and the complete final text for saving or further processing. Accumulate the deltas in a list:

collected = []

for event in stream:
    if event.type == "response.output_text.delta":
        collected.append(event.delta)
        print(event.delta, end="", flush=True)

full_text = "".join(collected)
print("\n--- full text captured ---")
print(full_text)

Streaming in Chat Completions

The Chat Completions API streams with a different event vocabulary but the same idea. If you ever need to call it, the shape looks like this:

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "Answer briefly."},
        {"role": "user", "content": "What is a token?"},
    ],
    stream=True,
)

for chunk in stream:
    piece = chunk.choices[0].delta.content
    if piece:
        print(piece, end="", flush=True)

Choose one API and stick with it inside a project. The Responses API is the newer, unified path and is what the rest of this course uses, but recognizing the Chat Completions streaming shape will help you read older code.

Summary

You streamed a model response with the Responses API, consumed individual text deltas, accumulated the full answer, and saw the equivalent Chat Completions pattern. Streaming turns a long wait into an immediate, progressive experience — a key trait of good generative user interfaces.
