Lab - Computer Vision - Python - Optical Character Recognition

So far the images you analyzed contained objects and scenes. Many real images are mostly text: photographed documents, whiteboards, receipts, screenshots, and signs. Optical character recognition (OCR) extracts that text so it can be searched, indexed, or fed into another AI model. In this lab you will pull the text out of an image with the read feature and print every detected line and word.

What You Need

  • Your Computer Vision endpoint and key.
  • Python 3 with the requests package installed.
  • A test image containing text — a screenshot, a photo of a sign, or a scanned page — saved as test.jpg.

Write the OCR Code

import os
import requests

ENDPOINT = os.environ["COMPUTER_VISION_ENDPOINT"]
KEY = os.environ["COMPUTER_VISION_KEY"]

ANALYZE_URL = ENDPOINT.rstrip("/") + "/computervision/imageanalysis:analyze"
params = {
    "api-version": "2024-02-01",
    "features": "read",
}

with open("test.jpg", "rb") as f:
    image_data = f.read()

headers = {
    "Content-Type": "application/octet-stream",
    "Ocp-Apim-Subscription-Key": KEY,
}

response = requests.post(ANALYZE_URL, params=params, headers=headers, data=image_data)
response.raise_for_status()

read = response.json()["readResult"]["blocks"]
for block in read:
    for line in block["lines"]:
        text = line["text"]
        words = [word["text"] for word in line["words"]]
        print(f"{text:<40} | words: {', '.join(words)}")

Run and Observe

Exercise 1: Extract text from an image

  1. Save the script as vision_ocr.py.
  2. Set the environment variables and run python vision_ocr.py.
  3. Read the printed output. Each line shows the detected line of text and the individual words that make it up.
  4. Test with a clean screenshot first, then a photo of a sign, then a page of handwritten notes. Notice how accuracy drops as the text gets messier or the lighting worsens.
  5. Print the boundingPolygon of a line as well, and compare it with the line's actual position in the image.

How the OCR Response Is Structured

The OCR result has three nesting levels, each with position information:

  • Blocks — the top level, usually one per text region in the image.
  • Lines — a horizontal grouping of words, with the text of the whole line.
  • Words — each individual word, with its own boundingPolygon coordinates.
{
  "readResult": {
    "blocks": [
      {
        "lines": [
          {
            "text": "WELCOME TO AI-103",
            "boundingPolygon": [{"x": 120, "y": 80}, {"x": 520, "y": 80}, {"x": 520, "y": 120}, {"x": 120, "y": 120}],
            "words": [
              {"text": "WELCOME", "confidence": 0.99},
              {"text": "TO", "confidence": 0.99},
              {"text": "AI-103", "confidence": 0.98}
            ]
          }
        ]
      }
    ]
  }
}

Note that word and line positions use a boundingPolygon — a list of corner points — rather than the boundingBox you saw in object detection. A polygon handles rotated text more honestly than a straight rectangle.

Turning OCR Output into Usable Text

Most applications want a plain string rather than a tree of blocks. Joining the lines in reading order gives you a full text document you can search or store:

full_text = "\n".join(
    line["text"]
    for block in read
    for line in block["lines"]
)
print(full_text)

For document-style images, joining lines with newlines preserves the page layout well enough for most downstream use. If you need true reading order across columns, use a document analysis service tuned for layouts rather than simple line joining.

The Dedicated Read API

The read feature we used returns results in a single synchronous response. Azure also offers a separate Read API designed for large documents: you submit the image, receive an operation ID, and poll until the analysis finishes. That asynchronous pattern is the right choice for multi-page scans and big files. For the small images in this course, the synchronous read feature keeps the code simple.

OCR output can contain personal information. A photo of a document may expose names, addresses, or account numbers in the extracted text. Store and transmit that text with the same care you would give the original document.

Common Issues

  • Blank or partial output: the text is too small, blurred, or rotated in the image. Crop and straighten the region first.
  • Unsupported language: confirm the text language is supported by the service, or use an OCR service with the language you need.
  • No text found: the image genuinely contains no readable text, or the text is part of a stylized graphic rather than a real scene.

Summary

You used the read feature to extract text from an image, walked the blocks, lines, and words hierarchy, and converted the structured result into plain text. OCR is the bridge between the physical world of printed text and the searchable digital world, and it will reappear throughout the rest of the course.
