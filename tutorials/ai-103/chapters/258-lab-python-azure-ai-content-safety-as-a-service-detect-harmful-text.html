Lab - Python - Azure AI Content Safety as a service - Detect Harmful text

In this lab you will use the Azure AI Content Safety SDK from Python to analyze text for harmful content. The service scores the input against categories such as hate, sexual, violence, and self-harm, and returns a severity value for each. You will write a small script that submits text and reports the results, then extend it with a policy that decides whether the text is acceptable.

Prerequisites

  • The Content Safety resource endpoint and key from an earlier lab.
  • Python 3.8 or later.
  • The azure-ai-contentsafety package installed (see the previous lab if you have not installed it yet).

Writing the Text Analysis Script

Step 1 — Create the script

Create a file named detect_text.py:

from azure.ai.contentsafety import ContentSafetyClient
from azure.core.credentials import AzureKeyCredential
from azure.ai.contentsafety.models import AnalyzeTextOptions

ENDPOINT = "YOUR_ENDPOINT"
KEY = "YOUR_KEY"

client = ContentSafetyClient(
    endpoint=ENDPOINT,
    credential=AzureKeyCredential(KEY),
)

sample_text = "Your sample text goes here."

request = AnalyzeTextOptions(text=sample_text)
result = client.analyze_text(options=request)

for analysis in result.categories_analysis:
    label = analysis.category
    severity = analysis.severity
    status = "flagged" if severity > 0 else "clean"
    print(f"{label}: severity {severity} ({status})")

Step 2 — Configure and run

  1. Replace YOUR_ENDPOINT and YOUR_KEY with your resource values.
  2. Put a short sentence into sample_text.
  3. Run the script:
python detect_text.py

Testing Different Inputs

The real value of moderation appears when you compare inputs. Try these one at a time:

  • A neutral sentence: "The meeting starts at nine in the morning."
  • Mild profanity or an insult directed at a person.
  • A violent threat phrased as a complete sentence.

Watch the severity numbers climb as the content becomes more hostile. Neutral text scores 0 in every category, while aggressive text pushes one or more categories above zero.

Severity is per category. A single message can be scored simultaneously for hate and violence, and the numbers are independent — a high hate score does not force a violence score. Your policy should evaluate each category separately.

Applying a Blocking Policy

Raw scores do not protect anything by themselves. The application decides. Add a threshold check so the script accepts or rejects the text:

THRESHOLD = 2

rejected = False
for analysis in result.categories_analysis:
    if analysis.severity > THRESHOLD:
        rejected = True
        print(f"Rejecting text: {analysis.category} severity {analysis.severity}")

if rejected:
    print("TEXT BLOCKED")
else:
    print("TEXT ACCEPTED")

With a threshold of 2, a severity of 0, 1, or 2 passes and anything higher is blocked.

Combining Text and Image Checks

Real applications usually moderate both sides of a conversation: the user's message and any image they attach. You can reuse the same client for both calls:

from azure.ai.contentsafety.models import AnalyzeImageOptions, ImageData

with open("upload.jpg", "rb") as img:
    image_result = client.analyze_image(
        options=AnalyzeImageOptions(image=ImageData(content=img.read()))
    )

for analysis in image_result.categories_analysis:
    print(f"Image {analysis.category}: {analysis.severity}")

Combining the two gives you a single verdict: reject the post if the text fails or the image fails.

Keep moderation results for auditing. Log the category, severity, timestamp, and the decision your policy made. If a user disputes a block, the log shows exactly why the content was rejected.

Summary

You analyzed text with Azure AI Content Safety from Python, inspected per-category severity scores, added a threshold-based policy, and extended the pattern to images. The combination of text and image analysis with a clear decision rule is the core of a responsible moderation pipeline.
