Using models to generate images

Reading images is only half of the story. Generative models can also create brand new pictures from nothing more than a text description. You describe a scene, the model produces pixels that match your words. This chapter explains how text-to-image generation works, which models are available in Microsoft Foundry, how to write prompts that produce good results, and what the generation API returns. The next chapter will turn all of this into a working Python lab.

From Text to Pictures

Image generation models are trained on enormous collections of images paired with text descriptions. During training the model learns the relationship between language and visual content: what a phrase like "a red wooden boat" usually looks like. When you send a prompt at inference time, the model starts from visual noise and progressively refines it, guided by your text, until a coherent image emerges. This family of techniques is often called diffusion, because the model learns to reverse a process of gradually adding noise to an image.

The important practical point is that the model has never seen your particular prompt before. Every image it creates is a fresh synthesis of patterns it learned, so two runs of the same prompt will usually produce two different pictures.

Image Models Available in Foundry

Microsoft Foundry offers several image generation models through its model catalog. The two you are most likely to use are:

ModelStrengthsCommon uses
gpt-image-1Strong prompt following, supports generating and editing, multiple aspect ratiosMarketing images, product mockups, editing workflows
dall-e-3Simple API, good at detailed natural-language promptsQuick illustrations, concept art, prototyping

Both are deployed in Foundry in the same way as chat models, and both are called through the OpenAI-compatible images endpoint rather than the chat completions endpoint.

Writing a Good Image Prompt

The quality of a generated image depends heavily on how clearly you describe it. A strong image prompt usually contains:

  • The subject: what is in the picture, for example "a fox sitting on a park bench."
  • The setting: where and when, for example "at sunset in a snowy city park."
  • The style: art direction, for example "watercolor, soft pastel colors."
  • The composition: framing and emphasis, for example "close-up, shallow depth of field."
  • Negative guidance: what to avoid, for example "no text, no people."

Prompts are interpreted statistically, not as instructions to a human painter. Instead of "make it look good," state the concrete properties you want: lighting, palette, angle, mood, and level of detail. The more specific the description, the more control you have over the result.

Generation Parameters

The generation call accepts several parameters that shape the output beyond the prompt itself:

ParameterWhat it controlsTypical values
sizeResolution and aspect ratio of the output1024x1024, 1792x1024
qualityTrade-off between detail and speed/coststandard, hd
styleVisual treatment applied to the imagenatural, vivid
nHow many images to produce1 for most workflows

Higher quality and larger sizes consume more tokens and therefore cost more. For experiments and early prototypes, start with the standard quality and the smallest size that still shows the detail you care about.

What the API Returns

The response from the image endpoint wraps each generated picture in a data object. Depending on the model and request, the image is returned either as a public URL you can download or as a base64-encoded blob you can write straight to a file. The response also reports usage, which you can read to understand the token cost of the generation.

You never get the raw image bytes back in the same place you get a chat message. Your code must read the URL or the base64 string and then save it as a file. That step is covered in detail in the next chapter.

Responsible Use

Image generation raises real responsibility questions, and the service applies content filters to every request. Even so, build your applications with intent:

  • Verify the rights you need before using generated images in commercial products.
  • Never generate images of real people in compromising situations, or of real individuals being depicted falsely.
  • Do not use generated images to mislead people, such as fabricated evidence or impersonation.
  • Tell users when content is AI-generated, especially in public-facing applications.

Because image generation can produce visual content that is easy to misuse, Azure applies additional content safety checks to generation requests. Do not attempt to craft prompts that bypass those checks. Account-level moderation rules and the content policies still apply to generated output.

Summary

Image generation models synthesize new pictures from text by reversing the noise added during diffusion training. In Foundry you deploy models such as gpt-image-1 and dall-e-3, drive them with detailed prompts, and control the output with parameters like size, quality, and style. The response returns each image as a URL or base64 blob that your code must save to disk. In the next chapter you will write exactly that code.
