Lab - Conversational Language Understanding - Deploying the Model

A trained model is only an artifact until it is published. In this lab you will create a deployment that exposes your trained CLU model through a prediction endpoint, find the prediction URL and key, and test it both from Language Studio and with a direct REST request. After this lab your model will be genuinely callable from any application.

Prerequisites

  • A successfully trained model version from the previous lab.
  • The Azure AI Language resource that hosts the project, with its key and endpoint handy.

How Deployment Works in CLU

Deployment binds a trained model version to a public endpoint. Language Studio lets you create a deployment, assign a trained model to it, and swap which version the endpoint serves without changing the URL. Applications always call the deployment name, which means you can roll a new model forward or back instantly.

The prediction endpoint is separate from the authoring endpoint. You authorize prediction calls with a language resource key, and you must include the correct API version and the project and deployment names in the URL.

Step 1: Create a Deployment

Exercise 1: Publish the trained model

  1. In Language Studio, open your project and select Deploying a model from the left menu.
  2. Click Add deployment.
  3. Give the deployment a name such as production.
  4. Select the trained model version you created in the previous lab.
  5. Click Deploy. The deployment appears in the list with its assigned model.

Step 2: Test in the Portal

Exercise 2: Try the deployed model

  1. Open the deployment's test pane in Language Studio.
  2. Type a sentence that your model has never seen, for example I want to fly to Berlin tomorrow.
  3. Look at the result: the predicted intent, its confidence score, and any extracted entities with their values and spans.
  4. Try a second sentence phrased very differently, such as what does this app do, and confirm it maps to the GetHelp intent.

Step 3: Find the Prediction URL and Key

To call the model from code you need three things: the endpoint, the deployment name, and a key.

  • Endpoint: the Azure AI Language resource overview shows an endpoint of the form https://YOUR_RESOURCE.cognitiveservices.azure.com/.
  • Deployment name: the value you typed when creating the deployment, for example production.
  • Key: one of the keys listed on the resource's Keys and Endpoint page.

Step 4: Call the Prediction Endpoint Directly

Exercise 3: Verify with a raw HTTP request

Using a REST client or curl, send a POST request to the prediction URL. Replace the placeholders with your values:

curl "https://YOUR_RESOURCE.cognitiveservices.azure.com/language/:analyze-conversations?api-version=2022-10-01-preview" \
  -H "Ocp-Apim-Subscription-Key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d "{
    \"kind\": \"Conversation\",
    \"analysisInput\": {
      \"conversationItem\": {
        \"id\": \"1\",
        \"participantId\": \"user\",
        \"text\": \"Book me a flight to Paris on Sunday\"
      }
    },
    \"parameters\": {
      \"projectName\": \"YOUR_PROJECT\",
      \"deploymentName\": \"production\"
    }
  }"

The response contains a JSON object with the detected intent, its confidence score, and the extracted entities. Compare those values with what the portal showed in the test pane — they should agree.

The key in your request authenticates you and is billed per call. Never embed it in client-side code or commit it to a repository. Store it in environment variables or a secret manager and rotate it regularly.

Step 5: Swap Versions and Roll Back

  • To release a newer model, train it, then assign it to the same deployment name.
  • To roll back, reassign the deployment to the previous model version.
  • Applications keep working unchanged because the URL still contains the same deployment name.

Summary

You deployed a trained model version, tested it from Language Studio, found the prediction endpoint and key, and verified the endpoint with a direct REST request. The model is now live and callable. In the next chapter you will consume the same endpoint from a Python application.
