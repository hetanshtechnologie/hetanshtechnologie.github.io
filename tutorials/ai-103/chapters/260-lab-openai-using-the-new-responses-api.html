Lab - OpenAI - Using the New Responses API

The OpenAI platform offers several APIs for talking to models. The newer Responses API is designed to unify chat, tools, and structured output into a single endpoint, whereas the older Chat Completions API split those concerns across different calls. In this lab you will make your first call to the Responses API from Python and inspect the response structure.

Prerequisites

  • An OpenAI API key (or an Azure OpenAI endpoint and key).
  • The openai Python package installed:
pip install openai

Making Your First Response

Step 1 — Create the script

Create a file named first_response.py:

from openai import OpenAI

client = OpenAI(api_key="YOUR_API_KEY")

response = client.responses.create(
    model="gpt-4o-mini",
    instructions="You are a friendly travel assistant.",
    input="Suggest two fun activities for a weekend in Seattle.",
)

print(response.output_text)

Step 2 — Run it

  1. Replace YOUR_API_KEY with your key.
  2. Run the script:
python first_response.py

The assistant's reply is printed to the console.

If you are using Azure OpenAI, the client initialization is slightly different. Instead of only the key, pass an azure_endpoint and an api_version, and the model name becomes the deployment name you created in Azure AI Foundry. The request and response shapes stay the same.

Anatomy of the Response

The responses.create call returns a rich object. Beyond the plain text, it contains the full conversation trail:

  • output_text — the assistant's message as a single string, easiest for simple apps.
  • output — the list of individual output items (messages, tool calls, and more).
  • usage — token counts so you can track cost.
  • id — the response id, useful for logging and follow-up work.
print("Response id:", response.id)
print("Usage:", response.usage)
for item in response.output:
    print("Output item type:", item.type)

Using Instructions vs Input

The Responses API separates the two roles of a prompt. The instructions parameter carries the standing guidance that sets the model's behavior, and input carries the user's actual message. This keeps the system-level rules separate from the conversation, which becomes important as you add multiple turns or streaming.

response = client.responses.create(
    model="gpt-4o-mini",
    instructions="You only answer in three bullet points.",
    input="How should I prepare for a job interview?",
)

print(response.output_text)

Keep the instructions stable across the whole session and vary only input between turns. That makes your code easier to reason about and keeps the model's behavior consistent.

Testing Different Inputs

Modify the input string and rerun to confirm the model responds appropriately:

  • Ask a factual question and check the answer is plausible.
  • Ask for the same answer in different styles to see how instructions shapes the output.
  • Send a multi-line input and observe that the reply handles it as one message.

Summary

You made your first call to the OpenAI Responses API, separated instructions from input, and explored the response object's key fields. The Responses API will be the foundation for the next several labs, including streaming and structured output.
