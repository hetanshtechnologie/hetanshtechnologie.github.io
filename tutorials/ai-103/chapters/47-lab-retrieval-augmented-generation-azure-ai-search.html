Lab - Retrieval Augmented Generation - Azure AI Search

The previous lab produced data/chunks.jsonl, a file of clean text chunks ready to be searched. Now you need somewhere to search them. This lab creates an Azure AI Search resource, which will store the chunks and their vector embeddings and answer retrieval queries. You will also define the index schema, the contract that describes which fields every searchable document has.

What Azure AI Search Provides

Azure AI Search is a managed search service built into Azure. It gives you:

  • Indexes: collections of documents that share a schema.
  • Keyword search: classic full-text matching with scoring.
  • Vector search: similarity search over embedding fields.
  • Hybrid search: keyword and vector results combined and re-ranked.
  • Scoring profiles and filters that shape which results rank highest.

For RAG, you use it as the retrieval store: the index holds chunks plus their embeddings, and a query returns the chunks most relevant to a question.

Create the Resource in the Portal

  1. In the Azure portal, search for Azure AI Search and choose Create.
  2. Pick your subscription, a resource group, and a unique service name such as cloudxeus-search.
  3. Choose a pricing tier. Prefer Free if available, otherwise Basic.
  4. Set a region close to your other resources, review, and create.
  5. Wait for deployment to finish before continuing.

The Free tier is ideal for learning but is limited to a single partition and a smaller document quota. If you plan to index thousands of chunks, use the Basic tier instead.

Create the Resource with the CLI

If you prefer automation, the same steps in Azure CLI look like this:

az group create --name cloudxeus-rg --location eastus

az search service create --resource-group cloudxeus-rg --name cloudxeus-search --sku free --location eastus

Record the endpoint URL: it will look like https://cloudxeus-search.search.windows.net.

Endpoint and Keys

  • Open the search resource in the portal.
  • Copy the Url from the overview page: this is your YOUR_SEARCH_ENDPOINT.
  • Under Keys, copy the primary admin key: this is your YOUR_SEARCH_ADMIN_KEY.

The admin key grants full control, including deleting indexes. Use a query key for read-only application code in production, and never commit keys to source control. For this course the admin key is convenient, but treat it as a secret.

Define the Index Schema

An index describes the fields of each searchable document. Our schema has a text field per chunk plus a vector field that will hold the chunk's embedding. Save the following as scripts/index_schema.json:

{
  "name": "cloudxeus-docs",
  "fields": [
    {"name": "id", "type": "Edm.String", "key": true, "searchable": false},
    {"name": "title", "type": "Edm.String", "searchable": true, "filterable": true},
    {"name": "source", "type": "Edm.String", "searchable": true, "filterable": true},
    {"name": "content", "type": "Edm.String", "searchable": true},
    {"name": "content_vector", "type": "Collection(Edm.Single)",
     "searchable": true, "retrievable": false, "dimensions": 1536,
     "vectorSearchConfiguration": "vector-config"}
  ],
  "vectorSearchConfigurations": [
    {"name": "vector-config",
     "kind": "vector",
     "algorithmConfigurations": [{"name": "hnsw-config", "kind": "hnsw"}]}
  ]
}

Create the Index

Exercise — Create the Index

  1. From the project root, create the index with Azure CLI:
az search index create --service-name cloudxeus-search --resource-group cloudxeus-rg --admin-key YOUR_SEARCH_ADMIN_KEY --name cloudxeus-docs --index-json @scripts/index_schema.json
  1. Verify it exists:
az search index list --service-name cloudxeus-search --resource-group cloudxeus-rg --admin-key YOUR_SEARCH_ADMIN_KEY
  1. You should see cloudxeus-docs in the output.

The dimensions value must match the embedding model you use. A model like text-embedding-ada-002 returns 1536 dimensions; other embedding models differ, so check the model's documentation before you create the index.

Summary

You now have an Azure AI Search service, an index schema, and an empty cloudxeus-docs index. The next lab fills that index: it reads the chunk file, generates embeddings, and uploads the documents from Python.
