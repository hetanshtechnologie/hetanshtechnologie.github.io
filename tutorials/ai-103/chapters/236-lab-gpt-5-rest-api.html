Lab - GPT 5 - REST API

Every model deployment in Azure AI Foundry exposes a REST API — a plain HTTP endpoint that any programming language can call. Before you write Python, this lab calls that endpoint directly with curl, so you see the request and response in raw form. Understanding the wire protocol first makes the SDK code in the next labs much easier to read.

What You Will Need

  • A deployed chat model (your ai103-chat-deploy deployment from the earlier lab).
  • The deployment's Endpoint URL and Key, from the Foundry project's Deployments or Keys page.
  • A terminal — PowerShell on Windows, or any shell on macOS/Linux. Windows users must use curl.exe, not the curl alias.

Never paste your key into chat messages, emails, or files you share. If you think a key leaked, regenerate it in the portal and update the places that use it.

The Request Shape

The chat-completions REST call is a single POST to your endpoint with three pieces of information:

  • URL: your endpoint path plus the deployment name and an API version.
  • Header: your key sent as api-key.
  • Body: a JSON document containing the messages array and parameters.
POST /openai/deployments/YOUR_DEPLOYMENT_NAME/chat/completions?api-version=2024-06-01
Headers:
  api-key: YOUR_KEY
  Content-Type: application/json
Body:
{
  "messages": [
    {"role": "system", "content": "You are a concise assistant."},
    {"role": "user", "content": "Say hello in five words."}
  ],
  "max_tokens": 50
}

The deployment name in the URL is the name you chose when you deployed the model — not the model family name. A 404 error almost always means this name (or the API version) is wrong, not that the model is broken.

Step 1: Call with curl

Exercise 1: Send your first REST request

  1. Open a terminal.
  2. Save the request body to a file named request-body.json to avoid shell-quoting problems on Windows.
  3. Run the curl command below with your values substituted.
{
  "messages": [
    {"role": "system", "content": "You are a concise study assistant."},
    {"role": "user", "content": "List three benefits of calling a model via REST API."}
  ],
  "temperature": 0.5,
  "max_tokens": 150
}
# Windows PowerShell (note: curl.exe)
curl.exe "https://YOUR_ENDPOINT/openai/deployments/YOUR_DEPLOYMENT_NAME/chat/completions?api-version=2024-06-01" `
  -H "api-key: YOUR_KEY" `
  -H "Content-Type: application/json" `
  -d "@request-body.json"
# macOS / Linux
curl "https://YOUR_ENDPOINT/openai/deployments/YOUR_DEPLOYMENT_NAME/chat/completions?api-version=2024-06-01" \
  -H "api-key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d @request-body.json

Keep the JSON in a file whenever a command line grows this long. It survives copy-paste cleanly, avoids quoting bugs, and lets you edit the request without rewriting the shell command.

Step 2: Read the Response

A successful call returns a JSON document with three important blocks:

{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "choices": [
    {
      "index": 0,
      "finish_reason": "stop",
      "message": {
        "role": "assistant",
        "content": "1. Language-agnostic ... 2. Callable from any tool ... 3. Simple to test."
      }
    }
  ],
  "usage": {
    "prompt_tokens": 33,
    "completion_tokens": 27,
    "total_tokens": 60
  }
}
  • choices[0].message.content — the text you actually want.
  • choices[0].finish_reason — why generation stopped: stop naturally, length when the token cap hit, or content_filter.
  • usage — the token counts that determine your bill.

Notice the response wraps the text in the same role/content structure the request used. In a multi-turn app you append this assistant message to the array and send it back — that is how the model remembers the conversation.

Step 3: Interpret Common Errors

HTTP statusMeaningFix
401Key rejectedCheck the key; regenerate if it changed
404Deployment or API version not foundVerify deployment name and api-version
429Rate limit or quotaWait, or request a higher quota
400Malformed bodyValidate JSON; check parameter names
500/503Service issueRetry; if persistent, check Azure status

Add -i to curl to print the response headers. The x-ms-ratelimit-* headers reveal how close you are to the rate limit — useful when your app starts hitting 429s in production.

Step 4: Try a Multi-Turn Request

Extend the JSON file with a short conversation history so the model answers in context:

{
  "messages": [
    {"role": "system", "content": "You are a helpful cooking assistant."},
    {"role": "user", "content": "I am making pancakes. What is the first step?"},
    {"role": "assistant", "content": "Mix flour, eggs, and milk until smooth."},
    {"role": "user", "content": "Now what do I do with the pan?"}
  ],
  "max_tokens": 100
}

Resend the request. The model answers the latest question while using the earlier turns for context — the same mechanism the playground used, exposed over plain HTTP.

Summary

You called your GPT deployment over raw HTTP with curl, read the JSON response, learned the three blocks every response contains, mapped common error codes to fixes, and carried a conversation across turns. This wire-level understanding carries directly into the Python SDK, which wraps this exact protocol. Next you will reproduce this call in Python.
