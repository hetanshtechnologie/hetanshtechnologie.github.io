Knowledge source pre-requisites - Deploying the models

The knowledge base pipeline needs two models: an embedding model to vectorize the course chunks and the question, and a chat model to write the grounded answers. Neither exists until you deploy it in your Foundry project. This chapter deploys both and verifies they respond, so every later step has concrete endpoints and deployments to use.

Which Models to Deploy

RoleModelWhy this choice
Embeddingstext-embedding-3-small1536 dimensions, fast, low cost, matches the index created in the search labs
Chatgpt-4o-miniCapable enough for grounded answers, inexpensive for many conversations

Both models are available from the Azure OpenAI model catalog in Foundry. You can substitute other models, but keep the embedding dimensions in sync with your index — the index in the search labs was created with 1536 dimensions.

Step 1 - Open Your Project and Check Quota

Sign in to the Foundry web portal and open your capstone project. Before deploying, check the quota page: each deployment consumes tokens-per-minute from your project's model quota. If quota is exhausted, pick the same model in a different region or request an increase.

Model availability varies by region. If a model does not appear in the catalog for your project's region, switch the project to a region that hosts it, or deploy from a different supported region. Choosing the region before you build the pipeline avoids rework later.

Step 2 - Deploy the Embedding Model

  1. In Foundry, open Model catalog and search for text-embedding-3-small.
  2. Select the model and choose Deploy.
  3. Name the deployment text-embedding-3-small (match the index's expectations).
  4. Pick the SKU. GlobalStandard is a good default for this project; it routes traffic through a globally distributed pool with your subscription quota.
  5. Leave the token rate limit at its default for now and confirm the deployment.

The deployment usually becomes ready within a minute. Copy the deployment name and the project endpoint — you will need them when the indexer embeds chunks.

Step 3 - Deploy the Chat Model

Repeat the same steps for the chat model:

  1. In the model catalog, search for gpt-4o-mini.
  2. Select it and choose Deploy.
  3. Name the deployment gpt-4o-mini.
  4. Choose GlobalStandard and confirm.

This deployment is what the assistant will use when it writes answers. You will reference its deployment name when you create the agent.

Give deployments exactly the names used in your code and index configuration. A deployment named gpt-4o-mini is easier to reason about than model-a-test-2, and the embedding deployment name appears in your skillset, so consistency prevents subtle configuration mismatches.

Step 4 - Deploy with the CLI (Alternative)

If you prefer automation, the same deployments can be created with the Azure ML CLI against your Foundry project's workspace. Save this as deploy-embed.json:

{
  "name": "text-embedding-3-small",
  "model": "azureml://registries/azure-openai/models/text-embedding-3-small/versions/latest",
  "type": "azureopenai",
  "sku": "GlobalStandard"
}

Then deploy it, repeating with a similar file for the chat model:

$ws = "YOUR_FOUNDRY_WORKSPACE_NAME"

az ml model create `
  --file deploy-embed.json `
  --resource-group $rg `
  --workspace-name $ws

The type: azureopenai and the exact registry path must match what your Foundry version accepts. If the CLI rejects the model path, deploy through the portal instead and verify the deployment name in the Deployments page — the result is identical.

Step 5 - Verify the Deployments

Open the project's Deployments page. You should see two entries with a Ready status. Then confirm each answers a real request from code. For the embedding model, embed a short sentence and check the output shape:

pip install openai

from openai import AzureOpenAI

client = AzureOpenAI(
    api_key="YOUR_KEY",
    api_version="2024-10-21",
    azure_endpoint="https://YOUR_ENDPOINT",
)

response = client.embeddings.create(
    model="text-embedding-3-small",
    input="What is hybrid search?",
)

print(len(response.data[0].embedding))  # expect 1536

Do not hard-code the key. Read it from an environment variable in your real scripts, as the capstone labs do. For local development, DefaultAzureCredential can authenticate to Foundry without any key at all once the permissions chapter adds the right role.

Troubleshooting

SymptomLikely causeFix
Model not in the catalogNot offered in your regionCheck regional availability or switch project region.
Quota exceeded at deployTPM quota exhaustedChoose GlobalStandard or request a quota increase.
Embedding length is not 1536Wrong model or trimmed dimensionsConfirm the deployment is text-embedding-3-small; align the index.
401 on the test callKey or endpoint mismatchCopy the key and endpoint from the Deployments page.

Summary

You deployed an embedding model and a chat model in your Foundry project, checked quota and regional availability, and verified the embedding model returns 1536 dimensions from a real call. These deployments are the intelligence of the knowledge base. The next chapter grants the identities that let the pipeline and the agent call them securely.
