Retrieval Augmented Generation - The Full Loop - Review

You have now built a complete RAG loop: prepared documents, embedded them, indexed them, searched them, and grounded chat answers in what was retrieved. This review checks that you remember how the pieces fit together. Answer the eight questions below, then compare against the answer key at the bottom.

Questions

  1. What does RAG do differently from a plain chat model?

    1. It retrains the model on every new query.
    2. It retrieves relevant documents and includes them in the prompt as context. (correct)
    3. It blocks the model from seeing any external data.
    4. It only works with image inputs.

  2. Which step happens during the offline indexing phase?

    1. Embedding the user's question.
    2. Sending the assembled prompt to the chat model.
    3. Splitting documents into chunks and embedding them. (correct)
    4. Calling the Azure Functions orders API.

  3. Why must the same embedding model be used for indexing and querying?

    1. Because it is cheaper than switching models.
    2. So query vectors and stored vectors live in the same vector space and are comparable. (correct)
    3. Because the search service requires the model by name.
    4. It is not required at all.

  4. In Azure AI Search, what is an index?

    1. A set of documents that share a common schema. (correct)
    2. A Python package used to extract PDFs.
    3. A deployed chat model endpoint.
    4. A container registry for images.

  5. A hybrid search combines:

    1. Two different chat models.
    2. Keyword search results and vector search results. (correct)
    3. Two different search services.
    4. Image and text queries.

  6. Which system prompt instruction best describes a grounded RAG assistant?

    1. Answer from general knowledge only.
    2. Answer only from the supplied context and state when the context lacks the answer. (correct)
    3. Never mention any source document.
    4. Always retrain the model first.

  7. In which format were the prepared chunks stored during data preparation?

    1. CSV.
    2. JSONL. (correct)
    3. XML.
    4. INI.

  8. When the retrieved chunks are irrelevant, what should you investigate first?

    1. The GPU in your virtual machine.
    2. Retrieval quality: chunking, top-k, and hybrid search settings. (correct)
    3. The search service billing tier.
    4. The color scheme of the web application.

Answer Key

  1. b — RAG augments the prompt with retrieved documents; it never retrains the model.
  2. c — Indexing is the offline phase: parse, chunk, embed, and store.
  3. b — Matching vector spaces is essential for similarity to be meaningful.
  4. a — An index is a collection of documents with a shared schema.
  5. b — Hybrid search runs keyword and vector searches and merges the results.
  6. b — Grounding instructions constrain the model to the context and enable honest answers when information is missing.
  7. b — The lab wrote one chunk per line to chunks.jsonl.
  8. b — Retrieval quality is the usual culprit, and logging the retrieved chunks reveals it.

Summary

RAG keeps three phases straight: index your data, retrieve the best chunks for a question, and generate an answer grounded in those chunks. If you scored all eight, you are ready to move retrieval beyond the one-shot script. The next lab turns the search into a reusable tool the model decides to call, so it works inside a larger agent.
