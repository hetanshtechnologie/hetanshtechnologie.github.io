Lab - OpenAI - Understanding Structured Outputs

Large language models are great at writing prose, but applications need reliable data. If you ask a model for a person's name and age, the reply might come back as a sentence, a list, or a paragraph — none of which your code can parse confidently. Structured outputs solve this by forcing the model to reply in a schema you define, such as JSON with specific fields and types. This lab explains the concept and shows you how to request structured responses.

The Parsing Problem

Consider asking a model: "Extract the name and age from this email." Without constraints, one run might answer Jane, 34, another "Her name is Jane and she is thirty-four.", and a third might add a whole explanation. Writing a parser that handles every variant is brittle.

Structured outputs eliminate most of that variety. You declare an exact shape, and the model fills it in:

{
  "name": "Jane Doe",
  "age": 34
}

Because the shape is fixed, your code can deserialize it directly into an object with no fuzzy parsing.

How the Model Guarantees the Shape

When you provide a JSON schema, the platform guides the model's decoding so the emitted text conforms to the schema. This is stronger than asking "please output JSON" in a prompt, which a model may or may not honor. With structured outputs:

  • Required fields are always present.
  • Values match the declared types, such as string or integer.
  • Enumerations restrict values to the allowed set.
  • Nested objects follow the nested schema.

Structured outputs constrain the format, not the meaning. A schema that says "age": integer guarantees a number, not a correct number. Always validate the values for correctness and ranges in your own code.

Defining a Schema

Schemas are expressed as JSON Schema objects. A simple schema for contact extraction:

schema = {
    "type": "object",
    "properties": {
        "name": {"type": "string"},
        "age": {"type": "integer", "minimum": 0},
        "city": {"type": "string"}
    },
    "required": ["name", "age"],
    "additionalProperties": False
}

The fields tell the model what to produce: a string name, an integer age that cannot be negative, and an optional city. The required list forces name and age to always appear.

Keep schemas as small as you can. A huge schema with dozens of nested fields makes generation slower and increases the chance the model misplaces a value. Extract only what your application actually needs.

The takeaway: use structured outputs when downstream code depends on a precise shape, which is almost always true in real applications.

Summary

Structured outputs make model responses predictable by enforcing a JSON schema you define. You learned why fuzzy text parsing is fragile, how schemas constrain the model's output, and where structured outputs sit relative to plain prompting and JSON mode.
