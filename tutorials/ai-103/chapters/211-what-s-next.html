What's next

You have reached the midpoint of the first big arc of this course. So far you have built a mental model of generative AI, learned how large language models work, met the OpenAI API platform, and practiced driving models with system messages and prompts. Before you move to the cloud, this short chapter connects what you already know to where you are going: Azure, Azure OpenAI, and Microsoft Foundry.

Where You Have Been

Let's recap the journey so far. You learned that generative models synthesize new content by sampling from patterns learned during training. You discovered that large language models work token by token, predicting what comes next. You explored the OpenAI API platform — signing up, opening the playground, and sending your first chat completions. Finally, you saw how system messages set the role and rules for a model while user messages carry the actual request.

That hands-on experience matters. The message format, the response structure, the notion of tokens, and the practice of writing good prompts are all concepts that transfer directly to the next section. Everything you did with the OpenAI platform you will soon do again inside Microsoft Foundry — with a few important differences.

Why Move to the Cloud

Running models on a public platform is a great way to learn, but production applications have additional requirements. You need predictable pricing, contractual data handling, regional availability, compliance and governance controls, monitoring, and the ability to serve users at scale. These are not features of a single model API — they are features of a cloud platform.

  • Data governance: control where your data is processed and who can access it.
  • Enterprise controls: identity management, role-based access, and audit logs.
  • Integration: connect models to storage, databases, and application services.
  • Lifecycle management: deploy, monitor, and retire models in a controlled way.

Do not throw away the code or prompts you wrote in the previous chapters. In the next section you will reuse the same chat-completion pattern against an Azure-hosted endpoint. The core skill is portable; only the connection details change.

What the Next Section Covers

The next chapters introduce the Azure platform step by step. You will start with the fundamentals of cloud computing and Azure itself, then create a free account and tour the Azure portal. From there you will look at Azure AI services, the family of managed AI capabilities that Microsoft offers, and at the principles that guide responsible use of AI. You will then meet two closely related tools:

  • Azure OpenAI Service, which brings the OpenAI models you already know into Azure with enterprise controls.
  • Microsoft Foundry, the unified platform where you manage, deploy, test, and monitor AI applications.

What You Will Build

By the end of this section you will have a working cloud setup of your own:

  1. An Azure free account that costs you nothing for the exercises.
  2. An Azure AI Foundry resource, often called a hub, plus a project inside it.
  3. A deployed model endpoint you can call from the Foundry playground, from curl, and from Python.

That endpoint becomes the foundation for every later chapter in the course — the place where your prompts, your RAG pipelines, and your agents will run.

How to Approach This Section

This section is more step-by-step than the conceptual chapters you just finished. Expect to switch between reading and doing: follow along, click through the portal, and try each deployment yourself. A few habits will make it smoother:

  • Write down your resource names, endpoint URLs, and keys as you create them. You will need them repeatedly.
  • Prefer free tiers where they exist, and delete resources you are not using so you do not accumulate charges.
  • When a step fails, read the error message and fix the specific value — usually a region, a name, or a quota — rather than starting over.
