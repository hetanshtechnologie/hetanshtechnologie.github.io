Lab - Creating an Azure AI Content Safety resource

Before any moderation code can run, you need an Azure AI Content Safety resource. The resource holds your endpoint and keys, tracks usage for billing, and is the home for blocklists and custom configuration. In this lab you will create a Content Safety resource in the Azure portal and with the Azure CLI, then collect the values your code will need.

Prerequisites

  • An Azure subscription. If you do not have one, create a free account before starting.
  • Access to the Azure portal at portal.azure.com.
  • Optionally, the Azure CLI installed locally for the command-line path.

Creating the Resource in the Portal

Step 1 — Start the create flow

  1. Sign in to the Azure portal.
  2. Select Create a resource from the top-left corner.
  3. Search for Content Safety and choose Azure AI Content Safety from the results.
  4. Select Create to open the creation blade.

Step 2 — Fill in the basics

  1. Subscription: pick the subscription that will own the resource.
  2. Resource group: choose an existing group or select Create new and give it a name such as rg-ai103.
  3. Region: choose a region close to your users, for example East US or West Europe.
  4. Name: enter a globally unique name such as cs-ai103-demo.
  5. Pricing tier: select the Free F0 tier if it is available in your region, otherwise choose the standard tier.

Step 3 — Create and verify

  1. Select Review + create, then Create.
  2. Wait for the deployment to finish, then select Go to resource.
  3. On the resource overview page, confirm that the endpoint URL and keys are visible.

The free tier has rate and monthly limits. If you hit errors during testing, check whether you have exceeded the free quota before assuming a problem with your code.

Creating the Resource with the Azure CLI

If you prefer automation, the same resource can be created from a terminal. Run each command from a shell where you are signed in with az login.

# Sign in and set the target subscription
az login

# Create a resource group
az group create --name rg-ai103 --location eastus

# Create the Content Safety resource
az cognitiveservices account create \
  --name cs-ai103-demo \
  --resource-group rg-ai103 \
  --kind ContentSafety \
  --sku F0 \
  --location eastus

After creation, list the keys and endpoint:

# Show the endpoint
az cognitiveservices account show \
  --name cs-ai103-demo \
  --resource-group rg-ai103 \
  --query properties.endpoint

# Show the keys
az cognitiveservices account keys list \
  --name cs-ai103-demo \
  --resource-group rg-ai103

The output gives you everything your code needs: an endpoint URL and a set of keys.

Collecting the Connection Values

No matter how you created the resource, you need two values before moving on:

  • Endpoint: the HTTPS URL shown in Keys and Endpoint, for example https://cs-ai103-demo.cognitiveservices.azure.com/.
  • Key 1 or Key 2: one of the two access keys. Either works; rotate between them when you manage credentials.

Treat keys like passwords. Store them in a key vault or environment variable, never in source control. In these labs you will use placeholder values such as YOUR_ENDPOINT and YOUR_KEY — substitute your real values when you run the code.

What Next

With the resource created you can move in several directions:

  • Open the resource in Content Safety Studio to test moderation interactively (the next lab).
  • Call the REST API or SDK directly from code to analyze text and images.
  • Create a blocklist for deterministic term filtering as described in the previous chapter.

Summary

An Azure AI Content Safety resource is the foundation for all moderation work. You created one through the portal and the CLI, and you collected the endpoint and key values that every later lab depends on. Keep these values handy — the remaining Content Safety labs assume you have them.
