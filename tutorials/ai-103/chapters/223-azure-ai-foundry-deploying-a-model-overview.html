Azure AI Foundry - Deploying a model - Overview

Exploring models is browsing; deploying a model makes it callable. When you deploy a model in Foundry, you create a dedicated endpoint for that model, with a name, a region, and a rate limit, and from that moment your code can call it exactly like the OpenAI chat API you practiced with earlier. This chapter explains what a deployment really is and the choices you make when creating one.

What a Deployment Is

A deployment is a specific model version, bound to a named endpoint, running on capacity you control. Before you deploy, the model is a file in the catalog — an idea. After you deploy, it is infrastructure: an endpoint that accepts requests, applies your configuration, and returns responses.

The deployment has three identity facts your code needs:

  • Endpoint URL: the base address of the model service (for example https://ai103-hub.cognitiveservices.azure.com).
  • Deployment name: the name you give this deployment (for example ai103-chat-deploy). It is part of the request URL.
  • API version: the version of the API contract you are calling (for example 2024-06-01).

On Azure, the deployment name and the model name are different things. The model is gpt-4o-mini (the catalog entry); the deployment is ai103-chat-deploy (your endpoint's name). Your code refers to the deployment name — so choose it deliberately, because changing it later means changing your code.

Tokens per Minute and Quota

Every standard deployment has a rate limit, expressed as tokens per minute (TPM). This is the speed limit of your endpoint: requests beyond it are throttled or rejected. Your subscription's quota in the region is the total pool of TPM you can allocate across deployments.

For course-scale work, set the TPM small — the lowest option the portal offers. This keeps your deployments inside quota, and rate limits will never be hit by a handful of lab requests. If you later run a real workload, raise the TPM (and accept the higher cost ceiling) deliberately.

Content Filtering on Deployments

When you create a deployment you choose a content-filtering configuration. The default applies standard filters across harm categories to both input and output; you can also select a stricter or more lenient profile. These filters are evaluated on every request and response, and a blocked response arrives with a content-filter reason in the API response rather than normal content.

Keep the default content filtering for this course. Later chapters cover how to tune it and how to use Azure AI Content Safety as a second layer — changing the deployment filter now only adds variables to your first experiments.

Pricing Modes

The catalog offers different deployment billing modes; the two you will see for chat models are:

ModeHow you payWhen to use it
Standard (pay-as-you-go)Per token usedVariable, low-to-medium workloads — including all labs
Provisioned throughputReserved capacity, fixed monthly priceHigh, steady, latency-sensitive production traffic

Some models also offer a free tier with strict rate limits — the ideal choice for this course where it is available in your region.

Never pick provisioned throughput for learning. It reserves and bills capacity continuously whether you use it or not. Standard pay-as-you-go costs money only when requests actually flow, which for lab-scale usage is effectively nothing — but you should still delete deployments when you finish.

What Happens at Deployment Time

When you click deploy, Foundry allocates capacity in the underlying model service, provisions the endpoint, and attaches your configuration. The deployment appears in the project's Deployments page with a status that moves from provisioning to ready. Once ready, it is immediately callable from:

  • The playground, for interactive testing.
  • curl or any HTTP client, using your endpoint and key.
  • Python or other SDKs, using the OpenAI-compatible client pointed at your endpoint.

Every one of those paths uses the same deployment name, endpoint, and key — which is why the lab that follows collects all three carefully.

Summary

Deploying a model creates a named, rate-limited, content-filtered endpoint in your model service, billed per token under standard pricing or by reserved capacity under provisioned. The identity of your endpoint is its URL, deployment name, and API version; your code depends on all three. In the next lab you will create your first real deployment and call it from the playground, curl, and Python.
