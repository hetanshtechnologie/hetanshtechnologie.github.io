Lab - AI Enrichment and Skillsets

In this lab you turn your keyword-only index into a semantic one. You will create a skillset that splits each document into chunks and embeds every chunk with a deployed embedding model, then attach it to a new indexer and verify that the index now holds vectors. When you finish, your search service can match on meaning, not just exact words.

What You Need Before Starting

  • The data source docs-datasource and the populated blob container.
  • A deployed embedding model, for example text-embedding-3-small, in a Foundry or Azure OpenAI resource. Note its endpoint and a key with access to the deployment.
  • The search service name, admin key, and resource group variables.
  • The azure-search CLI extension installed.

Enrichment invokes paid services. Each chunk you embed is a separate model call billed against your embedding deployment, and the text-split step runs within the search service tier you chose. For the few sample documents in this lab the cost is trivial, but the pattern matters: review spending before running skillsets over large corpora.

Step 1 - Create a Chunked Index

A skillset that splits and embeds needs an index where each chunk is its own document, not one document per blob. Save this as index-chunked.json:

{
  "name": "docs-index-chunked",
  "fields": [
    { "name": "id", "type": "Edm.String", "key": true, "searchable": false, "retrievable": true },
    { "name": "content", "type": "Edm.String", "searchable": true, "retrievable": true },
    { "name": "embedding", "type": "Collection(Edm.Single)", "searchable": true, "retrievable": false, "dimensions": 1536, "vectorSearchConfiguration": "docs-vector-profile" },
    { "name": "metadata_storage_name", "type": "Edm.String", "searchable": false, "filterable": true, "retrievable": true },
    { "name": "metadata_storage_path", "type": "Edm.String", "searchable": false, "filterable": true, "retrievable": true }
  ],
  "vectorSearch": {
    "algorithmConfigurations": [
      {
        "name": "docs-hnsw",
        "kind": "hnsw",
        "hnswParameters": { "metric": "cosine", "m": 16, "efConstruction": 400, "efSearch": 500 }
      }
    ],
    "profiles": [
      { "name": "docs-vector-profile", "algorithm": "docs-hnsw" }
    ]
  }
}

Create it with the same command pattern you used for the first index:

az search index create `
  --service-name $searchName `
  --resource-group $rg `
  --admin-key $adminKey `
  --name docs-index-chunked `
  --index-json (Get-Content -Raw index-chunked.json)

Step 2 - Write the Skillset

The skillset chains two skills. The split skill breaks each document's text into pages of a chosen length; the embedding skill turns each page into a 1536-dimension vector. Save this as skillset.json, replacing the model endpoint and key with your deployment values:

{
  "name": "docs-skillset",
  "description": "Chunks document text and embeds each chunk",
  "skills": [
    {
      "@odata.type": "#Microsoft.Skills.Text.SplitSkill",
      "name": "split-skill",
      "context": "/document",
      "textSplitMode": "pages",
      "maximumPageLength": 3000,
      "defaultLanguageCode": "en",
      "inputs": [
        { "name": "text", "source": "/document/content" }
      ],
      "outputs": [
        { "name": "textItems", "targetName": "pages" }
      ]
    },
    {
      "@odata.type": "#Microsoft.Skills.Text.AzureOpenAIEmbeddingSkill",
      "name": "embed-skill",
      "context": "/document/pages/*",
      "resourceUri": "https://YOUR_OPENAI_ENDPOINT.openai.azure.com",
      "deploymentId": "text-embedding-3-small",
      "apiKey": "YOUR_OPENAI_KEY",
      "inputs": [
        { "name": "text", "source": "/document/pages/*/text" }
      ],
      "outputs": [
        { "name": "embedding" }
      ]
    }
  ]
}

Create the skillset:

az search skillset create `
  --service-name $searchName `
  --resource-group $rg `
  --admin-key $adminKey `
  --name docs-skillset `
  --skillset-json (Get-Content -Raw skillset.json)

The split skill also emits document_common_ancestor_id and a per-page document_id on each page. The indexer mappings below use those values to build stable chunk keys, which keeps each chunk a unique search document while still pointing back at the source file.

Step 3 - Create the Enriched Indexer

The indexer now references the skillset and maps the enriched outputs into the chunked index. Save this as indexer-enriched.json:

{
  "name": "docs-indexer-enriched",
  "dataSourceName": "docs-datasource",
  "targetIndexName": "docs-index-chunked",
  "skillsetName": "docs-skillset",
  "parameters": {
    "batchSize": 10,
    "maxFailedItems": 10,
    "maxFailedItemsPerBatch": 10
  },
  "outputFieldMappings": [
    { "sourceFieldName": "/document/pages/*/document_common_ancestor_id", "targetFieldName": "id" },
    { "sourceFieldName": "/document/pages/*/text", "targetFieldName": "content" },
    { "sourceFieldName": "/document/pages/*/embedding", "targetFieldName": "embedding" },
    { "sourceFieldName": "/document/metadata_storage_name", "targetFieldName": "metadata_storage_name" },
    { "sourceFieldName": "/document/metadata_storage_path", "targetFieldName": "metadata_storage_path" }
  ]
}

Create and run it:

az search indexer create `
  --service-name $searchName `
  --resource-group $rg `
  --admin-key $adminKey `
  --name docs-indexer-enriched `
  --indexer-json (Get-Content -Raw indexer-enriched.json)

az search indexer run `
  --service-name $searchName `
  --resource-group $rg `
  --admin-key $adminKey `
  --name docs-indexer-enriched

Step 4 - Verify the Enrichment

Wait a few seconds, then check the run result and the document count. Because each blob is now split into multiple chunks, the count should be several times larger than your number of files:

az search indexer show `
  --service-name $searchName `
  --resource-group $rg `
  --admin-key $adminKey `
  --name docs-indexer-enriched

az rest --method get `
  --uri "https://$searchName.search.windows.net/indexes/docs-index-chunked/stats?api-version=2023-11-01" `
  --headers "api-key=$adminKey"

Finally, pull one document and confirm the embedding field is populated with numbers:

az rest --method post `
  --uri "https://$searchName.search.windows.net/indexes/docs-index-chunked/search?api-version=2023-11-01" `
  --headers "api-key=$adminKey" `
  --body '{"search": "*", "top": 1, "select": "id,content,metadata_storage_name"}'

Querying * matches everything; the returned document should have a short content — a chunk, not a whole file — which proves the split ran.

If you see errors in the indexer's lastResult, the most frequent causes are a mistyped deployment name, a key that cannot reach the embedding deployment, or a region mismatch between the search service and the model resource. Fix the value in the skillset, then reset and rerun the indexer: az search indexer reset followed by az search indexer run.

Troubleshooting

SymptomLikely causeFix
Embedding skill errors on every documentModel endpoint, deployment, or key wrongVerify the deployment id and key, then reset and rerun.
Document count is 0Indexer never ran or failed earlyCheck lastResult; run az search indexer reset then run again.
Embedding dimension mismatchModel output differs from dimensionsSet dimensions to 1536 for text-embedding-3-small.
Chunks missingText split output path wrongConfirm the split output target pages matches the embedding skill's context.

Summary

You created a chunked index, a skillset that splits and embeds every document, and an enriched indexer that maps the skill outputs into the index. The index now stores meaningful chunks with vectors, ready for semantic and hybrid search. The next chapter shows how an agent uses this index to ground its answers.
