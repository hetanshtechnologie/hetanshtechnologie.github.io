Lab - Azure AI Foundry - Deploying a model

This lab deploys your first real model in Azure AI Foundry and then calls it from three places: the playground, the command line, and Python. When you finish, you will hold the endpoint, deployment name, and key that every later chapter reuses, and you will have repeated the create-test-cleanup cycle that the rest of the course is built on.

What You Will Need

  • The hub and project from the earlier lab (ai103-hub and ai103-project).
  • Your endpoint URL and one key, from the model service's Keys and Endpoint page in the Azure portal.
  • A chat-completion model chosen from the catalog that is available in your region with a free or standard tier.
  • Python 3.9 or newer and the openai package installed (pip install openai).

Pay-as-you-go deployments are billed per token, and lab traffic is tiny — fractions of a cent. The real cost risk is leaving the deployment running forever. Follow the cleanup step at the end and delete the deployment when you are done, or your account will quietly accrue small charges over time.

Step 1: Deploy the Model

Exercise 1: Deploy a chat model to an endpoint

  1. In the Foundry portal, open your project and click Model catalog.
  2. Filter to chat completion and choose a general-purpose model available in your region (for example a GPT family model).
  3. Open the model card, read the summary, and click Deploy (or Deploy to endpoint).
  4. Set the deployment name to ai103-chat-deploy. Type it exactly — your code will reference this string.
  5. Choose your region and the smallest capacity option. Prefer a free tier if one is offered; otherwise standard pay-as-you-go.
  6. Leave content filtering at its default.
  7. Click Deploy and wait for the status to change to Ready on the Deployments page.
  8. Open the deployment and note its Endpoint URL and Deployment name.

If deployment fails, the error usually names the problem: region availability or quota. Try a smaller sibling model or a different region — do not change your resource group or project to work around it.

Step 2: Test in the Playground

Before writing code, confirm the endpoint is healthy from the playground:

  1. Open Playground in the left menu.
  2. Select ai103-chat-deploy from the model dropdown.
  3. Send the prompt "Explain the difference between a deployment name and a model name in one sentence."
  4. Move the temperature slider and resend. Notice the same prompt can produce different wording — sampling in action.

The playground calls the exact endpoint your code will use. If the playground works, your deployment is healthy; if your code then fails, the bug is in the code or the connection values, not the deployment.

Step 3: Call the Deployment with curl

Now verify the endpoint from outside the portal. Replace YOUR_ENDPOINT, YOUR_KEY, and YOUR_DEPLOYMENT_NAME with your own values. On Windows PowerShell, put the JSON body in a file to avoid quoting problems:

# request-body.json
{
  "messages": [
    {"role": "system", "content": "You are a concise study assistant."},
    {"role": "user", "content": "List three steps to deploy a model in Foundry."}
  ],
  "temperature": 0.7,
  "max_tokens": 120
}
# Call the deployment (Windows PowerShell)
curl.exe "https://YOUR_ENDPOINT/openai/deployments/YOUR_DEPLOYMENT_NAME/chat/completions?api-version=2024-06-01" `
  -H "api-key: YOUR_KEY" `
  -H "Content-Type: application/json" `
  -d "@request-body.json"
# Same call on macOS or Linux in one line
curl "https://YOUR_ENDPOINT/openai/deployments/YOUR_DEPLOYMENT_NAME/chat/completions?api-version=2024-06-01" \
  -H "api-key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"system","content":"You are a concise study assistant."},{"role":"user","content":"Say hello in five words."}],"max_tokens":50}'

A healthy response contains a choices array with the model's text and a usage block with token counts. An authentication error points at the key; a 404 points at the deployment name or API version.

Step 4: Call the Deployment from Python

Save the following as chat_demo.py. It reads your credentials from environment variables so the key never sits in the source file:

import os
from openai import AzureOpenAI

endpoint = os.environ["AZURE_OPENAI_ENDPOINT"]
api_key = os.environ["AZURE_OPENAI_KEY"]
deployment = os.environ["AZURE_OPENAI_DEPLOYMENT"]

client = AzureOpenAI(
    azure_endpoint=endpoint,
    api_key=api_key,
    api_version="2024-06-01",
)

messages = [
    {"role": "system", "content": "You are a friendly tutor."},
    {"role": "user", "content": "What is a token in a language model?"},
]

response = client.chat.completions.create(
    model=deployment,
    messages=messages,
    temperature=0.5,
    max_tokens=150,
)

print(response.choices[0].message.content)
print("Tokens used:", response.usage.total_tokens)

Set the environment variables and run it:

# Windows PowerShell
$env:AZURE_OPENAI_ENDPOINT = "https://YOUR_ENDPOINT"
$env:AZURE_OPENAI_KEY = "YOUR_KEY"
$env:AZURE_OPENAI_DEPLOYMENT = "ai103-chat-deploy"
python chat_demo.py

# macOS / Linux
export AZURE_OPENAI_ENDPOINT="https://YOUR_ENDPOINT"
export AZURE_OPENAI_KEY="YOUR_KEY"
export AZURE_OPENAI_DEPLOYMENT="ai103-chat-deploy"
python chat_demo.py

Notice the key is never typed into the script. The environment-variable pattern is the minimum bar for keeping secrets out of code. Once this works, you have a complete, reusable calling pattern for every model you deploy in the course.

Step 5: Inspect the Response

Print the full response object once to see what the API returns:

  • choices[0].message.content — the generated text your app uses.
  • choices[0].finish_reason — why generation stopped (stop naturally, length when the cap was hit, or a filter reason).
  • usage.prompt_tokens and usage.completion_tokens — the basis of your per-token cost.

If finish_reason is length, the output was cut off. Production code should detect this and tell the user the answer was truncated rather than silently presenting an incomplete answer.

Step 6: Clean Up

When you finish, delete the deployment unless you are immediately continuing:

  1. Open Deployments in your project.
  2. Select ai103-chat-deploy and choose Delete.
  3. Confirm. The catalog entry stays available; you can redeploy any time.
# Optional: delete via Azure CLI
az cognitiveservices account deployment delete \
  --resource-group rg-ai103 \
  --name YOUR_MODEL_SERVICE_NAME \
  --deployment-name ai103-chat-deploy

Summary

You deployed a chat model to a named endpoint, verified it in the playground, called it with curl, called it from Python through environment-variable credentials, read its response structure, and cleaned up. You now hold the endpoint, deployment name, and key that power the rest of the course, plus a Python pattern you will reuse dozens of times. Next you will practice more with the playground.
