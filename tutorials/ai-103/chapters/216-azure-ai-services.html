Azure AI services

Azure does not offer a single AI feature — it offers a family of them. Azure AI services are managed, pre-built AI capabilities you call through simple APIs or connect to inside the Foundry platform. This chapter maps the family, so you understand what exists, what each service is for, and which ones this course actually uses.

What Azure AI Services Are

An Azure AI service is a managed capability that packages machine learning behind a REST API and an SDK. Microsoft trains or hosts the models, runs the infrastructure, and exposes predictable endpoints. You do not train anything; you call the service with an API key and an endpoint, and receive results. This is the opposite of building a model from scratch — it is consuming AI as a utility.

Two flavors of AI services exist. Pre-built services offer fixed capabilities — language understanding, speech recognition, image analysis — out of the box. Generative model services offer foundation models you prompt and deploy, most prominently through Azure OpenAI Service. Modern generative applications typically combine both: a foundation model handles the open-ended reasoning while pre-built services handle the specialized, high-accuracy tasks.

How the Services Fit Together

Real applications rarely use a single service. A typical generative application in this course stacks them:

  • Azure OpenAI Service powers the chat model that answers questions.
  • Azure AI Search finds relevant passages in your documents so the model can answer from your data (retrieval-augmented generation).
  • Azure AI Document Intelligence turns uploaded PDFs into usable text.
  • Azure AI Content Safety screens both user input and model output.
  • Azure AI Foundry ties it together, manages the deployments, and evaluates quality.

You do not need to memorize every service now. The course introduces each one in context. For now, the important mental model is: one platform (Foundry) for building, and a set of specialized services you plug in as the application requires.

Service Keys and Endpoints

Every AI service resource you create exposes two connection facts: an endpoint (the URL where the API lives, like https://YOUR_RESOURCE.cognitiveservices.azure.com) and keys (secrets used to authenticate calls). You will find both under Keys and Endpoint on the resource's page in the Azure portal.

Treat keys like passwords:

  • Never commit keys to source code or paste them into public forums.
  • Prefer the Azure identity system where possible instead of key-based authentication.
  • If a key leaks, rotate it from the portal — the old key stops working immediately.

For the labs you will copy a key into a local configuration file or environment variable. That is fine on your own machine. The moment a file containing a key is destined for a shared repository, replace the literal key with a placeholder and load the real value from an environment variable.

How AI Services Are Charged

Pricing models vary by service, but three patterns dominate:

  • Per call or per unit: a fixed price per API request or per quantity processed, such as per 1,000 characters of text.
  • Per token: generative models bill based on the tokens sent in the prompt plus the tokens generated in the response.
  • Provisioned throughput: you reserve a fixed amount of capacity for a steady price, used by high-volume workloads.

Generative billing deserves particular attention because cost grows with usage: a long document summarized by a large model costs more than a short reply. The labs keep you in free tiers and small requests, but every deployment you leave running is potentially billable.

Summary

Azure AI services are managed AI capabilities — pre-built models and generative platforms — accessed through endpoints and keys, priced per call, per token, or per reserved capacity. Foundry is the platform, Azure OpenAI hosts the generative models, and specialized services handle language, speech, vision, documents, search, and safety.
