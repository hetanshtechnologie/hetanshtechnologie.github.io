What are the objectives we are going to cover in this section

The previous section taught you how to give an agent tools. This section turns to a different problem: making an agent remember. A model call is stateless, but a useful assistant must recall what you said earlier, hold context across turns, and keep preferences between sessions. This short chapter sets out the objectives and roadmap for that topic.

The Objectives of This Section

  • Understand state: explain why model APIs are stateless and where state must come from.
  • Model conversations: describe how conversation history, sessions, and context windows relate to one another.
  • Explain memory: distinguish memory types and scope, and describe the lifecycle of memory in an agent.
  • Design for persistence: decide what an agent should remember, for how long, and where it should store it.
  • Apply the concepts: use these ideas to make a Foundry agent carry context across turns and sessions.

What You Will Build

Over the coming chapters you will work with an agent that remembers: it follows up on earlier answers, recalls details you gave it in previous turns, and keeps working context alive across a session. The pattern you study here is the foundation of the CloudXeus course assistant, which must remember what a learner asked earlier in the course.

How This Section Is Organised

  1. A lecture on state, conversations, session context, and memory, defining the core vocabulary.
  2. A lecture on how memory works: its lifecycle, the memory types, and the scope of each.
  3. Hands-on chapters that show memory in a real agent and how to control what it retains.

Prerequisites

  • A Foundry project with a deployed chat model.
  • The agent-building patterns from the earlier sections, including how to run an agent loop.
  • Familiarity with the idea of stateless API calls and the conversation array you have been sending.

What You Should Be Able to Do at the End

  • Explain, in your own words, why an LLM call forgets everything after each reply.
  • Describe the difference between a session, conversation history, and persistent memory.
  • Name the memory types and the scope each one is suited for.
  • Trace the lifecycle of a memory from capture to retrieval to removal.
  • Configure an agent so it holds context across turns without leaking data between users.

None of this requires retraining a model. Memory is an engineering layer around stateless calls: the code decides what to keep, how long to keep it, and what to send back into the context window.

Summary

This section makes your agents remember. The objectives are concrete: understand state, model conversations, explain memory types and lifecycle, and apply them in a Foundry agent. The next chapter starts with the core distinction between state, conversations, session context, and memory.
