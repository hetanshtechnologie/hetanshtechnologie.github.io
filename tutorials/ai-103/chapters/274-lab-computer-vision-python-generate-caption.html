Lab - Computer Vision - Python - Generate caption

Tagging gives you individual words; captioning gives you sentences. In this lab you will ask your Computer Vision resource to generate a natural-language description of an image. Captions power accessibility features — the auto-generated alt text that screen readers announce — and are a handy building block for describing photos in any application.

What You Need

  • Your Computer Vision endpoint and key.
  • Python 3 with the requests package installed.
  • A local test image named test.jpg.

Write the Captioning Code

The script is nearly identical to the tagging lab — only the features value and the parsed field change.

import os
import requests

ENDPOINT = os.environ["COMPUTER_VISION_ENDPOINT"]
KEY = os.environ["COMPUTER_VISION_KEY"]

ANALYZE_URL = ENDPOINT.rstrip("/") + "/computervision/imageanalysis:analyze"
params = {
    "api-version": "2024-02-01",
    "features": "caption",
}

with open("test.jpg", "rb") as f:
    image_data = f.read()

headers = {
    "Content-Type": "application/octet-stream",
    "Ocp-Apim-Subscription-Key": KEY,
}

response = requests.post(ANALYZE_URL, params=params, headers=headers, data=image_data)
response.raise_for_status()

caption = response.json()["captionResult"]["text"]
confidence = response.json()["captionResult"]["confidence"]
print(f"Caption: {caption}")
print(f"Confidence: {confidence:.2f}")

Run and Observe

Exercise 1: Generate a caption for a local image

  1. Save the script as vision_caption.py.
  2. Set COMPUTER_VISION_ENDPOINT and COMPUTER_VISION_KEY in your terminal, then run python vision_caption.py.
  3. Read the printed caption. Does it describe the main subject and setting correctly?
  4. Run the script against several images. Try a close-up of a single object, a busy street scene, and a dark or blurry photo. Note how the caption quality changes as the image gets more complex.

Captions describe the most prominent subject of the image. If you want a caption about something specific — a person in the background, or text on a sign — tags and object detection are the better tool, because they return the individual elements you can then reason about.

How the Response Is Structured

The caption arrives in its own block, separate from the tags block you parsed earlier:

{
  "metadata": {"width": 640, "height": 480},
  "captionResult": {
    "text": "a person standing on a mountain looking at a lake",
    "confidence": 0.91
  }
}

Two values matter here:

  • text — the generated sentence describing the image.
  • confidence — how certain the service is about the caption. Treat low-confidence captions with suspicion.

Requesting Caption and Tags Together

Features are not mutually exclusive. You can request several at once by separating them with commas, and the response will contain a block for each:

params = {
    "api-version": "2024-02-01",
    "features": "caption,tags",
}

result = response.json()
print(result["captionResult"]["text"])
for tag in result["tagsResult"]["values"]:
    print(f"{tag['name']:<20} {tag['confidence']:.2f}")

Each feature you add increases the amount of processing and therefore the cost of the call. Request only the features your workflow actually consumes.

Using Captions in an Application

A caption is a natural fit for generating alt text, building image search descriptions, or letting users preview photos without seeing them. When you display a caption, always pair it with the confidence value so downstream code can decide whether to show it, hide it, or ask a human to rewrite it.

Never present a generated caption as fact. The model can misdescribe an image, especially when faces or text are involved. In accessibility features, a wrong caption is worse than none — it actively misleads the reader.

Summary

You called the Image Analysis caption feature from Python, read the generated sentence and its confidence score, and learned how to combine captioning with tagging in a single request. The same analyze endpoint with a different feature list powers the remaining vision labs.
