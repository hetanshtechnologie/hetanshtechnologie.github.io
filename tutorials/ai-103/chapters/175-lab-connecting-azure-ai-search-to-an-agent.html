Lab - Connecting Azure AI Search to an Agent

Your index holds enriched, searchable chunks. This lab connects it to an agent so you can hold a conversation grounded in your documents. You will create an agent in Azure AI Agent Service, attach the search index as a tool, and watch the model decide to search, read the results, and answer with sources.

What You Need Before Starting

  • The chunked index docs-index-chunked with vectors from the enrichment lab.
  • A Foundry project and its connection string (found on the project overview page).
  • A deployed chat model, such as gpt-4o-mini, in that project.
  • Python 3.9 or later with a virtual environment, and the packages installed: 
    pip install azure-ai-projects azure-identity

The code below authenticates with DefaultAzureCredential, which works with az login from the Azure CLI. When you run the script locally, sign in first with az login so the credential can obtain a token for your subscription.

Step 1 - Understand the Tool Definition

The search index tool tells the agent that a searchable index exists. It carries the index name and, in this simple setup, a search key for access. During a conversation the agent decides when to call the tool and what to search for; the platform performs the request and hands the top chunks back as tool output.

Putting an API key in the tool definition is fine for a local lab. For production, remove the key and give the agent's identity a role such as Search Index Data Reader on the search service instead — the pattern used later in the capstone project's permissions chapter.

Step 2 - Write the Agent Script

Save the following as agent_search.py and replace the three placeholders with your project connection string, index name, and search key:

from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import SearchIndexTool
from azure.identity import DefaultAzureCredential

conn_str = "YOUR_PROJECT_CONNECTION_STRING"
index_name = "docs-index-chunked"
search_api_key = "YOUR_SEARCH_API_KEY"

project = AIProjectClient.from_connection_string(
    conn_str=conn_str,
    credential=DefaultAzureCredential(),
)

tool = SearchIndexTool(
    index={"index_name": index_name, "api_key": search_api_key}
)

agent = project.agents.create_agent(
    model="gpt-4o-mini",
    name="docs-assistant",
    instructions=(
        "You are a support assistant that answers from the course documents. "
        "Answer only using the search results you are given. "
        "If the results do not contain the answer, say that you could not find it. "
        "Always name the source file you are citing."
    ),
    tools=[tool.definition],
)

thread = project.agents.create_thread()

project.agents.create_message(
    thread_id=thread.id,
    role="user",
    content="How do I reset the device to factory defaults?",
)

run = project.agents.create_and_process_run(
    thread_id=thread.id,
    agent_id=agent.id,
)

messages = project.agents.list_messages(thread_id=thread.id)
for message in messages.data:
    if message.role != "assistant":
        continue
    for item in message.content:
        if hasattr(item, "text"):
            print(item.text.value)
        elif hasattr(item, "tool_call"):
            print("[tool call]", item.tool_call.tool_name)

Step 3 - Run and Observe the Search

Run the script from your virtual environment:

python agent_search.py

The printed output should include two things: a tool call line showing the agent searched the index, and an assistant answer that cites a source file and stays within the retrieved content.

Turn on tracing if you want to see the exact query the model chose and the chunks that were retrieved:

pip install azure-monitor-opentelemetry azure-ai-projects[telemetry]

Then inspect the tool call arguments in the trace to judge whether the model composed good search terms.

Step 4 - Try Questions That Need No Search

The point of an agent is that it decides. Ask a greeting — "Hi, what can you help me with?" — and then a grounded question. The first should not trigger a tool call; the second should. If the agent searches on the greeting, tighten the instructions so it only queries when the index is actually needed.

Step 5 - Create the Same Agent in the Portal (Optional)

To see the same wiring without code: open your Foundry project, create an agent, choose your chat model, then add an Index connection pointing at docs-index-chunked. Set the same grounding instructions in the agent's system message and chat in the playground. The portal path and the SDK path configure the same capabilities.

If you use the portal's index connection instead of the code tool, retrieval may run automatically for every message rather than at the model's discretion. That is fine for demo purposes; the code tool is what gives you the explicit control most production agents need.

Troubleshooting

SymptomLikely causeFix
Script exits with a credential errorNo Azure token availableRun az login and retry.
Agent never calls the toolInstructions too vague or no tool attachedConfirm tools=[tool.definition] and describe when to search.
Index not found in tool callIndex name or key mismatchVerify index_name and the key via az search index list.
Answers not groundedModel answers from trainingStrengthen the instruction to answer only from results.
Empty result setIndex empty or terms absentCheck documentCount; re-run the enrichment indexer.

Summary

You attached your chunked search index to an agent as a tool, ran a grounded conversation from Python, verified the model both searched and cited sources, and reproduced the setup through the portal. Your agent now answers from your documents instead of its training data. The next chapter is the section quiz that reviews the whole search arc.
