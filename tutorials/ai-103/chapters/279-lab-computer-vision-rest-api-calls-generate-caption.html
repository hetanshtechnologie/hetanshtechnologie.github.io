Lab - Computer Vision - REST API Calls - Generate caption

You have now generated captions from Python and explored requests from Visual Studio Code. In this lab you make the caption call in its purest form: raw REST, with no SDK and no helper script. You will send an HTTP POST to the Image Analysis endpoint with the caption feature and read the JSON that comes back. This is exactly the traffic your Python code produced under the hood, and it is the fastest way to understand what the service expects and returns.

Anatomy of the Request

Every caption request has the same shape:

  • A POST to /computervision/imageanalysis:analyze on your resource endpoint.
  • A query string with the API version and the requested feature: ?api-version=2024-02-01&features=caption.
  • Two headers: Content-Type telling the service how the image is provided, and Ocp-Apim-Subscription-Key carrying your key.
  • A body containing the image, either as raw bytes or as a public URL in JSON.

Generate a Caption with cURL

From a terminal, sending an image URL is a single command. Fill in your own endpoint and key:

curl -X POST \
  "https://YOUR_ENDPOINT/computervision/imageanalysis:analyze?api-version=2024-02-01&features=caption" \
  -H "Content-Type: application/json" \
  -H "Ocp-Apim-Subscription-Key: YOUR_KEY" \
  -d '{"url": "https://upload.wikimedia.org/wikipedia/commons/1/1e/Cat_and_dog.jpg"}'

You can also send a file on your machine. cURL reads the file and streams its bytes as the request body:

curl -X POST \
  "https://YOUR_ENDPOINT/computervision/imageanalysis:analyze?api-version=2024-02-01&features=caption" \
  -H "Content-Type: application/octet-stream" \
  -H "Ocp-Apim-Subscription-Key: YOUR_KEY" \
  --data-binary "@C:\path\to\test.jpg"

Generate a Caption with REST Client

The same request in your vision.http file, reusing the variables from the previous lab:

### Generate caption from a URL
POST {{endpoint}}computervision/imageanalysis:analyze?api-version=2024-02-01&features=caption
Content-Type: application/json
Ocp-Apim-Subscription-Key: {{key}}

{
  "url": "{{imageUrl}}"
}

### Generate caption from a local file
POST {{endpoint}}computervision/imageanalysis:analyze?api-version=2024-02-01&features=caption
Content-Type: application/octet-stream
Ocp-Apim-Subscription-Key: {{key}}

< C:\path\to\test.jpg

Read the Response

A successful call returns JSON. The caption is in the captionResult block:

{
  "metadata": {"width": 640, "height": 480},
  "captionResult": {
    "text": "a dog and a cat lying together on a sofa",
    "confidence": 0.92
  }
}

Exercise 1: Send and verify a caption request

  1. Run the cURL command (or the REST Client request) against a public image URL.
  2. Confirm the response status is 200 and the body contains captionResult.
  3. Change the URL in the body to a different public image and send again. Compare the two captions.
  4. Switch the request to send a local file via --data-binary or <, and verify the same response shape.
  5. Remove the features=caption parameter and send once more. Note that the caption block disappears from the response.

If the response has no captionResult, the request was valid but the caption feature was not requested. The features query parameter controls exactly which analysis runs and which blocks appear in the response.

Requesting Both Captions and Tags

Separate features with commas to get both blocks in one call:

curl -X POST \
  "https://YOUR_ENDPOINT/computervision/imageanalysis:analyze?api-version=2024-02-01&features=caption,tags" \
  -H "Content-Type: application/json" \
  -H "Ocp-Apim-Subscription-Key: YOUR_KEY" \
  -d '{"url": "https://upload.wikimedia.org/wikipedia/commons/1/1e/Cat_and_dog.jpg"}'

This response contains both captionResult and tagsResult. The JSON grows with each feature you add, which is why production code requests only what it needs.

Troubleshooting

  • Authentication failed (401): verify the key header is spelled Ocp-Apim-Subscription-Key and the value matches exactly.
  • Invalid endpoint (404): confirm the endpoint includes the scheme and host, and that the path computervision/imageanalysis:analyze is correct.
  • Bad request (400): the JSON body is malformed or the image URL is unreachable from Azure.
  • Unsupported feature (400): the feature name in the query string is misspelled or not available in the API version you chose.

Summary

You generated image captions with raw REST calls using both cURL and REST Client, read the captionResult JSON, and combined caption and tags in a single request. The pattern extends directly to the other features, which you will call in the next lab.
