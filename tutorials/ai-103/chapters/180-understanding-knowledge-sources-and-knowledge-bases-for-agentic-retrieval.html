Understanding Knowledge Sources and Knowledge Bases for Agentic Retrieval

Two terms come up constantly when you build an agent that answers from documents: knowledge source and knowledge base. They are often used as if they were the same thing, but they describe two different stages of the pipeline. This chapter defines both, shows how raw documents become a retrievable knowledge base, and explains the retrieval patterns an agent uses against it.

Knowledge Source: Where the Raw Content Lives

A knowledge source is the original location of your content — the raw material before any AI processing. For the capstone that is the blob container holding the course PDFs, but the same idea covers databases, SharePoint sites, web pages, and APIs. A knowledge source has three defining traits:

  • It holds content in its original format — PDF, table, web page — not yet restructured for search.
  • It is the source of truth: edits happen here, and downstream systems are refreshed from here.
  • It is not directly queryable by an agent in the way a search index is.

You can think of a knowledge source as the library shelf and a knowledge base as the searchable card catalog with its own index, summaries, and pointers back to the shelf. The librarian's job — building and maintaining the catalog — is done by the enrichment pipeline.

Knowledge Base: The Searchable Form

A knowledge base is the processed, queryable version of one or more knowledge sources. It is built by a pipeline that, for each document:

  1. Extracts the text and structure from the source file.
  2. Chunks the content into retrievable pieces.
  3. Embeds each chunk into a vector representation.
  4. Indexes the chunk, vector, and metadata into a search index.

In this course the knowledge base is an Azure AI Search index, exactly the kind built in the search labs. The agent never reads the PDFs; it queries the index, and the index points back at the source file through metadata such as the blob path.

Why the Distinction Matters

Keeping the two concepts separate forces you to think about the pipeline as data flowing through stages. It also clarifies what "updating the assistant's knowledge" means: you do not change the model, you change the source and re-run the pipeline that rebuilds the knowledge base. The model and the agent stay identical while the knowledge changes.

A common production mistake is pointing an agent directly at raw documents and asking the model to read them. That fails at scale: files are too large for context windows, no relevance ranking exists, and every answer re-reads everything. The knowledge base exists precisely to solve those problems with fast, ranked retrieval.

Agentic Retrieval: How the Agent Uses the Knowledge Base

Agentic retrieval means the agent participates in the search, rather than a fixed script always running the same query. Two behaviors matter:

  • Decision — the agent judges whether a question needs the knowledge base at all, so greetings and chit-chat skip retrieval.
  • Iteration — the agent can rephrase a weak query, filter results, or search again if the first attempt returns nothing useful.

That is the difference between a RAG script and a RAG agent: the script retrieves unconditionally, the agent retrieves deliberately.

Give the knowledge base a precise description when you attach it to the agent. State what content it covers and when to use it — for example, "Search the course knowledge base when the question is about course topics, labs, or concepts. Returns chunks with source file names." The description is the model's manual for correct use.

Unstructured and Structured Knowledge

Course PDFs are unstructured text — the knowledge base stores their chunks as searchable text with vectors. But knowledge bases can also hold structured data, like tables of scores or dates, where exact filtering matters more than meaning. Most real assistants combine both: an unstructured index for explanations and a structured store for precise lookups.

Permissions Gate the Knowledge Base

A knowledge base is worthless if the pipeline cannot reach the source or the agent cannot reach the index. The capstone dedicates a chapter to permissions because three identities need the right roles: the indexing pipeline reading blobs, the embedding step calling the model, and the agent querying the index. Each is a separate role assignment, and together they are what keep the system secure without embedding secrets in code.

Summary

A knowledge source holds raw content; a knowledge base is its chunked, embedded, searchable form. The pipeline converts one into the other, and an agent queries the knowledge base deliberately — deciding when to search and iterating when necessary.
