Lab - OpenAI - Structured Output - Using the Chat Completions API

The Chat Completions API is the older sibling of the Responses API, but it is still widely used. It also supports structured outputs, configured through the response_format parameter. In this lab you will reproduce the order-issue extraction from the previous lab using Chat Completions, then compare the two approaches.

Setting Up Structured Output

With Chat Completions, the call uses a messages list instead of instructions and input, and the schema is passed through response_format.

Step 1 — Create the script

Create a file named structured_chat.py:

from openai import OpenAI

client = OpenAI(api_key="YOUR_API_KEY")

schema = {
    "type": "object",
    "properties": {
        "customer": {
            "type": "object",
            "properties": {
                "name": {"type": "string"},
                "email": {"type": "string"}
            },
            "required": ["name", "email"],
            "additionalProperties": False
        },
        "order_number": {"type": "string"},
        "issue": {"type": "string"}
    },
    "required": ["customer", "order_number", "issue"],
    "additionalProperties": False
}

email_text = """
Hi, I am Meera. My email is meera@example.com. Order 99211
was billed twice and I need a refund.
"""

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "Extract the requested details from the message."},
        {"role": "user", "content": email_text},
    ],
    response_format={
        "type": "json_schema",
        "json_schema": {
            "name": "order_issue",
            "schema": schema,
            "strict": True
        }
    },
)

print(response.choices[0].message.content)

Step 2 — Run it

python structured_chat.py

The response should again be clean JSON following your schema.

Reading the Result

Chat Completions places the JSON in the assistant message's content. Parsing works the same way as before:

import json

payload = json.loads(response.choices[0].message.content)
print("Customer:", payload["customer"]["name"])
print("Order:", payload["order_number"])

Some environments (especially with tool calling) return the content inside message.tool_calls[0].function.arguments instead. If message.content is empty, check whether a tool call carried the JSON.

The schema itself and the strictness rules are nearly identical; only the transport differs.

Handling a Parsing Failure

Even with structured outputs, defensive code is cheap. Wrap the parse in a try/except so a malformed payload fails loudly instead of crashing mid-application:

try:
    payload = json.loads(response.choices[0].message.content)
except json.JSONDecodeError as exc:
    print("Could not parse model output:", exc)
    raise

Structured outputs constrain the format the model emits, but a transport or truncation problem can still produce unusable content. Keep the try/except, and log the raw content whenever parsing fails — the raw text is the first clue for debugging.

Summary

You applied structured output to the Chat Completions API with response_format, parsed the JSON from the assistant message, and compared the setup with the Responses API. You can now choose whichever API fits your existing code while keeping the same schema and guarantees.
