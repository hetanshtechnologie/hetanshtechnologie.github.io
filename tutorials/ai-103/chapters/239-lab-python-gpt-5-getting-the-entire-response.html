Lab - Python - GPT 5 - Getting the entire response

In the previous labs you called the chat completion API and pulled one value out of the result — usually the assistant's message text. But the object the SDK returns holds much more than that single string: metadata, token usage, finish reasons, and sometimes several candidate responses. In this lab you will stop throwing that information away and learn to inspect the entire response object, so you can read exactly what the model produced and how much it cost.

Why the Full Response Matters

When you print a response directly with print(response), most SDKs render a compact, human-readable summary. That hides almost everything. The actual object is a nested structure with several top-level fields, and each one is useful in production code:

FieldWhat it holds
idA unique identifier for the request, useful for correlating logs and support calls.
modelThe deployment or model that produced the answer.
createdA Unix timestamp of when the response was generated.
choicesA list of candidate responses. Each choice contains a message, a finish reason, and an index.
usageToken counts: prompt_tokens, completion_tokens, and total_tokens.

Getting into the habit of inspecting the full response early saves debugging time later. When a deployment misbehaves, the first questions are usually "what finish reason did it return?" and "how many tokens did it consume?" — both live in the response object.

Step 1: Set Up the Script

Exercise 1: Print the complete response as JSON

  1. Create a folder named ai103-lab239 and open it in VS Code.
  2. Create a file called full_response.py.
  3. Set your endpoint and key as environment variables so the script stays free of hard-coded secrets:
$env:AZURE_OPENAI_ENDPOINT = "https://YOUR-RESOURCE.openai.azure.com/"
$env:AZURE_OPENAI_KEY = "YOUR_KEY"
  1. Paste this script and replace YOUR_DEPLOYMENT_NAME with your chat deployment name:
import os
from openai import AzureOpenAI

client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2025-01-01-preview",
)

response = client.chat.completions.create(
    model="YOUR_DEPLOYMENT_NAME",
    messages=[
        {"role": "system", "content": "You are a concise assistant."},
        {"role": "user", "content": "Name three cloud computing benefits."},
    ],
)

print(response.model_dump_json(indent=2))
  1. Run the script:
python full_response.py

The output is the complete response serialized as JSON. Scroll through it and locate the choices and usage sections.

Step 2: Read Individual Fields

Now that you have seen the whole object, practice pulling specific values out of it. Each access follows the same pattern: navigate from response down through the nested structure.

Exercise 2: Extract the pieces you care about

Create inspect_response.py with this code:

import os
from openai import AzureOpenAI

client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2025-01-01-preview",
)

response = client.chat.completions.create(
    model="YOUR_DEPLOYMENT_NAME",
    messages=[
        {"role": "system", "content": "You are a concise assistant."},
        {"role": "user", "content": "Summarize the Agile manifesto in one sentence."},
    ],
)

choice = response.choices[0]
print("Request id :", response.id)
print("Model      :", response.model)
print("Finish     :", choice.finish_reason)
print("Role       :", choice.message.role)
print("Content    :", choice.message.content)
print("Prompt tokens     :", response.usage.prompt_tokens)
print("Completion tokens :", response.usage.completion_tokens)
print("Total tokens      :", response.usage.total_tokens)

python inspect_response.py

Run the script and read each printed line. Note how the fields map one-to-one to the JSON you saw in Exercise 1.

The finish_reason value is worth watching. A normal response ends with stop. A value of length means the model hit the maximum token limit and the answer was cut off. If you see content_filter, the response was stopped by a safety filter — a sign you may need to rephrase the prompt or review your content filter settings.

Step 3: Inspect Multiple Choices

The n parameter asks the model for several candidate answers in a single call. Each candidate appears as a separate entry in the choices list, so you can compare alternatives or pick the best one.

Exercise 3: Request three candidates

Modify inspect_response.py to pass n=3 and then loop over every choice:

response = client.chat.completions.create(
    model="YOUR_DEPLOYMENT_NAME",
    messages=[
        {"role": "system", "content": "You are a concise assistant."},
        {"role": "user", "content": "Suggest a tagline for a coffee shop."},
    ],
    n=3,
)

for i, choice in enumerate(response.choices):
    print(f"Candidate {i}: {choice.message.content}")
    print(f"Finish reason: {choice.finish_reason}")

python inspect_response.py

Run it a few times. Because sampling is random, the three candidates usually differ on every run — even for the same prompt.

Each candidate in a multi-choice request consumes completion tokens. Setting n high is a quick way to multiply your token spend, so reserve it for cases where you genuinely need alternatives and always inspect the usage numbers afterward.

Summary

You learned that a chat completion response is a rich object, not a single string. You serialized the whole response to JSON, extracted the message, finish reason, and token usage field by field, and generated several candidate answers with n=3. This foundation makes the rest of the course easier, because every downstream pattern — including the monitoring you will read about next — depends on reading values out of the response object.
