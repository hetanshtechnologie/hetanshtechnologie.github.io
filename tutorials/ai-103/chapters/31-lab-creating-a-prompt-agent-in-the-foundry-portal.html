Lab - Creating a Prompt Agent in the Foundry Portal

In this lab you will create your first prompt agent using the Foundry portal — no code required. You will define the agent's instructions, choose the model it runs on, and chat with it in the built-in playground to confirm it behaves the way you want. This is the fastest possible path from an idea to a working agent, and it gives you a reference agent you will publish and invoke in the chapters that follow.

Objectives

  • Open your Foundry project and navigate to the agent area.
  • Create a new prompt agent with a model deployment and system instructions.
  • Configure the agent's instructions, input, and output behavior.
  • Test the agent in the chat playground and refine its responses.

Prerequisites

You need a Microsoft Foundry hub and project where you have contributor access, and at least one deployed chat model such as GPT-4o. The previous labs in this course walked through creating those resources.

Step 1: Open the Agents page

Sign in to the Microsoft Foundry portal, open your project, and look for the Agents section in the left navigation. The page lists any agents you have already created and offers a button to create a new one.

Create the agent

  1. In your project, select Agents from the left menu.
  2. Click Create and choose Prompt agent from the options.
  3. Give the agent a name, such as trip-planner.
  4. Select the chat model deployment you created earlier from the model dropdown.

Step 2: Write the agent instructions

The next screen is the agent setup page. The Instructions field is the most important part: it is the system prompt that shapes everything the agent does. Write instructions that state the role, the audience, and the working rules clearly.

Add a working instruction prompt

You are a friendly travel planning assistant for a small agency.
- Help customers build day-by-day itineraries.
- Before recommending anything, ask for their destination, budget,
  number of travelers, and preferred dates.
- Suggest 3 options when a customer is unsure about activities.
- Keep answers under 150 words and end with one clarifying question.
- Never invent hotel or flight prices; use rounded estimates and say
  they are approximate.
  1. Paste the text above into the Instructions field.
  2. Review the default settings for temperature and other sampling controls. A lower temperature makes the agent more consistent, which suits a customer-facing assistant.
  3. Save the agent.

Notice that the instructions do not say what model to use or how to talk to it. The agent's interface is defined by its behavior, not by its plumbing. That separation is why you can iterate on the prompt without touching any application code.

Step 3: Test in the chat playground

The setup page includes a chat panel where you can talk to the agent immediately. Testing here costs the same tokens as any other model call, so treat it as your primary tuning loop.

Chat with the agent

  1. In the chat panel, type: Plan a 4-day trip to Barcelona for a family of three.
  2. Watch the agent respond. It should ask for the clarifying details first, because the instructions demand it.
  3. Answer the clarifying question, for example Budget is around 2000 dollars total.
  4. Verify the follow-up response stays under the word limit and ends with a question.
  5. Ask the same question again and compare the answers. With a low temperature the responses should be broadly consistent.

Step 4: Refine the behavior

Real agents improve through iteration. Try these adjustments and observe the effect:

  • Add a sentence to the instructions forbidding off-topic answers, then ask about the weather in a distant city and watch the agent decline gracefully.
  • Raise and lower the temperature and compare how varied the phrasing becomes.
  • Ask a question that mixes travel and non-travel content to test whether the role boundary holds.

Everything you type in the playground is sent to the model and may appear in telemetry. Do not paste secrets, personal data, or anything confidential into the chat panel, even in an internal test project.

The agent you just created lives inside your Foundry project. It is not yet callable from an application — publishing it to create a version and an endpoint is the topic of an upcoming chapter. For now, you have proven that your prompt produces the behavior you want.

Summary

You created a prompt agent in the Foundry portal, wrote role-defining instructions, attached a chat model deployment, and validated its behavior in the playground. This agent is now the reference implementation for the rest of this section: you will publish it, version it, invoke it from code, and eventually extend it with tools.
