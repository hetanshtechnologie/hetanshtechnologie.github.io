Getting started with Microsoft Foundry

With your Azure subscription ready, it is time to step inside Microsoft Foundry. This chapter covers the first practical moves: how to reach the Foundry portal, how to navigate its home screen, and how to create your first project. By the end you will have a working workspace in which the rest of the course's labs take place.

How to Reach the Foundry Portal

There are two common ways to open Microsoft Foundry, and you will likely use both depending on the day:

  • From the Azure portal: Sign in at https://portal.azure.com, search for AI Foundry, open your resource, and click the button that launches the Foundry web portal.
  • Directly: Navigate to the Foundry portal URL and sign in with the same Microsoft account. Foundry lists the resources you can access and lets you pick one.

The Foundry portal is a separate web application from the Azure portal. Azure manages resources and billing; Foundry manages your AI projects and models. Both share the same login, but they show different content, so do not be surprised when the interface looks nothing like what you saw in Azure.

The Foundry Home Screen

When you first sign in, the portal presents a welcome view with several obvious entry points. Take a minute to recognize what each area is for before you start clicking:

  • All projects: The list of every project across your resources. This is where your work lives.
  • Model catalog: The gallery of deployable models, searchable by publisher, task, and family.
  • Build and iterate: The workspace where you create prompts, agents, and evaluations around your models.
  • Management center: The settings for connections, deployments, and project-level administration.

Most chapters in this course live in the Build and iterate area, while model operations live under the Management center or inside a project's own navigation.

Create Your First Project

A project is the container for a unit of work: the deployments, data connections, and evaluations that belong to one effort. It is also the place where your API keys and endpoints are collected, so every lab in this course starts by opening a project.

Exercise 1: Create a project in Foundry

  1. Open the Foundry portal and sign in with your Microsoft account.
  2. From the home screen, click All projects and then Create project.
  3. Choose an existing Microsoft Foundry resource from the dropdown, or create a new one if you have none.
  4. Give the project a name that describes its purpose, such as ai103-chatbot-lab. The name appears in your code, so keep it short and use only letters, numbers, and hyphens.
  5. Leave the default hub settings alone for now — the defaults point the project at the resource's shared compute and connections, which is exactly what you want while learning.
  6. Click Create. Foundry provisions the project, which typically takes under a minute.
  7. When the project opens, look for the Overview page. Note the project ID and the endpoint values shown — you will paste these into code in later chapters.

Name projects after what they do, not after who you are. ai103-rag-lab tells you and your future self what the project is for; myproject1 tells nobody. Since you can create many projects under one resource, use a new project for each distinct experiment.

Managing Projects from the Command Line

Everything you do in the portal can also be done from the Azure CLI, which is essential when you want repeatable environments. The core project commands follow a consistent pattern:

# Sign in to Azure
az login

# List your Foundry resources
az ai project list --resource-group rg-ai103-rg

# Create a project inside a resource
az ai project create --resource-group rg-ai103-rg \
  --name ai103-project-demo \
  --kind "Project" \
  --display-name "AI-103 Demo Project"

The exact command set evolves as the platform does, so treat the snippet above as a template rather than a scripture — always check az ai project --help on your machine for the current arguments.

What Lives Inside a Project

Once a project exists, it becomes the home for the building blocks you will use in every later chapter:

ItemPurpose
Model deploymentsThe endpoints your code calls for inference.
Data connectionsLinks to storage, indexes, and external data sources.
Prompts and prompt flowsReusable prompt definitions and orchestrated workflows.
AgentsModel-powered assistants with tools and memory.
EvaluationsRuns that measure model quality against your criteria.
MonitoringDashboards of cost, latency, and content-safety metrics.

Do not try to memorize the full navigation tree now. It is enough to know that a project is your sandbox and that the left-hand menu of a project page is where every lab in this course will point you.

Projects are cheap and disposable while you learn, but the model deployments inside them are not. A running paid deployment accrues cost even when nothing calls it. In every lab that deploys a model, note whether the deployment is free-tier and delete it when the chapter says to clean up.

Summary

You can reach Microsoft Foundry through the Azure portal or directly, you understand the layout of its home screen, and you have created your first project — the container that will hold every deployment and evaluation in this course.
