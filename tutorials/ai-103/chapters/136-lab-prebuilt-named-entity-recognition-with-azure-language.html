Lab - Prebuilt Named Entity Recognition with Azure Language

Named entity recognition, or NER, extracts the specific things mentioned in a document — people, organizations, locations, dates, and quantities — and tells you their type. Azure AI Language's prebuilt NER model does this out of the box with no training data. In this lab you will extract entities, inspect their categories and spans, and compare the service's deterministic output with the entity extraction you performed earlier by prompting.

Prerequisites

  • The Azure AI Language resource, endpoint, and key from the earlier labs.
  • The text analytics SDK installed in your ai103-language environment.

Step 1: Set Up the Client

Exercise 1: Create the NER script

Create lang_ner.py:

import os

from azure.ai.textanalytics import TextAnalyticsClient
from azure.core.credentials import AzureKeyCredential
from dotenv import load_dotenv

load_dotenv()

client = TextAnalyticsClient(
    endpoint=os.getenv("AZURE_LANGUAGE_ENDPOINT"),
    credential=AzureKeyCredential(os.getenv("AZURE_LANGUAGE_KEY")),
)

Run the file once to confirm the client builds without error.

Step 2: Extract Entities from a Document

Exercise 2: List entities with types and spans

Append the extraction call:

document = (
    "Acme Robotics shipped its new inspection drone to Frankfurt on "
    "March 12. CEO Dana Whitfield announced the launch at the plant "
    "near Berlin, with a retail price of 2,400 euros."
)

result = client.recognize_entities(documents=[document])[0]
if result.is_error:
    print("Error:", result.error.code, result.error.message)
else:
    for entity in result.entities:
        print(
            f"{entity.text!r:25s} {entity.category:12s} "
            f"sub={entity.subcategory:12s} confidence={entity.confidence_score:.2f}"
        )
  1. Run the script. You should see entries such as Acme Robotics (Organization), Frankfurt and Berlin (Location), March 12 (DateTime), Dana Whitfield (Person), and 2,400 euros (Quantity).
  2. Note the category and subcategory fields. The taxonomy is fine-grained — dates are split into subtypes such as date, time, and duration.

Every entity carries its exact text and the confidence score. Compare this with the prompt-based entity extraction from the earlier lab: the categories here are standardized names, always present, with no prompting required. What you give up is flexibility — the prebuilt model knows its fixed taxonomy, and nothing else.

Step 3: Group Entities by Category

Exercise 3: Summarize the document by category

Group the detected entities into a small report:

from collections import defaultdict

def summarize(doc_text: str) -> dict:
    res = client.recognize_entities(documents=[doc_text])[0]
    if res.is_error:
        return {"error": res.error.message}
    grouped = defaultdict(list)
    for entity in res.entities:
        grouped[entity.category].append(entity.text)
    return {category: values for category, values in grouped.items()}


for category, values in summarize(document).items():
    print(f"{category}: {', '.join(values)}")
  1. Run the script. The document collapses into a compact by-category summary — exactly the shape a dashboard or a database ingest would want.
  2. Try it on a second document, such as a news headline, and confirm the grouping adapts.

Step 4: Process a Batch

Exercise 4: Extract entities from several documents

Run NER over a list of documents in one call:

batch = [
    "Microsoft announced a partnership with Contoso in Redmond last Tuesday.",
    "The conference runs from May 4 to May 6 at the Berlin Exhibition Grounds.",
    "Our supplier increased the unit price to 89 dollars effective July 1.",
]

results = client.recognize_entities(documents=batch)
for i, res in enumerate(results, start=1):
    if res.is_error:
        print(f"Doc {i}: error {res.error.code}")
        continue
    names = ", ".join(e.text for e in res.entities)
    print(f"Doc {i}: {names}")
  1. Run the script. Each document's entities are listed in document order.
  2. Verify the dates and amounts in document three are captured with their own categories.

NER is ideal for normalizing text into structured fields: extract the location, the date, and the amount from a document, then store them as columns. Combined with the confidence scores, you can push low-confidence entities to a review queue and import the rest automatically.

Step 5: Compare with Prompt-Based Extraction

Run the exact same document through the prompt-based extractor from the JSON-output lab, and through this service. The differences you will observe are the point:

  • Categories: the service uses its fixed taxonomy (Organization, Location); the LLM may invent or vary its labels unless you constrain them.
  • Spans: the service returns offsets into the original text; the LLM returns the text it believes is an entity.
  • Cost: the service call is a fixed per-document cost; the LLM call bills for every generated token.
  • Explanation: the LLM can explain why something is an entity; the service cannot.

Choose the service when the taxonomy fits your data and you need deterministic, high-volume extraction. Choose prompting when you need categories the service does not know, or when the analysis must be explainable.
