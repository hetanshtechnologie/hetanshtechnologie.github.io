Lab - Python - GPT 5 - Chat Completion API

The REST lab showed you the raw protocol; now you will call the same endpoint from Python using the official openai SDK. The SDK hides the HTTP plumbing behind a friendly client object, but the request it builds is identical to the one you sent with curl. By the end of this lab you will have a reusable Python script that sends a chat message to your GPT deployment and prints the reply.

What You Will Need

  • Python 3.9 or newer with the openai package installed (python -m pip install openai).
  • Your deployment's endpoint URL and key.
  • The ai103-lab workspace folder in VS Code.

The AzureOpenAI Client

Two client classes exist in the SDK: OpenAI for OpenAI's own service and AzureOpenAI for deployments in Azure AI Foundry. The Azure client differs in the URL it targets and the authentication it uses:

from openai import AzureOpenAI

client = AzureOpenAI(
    azure_endpoint="https://YOUR_ENDPOINT",
    api_key="YOUR_KEY",
    api_version="2024-06-01",
)

Note that the deployment name is passed as the model argument when you call the API — the URL from the REST lab is built for you internally. This is the single most common source of confusion when moving from curl to the SDK.

Step 1: Write the Script

Exercise 1: Send a chat completion from Python

  1. Create a file named chat.py in ai103-lab.
  2. Type the program below.
  3. Substitute your endpoint and deployment name; read the key from an environment variable rather than typing it into the file.
import os
from openai import AzureOpenAI

ENDPOINT = "https://YOUR_ENDPOINT"
DEPLOYMENT = "ai103-chat-deploy"
API_KEY = os.environ["AZURE_OPENAI_KEY"]

client = AzureOpenAI(
    azure_endpoint=ENDPOINT,
    api_key=API_KEY,
    api_version="2024-06-01",
)

messages = [
    {"role": "system", "content": "You are a concise study assistant."},
    {"role": "user", "content": "Explain in one sentence what an API does."},
]

response = client.chat.completions.create(
    model=DEPLOYMENT,
    messages=messages,
    temperature=0.3,
    max_tokens=120,
)

print(response.choices[0].message.content)

Notice the key comes from an environment variable, never from the source file. Reading secrets from the environment keeps them out of git history and out of screenshots — set AZURE_OPENAI_KEY once per terminal session.

Step 2: Set the Key and Run

Set the environment variable, then run the script:

# Windows PowerShell
$env:AZURE_OPENAI_KEY = "YOUR_KEY"
python chat.py
# macOS / Linux
export AZURE_OPENAI_KEY="YOUR_KEY"
python chat.py

The script prints the model's answer to the terminal. If you see an authentication error, the key variable is wrong; a 404 points at the endpoint or deployment name.

If a second terminal does not recognize AZURE_OPENAI_KEY, that is expected — environment variables set in one shell do not leak into another. Set the variable in every new terminal, or move it into a .env file you load explicitly.

Step 3: Inspect the Full Response Object

Change the final print to dump the whole response and see what the SDK gives you:

import json

full = response.model_dump()
print(json.dumps(full, indent=2))

You will see the same fields curl returned: id, object, created, model, choices, and usage. The SDK parses that JSON into typed objects, which is why response.choices[0].message.content works without any manual parsing.

model_dump() converts the SDK object back into a plain dictionary for printing. It is the modern replacement for the older __dict__ tricks and is the easiest way to inspect any response while you learn.

Step 4: Turn the Script into a Reusable Function

Refactor chat.py so any message list can be passed in. This is the shape every later lab reuses:

import os
from openai import AzureOpenAI

client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2024-06-01",
)


def ask(messages, deployment="ai103-chat-deploy", temperature=0.5, max_tokens=200):
    response = client.chat.completions.create(
        model=deployment,
        messages=messages,
        temperature=temperature,
        max_tokens=max_tokens,
    )
    return response.choices[0].message.content


if __name__ == "__main__":
    print(ask([
        {"role": "system", "content": "You are helpful."},
        {"role": "user", "content": "What is machine learning?"},
    ]))

Set both AZURE_OPENAI_ENDPOINT and AZURE_OPENAI_KEY, then run the file. The same ask() function will appear, extended, in the remaining labs.

Putting the call inside a function keeps your code testable and your experiments clean: each lab changes only the messages and parameters passed in, not the networking code.

Summary

You created an AzureOpenAI client, sent a chat-completion request with the SDK, printed the full response object, and refactored the call into a reusable ask() function with credentials read from environment variables. This is the calling pattern you will use for the rest of the course. Next you will add system messages and watch them steer the model's behavior from Python.
