LangChain Agent Core Components

In the previous chapter you saw LangChain's basic building blocks and a simple chain. This chapter adds the piece that turns a chain into an agent: a decision loop that lets the model call tools, inspect results, and keep going until the task is done. We will break down the core components of a LangChain agent — the model, the prompt, tools, memory, and the agent runner — and see how they work together with a concrete example.

What Makes an Agent Different from a Chain

A chain is a fixed sequence: every input flows through the same steps. An agent is a loop: the model decides what to do next, your code executes the chosen tool, the result returns to the model, and the loop repeats until the model decides the task is complete. The difference is that the path is chosen by the model at runtime rather than fixed at design time.

AspectChainAgent
FlowFixed sequence of stepsModel-driven loop
ToolsCalled by fixed codeChosen by the model as needed
End conditionLast stepModel decides it is done
Best forPredictable pipelinesTasks needing decisions and tools

The Five Core Components

Every LangChain agent is assembled from the same five parts:

  1. The model: the chat model that reasons and decides. It must support tool calling, because that is how it requests actions.
  2. The prompt: the instructions that define the agent's role, rules, and how it should use its tools.
  3. Tools: functions exposed to the model with names, descriptions, and argument schemas. A search function, a calculator, or an API call all become tools.
  4. Memory: the conversation state the agent uses to remember what happened earlier in the exchange.
  5. The agent runner: the loop that alternates between asking the model for the next action and executing that action.

Tools are the component that most dramatically changes behaviour. Without tools, an agent is just a chat model in a loop; with tools, it can look things up, compute, and act on external systems.

Defining a Tool

A tool is an ordinary Python function plus a schema that tells the model what it does. LangChain builds the schema from the function signature and docstring. Here is a small tool that returns the number of items in a product catalog:

from langchain_core.tools import tool


@tool
def catalog_count(category: str) -> int:
    """Return the number of products in the given category."""
    counts = {"laptops": 24, "phones": 18, "accessories": 57}
    return counts.get(category, 0)

The docstring becomes the tool's description, and the parameter type becomes its argument schema. The model reads both when deciding whether to call the tool and what arguments to pass.

Connecting the Model and Tools

Once you have a chat model and a tool, you bind the tools to the model. Binding tells the model that these tools exist and are callable in this conversation:

from langchain_openai import AzureChatOpenAI
import os

chat = AzureChatOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2025-01-01-preview",
    model="YOUR_DEPLOYMENT_NAME",
)

tools = [catalog_count]
chat_with_tools = chat.bind_tools(tools)

Building the Agent with a Runner

LangChain provides agents that wire the loop for you. The modern approach is create_agent, which takes the model, the tools, and the system prompt and returns a ready-to-invoke agent:

from langchain.agents import create_agent

agent_prompt = (
    "You are a store assistant. Use the catalog_count tool to answer "
    "questions about product availability. If the category is unknown, "
    "say so honestly."
)

agent = create_agent(
    model=chat,
    tools=tools,
    prompt=agent_prompt,
)

result = agent.invoke({"messages": [("user", "How many phones do you carry?")]})
print(result["messages"][-1].content)

Inside invoke, the runner executes the loop: the model sees the user question and the tool description, requests a call to catalog_count("phones"), your side executes the function, the result returns to the model, and the model writes the final answer.

To see the loop in action, stream the agent's execution instead of waiting for the final answer. LangChain's tracing integration can also log every step of the loop to Application Insights, so you can review which tools ran and why.

Why Tool Schemas Matter

The model never sees your Python code — it sees the tool's name, description, and parameter schema. That means quality of the description directly controls whether the model calls the tool correctly:

  • Name the tool with a verb-noun pair such as lookup_stock.
  • Describe what it returns and when to use it.
  • Keep argument schemas small and typed.

Tools give the model power to act. Every tool you attach should validate its inputs and be safe to call with unexpected arguments, because the model decides when to call it. Log tool invocations so a surprising sequence of calls is visible in your traces.

Summary

A LangChain agent combines five components: a tool-calling model, a system prompt, tools with schemas, memory, and an agent runner that loops until the task is done. You defined a tool from a Python function, bound it to a chat model, and invoked a full agent with create_agent. The next lab gets you hands-on with building an agent in LangChain from scratch.
