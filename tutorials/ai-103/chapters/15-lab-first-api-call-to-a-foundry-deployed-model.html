Lab - First API Call to a Foundry-Deployed Model

In this lab you will make your very first programmatic call to a model that is deployed in Microsoft Foundry. Up to this point you have probably chatted with a model through the interactive playground in the portal. Here we swap the graphical interface for Python code and use the same endpoint and credentials that real applications use. When you finish, you will have a reusable script that sends a message to your deployment, receives the model's reply, and prints it to the console.

What You Need Before Starting

Before you begin, confirm that you have the following pieces in place:

  • Python 3.9 or newer installed on your machine, as set up in the previous chapters.
  • VS Code installed and ready to run Python files.
  • A chat model deployed in your Microsoft Foundry project. If you completed the model deployment lab, you already have one.
  • The endpoint URL and API key for that deployment. You will copy these from the Foundry portal.
  • An active internet connection, because every API call travels to Azure.

If you are not sure which models you deployed, open your Foundry project and browse the Models or Deployments page. Pick a small, fast model such as gpt-4o-mini for this lab so that every call returns quickly and costs almost nothing.

Finding Your Endpoint and Key

The endpoint and key identify your deployment and prove you are allowed to use it. To find them:

  1. Sign in to the Microsoft Foundry portal and open your project.
  2. Navigate to the Models or Deployments page.
  3. Click the deployment you want to call, for example your gpt-4o-mini deployment.
  4. Copy the Target URI (the endpoint) — it looks similar to https://YOUR-RESOURCE.openai.azure.com/.
  5. Copy the Key shown for the deployment.

You will paste both values into your code, but not directly as hard-coded text. In this lab you will store them in environment variables so the script itself contains no secrets.

An API key is a credential. Never paste it into chat windows, screenshots you share, or files that get committed to a public repository. Treat it the same way you treat a password.

Installing the OpenAI Python SDK

Your Python code talks to the deployment through the openai package, which is the official client library for OpenAI and Azure OpenAI-compatible endpoints. Foundry deployments are exposed through the same interface, so the same SDK works.

Open a terminal in VS Code (use Terminal > New Terminal) and install the package:

pip install openai

If pip is not recognized, try python -m pip install openai. On some systems you may need pip3 instead of pip.

Write Your First Chat Script

Step 1 - Create the project folder

Create a folder named ai103-lab15 and open it in VS Code. Inside it, create a new Python file called chat.py.

Step 2 - Set your environment variables

In the integrated terminal, set two environment variables. Replace the placeholder values with the ones you copied from Foundry:

$env:AZURE_OPENAI_ENDPOINT = "https://YOUR-RESOURCE.openai.azure.com/"
$env:AZURE_OPENAI_KEY = "YOUR_KEY"

Step 3 - Paste the script

Paste the following code into chat.py and replace YOUR_DEPLOYMENT_NAME with the name of your deployed model:

from openai import AzureOpenAI
import os

client = AzureOpenAI(
    azure_endpoint=os.environ["AZURE_OPENAI_ENDPOINT"],
    api_key=os.environ["AZURE_OPENAI_KEY"],
    api_version="2025-01-01-preview",
)

response = client.chat.completions.create(
    model="YOUR_DEPLOYMENT_NAME",
    messages=[
        {"role": "system", "content": "You are a concise, helpful assistant."},
        {"role": "user", "content": "What is the capital of Japan?"},
    ],
)

print(response.choices[0].message.content)

Step 4 - Run the script

python chat.py

You should see a short answer such as "The capital of Japan is Tokyo." printed to the console.

Understanding What the API Returns

The call returns a structured response object, not just a string. The parts you will use most often are:

  • response.choices[0].message.content — the text the model produced.
  • response.choices[0].message.role — the role of the message, normally assistant.
  • response.usage.prompt_tokens — how many tokens your input consumed.
  • response.usage.completion_tokens — how many tokens the model generated.
  • response.usage.total_tokens — the combined total.

Add the following line to see your token usage:

print("Total tokens used:", response.usage.total_tokens)

Troubleshooting Common Errors

Error you may seeMost likely causeFix
401 Authentication failedThe API key is wrong or missing.Re-copy the key from Foundry and set the variable again.
404 Resource not foundThe deployment name or endpoint is incorrect.Check that model matches your deployment name exactly.
Connection errorNetwork issue or wrong endpoint URL.Verify the endpoint starts with https:// and ends with a slash.
ModuleNotFoundError: openaiThe SDK is not installed in the active Python environment.Run pip install openai in the same terminal you use to run the script.

The api_version value identifies which API surface you are speaking. If you change it, some parameters may not be recognized. When in doubt, use the version suggested in your Foundry deployment page.

Summary

You have made your first programmatic call to a Foundry-deployed model. You found the endpoint and key, installed the OpenAI SDK, sent a chat message from Python, and read the structured response. This script is the foundation for everything that follows: the same client object and pattern will now be extended with new parameters, new message types, and eventually tools and agents.
