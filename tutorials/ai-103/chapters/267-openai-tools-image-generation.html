OpenAI - Tools - Image Generation

In the previous chapter you saw the general idea behind tools: the model decides that it needs information or an action it cannot produce itself, and it asks your application to supply that piece through a structured request. Image generation is one of the tools that the API can invoke for you. Instead of writing code that calls an image endpoint directly and then asking the model to react to the result, you declare an image generation tool, and the model requests the image at the moment it decides the conversation needs one. This chapter explains how that tool works and how you read its output.

What the Image Generation Tool Does

The image generation tool gives the model the ability to create pictures on demand. When you attach the tool to a request, the model can decide — based on your instructions and the conversation — that producing an image is the right way to respond. The tool takes a text description as its effective input and returns a freshly generated image.

This is different from a hand-coded flow where you detect a keyword, call an image API yourself, download the result, and hand it back to the model. With the tool, the model performs that coordination. Your code still receives the image, but the decision about when to generate one is made by the model inside the same response.

Declaring the Tool

You attach the tool by adding an entry to the tools list in your request. Each entry declares the tool type, a name your code can recognize, a description the model reads to decide when to use it, and a couple of settings that shape the output.

from openai import OpenAI
import os

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

response = client.responses.create(
    model="gpt-5",
    instructions="You are a designer who creates product illustrations on request.",
    input="Generate an image of a hiking backpack for our product page.",
    tools=[
        {
            "type": "image_generation",
            "name": "image_gen",
            "description": "Creates an image from a detailed text description.",
            "input_size": 1024,
            "output_format": "png",
        }
    ],
)

The same declaration looks like this if you prefer to call the REST API directly:

{
  "model": "gpt-5",
  "input": "A red fox standing in a snowy forest at dusk",
  "tools": [
    {
      "type": "image_generation",
      "name": "image_gen",
      "description": "Generates an image from a detailed text description.",
      "input_size": 1024,
      "output_format": "png"
    }
  ]
}

Understanding the Tool Settings

Two settings deserve attention because they shape the images you get back:

  • input_size — the edge length of the generated image in pixels. A single number such as 1024 produces a square image at that resolution. Larger sizes use more compute, so choose the smallest size that satisfies your use case.
  • output_format — the encoding of the returned image, commonly png or jpeg. PNG preserves detail and supports transparency; JPEG produces smaller files at a slight quality cost.

Keep the description on the tool short and behavioral: tell the model when to use the tool and what it produces. The fine detail of the image itself belongs in the conversation, not in the tool schema.

How the Model Decides to Use the Tool

The model does not generate an image automatically just because the tool is attached. It weighs the request against your instructions and picks the tool only when producing an image is genuinely the best response. If you ask a purely textual question while an image tool is attached, the model answers with text and never touches the tool.

This decision making is why tool schemas carry descriptions: the model reads them to learn what each tool does. A precise description, such as "creates product illustrations" instead of "creates images", steers the model toward appropriate use and away from generating images for every question.

Reading the Tool Output

When the model generates an image, the response contains a new output item for it. Your code walks the output list and looks for the image item, then either displays the returned URL or saves the base64-encoded image data to a file.

for item in response.output:
    if item.type == "image":
        # The exact attribute depends on your SDK version;
        # it is typically a public URL or base64 image data.
        if getattr(item, "url", None):
            print("Image URL:", item.url)
        else:
            print("Image saved as base64 data, length:", len(item.image_base64))

The Responses API groups everything that happened during the call into one output list: the reasoning, the tool call, and the generated artifact. Iterating the list and switching on the item type is the reliable pattern, because the order of items is not guaranteed.

Tool-Driven vs. Direct Image Generation

There are two legitimate ways to generate images with these models, and the choice depends on who decides.

ApproachWho decidesBest when
Direct image API callYour codeYou know in advance that every request must produce an image, such as a form that always renders a logo
Image generation toolThe modelThe conversation is open-ended and the model should decide when an image helps

In a workflow where images are always required, a direct call is simpler and cheaper to reason about. In an assistant that mixes text answers with occasional images, the tool keeps the decision logic inside the model where it naturally belongs.

Responsible Use

Generated images carry the same risks as any generative output, plus a few of their own:

  • Models can depict real people or brands in ways you should not assume are accurate or permissible.
  • Images intended to mislead or impersonate require the same scrutiny as synthetic text.
  • Audit the prompts your application sends. User-supplied descriptions can be used to attempt to bypass your content policies.

Never let a generated image be presented as a real photograph of a real event or person without a clear label. Add visible watermarks or disclaimers in applications where users could confuse synthetic images with reality.

Summary

The image generation tool moves the decision of when to create an image into the model. You declare the tool with a name, a description, a size, and a format; the model calls it during the response; and your code finds the generated image in the output items. Use the tool when the model should control whether an image is needed, and use direct calls when every request must produce one.
