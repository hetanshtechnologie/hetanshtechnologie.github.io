Lab - Retrieval Augmented Generation - Data Preparation

Before any text can be searched or embedded, it has to be extracted from its source documents, cleaned, and split into chunks. This lab does exactly that for the CloudXeus support material. By the end you will have a JSONL file, chunks.jsonl, where every line is one chunk of text plus metadata that the search index can consume in the next labs.

About the Data

Gather a small set of CloudXeus documents. If you have your own PDFs, put up to a dozen of them in data/source. If not, create a few short text files that read like support material, for example an FAQ about a fictional CloudXeus EdgeCam 300 security camera. The pipeline is identical either way; only the source files change.

Aim for a few hundred kilobytes total. This keeps the free search tier and quick indexing runs comfortable while still giving you meaningful chunks to search.

Extracting Text

For PDFs we use pypdf to pull the text out of each page. The script below walks the source folder and produces one string per PDF, keeping the filename so we can trace chunks back to their origin.

from pathlib import Path
from pypdf import PdfReader

SOURCE_DIR = Path("data/source")

def extract_pdfs(folder: Path) -> list[dict]:
    docs = []
    for pdf_path in sorted(folder.glob("*.pdf")):
        reader = PdfReader(str(pdf_path))
        text = "\n".join(page.extract_text() or "" for page in reader.pages)
        docs.append({"title": pdf_path.stem, "source": pdf_path.name, "text": text})
    return docs

Cleaning the Text

Extracted text is full of stray whitespace, awkward line breaks, and odd unicode. A short cleaning pass normalizes it so chunking works on real sentences rather than fragments.

import re

def clean_text(text: str) -> str:
    text = text.replace("\r\n", "\n")
    text = re.sub(r"[ \t]+", " ", text)
    text = re.sub(r"\n{3,}", "\n\n", text)
    text = re.sub(r"[^\S\n]+", " ", text)
    return text.strip()

Chunking the Documents

Chunks are the units of retrieval: too large and they are vague, too small and they lack context. A useful default is to aim for roughly 400 to 600 words per chunk with a small overlap so a topic that straddles a boundary is still captured.

def chunk_text(text: str, chunk_words: int = 450, overlap_words: int = 50) -> list[str]:
    words = text.split()
    chunks = []
    start = 0
    while start < len(words):
        end = min(start + chunk_words, len(words))
        chunks.append(" ".join(words[start:end]))
        if end == len(words):
            break
        start = end - overlap_words
    return chunks

Writing Chunks to JSONL

Each chunk becomes a JSON line with an id, the source title, and the cleaned text. The JSONL format is easy for the indexing script to stream later.

import json

def build_chunks(docs: list[dict]) -> list[dict]:
    records = []
    for doc in docs:
        chunks = chunk_text(clean_text(doc["text"]))
        for i, chunk in enumerate(chunks):
            records.append({
                "id": f"{doc['source']}-{i:03d}",
                "title": doc["title"],
                "source": doc["source"],
                "content": chunk,
            })
    return records

Running the Pipeline

Exercise — Generate the Chunk File

  1. Save the code blocks above into scripts/prepare_data.py, keeping the imports at the top and adding these calls at the bottom:
docs = extract_pdfs(SOURCE_DIR)
records = build_chunks(docs)
out = Path("data/chunks.jsonl")
with out.open("w", encoding="utf-8") as fh:
    for record in records:
        fh.write(json.dumps(record, ensure_ascii=False) + "\n")
print(f"Wrote {len(records)} chunks to {out}")
  1. Run python scripts/prepare_data.py from the project root.
  2. Confirm the output: it should print the number of chunks, and data/chunks.jsonl should exist.
  3. Inspect the first lines with Get-Content data\chunks.jsonl -TotalCount 2 (Windows) or head -n 2 data/chunks.jsonl (macOS/Linux).

If a PDF yields little or no text, the pages may be scanned images. Run such a file through an OCR tool or replace it with a text version for now; OCR is a separate topic covered later in the course.

Summary

Your source documents are now extracted, cleaned, and split into uniform chunks stored in data/chunks.jsonl. Each chunk carries the metadata the search index will need.
