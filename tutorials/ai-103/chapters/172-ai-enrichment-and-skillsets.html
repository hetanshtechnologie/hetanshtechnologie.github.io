AI Enrichment and Skillsets

So far your index stores raw extracted text. That is enough for keyword search, but not for the semantic search RAG needs. AI enrichment changes the picture: during indexing, a pipeline of skills transforms each document — extracting entities, recognizing language, splitting text, and computing embeddings — so the resulting index carries meaning, not just words. This chapter explains what skillsets are, which built-in skills matter for RAG, and how the enrichment pipeline fits inside the indexer.

What a Skillset Is

A skillset is a collection of AI operations that run on each document as the indexer processes it. Every skill takes input fields, does one focused job, and produces output fields. Skillsets attach to an indexer, and the indexer orchestrates them in the order you declare them. The outputs can be written to the index, or stored in a knowledge store — a separate Azure Storage location that keeps the enriched structures for later use.

Enrichment changes the pipeline from copy text into the index to extract, understand, transform, and then store. The skills run in sequence, so one skill's output can feed the next skill's input.

A skill never modifies the original source document. Enrichment produces new derived fields that live in the index or the knowledge store. The blob in storage stays untouched, which keeps the pipeline safe to re-run.

Built-In Skills You Will Use

Azure AI Search ships a catalog of prebuilt skills. The ones that matter most for RAG fall into four groups:

SkillWhat it doesWhy RAG cares
Document ExtractionPulls text and layout from PDFs, Office files, and images (OCR)Makes scanned and structured documents searchable
Language Detection / Entity RecognitionDetects language, names, organizations, locationsEnables metadata filters and topic grounding
Text SplitSplits long text into chunks of a target sizeProduces the chunks that get embedded and retrieved
AzureOpenAIEmbeddingEmbeds a chunk with a deployed embedding modelCreates the vector field that powers semantic search

Each skill consumes context — usually the whole document or one chunk of it — and emits outputs under a structured path such as /document/content or /document/chunks/*.

How Skills Flow Through the Pipeline

A typical RAG skillset chains skills in this order:

  1. Extract text from the source file with the document extraction skill.
  2. Split the extracted text into overlapping chunks with the text split skill.
  3. Embed each chunk with the embedding skill, producing a vector per chunk.
  4. Map the chunk text and vectors into the index fields via output field mappings.

The indexer definition is what ties this together. Skillsets are referenced by name from the indexer, and outputFieldMappings tell the indexer where each skill output lands in the index — for example, the embedding skill's vector output flowing into the index's embedding field.

Enrichment costs money. Each skill invocation that calls an AI service — document intelligence for extraction or an OpenAI deployment for embeddings — is billed by that service. A large document collection with OCR and embedding can accumulate noticeable charges, so design skillsets to skip enrichment when it is not needed, and always set chunk sizes deliberately to control embedding calls.

Text Split: The Skill Everything Hangs On

Chunking quality drives retrieval quality. The text split skill splits content on a chosen pageSize (in characters or tokens) with an optional overlap so context survives chunk boundaries. Typical settings for RAG:

  • pageSize around 800 tokens — small enough to keep answers focused.
  • overlap of about 15 percent — keeps a sentence that spans a boundary in both chunks.
  • splittingMode of pages for text or definedLength when you need exact sizes.

There is no universally correct size. Short chunks retrieve more precisely but lose surrounding context; long chunks keep context but dilute relevance. Your chunking parameters should be tuned against real questions from your domain.

The Knowledge Store

Besides the index, a skillset can write its enriched output to a knowledge store — a projection of the enriched documents into Azure Tables or Blob Storage. This is useful when you want the enriched data for other systems, dashboards, or re-indexing without re-running the skills. Think of it as a by-product of indexing rather than the search path itself.

When a RAG answer seems wrong, inspect the chunks rather than blaming the model. Search the knowledge store or log the retrieved chunks. If the right information is not inside them, the split size, overlap, or embedding model — not the chat model — is what needs adjusting.

Summary

A skillset is an ordered list of AI skills that enrich documents during indexing. Document extraction makes content readable, text split turns it into chunks, and embedding turns each chunk into a vector. Skill outputs flow into the index through output field mappings, and a knowledge store can keep enriched structures for other consumers.
