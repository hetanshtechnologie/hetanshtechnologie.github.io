Glossary

TermMeaning
BaselineA simple reference model (mean prediction, majority class) every better model must beat.
Bias (statistical)Systematic error from a model being too simple (underfitting).
Bias (fairness)Systematic disadvantage of one group caused by data, labels, model, or deployment.
BootstrapResampling with replacement to estimate uncertainty without formulas.
Confidence intervalRange of plausible values for a parameter from a procedure with known coverage.
Cross-validationRepeated train/validate splits that estimate generalization performance.
Data driftThe input distribution shifts from what the model was trained on.
ELTExtract, Load, Transform — load raw data first, transform in the warehouse.
EmbeddingA dense numeric vector representing text (or other objects) so similarity is distance.
Exploratory Data AnalysisThe disciplined exploration of data to find patterns, problems, and hypotheses.
FeatureAn input column a model uses to make predictions.
Feature storeA system serving the same features to training and live scoring.
ImputationFilling missing values with estimates (mean, median, mode, model prediction).
LeakageInformation from the future/test set entering training, inflating performance.
Model cardA one-page spec of a model: purpose, data, metrics, limitations, uses.
OverfittingMemorizing training noise; great train scores, poor test scores.
p-valueProbability of the observed result (or more extreme) if the null hypothesis were true.
PipelineChained preprocessing + model steps executed and saved as one object.
PowerThe probability of detecting a true effect (1 − Type II error).
StationarityA time series with constant mean and variance over time.
Train/test splitHolding out part of the data to evaluate generalization.
Variance (statistical)Error from a model being too sensitive to training data (overfitting).
Window functionA SQL function computing over a row set without collapsing rows.

Public Datasets to Practice On

  • Kaggle — competitions and datasets with notebooks to learn from.
  • UCI ML Repository — classic datasets for every task.
  • Google BigQuery public datasets — huge real-world tables for SQL and cloud practice.
  • Statsmodels / seaborn sample datasets — built-in practice data.
  • Awesome Public Datasets — a curated index of everything else.

Books & Documentation to Keep Around

  • pandas documentation — the reference you will use daily.
  • scikit-learn user guide — best in-class explanations of every algorithm.
  • "Python for Data Analysis" (Wes McKinney) — pandas depth.
  • "An Introduction to Statistical Learning" (James, Witten, Hastie, Tibshirani) — the theory behind Chapters 10–12.
  • "Storytelling with Data" (Cole Nussbaumer Knaflic) — chart design and narrative.
  • "The Elements of Statistical Learning" (Hastie et al.) — the deeper graduate-level companion.

Concepts to Revisit Per Chapter

ChapterKey ideas to remember
1Data science = stats + code + domain. Frame the problem first.
2Virtual environments, Git, notebooks for exploration, modules for production.
3Document provenance and licenses; respect APIs and scraping rules.
4Missingness strategy, dedupe with intent, investigate outliers, never leak.
5EDA generates testable hypotheses; mean vs median; correlation ≠ causation.
6Pick the right chart, label everything, keep axes honest.
7Base rates matter (Bayes); CLT powers inference; CI is a procedure property.
8Pre-register tests, size for power, don't peek, correct for multiple comparisons.
9Execution order, joins and cardinality, window functions, CTEs.
10Generalize, not memorize; leakage; bias-variance; metrics match the task.
11Pipeline everything; baseline first; SHAP to explain.
12Scale features before clustering; validate segments by business actionability.
13Chronological splits; decompose; stationarity; forecast error vs baseline.
14TF-IDF for medium texts; embeddings for meaning; anonymize text data.
15Features beat algorithms; no future leaks; monitor drift after launch.
16Filter early on the cloud; MLflow for runs; register models.
17Audit across groups; write model cards; keep a human for high stakes.
18Complete documented projects beat many demos; interviews test fundamentals.
