18. Projects, Portfolio & Career Path

Chapter 18

The Portfolio Is the Resume

Employers cannot see your coursework, but they can read your code and notebooks. A small number of complete, documented projects beats a long list of started-but-unfinished ones. Each project should tell a story: problem → data → analysis → model → conclusion → action.

The Three Signature Projects

ProjectWhat it provesBuilds on
1. End-to-end EDA + dashboardWrangling, analysis, visualization, communicationCh. 3–6
2. Predictive model with deploymentML workflow, pipelines, serving, monitoringCh. 10–15
3. A specialization (time series / NLP / clustering)Depth in one areaCh. 12–14

What Makes a Project Stand Out

  • A real question, not a toy dataset demo — "predict my city's bike-share demand," "segment our store's customers."
  • Clean code: README.md with setup instructions, well-named modules, no notebooks full of dead cells.
  • Good hygiene: requirements.txt, .gitignore, a license, and commits with meaningful messages.
  • A model card (Chapter 17) and an honest discussion of limitations.
  • Deployment: a live Streamlit app or FastAPI endpoint is worth more than ten notebooks.
  • Visuals: a strong readme image or dashboard screenshot.

Portfolio Checklist

  1. GitHub profile with 2-3 pinned repositories, each documented.
  2. A one-page resume: skills, 2-3 projects with measurable outcomes, tools.
  3. A LinkedIn presence with your projects linked.
  4. Optional but powerful: a short blog post or notebook walkthrough for your best project.

Career Roadmap

  1. Foundations (weeks 1-8): Chapters 1–9 — Python, pandas, EDA, stats, SQL.
  2. Modeling (weeks 9-14): Chapters 10–15 — ML, pipelines, deployment.
  3. Depth (weeks 15-18): Pick a track — forecasting, NLP, or cloud/MLOps (Chapters 13, 14, 16).
  4. Portfolio (weeks 19-24): Build and polish the three signature projects; write model cards.
  5. Job search: apply widely, ask for feedback on rejections, and keep one project improving while you interview.
Growth mindset: data science changes fast. The durable skills are the ones this book emphasizes — asking the right question, clean data work, honest statistics, clear communication, and responsible practice. Tools change; those skills compound.

Community & Continued Learning

  • Kaggle competitions (start with getting top 25%, not winning).
  • Open-source: contribute documentation or bug fixes to the libraries you use.
  • Meetups and conferences (local or virtual) to meet practitioners.
  • Follow the maintainers and papers of your favorite tools.
