2. Setting Up Your Data Science Environment

Chapter 2

Why Environment Setup Matters

A reproducible environment is the foundation of every data science project. If your code works on your machine but not a teammate's, it is not yet science. This chapter sets up a clean, version-controlled Python workspace you will use for the rest of the book.

Install Python

Install a recent Python 3 (3.10 or newer) from python.org. On Windows, tick "Add Python to PATH" during installation. Verify:

python --version
# Python 3.12.x
Python vs Anaconda: Anaconda bundles Python with a large scientific stack and is convenient for beginners. For this book a plain Python install plus pip and virtual environments is cleaner and matches how professionals work. Choose Anaconda only if you prefer its ecosystem.

Virtual Environments

A virtual environment isolates the packages of one project from the rest of your system, so different projects can use different versions of the same library without conflicts.

# Create a project and its environment
mkdir data-science-project
cd data-science-project
python -m venv .venv

# Activate (Windows)
.venv\Scripts\activate
# Activate (macOS / Linux)
source .venv/bin/activate

# Install the scientific stack
pip install numpy pandas matplotlib seaborn scikit-learn jupyter scipy statsmodels plotly

Record your dependencies so the project is reproducible:

pip freeze > requirements.txt
# or, the modern alternative
pip install pip-tools
When to upgrade: data science libraries release frequently. Pin exact versions in requirements.txt for reproducibility, but test upgrades in a branch so you know what changes break your work.

Jupyter Notebooks

Jupyter notebooks combine code, output, text, and visualizations in one document — ideal for exploration. Launch from your activated environment:

jupyter notebook
# or the newer web app
jupyter lab

Notebooks are great for exploration but poor for production code. A healthy pattern: explore in notebooks, then move the working logic into plain .py modules that notebooks import.

Notebook hygiene: notebooks silently keep stale state (a variable from a deleted cell still exists). Run cells top-to-bottom and occasionally restart the kernel and run all to confirm the notebook actually works.

VS Code as Your Editor

VS Code is a great all-rounder for data science: full Python debugging, Git integration, and Jupyter support built in.

  • Install the Python and Jupyter extensions.
  • Open your project folder and select your .venv as the interpreter (Ctrl+Shift+P → Python: Select Interpreter).
  • Use the built-in terminal so your active environment is consistent with the editor.

Git & GitHub

Version control is non-negotiable: it is your undo history, your backup, and your portfolio.

git init
git add .
git commit -m "Initial data science project"
git branch -M main
git remote add origin https://github.com/you/data-science-project.git
git push -u origin main

Add a .gitignore to avoid committing junk:

# .gitignore
.venv/
__pycache__/
.ipynb_checkpoints/
.DS_Store
*.ipynb   # optional — some teams commit notebooks deliberately
Reproducibility gold standard: environments can also be captured as conda env export > environment.yml or as a Dockerfile. For this book, requirements.txt + a README with setup instructions is enough.

Your First Data Science Script

import numpy as np
import pandas as pd

data = pd.DataFrame({
    "age": [25, 31, 45, 28, 52, 33],
    "spend": [120, 250, 480, 180, 610, 220]
})

print(data.describe())
#       age       spend
# count  6.0    6.000000
# mean  35.7   310.000000
# ...
