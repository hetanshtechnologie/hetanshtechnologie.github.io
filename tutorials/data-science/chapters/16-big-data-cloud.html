BigQuery for Data Science

BigQuery answers SQL on huge tables almost instantly. It also trains models and makes predictions without moving data:

-- Train a model in SQL (BigQuery ML)
CREATE OR REPLACE MODEL `project.dataset.churn_model`
OPTIONS(model_type='LOGISTIC_REG', input_label_cols=['is_churned']) AS
SELECT spend, support_tickets, tenure, is_churned
FROM `project.dataset.customer_features`;

-- Predict
SELECT *
FROM ML.PREDICT(MODEL `project.dataset.churn_model`,
                (SELECT spend, support_tickets, tenure FROM `project.dataset.new_customers`));
Read this before computing: cloud services bill by bytes scanned and compute time. Filter early, select only needed columns, partition and cluster tables, and use previews before running queries. A SELECT * over a huge table is an expensive habit.

Spark: Distributed Python

Apache Spark runs pandas-style operations across a cluster. Its DataFrame API feels familiar:

# pip install pyspark
from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("ds").getOrCreate()

df = spark.read.parquet("gs://my-bucket/events/")
df.printSchema()

from pyspark.sql import functions as F
summary = (df
    .filter(F.col("event_type") == "purchase")
    .groupBy("customer_id")
    .agg(F.sum("amount").alias("total_spend"),
         F.count("*").alias("orders"))
    .orderBy(F.col("total_spend").desc())
    .limit(1000))
summary.show()

Spark lazily builds a plan and only executes when an action (show, count, write) runs — so you can chain transforms without materializing intermediates.

Scaling Machine Learning

Scikit-learn does not scale horizontally. Options:

  • Spark MLlib — distributed training of classical models.
  • XGBoost/LightGBM + Dask — distributed gradient boosting.
  • BigQuery ML — train in-warehouse without a cluster.
  • Deep learning frameworks (PyTorch/TensorFlow) — GPU training, distributed data parallel.

MLOps: The Production Discipline

MLOps applies DevOps practices to machine learning so models ship reliably and stay healthy:

  • Versioning — code, data, and models all versioned (dvc or cloud ML metadata).
  • Reproducible runs — same inputs → same outputs; log parameters and metrics (MLflow).
  • CI/CD — tests run before a model is promoted; automated pipelines rebuild on data changes.
  • Registry — model registry holds approved versions with metadata (Vertex AI Model Registry, MLflow).
  • Monitoring & retraining — drift detection and scheduled retraining (Chapter 15).

A Pragmatic Cloud Workflow

  1. Prototype locally in a notebook on a sample.
  2. Move heavy ETL to the warehouse (BigQuery SQL) or a Spark job.
  3. Train with managed ML (or BigQuery ML) so jobs are tracked and reproducible.
  4. Register the model and serve via batch or an endpoint.
  5. Schedule pipelines and monitor drift.
