9. SQL for Data Science

Chapter 9

Why Data Scientists Need SQL

Most business data lives in relational databases and warehouses. Even with pandas skills, you will reach for SQL because the data is too large to copy, or because it lives behind a warehouse that only answers SQL. SQL is the most transferable data skill — every BI tool, warehouse, and many pipelines speak it.

Core Query Shape

SELECT city, COUNT(*) AS customers, AVG(spend) AS avg_spend
FROM customers
WHERE plan = 'enterprise'
GROUP BY city
HAVING AVG(spend) > 500
ORDER BY avg_spend DESC
LIMIT 10;

Execution order (conceptual): FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT. This explains why you cannot use an alias defined in SELECT inside WHERE but can in ORDER BY.

Filtering & NULLs

SELECT * FROM orders
WHERE created_at >= '2026-01-01'
  AND status IN ('paid', 'shipped')
  AND discount IS NOT NULL;      -- NULLs need IS NULL / IS NOT NULL

Joins

JoinRows returned
INNER JOINOnly rows that match in both tables
LEFT JOINAll rows from the left table, matched rows from the right (NULL where missing)
RIGHT JOINAll rows from the right table (mirror of LEFT)
FULL OUTER JOINAll rows from both
SELECT o.order_number, o.total, c.full_name
FROM orders o
LEFT JOIN customers c ON c.id = o.customer_id
WHERE c.full_name IS NULL;   -- orders with no customer
Cardinality check: a JOIN that multiplies rows (one-to-many joined to another one-to-many) inflates aggregates. After joining, verify COUNT(*) against expectations before trusting your numbers.

Aggregation

SELECT
  date_trunc('month', created_at) AS month,
  COUNT(*)                         AS orders,
  SUM(total)                       AS revenue,
  AVG(total)                       AS avg_order,
  MIN(total)                       AS min_order,
  MAX(total)                       AS max_order
FROM orders
GROUP BY 1
ORDER BY 1;

Window Functions

Window functions compute over a set of rows without collapsing them — perfect for rankings, running totals, and comparisons.

SELECT
  order_number, customer_id, total,
  ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY created_at) AS order_num,
  SUM(total) OVER (PARTITION BY customer_id)                      AS lifetime_value,
  LAG(total)  OVER (PARTITION BY customer_id ORDER BY created_at) AS prev_order,
  total - LAG(total) OVER (PARTITION BY customer_id ORDER BY created_at) AS delta,
  RANK()      OVER (ORDER BY total DESC)                          AS rank
FROM orders;

CTEs (Common Table Expressions)

CTEs make complex queries readable and reusable:

WITH cohort AS (
  SELECT customer_id, MIN(created_at)::date AS first_order_date
  FROM orders GROUP BY customer_id
)
SELECT
  date_trunc('month', c.first_order_date) AS cohort_month,
  COUNT(DISTINCT c.customer_id)           AS customers,
  COUNT(DISTINCT o.customer_id)           AS retained
FROM cohort c
LEFT JOIN orders o ON o.customer_id = c.customer_id
  AND date_trunc('month', o.created_at) = date_trunc('month', c.first_order_date) + INTERVAL '1 month'
GROUP BY 1;

Querying with pandas-sql combo

import sqlite3, pandas as pd
conn = sqlite3.connect("data/app.db")

# pull a subset to pandas, then analyze
df = pd.read_sql_query("""
  SELECT c.city, o.total, o.created_at
  FROM orders o JOIN customers c ON c.id = o.customer_id
  WHERE o.created_at >= '2025-01-01'
""", conn)
conn.close()
BigQuery in the browser: for large public data, Google BigQuery's free tier lets you practice SQL on real datasets (e.g., GA4 sample data, GitHub commits) with no setup — an excellent playground to master warehouse SQL and window functions.

Query Performance Habits

  • Filter (WHERE) before joining and aggregating where possible.
  • Only SELECT the columns you need.
  • Use EXPLAIN on warehouses to see the plan.
  • In BigQuery, partition and cluster tables by the columns you filter most.
  • Prefer COUNT(DISTINCT ...) over joining to dedupe.
