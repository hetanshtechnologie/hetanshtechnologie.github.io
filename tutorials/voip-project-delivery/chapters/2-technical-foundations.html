2. Technical Foundations

Part II

SIP Protocol Deep Dive

SIP (Session Initiation Protocol) is an application-layer control protocol defined in RFC 3261. It is text-based, similar to HTTP, and uses a request-response model.

Key SIP Methods

MethodPurpose
INVITEInitiate a session (call setup)
ACKConfirm receipt of final response to INVITE
BYETerminate a session
REGISTERRegister a SIP URI with a registrar
CANCELCancel a pending request
OPTIONSQuery capabilities of a SIP server
SUBSCRIBE / NOTIFYEvent notification (presence, MWI)

Key SIP Headers

  • From / To — Identifies originator and recipient
  • Call-ID — Unique identifier for the call session
  • CSeq — Command sequence number for ordering
  • Via — Path taken by the request (used for routing responses)
  • Contact — Direct contact address for subsequent requests
  • Content-Type / Content-Length — Describes the message body (typically SDP)

Call Flow and Signaling

A complete SIP call flow between two endpoints (Alice and Bob) via a SIP proxy:

Alice                    SIP Proxy                  Bob
  |                          |                       |
  |------- INVITE ---------->|                       |
  |                          |------- INVITE ------->|
  |                          |<--- 180 Ringing -----|
  |<--- 180 Ringing --------|                       |
  |                          |<--- 200 OK ----------|
  |<--- 200 OK --------------|                       |
  |------- ACK ------------->|                       |
  |                          |------- ACK --------->|
  |                          |                       |
  |<================= RTP Media (direct) ============>|
  |                          |                       |
  |------- BYE ------------->|                       |
  |                          |------- BYE --------->|
  |                          |<--- 200 OK ----------|
  |<--- 200 OK --------------|                       |
SDP (Session Description Protocol): Carried in the INVITE and 200 OK bodies, SDP describes media capabilities — codecs, IP addresses, ports, and media types (audio, video).

NAT Traversal and Media Handling

NAT (Network Address Translation) poses a significant challenge in VoIP because SIP and RTP carry IP addresses in their payloads, not just in packet headers. Solutions include:

STUN (Session Traversal Utilities for NAT)

Allows endpoints to discover their public IP address and port by querying a STUN server. Works for most NAT types but not symmetric NAT.

TURN (Traversal Using Relays around NAT)

When STUN fails, TURN relays media through a public server. Essential for peer-to-peer calls where both parties are behind symmetric NAT.

ICE (Interactive Connectivity Establishment)

A framework that combines STUN and TURN to find the best media path. Endpoints gather candidate addresses (host, server-reflexive, relayed) and test connectivity through connectivity checks.

SBCs (Session Border Controllers)

SBCs sit at network borders and handle NAT traversal by fixing SIP headers and managing RTP sessions. They also provide security, QoS marking, and protocol normalization.

Security in VoIP Systems

  • TLS (Transport Layer Security) — Encrypts SIP signaling between endpoints and servers (SIPS URI scheme).
  • SRTP (Secure RTP) — Encrypts and authenticates RTP media streams; prevents eavesdropping and tampering.
  • Authentication — SIP digest authentication (MD5) for REGISTER and INVITE requests.
  • DDoS Prevention — Rate limiting, fail2ban, geo-blocking, and SIP-aware firewalls.
  • Filtering — Block toll fraud attempts, rogue REGISTER attempts, and malformed SIP messages.

Integrating VoIP with Cloud Infrastructure

Deploying VoIP on cloud platforms like AWS, Azure, or GCP requires careful architecture:

  • Compute — Use VM scale sets or containerized (Docker/Kubernetes) deployments for media and signaling servers.
  • Networking — VPCs with proper security groups; Elastic IPs for public-facing SBCs; VPN for PSTN gateway connectivity.
  • Monitoring — Cloud-native monitoring (CloudWatch, Azure Monitor) plus VoIP-specific tools (Homer, SIPp).
  • Scaling — Auto-scaling groups based on CPU/memory for signaling; careful capacity planning for media (RTP) which requires consistent network performance.
  • High Availability — Deploy SIP servers across availability zones; use load balancers for SIP traffic; geo-redundant SBCs.

Summary

A strong grasp of SIP signaling, call flows, NAT traversal techniques, and security fundamentals is critical before building or managing VoIP systems. Cloud deployment brings scalability and resilience but requires attention to network architecture and monitoring.
